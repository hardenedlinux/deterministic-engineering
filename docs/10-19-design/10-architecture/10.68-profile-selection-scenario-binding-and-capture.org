* SPECIFIED P3 result and trust boundary
:PROPERTIES:
:CUSTOM_ID: p3-selection-binding-capture
:STATUS: Source/design and static documentation only; no implementation, acquisition execution, acceptance run or delivery
:END:

P3 consumes actual checked Library Scopes, binds a normalized Profile to a supported
model/slice/policy and explicit project request, acquires independently required
inputs at their actual owners, and forms one Scenario-owned capture C. The same C
is consumed by later methods, observers, ResourceEvidence, Aitia and receiver work.
Profile intent, structural conformance, source acquisition, actual capture issuance
and current eligibility are separate assertions. None substitutes for the others.

This chapter consolidates 10.56 with P0-P2. It keeps POO values/Function Types,
existing Core Scope/read/verification mechanisms and actual qualified Host inputs.
It adds no Profile loader, public hash-signing service, provenance registry, second
Rust Context, C reconstruction route or Aitia verification-purpose symbol.
Origin binding below is a target composition of existing mechanisms, not a claim
that current Scenario code or Core alone implements authenticated project capture.

* SPECIFIED Project request, independent demand and acquisition
:PROPERTIES:
:CUSTOM_ID: p3-input-demand-acquisition
:END:

bind consumes an explicit project request as well as the Profile: intended subject,
repo/worktree restrictions, logical Library/reference/project roles, permitted read
and output intent, bounded acquisition class and relevant prior mandate references.
A path/URL/revision supplied by a caller is a request, not an observed source fact
or permission to install, fetch, build, run verification or submit review.

Selection derives complete independently required units/input roles first from
selected declarations, claims, parameters, policy and intended operation. Acquisition
then supplies every required role with qualified observation or a typed gap. Bounded
list/map keys and multiplicities come from P1; premise IDs are not new role enums.

| Input role / actual owner | Required acquired basis and limit |
|----------------------------+-----------------------------------|
| Library/provider | Actual checked Generic/Rust/Integration/parents/policies/Contracts/mapping/delta/asset and selected implementation sources; dirty/import/build/load associations as required or explicit unresolved gap |
| Reference six-case workload | Provider-owned crate/lock/source/oracle/protocol and required facet definitions when selected. Distinct reference subject; results never silently prove a network-service implementation |
| Project implementation | Explicit repo/worktree/subject, observed revision plus included dirty/untracked bytes, path/include/exclusion/negative-directory observations, lock/build/model/config inputs and full required dependency domains |
| Architecture/Org/decision products | Exact required/actual product role, bytes/base/selector/actual-target/historical-current, reference demand and retained access/limits; shared sections permitted with real coverage |
| Tools/environment | Actual selected executable/source/compiled/ABI/config/env/worker/limit identities from supported qualified reads; requested tool labels are not observed versions or execution results |
| Governance/history/receiver intent | Actual adopted mandate/policy/role/source/recipient-purpose inputs with qualified origins or explicit gaps. C neither appoints people nor contains future decisions/adoption |
| Causal/model/data/measurement inputs | Exact question/subject/domain/variables/data/model/intervention/measurement/identification/transport premise inputs required by selected claim. Missing data/check capability stays unsupported; no fabricated effect estimate |

Library and project roots remain different logical roles even for DE-CASE-01 using
the same physical files. Byte storage may deduplicate; subject/demand/dependency/origin
edges may not. Arbitrary service sources cannot be relabelled reference six-case
protocol. Explicitly unsupported workload/model domains refuse affected operations.

Acquire through real source-qualified readers bound by the Scope/Host operation,
not project-input fields containing current! lambdas, generic SourceRef labels or
precomputed hashes. Keep actual operation/input/result/reader-source/cut/limits and
owned bytes or supported immutable retained source domain together. Use guarded
native object reads only where the actual producer supports them: forward original
issued tokens/dependency roots, never make a synthetic read token with an always-true
checker. Those tokens authenticate that POO read domain, not external file contents.

For files/data/tools, qualify actual OS/Host read-result provenance, owning base,
symlink/alias/relocation policy, content/enumeration/negative dependency and supported
stability checks at that owner. Existing module SourceRef and POO receipts do not
already provide a universal arbitrary-repo snapshot reader. Missing qualified reader
support blocks the required complete acquisition; a supported partial capture may
record the precise unavailable role, never claim coherent ready inputs.

There is no atomic whole-filesystem snapshot claim. Changes during acquisition must
be refused/reacquired under supported guards or preserved as explicit unstable gaps.
Do not join pre-change metadata with post-change bytes as one stable cut. Later
methods consume retained owned inputs; checking a hash then reopening mutable paths
is not the same captured basis. Any staging/materialization records original-to-copy
and actual byte/operation origin and belongs to its own explicit permitted operation.

* SPECIFIED Actual capture origin using existing Core ownership
:PROPERTIES:
:CUSTOM_ID: p3-origin-protocol
:END:

The target protocol uses Core's existing verification adapter as the private issuance
owner for a precise capture-origin assertion, composed with real Scenario acquisition.
It does not make Core verify arbitrary file truth or use an Aitia review purpose.
The trusted Scenario operation binds the expected adapter and snapshot/verification
bodies from its actual qualified source; it never accepts an adapter/validator from
Profile, C or a caller. Core permits anyone to construct an adapter, so registered
adapter status alone is insufficient: exact expected producer/source binding is
required at every consuming operation.

| Boundary / existing mechanism | Required target association and output |
|--------------------------------+----------------------------------------|
| Scope-bound capture operation | Actual admitted source/selection/reader/Host/clock/lease bindings, recognized selection and project request. A caller chooses data/intent only within the supported operation, not who authenticates it |
| Real acquisition and basis admission | Acquire demanded inputs/gaps with actual read-result origins; normalize complete owned input-basis once, retain returned candidate. Scenario assigns a new capture occurrence, not a caller reuse token or content digest |
| Scenario capture-origin verification operation | Core adapter's trusted operation checks that exact occurrence/basis against actual acquisition output, selected producer/reader/declaration/parameter/policy and allowed gaps; checks real source/read stability and observed Host instant/lease policy. Shape/hash equality alone cannot return success |
| Core poo-flow-verify | Existing pre/post canonical snapshot equality and private receipt issuance bind the verified capture-basis snapshot and validity interval. A genuine receipt establishes only that precise operation assertion, not positive premises, policy adoption or method outcomes |
| Final C admission | ResourceCapturedUseContract composes normalized captured basis and its genuine origin association in existing acquisition/origin fields. Retain returned C; final normalization must preserve sealed basis and actual producer association or refuse |
| Actual current!/method/evidence/review adapter | Resolve expected producer/source from qualified Scope/operation; verify original receipt through that exact adapter plus exact basis/occurrence/limits. Add actual fresh source/status/purpose prerequisites before use, not a saved admission verdict |

The effective acquisition/origin refinement declares basis-ref, actual acquisition
operation/result refs, selected producer/source/generation, qualified reader support,
original Core receipt association, clock/lease limits and diagnostics. Adapter/receipt
refs are recognized owner-bound values, not reconstructible alists. These fields
refine P1's existing C acquisition/origin group before closed validation; they are
not a new Contract generation or a caller-controlled method table.

Occurrence identity is scoped to the actual producer/owner instance and its source
association. A printed counter or digest claims neither global uniqueness nor
survival across restart; equivalent data cannot supply the missing owner identity.

The normalized capture basis is an input to issuance. Origin receipt is a later
binding of that basis; it is not recursively an input to its own seal. The final
C carrier combines them without modifying the sealed meaning, post-admission field
patching or producing a second authoritative C. Failure after actual receipt issuance
retains the failed attempt/origin; do not claim rollback of Core issuance or return
a partial recognized C. Missing qualified origin operation yields an unrecognized
draft/acquisition diagnostic, not an authentic C with a fabricated receipt.

Core snapshot validity alone accepts matching encoded meaning; it does not prove
physical object identity or a new capture occurrence. Equal-field/JSON copies without
actual trusted receipt/source association refuse. Borrowed genuine receipt with a
different occurrence/basis/producer/scope refuses. A supported normalized presentation
of the very same original occurrence requires the actual qualified origin association;
it is not a new occurrence or private receipt reissuance. Arbitrary wrappers are not
admitted merely because their printed fields match. No blanket object-equality check
replaces source/issuer recognition.

Core's pre/post snapshot comparison is value equality, not an atomic read transaction
or detection of every mutate-and-restore change. Keep owned immutable basis and actual
native generation/reader guards across the supported operation; unsupported external
ABA/stability guarantees remain gaps. The Scenario/Host wrapper obtains actual clock
instants and checks source/read/lease prerequisites again at final exposure/use;
caller now/until values and an interval accepted earlier do not authorize that gate.

Raw native read records, caller true/current flags and copied Core receipt objects
cannot authenticate capture. Core's private receipt tables remain at Core; Scenario
does not mirror them in an identity/nonce/issuer directory. No public API seals
arbitrary submitted C data or grants retrospective origin to a reconstructed result.
Original token/receipt authenticity, actual read provenance and semantic adequacy
remain separate controls.

Runtime consumers are joined through actual trusted Scenario/Host adapters to Library
operations with retained C/origin association. Library common Context Types do not
import Scenario or authenticate C structurally. The P4 issuer must recognize that
actual call/input association rather than an editable already-checked flag; the
cross-owner call/receipt route is an explicit qualification obligation, not an assumed
capability supplied by Function conformance or a public capture callback.

This protocol is process/owner-bound. Serialization or restart loses private handle
authority unless an independently supported recovery/portable-origin protocol verifies
retained original assertions and creates its own local association. No JSON load, old
time argument or historical receipt snapshot restores an issuer or current eligibility.
Receipt expiry/revocation blocks uses requiring it but does not edit captured history.
Fresh origin/use verification, when supported, has a real new observation over the
original occurrence; it does not extend old seals or silently recapture C.

* SPECIFIED Unique C, logical calls and operation lifetimes
:PROPERTIES:
:CUSTOM_ID: p3-calls-and-lifetimes
:END:

One C holds its occurrence/normalized input-basis, checked selection/Profile/parameter/
model/ordered parents/two-policy associations, actual project/reference subjects and
source roles, independent requirements/products, owned inputs/prior mandate references,
acquisition/origin/limits and every gap. No new version field, global ready flag,
later A/E/W/Q/R/decision output or mutation of previously captured inputs.

| Existing target operation name | Complete input -> retained output / limit |
|--------------------------------+-------------------------------------------|
| bind(Profile, project-request) | Actual admitted Scope-bound selector -> checked ResourceSelectionContract; retain normalized Profile/parameter/project request and actual parent/policy/expected capability/demand associations |
| capture(selection, project-inputs) | Recheck recognized selection; actual qualified acquisition/owned basis/origin -> checked ResourceCapturedUseContract C or explicit diagnostic. Submitted project-input values cannot authenticate their own source |
| current!(C, use-purpose) | Original recognized C plus exact intended operation -> fresh bounded source/lease/premise/status finding or refusal; no recapture or permanent Boolean authorization |
| observe/method(C, application-request, destination) | Recognized same C plus supported target claim/mode/owned execution options -> actual prepared A and later E/Observation/W/use under P4; no independent overriding root/Profile/policy/tool meaning |
| open-evidence(C, qualified-results/uses) | Same C -> ResourceEvidence association/Session, including honest empty initial evidence; Q comes from P5's actual accepted projection, not Scenario synthesis |
| prepare-review(C, exact-Q/uses, additional-inputs) | Same actual C and definite Q -> S6 R with required policy/role/product/context gaps preserved. This prepares no accepted decision or submission |

These are target existing-design signatures, not new implemented exports. Scenario
Scope advertises selection-profile-contract, project-request-contract, project-inputs-
contract, selection-contract, capture-contract and operation-contracts with the real
supported operations. Retain all normalized callable wrappers and final Scope/provider
coherence from P2; no P3-local cache or double validation to conceal Core defects.

Actual project acquisition is permitted bounded reading only under prior Host/project
mandate. It is not a model check, build, method run, appointment, dependency install
or review action. Output destination/options affecting later execution belong to the
prepared operation input footprint, not post-hoc edits to C. A newly discovered
unbound transitive input stops affected use and requires new acquisition/C, unless
already inside an actually supported captured immutable source domain.

| Change / operation | C and later-result behavior |
|--------------------+-----------------------------|
| Same captured inputs, later question within supported domain | Same C -> distinct actual A/E/use/Q as demanded; no duplicate Context |
| Captured model/policy/parameter/source/product/mandate meaning changes | New selection/acquisition occurrence/C; preserve original C0/outputs |
| Source/role/status/premise check changes without editing captured meaning | Fresh scoped check/impact/use, block unsupported current eligibility; preserve historical C/W/Q/R even on Session rollback |
| New technical/content/check findings change query basis | New Q/R as required, never append findings into C |
| Equal bytes acquired again, retry or restart | Distinct real capture occurrence unless genuinely returning the same retained owner-bound C; no digest-based deduplication of occurrence authority |
| Receiver/project/domain/transport basis differs | Receiver own selection/C and qualified comparison/identification or gap; reference/provenance receipt cannot transfer an empirical causal effect |

Honest C with permitted missing reviewer/data/model/product may be recognized as a
capture with gaps. It does not certify the missing role, fulfilled criterion or ready
operation. Unrelated supported analysis can proceed only under its own explicit
complete prerequisites. Forged acquisition/identity/issuer or incoherent source cut
is refused, not represented as an ordinary favorable missing-input capture.

* SPECIFIED Direct migration and implementation dependency

   route while real source provenance remains absent.
4. Normalize input basis, preserve actual acquisition -> issuance -> final C association,
   then bind current!/method/evidence/review adapters to the same genuine C/origin.
   Keep this coordinated unit unpublished until actual producer recognition works.
5. Directly migrate native-context/current! flat arguments, gateway fallback, examples,
   ResourceEvidence and review adapters. Retain bounded fixtures as tests only; remove
   old production routes rather than aliases accepting both C and overriding inputs.
6. Map and qualify owner controls/source/compiled/cold/recovery lanes when authorized.
   Pure acquisition/capture tests do not need to launch verification methods. Actual
   method issuance, deterministic Q, Aitia review/authority and receiver work keep
   their independent P4-P8 gates and immutable original evidence.
