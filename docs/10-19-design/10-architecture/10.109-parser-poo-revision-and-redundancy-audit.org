** R0: reproduced normalization loss and mutable-Contract bypass

Parser's =parser-object-validate= admits a refined descriptor through Core but
returns the original candidate. Core's authoritative implementation at
=object-types/contracts.ss:312--316= returns the evidence's actual candidate.

Read-only native cohort67 uses a legitimate normalizing value Type on a refined
Grammar Contract. Core evidence contains name=normalized; Parser validate returns
name=original. The probe reports =NORMALIZATION-LOSS-REPRODUCED= in6.96s.

Cohort69 then uses supported POO slot mutation in a disposable process, restoring
the slot on exit. Adding a rejecting obligation to the exact builtin Grammar
Contract yields Core admitted=#f, Parser member=#t and Parser validate returning
the candidate. It reports =BUILTIN-CONTRACT-OBLIGATION-BYPASSED= in6.90s.
The private exact-descriptor comparison protects neither revision nor the actual
obligation/classifier/responsibility protocol. No source or installed file is
changed by these probes.

Remove the Parser-specific success path rather than adding another revision or
validation cache. Inherit Core's element/validate/admit behavior, retaining stable
family prototypes, Parser identities and grammar graph/composition obligations.
Any genuinely needed fast path belongs in the framework under its complete
mutation and normalization contract, with measured cost and parity controls.

Acceptance requires the normalized result and Function wrappers to reach callers;
supported descriptor changes to be honored or explicitly refused; classifier and
obligation execution exactly once; correct missing-field/ancestry refusal; and
original callback exception identity. Existing refinement tests are retained.
The green145-module baseline did not test these two specific observations.

** R1 and R5: ordered lists are not an arbitrary Set/Table

Cohort68 selects Bool rows and Symbol keys through the actual typed
=make-list-operations=. Merging existing rows=(#f) with incoming=#t under the
same key returns(#f #t) and calls the conflict handler zero times. It reports
=FALSE-ROW-COLLISION-LOST= in7.43s. Both values are legal Bool rows; this is not
an invalid-input case. Existing Option distinguishes missing from=(some #f)=.

Retain the existing collision policy: identical duplicates reuse the original
rows, conflicting duplicates invoke the domain handler, and a new row appends.
Do not replace it blindly with latest =.<-iter=, whose repeated-key policy is
last-wins, or a backend constructor with its own duplicate convention.

The duplicate append-unique body can share its existing utility implementation.
=union-values= deliberately preserves duplicates already in the left sequence.
An unordered Set or a sorted Table would change observable ordering and possibly
serialized IR digests. Acceptance includes false rows, absent rows, equal versus
conflicting duplicates, handler count/cause, left identity and exact list order.

** R2: use existing native declarations without changing evidence silently

Core already exports =yuanxu-predicate-contract= and native POO already exports
Symbol, Exactly, Enum, Pair, List, Record, Map and Function. Parser's five
scalar classification wrappers repeat this framework behavior. Ordinary field
Types should migrate to one native value declaration; contextual responsibilities
must describe contextual obligations rather than a second ordinary field schema.

Do not replace ParserList with List Any. Give parents, roles and composition
their actual domains; define section rows from the existing grammar vocabulary.
Record versus nominal defstruct is a representation choice, not a requirement
to convert all runtime carriers into open objects.

There is a compatibility boundary: predicate classification can produce rejection
evidence whereas native value validation can raise TypeError. Preserve/document
the public identity, boolean membership, error/diagnostic order and contextual
admission contract before removing named wrappers. Native Record must not be
used to silently alter this distinction. Parser keeps grammar semantics.

** R3: share the data vocabulary, retain producer and execution rules

The compiler requires bounded state/production indexes and flat multi-alternative
forks, and permits layout guards only under the declared layout capability.
The runtime selected-action Type also admits layout-shift and recursively checks
fork branches. These are distinct phases, so sharing a predicate wholesale is
incorrect. Current duplicated leaf descriptions have already required a shift
precedence correction during10.108.

Define the common terminal/precedence/atomic-action vocabulary once using native
Types where useful. Overlay full-table bounds/capability checks and selected-action
projection checks at their actual owners. Preserve the existing tagged-list wire
format unless an explicitly qualified migration replaces it. Wrong tags/arity,
negative/out-of-range indexes, malformed precedence, raw guard escape, cycles,
fork cardinality and original failures need distinct positive/negative controls.

* Where the latest POO revision actually helps

POO =table/mapping.scm:6--21= captures list spines and binding Pair shells before
metadata discovery and constructors. =table/styles.scm:525--532= does the same
before public style delegates. =table-sources= captures declared origins before
later getters; operations guard supported descriptor mutations. Latest7f133e94
also captures finite image outputs before Set element recognition.

These capabilities fit declared catalog/registry or graph-index construction when
a persistent snapshot or derived indexes are required. They do not promise deep
immutability of arbitrary row objects, safe stateful callbacks, external-effect
rollback, a global revision/ABA fence or a universal speed improvement.

For the current graph context, start with an explicit Id-to-Row Map Type rather
than hash-table? alone, retain the normalized index result, and specify whether
the returned context exposes a live mutable carrier or a captured snapshot.
Capture derived identities/parents/kinds under a declared callback policy if that
is the intended snapshot. Membership/type checks do not prove index/view/count
agreement; Parser must enforce those graph invariants and its duplicate/parent
policy. Do not silently change the current #f no-parent sentinel policy.

A persistent Table backend is a subsequent design choice. RationalDict is
numerically keyed: overriding Key to Symbol does not change its numeric comparer
or tree semantics. Generic graph Id Types require a compatible explicitly
selected backend/equivalence, or the current hash backend. There is no automatic
representation inference. Preserve callback exceptions and ordering.

Adoption controls include mutation of input spines/Pair shells from metadata or
child callbacks, invalid occurrences hidden by later duplicates, descriptor
changes, normalized Function leaf identity, missing versus stored false, declared
key equivalence, late failure without partial publication and exact row order.
Do not reimplement Table delta/index/style/origin machinery in Parser.

* Retain and avoid speculative rewrites

- =compiler/funcs.ss= dense-ID bitsets, LR worklists and specialized runtime
  action indexes are compiler representations, not redundant application tables.
  Generic collection APIs require a separately measured semantic/cost comparison.
- Existing token/checkpoint defstruct carriers plus POO Types retain nominal
  worker ownership and byte-offset invariants; no blanket Record conversion.
- Character and parse-artifact predicates express actual host/domain properties.
  Keep them where no equivalent declared primitive exists.
- Graph duplicate/parent/lineage semantics and grammar/LR normalization remain
  Parser responsibilities. POO collections do not infer graph policy.
- Gerbil module loading, Core source/currentness and build supervision are not
  replaced by POO Table origins. The latter do not attest source bytes or issue
  publication authority.
- Keep the seven documented Any boundaries unless their semantics change. Do
  not hide a broad domain behind a nominal alias merely to remove the spelling.
