* Scope, invariant and design boundary
:PROPERTIES:
:CUSTOM_ID: i1-106-scope
:END:

This unifies 10.98 with 10.104/10.105 and current Core. POO owns value/Function/
receiver normalization; Core admission returns evidence whose candidate is the actual
effective receiver. Core must retain that candidate at Context, consumer dependency
and final Scope boundaries while preserving source ownership, package realization,
configuration validation, opt-in export binding and consumer isolation.

#+begin_example
K0 -> actual Context evidence EK -> K1 = EK.candidate
provider final SP -> exact alias-local package override -> SX
SX -> consumer requirement evidence ED under K1 -> SD = ED.candidate
factory(bindings of SD) -> owner-local package override
 -> declared public config admission -> opt-in export binding -> S0
S0 -> final Scope evidence ES under K1 -> S1 = ES.candidate
record.scope = S1 -> facade.scope / selected records / later edges
#+end_example

Symbols describe actual existing values, not new public fields, wire tags, versioned
Namespaces or credentials. Every real admission owns its descriptor/input/context/
source and returned receiver; candidate extraction is not repeated validation.
Within one process retain actual references and behavior; across processes compare
independent meanings and genuine new evidence, not pointer or report equality.

Only read-only source inspection and Org/D2 editing/rendering occur here. No code,
package/model/directory change, build/load/test/acceptance, cold start/restoration,
C acquisition/inference/validation/publication or orchestration extension is performed.
All operational changes and controls remain proposed. I0 readiness and final complete
application lane qualification remain distinct, as required by 10.104.

The directory entry creates lazy reader-ref/context/original-current?/read-located/
candidate-read/location closures before linking. Rebinding only an inner variable
cannot retarget them. K1 must remain compatible with the actual native owner,
generation, roots and callback association, or the real owner must reprepare/refuse.
An adequate supported ordinary guarded path may be used where actually provided;
shape/callback copying cannot inherit closed-prefix privilege. No author/MOP/
normalizer callback may execute inside a reused pure filesystem window. Preserve
cache-miss reader laziness and cold unrelated siblings.

In =(.o self: result ...)=, self: is parsed as a lexical object option by POO's
support/object-syntax.ss and object.ss, not lowered as a public field. The receiving
object is bound as result within the configured object body; it is distinct from
K1 and from any previous selection. Qualify selected Graph/module/record/with-packages
behavior on the actual receiver, including inherited/cached fields where supported.
This neither rewrites a lambda that closed over raw K0 nor proves the final Scope is
normalized. 10.105's earlier wording calling it a self slot is corrected as prose;
no new public slot, descriptor or Namespace is introduced.

Package relink shares actual publications/preparations and may retain original Graph,
but creates a fresh linker session and real Context evidence. Earlier publication
evidence keeps its original context. Reuse needs actual source/Contract/selection/
currentness compatibility; changed roots/permissions cannot seed old Graph metadata
under a new name. Actual .with-packages does not forward every directory-paired reader
argument, so qualify its ordinary guards and laziness independently; no assumed fast
prefix or second realization. Full package effects stay outside pure source caches.

The new composition intends to retain selected source prototypes/Contract declarations
rather than import another evaluation context's ancestors. Verify this through actual
POO receiver/ancestry/Contract tests: .mix direct specs/defaults are not a proof of
semantic compatibility, purity or expected descriptor identity. Do not flatten all
inherited slots, use .+ with foreign ancestors, mutate SP or replace final S1.
Overrides cannot choose a different expected validator merely by carrying equal labels
or config/types-shaped fields. Actual source declarations, supported override rules,
expected descriptor association and final admission must enforce the required meaning.
Missing coverage remains a blocker, not an invented global allowlist.

Package direct slot computations must observe the effective source receiver/defaults
under actual POO semantics; foreign lexical captures do not retarget automatically.
Retain exact actual package request/source/currentness and produced SX/owner Scope.

before final admission completes. Freshness reads do not repeatedly compose or
normalize new wrappers to hide unstable identity.

Source factory still executes before owner-local overrides. It must remain bounded

linker/realization provenance or K1/SD/S1 qualification. Distinct actual admission
boundaries may legitimately each normalize; accidental repeated validation at warm
getter/currentness boundaries is not legitimate replacement for retention.

* SD/S1 isolation, currentness and refusal
:PROPERTIES:
:CUSTOM_ID: i1-106-isolation
:END:

Provider SP stays its actual final value. A realized alias may use a persistent local
provider-record child with scope=SX while original scope-evidence still describes SP.
Do not call that old evidence proof of SX. Actual package provenance and ED describe
the edge; factory uses ED.candidate=SD. Neither SD nor ED overwrites provider state.
Two consumers/aliases get independent actual ED/SD even for equal-looking Contract
names or values. Final consumer ES/S1 is likewise local. Expected exact references
plus independent child/Function/derived-field behavior are required in-process.

After factory/owner/config/export assembly, actual final admission yields S1. Every
resolver, .selected-record.scope, selected-records, future dependency, namespace leaf
and building module-view.scope/thunk returns that same S1. Facade identity and tests
are separate; reading tests must not eagerly demand business Scopes. No raw fallback,
Config-to-Scope reconstruction, field-copy repair or .bind-publication after ES.

Warm reads keep receiver identity and factory/normalizer counts stable; real required
source/Contract/value-policy/override/declaration/Function guards still execute at use.
The existing publication metadata replay is useful but does not automatically cover
all new EK/ED/ES/config/realization normalization inputs. Identify actual supported
read/guard footprint at those owners. Missing callback coverage is explicit; no broad
snapshot, arbitrary liveness callback or pure-window expansion is introduced.

Rejection of requirement/realization/config/factory/final/currentness inserts no
accepted consumer. Active markers unwind; actual resolve/prepare fences prevent
same-session sibling bypass after refusal. Isolation means no provider/sibling value
mutation, not permission to use another module in a refused session. Compare unaffected
meaning in an independently fresh admitted session; held historical values are not
current authority. External effects from unsupported author code are not rolled back
by source/Session refusal.
