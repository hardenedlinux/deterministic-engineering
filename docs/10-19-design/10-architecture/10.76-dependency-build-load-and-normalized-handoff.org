* SPECIFIED P0 target and bounded claims
:PROPERTIES:
:CUSTOM_ID: p0-unified-source-handoff
:STATUS: Source/design and static documentation only; no implementation, package mutation, acceptance execution, provisioning or actual delivery
:END:

P0 unifies one qualified dependency source set with its real compiled/loaded closure
and Core's normalized Context/required-edge/final Scope handoff. It is a prerequisite
for P1-P9 runtime claims, not another version manager or project-local repair facade.
Declarations express intended dependencies; actual checkout/dirty bytes, build inputs,
artifacts and per-process loaded modules are distinct observed facts. All must agree
through a qualified route before that route can be called complete.

The Library declaration's sole generation remains V1. Package source revisions,
semantic revisions, document revision and runtime/load identities remain separate;
manifest.ss and Org/D2 do not become dependency resolution or Library version owners.
No new Namespace suffix, compatibility facade, alternate Contract system or global
load/receipt registry is introduced. Historical build/recovery/dossier receipts remain
at their original identities, including failures. No implementation or tests run here.

* SPECIFIED One dependency direction and actual source-set qualification
:PROPERTIES:
:CUSTOM_ID: p0-dependency-direction
:END:

Target direction remains POO -> Core -> ASCENT -> Flow application owners -> project
consumers, with direct POO/Core imports declared where used. Core must not depend on
Flow/Aitia or this Library to fix normalization. ASCENT owns generic Program/Session;
Flow owns actual Clue/history/evidence-assessment applications; Aitia owns review;
Library owns domain meaning. A transitive package presence is not a supported public
module facade. Keep declaration paths/package identities at their real owner.

Coordinate the candidate source set in dependency order: qualify POO features ->
Core handoff/source/reader -> ASCENT current generic rules/Session -> Flow actual
application/collection exports -> project Library/Scenario/tests. Update each owning
gerbil.pkg to the qualified upstream revisions rather than hiding a contradictory
transitive pin behind a local link. Project declarations and metadata then follow.
A qualified diagnostic working-tree override remains explicitly an override and
cannot pass the declaration-matching reproducible lane.

One VM must use one coherent resolved POO/Core object/Contract/issuer implementation
for these shared APIs. Detect conflicting qualified module origins, duplicate/stale
producer implementations or unsupported transitive ABI. Different checkout copies may
exist as historical data; neither equal commit labels nor two directories prove two
compatible runtime authorities. Actual source guards, resolved modules and loaded
images determine the route. No global cache/pin table is added.

Migrate old imports directly at project ResourceEvidence, Library Rust methods and
dependency tests using actual rules/interface define-program and rules/declaration
rule-module-program plus supported Flow Clue/trajectory exports from 10.65. Validate
exact relation handles, complete named outputs and method bindings. Do not alias removed
Evidence APIs, copy application modules into ASCENT or substitute Evidence Assessment
for this project's stratified application. Missing supported package exports are owner
work, not a guessed import success. No implementation/directory change occurs here.

* SPECIFIED Context normalization before linker state creation
:PROPERTIES:
:CUSTOM_ID: p0-context-handoff
:END:

At link-module-context entry, retain initial admit-module-value! evidence and select
its candidate as the checked Context before reading generation, selected/module IDs,
locate/read/current callbacks, policies or constructing cache/closures/graph state.
The original supplied Context is only the initial admission input/bootstrap context;
it is not a fallback downstream subject after admission returns a different receiver.
Retain context evidence through the actual native read/admission mechanism as required
by the owner; do not introduce a duplicate private context approval cache.

All subsequent scope admissions use checked Context. The directory/reader's actual
source/generation/candidate-location capabilities already paired outside this function
must remain authentically associated with it. A normalized wrapper may differ in
identity; it cannot silently select another source/provider/clock/callback capability.
Where actual owner association or contextual obligations cannot be preserved, refuse
unsupported transformation instead of bypassing a guard or using old raw Context.
Do not normalize a context recursively using itself as already-authorized authority.

Current predicate-only default usually preserves identity. Positive nonidentity
qualification requires a real owner-scoped supported Contract fixture exercising the
actual handoff, not a forged evidence object, public validator argument or mutation
of production Contract just to make the test pass. If no such test seam exists, record
it as owner test work; an identity-only test cannot prove the nonidentity path. Keep
raw/current capability guards and external ABA limits explicit, not inferred from
canonical snapshot equality or native read forwarding alone.

* SPECIFIED Consumer-local dependency Scope and final Scope handoff
:PROPERTIES:
:CUSTOM_ID: p0-scope-handoffs
:END:

| Link boundary / existing fields | Target behavior |
|--------------------------------+-----------------|
| Actual provider record | Recursive link returns the provider's own admitted record/scope/source/publication. Keep this actual record unmodified in records.alias.provider; do not replace shared provider state with consumer-specific normalization |
| Realized dependency input | dependency-scope(owner,alias,provider-id,provider.scope) selects baseline or exact realized package scope. Retain actual realization/config-owner/alias/provider association; reject missing/ambiguous realization. Do not store a rewritten provider record merely to carry this edge input |
| Requirement admission | Admit exact requirement.contract over that effective input under checked Context. Retain records.alias.requirement-evidence; its candidate is the consumer-local edge result |
| Link bindings | bindings.alias must consume requirement-evidence.candidate, including nonidentity wrapped callables, not provider.scope or the precheck realized input. Two consumers can impose different valid requirements without contaminating provider or one another |
| Scope construction/export binding | baseline.link consumes those actual admitted bindings; bind-exports applies the existing selected publication association. These produce scope-value, the input to final admission, not automatically the final exported subject |
| Final admission/linked record | Admit baseline.scope-contract under checked Context; record.scope is scope-evidence.candidate. Return/cache/Graph views/build/export consumers observe that same admitted subject and normalized Functions. Keep final evidence and actual source/publication associations |
| Final coherence/failure | A returned final candidate must preserve required export/publication/model/parent/method-Contract coherence. If normalization changes callable/associated metadata inconsistently, reject at actual contextual owner rather than patch after admission. Finish currentness checks before publishing/caching record |

The tuple provider / requirement-evidence / final scope-evidence already supplies
these roles; no new public edge DSL or second graph is needed. If an internal pure
candidate-extraction helper removes repetition, it consumes actual accepted evidence,
not a caller-authored checked flag. Do not rerun normalizers merely to rediscover their
return: they may produce a distinct wrapper, and repeated evaluation is not identity.
Native contextual dependencies/obligations and diagnostics still belong to actual
admission/source/read machinery.

Core transports the actual checked subjects and runs expected generic obligations.
Library/model/method parent and metadata coherence belongs to their authored Contracts
and contextual responsibilities, not domain field checks hardcoded into Core.

No partial failed record enters accepted cache; active recursion state must unwind.
Existing linked-publication pending/accepted and graph/current guards remain at their
owners. Source/Contract/MOP mutation, reentry or a failing wrapper cannot make a stale
cached graph valid. These are current-use boundaries, not guarantees of global
transactional rollback over reader/tool effects. Publication admission's correct
candidate path stays intact and is covered by regression controls.
