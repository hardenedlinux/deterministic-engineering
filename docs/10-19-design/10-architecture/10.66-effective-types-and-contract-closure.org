* SPECIFIED P1 contract baseline and limits
:PROPERTIES:
:CUSTOM_ID: p1-effective-contracts
:STATUS: Design and static documentation only; no implementation, acceptance execution or delivery
:END:

P1 consolidates the complete expected receiver Types from 10.54 with the premise,
check, impact, evidence-strength and delivery-phase refinements in 10.55-10.65.
The target is ordinary POO Types/ObjectContract/Function, Core contextual Contract
admission and Aitia's existing CLOS class composition. Tables specify fields of
those existing owners; they introduce no schema language, parallel object registry,
generic assumption service or replacement verification engine.

10.54's identities, immediate parents, sibling policies, sole declaration generation
and twelve verification purposes remain. This chapter is the consolidated effective
refinement for P1: apply it before closed validation, rather than treating later
S6-S8 fields as optional unknown payload. Existing 10.54-10.65 semantics and control
IDs remain; this chapter makes their target field and call constraints explicit.
Unknown, incomplete, refuted and conflicting findings are valid data where their
variant permits them, but cannot satisfy a positive property or action prerequisite.

Current source inspection confirms P0's 19 selected source hashes unchanged at this
turn's observation; this is not a full dependency or loaded-process qualification.
Project HEAD remains 8044732d505f84e373119a70f947df00e1767300. Core types.ss is
still the dirty 3b1182030502571fcf4c54a458871b9e4160d5fe8da55c3c54159dad481129be

Value-shape reuse is separate from value ancestry. Model shapes share common
fields; concrete Generic, Rust and Integration constraints are sibling refinements
of the shared shape, so Rust does not inherit Generic's fixed identity/parent=false
check. Published values retain Generic -> Rust -> Integration immediate parents.
Both policies derive from common policy shape, parent=false, with distinct fixed
expected descriptors. Policy composition does not change that model parent chain.

Complete fields are the union of declared inherited fields and supported child
fields; all applicable inherited constraints conjoin. Derive the effective map
before closing it. CLOS allowed names come from the same effective class metadata,
including the exact framework marker; do not maintain a second field list or allow
all percent-prefixed slots. Cyclic declaration/input references, unknown enum tags,
extra semantic fields and wrong role ancestry refuse before unknown value demand.

The generation read remains checked Scope -> expected role descriptor -> admitted
BackpressureDeclarationContract -> contract-version V1. No policy/Scenario/Aitia/
manifest owns another generation. Semantic revision, project/document revision,
dependency commit/dirty hash, input/read generation and epoch remain separate.
Namespace names and Org/D2 only reference these associations.

Identity/text fields use their declared symbol or owned nonempty string Type, never
implicit interchange. Indices/counts use bounded nonnegative exact integers; time
and duration bind their actual clock domain/units and supported encoding. Validity
is the declared half-open [issued-at, expires-at) interval checked against a genuine
clock occurrence later, not caller-supplied now. Numerical findings require the
actual supported finite numeric/units/uncertainty representation; missing values
use a typed gap and are not zero/NaN/string sentinels. Collections/reference closure
obey selected finite cardinality/traversal limits with explicit incomplete results;
the candidate cannot widen those limits. These are domain field refinements on
upstream primitive Types, not replacements for them.

** Evidence strength is scoped and multidimensional

The strength field composes claim-kind, subject/proposition/domain, coverage,
premise-basis, supported method/semantic interpretation, uncertainty and limitations.
It is not a numeric confidence/rank. The target finite claim-kind domain at Library's
shared Types owner is content, execution, model-property, conditional-theorem,
empirical-causal, model-counterfactual, provenance. Actual policy may select a
narrower supported subset; new kinds require owner Contract changes, not arbitrary
symbols in records. Aitia's generic strength reference consumes the qualified
descriptor; it does not import/copy this Library enum into a generic base class.

| Kind / illustrative existing method | Qualified meaning / required limit |
|------------------------------------+------------------------------------|
| content / SysML or Org observer | Exact syntax/structure or independently established semantic assertion. Parsing/link closure alone does not prove architecture or causal adequacy |
| execution / Rust run | Actual bounded run/property/facet under complete launch/input/validator origin. Harness success and tested proposition polarity remain separate |
| model-property / QNT | Exact bounded state/action/invariant/path/domain/complete run; not Rust refinement or empirical causal effect |
| conditional-theorem / Lean | Exact theorem/polarity/axioms/kernel/imports and premises; proof of negation refutes the corresponding positive claim |
| empirical-causal / supported actual analysis | Defined target and actual data/intervention/identification/estimator/uncertainty/diagnostics/transport limits. No actual supported analysis means undetermined/unsupported, not an invented zero or interval |
| model-counterfactual / qualified model analysis | Precise alternative under stated model and identification assumptions; not observation of another historical outcome |
| provenance / source/receiver verification | Exact issuer/origin/content/signature/custody assertion and trust limits; authentic provenance is not property adequacy or permission |

Observed strength is checked against the independently required target claim at
actual use. No total ordering promotes provenance -> content -> theorem -> causal
truth. A supported cross-kind mapping must be explicitly qualified at its real
semantic owner with preserved origins and premises, or it refuses. Foreign source
verification creates a new local observation, never recreates private original W.
Comparable contrary claims retain both origins; different model/domain/polarity
or scope is not automatically a contradiction. Independence groups retain actual
method/source/author dependence; two records do not constitute independent support.

The result axes remain separate. execution uses not-started/refused/completed/
tool-failure/timeout/cancelled/drift/interrupted/unknown-completion; validation uses
accepted/rejected/incomplete; semantic conclusion uses holds/refuted/undetermined;
control uses met/failed/not-applicable with an explicit no-control basis. Fresh use
records eligible/ineligible/unestablished at a specified operation cut; it is never
a mutable global current? field. Existing raw tool outcomes are retained alongside
normalized values; unrecognized causes cannot be coerced to a known enum.

Premise checks use the same execution/validation axes and their declared proposition
conclusion. Refuted prerequisite, incomplete check, stale source, opposed comparable
findings and unsupported checking capability remain distinguishable. holds is
conditional evidence at a cut, not eternal premise truth. An impact record supplies
typed observations and required action; it cannot independently execute a recheck,
revoke another owner's receipt or approve an exception.

Q is a complete finite query result including pending/negative/conflict, not a
claim all duties passed. Accepted Session batch publication and definite Q formation
belong to S5. Failed replacement leaves earlier Q historical once known external
invalidation blocks live use. Closed row validation cannot repair batch atomicity,
authenticate a fabricated E/W/use or establish empirical causality.

* SPECIFIED Finite action, conclusion and stage domains
:PROPERTIES:
:CUSTOM_ID: p1-actions-and-stages
:END:

P1 makes the policy-neutral action domain concrete at Aitia types.ss: review,
exception, supersession, withdrawal, distribution, adoption, use. These target
symbols are a design refinement, not a claim that current exports implement them.
The trusted operation and actual adopted policy select a supported subset and
target kind. Existing standard-specific action formats keep their genuine route;
do not reinterpret historical signed actions through this new generic enum.

| Action / exact target | Required association and permitted meaning |
|-----------------------+--------------------------------------------|
| review / review-binding | Exact technical/context/content/history basis; conclude approved/rejected/deferred. approved is scoped review disposition, not distribution or receiver permission |
| exception / criterion | Exact retained unmet duty/negative, permitted scope/risk authority/mitigation/expiry; conclude approved/rejected/deferred. Approved exception does not change property truth |
| supersession / decision or exception | Exact predecessor/denial and proposed replacement/resolution, compatible scope and authority; approved replacement retains original and supersession edge. No last-write-wins deletion |
| withdrawal / receipt, evidence-use, grant, decision, exception, publication, adoption or owner | Exact target/real issuer or authorized owner/effective scope and status. Accepted decision must still reach the actual target owner's revocation/retirement boundary; no generic toggle |
| distribution / manifest | Finalized payload/recipient/project/intended-purpose and current scoped accepted authority; cannot be inferred from producer review |
| adoption / publication | Exact incoming manifest and receiver's own checked selection/C/Q/R/H/policy/mandate; pre-existing host mandate authorizes earlier inspection/provisioning |
| use / operation | Exact adoption/publication/manifest, receiver project/principal/purpose/immutable operation inputs/current premises and effect-owner conditions. Accepted adoption alone is insufficient |

The generic decision-conclusion domain is approved/rejected/deferred. Target-kind
domain is review-binding, criterion, decision, exception, receipt, evidence-use,
grant, publication, adoption, owner, manifest, operation. Reject mismatched action/
target pairs even if both tags are individually valid. Technical repair and
reassessment are findings/workflows, not authorizing actions. Repair may supply
new evidence for review or supersession; it never replaces a denial itself.

The assertion-stage domain is proposal, accepted-inclusion, current-use. Proposal
verification cannot assert storage inclusion; inclusion requires actual accepted
source/record/head binding; current-use requires fresh actual owner/status checks.
Decision conclusion, action, assertion-stage, review-stage and intended use have
different slots. review-stage is selected from the finite supported stage set in
the actual policy; this does not globally narrow legacy standard lifecycle text.
Intended use is constrained by that adopted policy/recipient/operation, not converted
into another verification-purpose enum or arbitrary permission-bearing string.

Authentic rejection/defer/withdrawal can target recognized incomplete or negative
technical basis under an operation that explicitly permits it. Required missing
associations are represented as typed gaps in that supported negative input variant;
they do not forge a complete Q/R or waive real target/source/authority checks.
Positive review/distribution/adoption/use requires its full positive prerequisites.
An authentic denial is retained even when the positive technical property is unproved.

finite phase labels below document the variants; there is no mutable phase field

DeliveryInventoryFacts bind exact manifest/intake/receiver/project/purpose and
independently required-versus-observed accessible closure/omissions. Correctly
accounting for missing items may verify; it does not establish complete payload.
DeliveryProvenanceFacts bind original assertion/conclusion/issuer/credential/root/
signature/custody/status plus real local verifier/operation/source cut. Verified
provenance of a refutation remains refutation; it is not a property-support receipt.

Changed payload/subset/recipient/intended-purpose requires a new manifest and
scoped distribution decision. Acknowledgements, fresh status and receiver reviews
retain their own identities; do not append them back into an already finalized
manifest. Unavailable current status can block use of an otherwise byte-complete
payload. No manifest claims immediate global recall, cross-host atomicity or trust
in a producer-local inaccessible .data path.
