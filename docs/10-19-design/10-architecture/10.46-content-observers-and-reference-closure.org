* DESIGN WP05 objective and scope
:PROPERTIES:
:CUSTOM_ID: content-observers-and-reference-closure
:STATUS: Target design and future acceptance controls only; no implementation, observation or review submission
:END:

WP05 supplies bounded content observations for DE-O-ARCH/DOC/DEC/TRACE, using
one C from WP03 and the application A, actual attempt E, observation, private W
and fresh use protocol from WP04. It does not create a second capture, result
store, document schema engine or review authority. DE-O-REVIEW remains the exact
context/content/history/disposition work of WP07-WP09; WP05 supplies its inputs.

The inspected repository has authored architecture/products/decisions and real
backpressure report auditing, but no installed DE-CASE-01 content observer.
This design specifies the complete target at existing owners and identifies
necessary future extracted units. Nothing described as a future capability,
policy, field or compilation unit is claimed to exist or execute now.

A mechanical result can establish a required role binding, unambiguous locator,
byte identity, declared relation or bounded coverage check. Source correspondence,
view fidelity and rationale adequacy require their own qualified operations and
independent semantic findings where required. No parser, hash, render, language
model opinion or authored accepted label can stand in for all of these claims.

A product manifest maps the actual existing Org tables/properties/sections into
these typed roles under a source-qualified reader. If a table/field is not yet
supported, capture an explicit authored binding or an unsupported gap; do not
infer arbitrary prose as verified structure. The binding points at the same
acquired content rather than maintaining another rewritten copy of its body.
Presence/shape and semantic checks remain distinct. Parser/format recipe identity
belongs to the actual reader input basis, not another declaration generation.

read, publication, projection and external boundary at the meaning selected by

supports declared constructs; unknown Scheme/macros/computed edges stay outside
that check until an appropriate actual parser/admission or independent inspection
qualifies them. Regex resemblance is not executable call-graph or behavior proof.

* SPECIFIED Same-C acquisition, calls and reference closure
:PROPERTIES:
:CUSTOM_ID: content-observer-calls-and-closure
:END:

WP03 acquisition and WP05 validation have distinct responsibilities. A bounded
reader can help Scenario discover a candidate manifest before C is sealed. Scenario
acquires the actual policy-required closure under its trusted source owner; it
records complete inputs or explicit gaps. Later observers consume those owned
inputs and validate that closure. They do not discover a missing ambient file and
append it to the already captured C. A missing required input needs proper new
acquisition/C, or a qualified immutable domain already included in that C.

| Call / owner | Inputs -> outputs | Boundary |
|--------------+------------------+----------|
| Prepare content A / Scenario + published capability | C + selected bounded subject/criterion + qualified upstream inputs -> checked A or refusal | Expected roles derive from policy, not available favorable documents; preserve missing duties even when application cannot execute |
| Parse/index / bound reader | Actual acquired bytes + captured parser/format/selector policy -> owned product candidates/index/spans/diagnostics | Parse the same bytes whose identity is bound. Filesystem path/hash followed by another uncontrolled read is insufficient. Candidate declarations remain claims to check |
| Resolve/check closure / actual observer | A + owned indices + typed demand/references + acquired target inventory -> scoped resolution/findings | Each required edge resolves uniquely or remains an explicit gap/boundary. An index does not authenticate semantic relations or the issuer of referenced evidence |
| Observe content/source/views / selected operations | Same A/C and exact resolved inputs/derivations -> E and scoped observations | Record actual source inspection/commands and supported limits; generated content is a derived output, not a late C input |
| Bind semantic findings / actual qualified reviewer operation | Same basis plus actually attributed source/product findings -> scoped observation or unresolved attribution/meaning | Verify actual identity/scope/independence through the selected trust route. No auto-appointment, fabricated approval or blanket prose-to-truth operation |
| Issue and check use / actual producer | Accepted bounded observation + retained E/input closure -> private W; W + target C/A -> fresh qualified use | Only exact qualified holds/refuted conclusions issue property W; refused/incomplete/unsupported attempts retain diagnostics. Original C/A/E and claim remain fixed |
| Project and review / existing owners | Required duties + C + actual A/E/W/uses/findings -> WP06 Q, then WP07 R | Session commits trusted projections. Aitia verifies exact Q/C/products/policy/roles/history; an observer's technical result is not its context/content receipt or disposition |

Closure is a finite typed demand graph rooted at required roles/claims, not a
recursive promotion of every hyperlink. Its rules are:

1. Derive required roles and relation kinds independently from the actual checked
   policy/capability. The project supplies concrete content bindings and may add
   references; it cannot mark a policy-required dependency context-only or remove
   a role by omitting it. A parser validates extracted bindings against that demand.
2. Resolve relative file links/includes against the owning artifact's acquired
   origin/base, not cwd or a destination output directory. Capture symlink/alias/
   case/path resolution under the supported filesystem policy. Reject ambiguous
   duplicate CUSTOM_ID/subject selectors and conflicting authority/revisions;
   identical bytes can serve multiple declared roles without inventing two subjects.
3. Resolve only supported selector forms. Named blocks, heading searches, ID links,
   include/macro expansion, generated indices or remote URLs need an explicit
   supported reader/recipe/access basis if demanded. Unsupported syntax remains
   a gap. Never run Babel, eval, export filters, shell blocks or instructions in
   prose to satisfy a reference. Org content and referenced tool output are data.
4. Preserve each demand edge, reason and exact target binding. A report manifest
   delegates only declared leaf roles under its expected historical reader; it
   cannot choose the whole application's mandatory source/criterion inventory.
   Wrong/extra ambiguous artifacts and conflicting path/digest/subject bindings
   are findings, not last-file-wins updates. External/context-only boundaries
   record their limits; a required inaccessible target blocks that claim.
5. Traverse with owned visited state, retaining all incoming demand edges and
   finite node/edge/depth/byte/time limits. Cross-references may cycle; decision
   supersession must be acyclic. Neither type of cycle justifies unbounded
   recursion or dropping a required edge. Limit exhaustion is incomplete, never
   a completed closure. Record actual attempts and diagnostics at declared budgets.
6. Bind full acquired file identities, selected spans, parser/recipe/source/tool
   inputs and relevant semantic relations. A whole-file change requires recheck
   under the current coarse file-bound policy even if selected text looks equal;
   section-only selective reuse needs an actually qualified finer dependency basis.

A mutable origin check and owned read do not establish an atomic global snapshot.
Historical source-copy paths can be resolved through an actual captured custody
association, preserving original origin and copied location separately; do not
silently rewrite historical paths into present project source identity.

A dossier can be an input draft or an assembled output at a particular stage.
10.34 and 90.97 were outputs excluded from their own historical input catalog.
A new C may acquire that finalized old draft as an input. WP05 reports/W, WP06 Q
and the new review dossier are later outputs; none is appended into its own C.
Any new final review manifest references already identified products/Q/W before
it is itself bound by R. A forward reference to a not-yet-produced query is an
explicit gap, not a hash self-cycle or a truth claim that certifies itself.

For the first bounded chain, use C1 requirements -> DE-R03/R04 -> DE-E06/I04
actual source delegation -> DE-T03 complete-capture target -> DE-D04 -> D03/D04/
D05/D06/D07/D08 -> the appropriate D09/D10 draft. The actual seven-role split
capture and the proposed full C must be reported separately. Existing unresolved
Content steward/reviewer appointments remain gaps. New design sections 10.37-10.46
can be demanded by a new selected basis; they are not retroactively inserted into
10.34's original catalog or counted as already implemented source behavior.

A project can request review of known gaps under a genuinely applicable policy.
That request records the gaps without claiming complete content. Each runnable
bounded application still needs its own required inputs; a full C1 semantic
claim cannot execute against a success-only subset. Actual required role/duty
coverage is preserved even when a particular check refuses before execution.

* SPECIFIED Historical references, current evidence and outcome meaning
:PROPERTIES:
:CUSTOM_ID: content-observer-evidence-states
:END:

| Association | Meaning permitted | Meaning excluded |
|-------------+-------------------+------------------|
| Authored candidate | Captured current product bytes and declared content/claims; can be inspected | Automatically accepted content, private W or an approved decision |
| Historical H / exact original artifact and context | Original observation/report/failed attempt, subject/revision/scope, source/tool/basis, custody/trust limits and original polarity retained | Current method success or a newly issued DE-O result merely because the file/hash still exists |
| Current integrity observation of H | New actual A/E/W, when qualified, says those exact historical bytes/references satisfy a bounded integrity claim now | Re-execution of the historical workload, recovery of unobserved commands, independent original issuance or applicability to the current project |
| New content observation / W | Actual C/A/E, exact criterion/product/input basis and scoped qualified holds/refuted conclusion | Universal architecture truth, unstated method strength, reviewer authority or whole-duty completion |
| Qualified current use of original W | Actual producer/verifier associates original W with target C/A after full footprint/subject/strength/criteria/issuer checks under WP04 | W origin mutated to the new C, a copied checked flag or a historical method relabeled as current execution |
| Missing/inaccessible/unsupported/incomplete | Exact required demand and diagnostic persist; affected conclusion is undetermined/pending | A fabricated fail/pass W, automatic waiver or deletion of the duty |
| Conflicting/contrary findings | Original claims and sources retained, with affected scope and resolution requirement | Selecting the newest-looking revision, majority of green rows or successful parser as adjudicator |

A verified counterexample to a precise content claim can issue refuted W. For
example, a complete observed file proves that a required unique selector is
absent, or a supplied source explicitly contradicts a declared actual edge.
Absence of an artifact/access/trusted reviewer, a parser failure or an incomplete
search does not prove that semantic content is false. If such a gap itself is
a separately declared availability/completeness criterion, its bounded factual
refutation needs a qualified observation of that criterion and domain; it is
not a fabricated refutation of unrelated architecture/rationale truth.

Preserve WP04's five dimensions: execution completion, interpretation validity,
semantic holds/refuted/undetermined, control expectation and current applicability.
A control that intentionally removes an anchor may succeed while refuting the
unique-anchor claim. A well-formed target can hold as a design record and still
leave its implementation duty pending. An attributed semantic disagreement is
retained as contrary evidence; it does not erase mechanical integrity support.

A pre-existing semantic finding is an acquired C input candidate. A finding
produced for this A after capture is an attributed operation output: it binds the
exact C/criterion/product/source identities actually inspected and the selected
qualified review channel, not a retroactive addition to C. E records the actual
request/response/attribution checks and their source/status basis, not a fictitious
re-execution of a human's reasoning. For a supported agent-assisted operation,
include its actual model/provider/configuration, prompts/context/tools and response
basis where relevant; an unqualified response remains a candidate, and policy
still determines required independence. A newly discovered unbound source or
role premise requires acquisition/new C. A reviewer of different bytes cannot
qualify this application's content by merely repeating its IDs.

Conflicting bindings (one subject/revision with incompatible authoritative bytes,
duplicate CUSTOM_ID, divergent mandatory source identity) refuse the ambiguous
application while retaining offending candidates. Two independently qualified
W with contrary conclusions about the same claim/basis both survive; WP06 marks
the conflict and policy blocks a success-only readiness decision. Different
claims/strengths/actual-target scopes are compared explicitly before declaring
conflict; they are not blindly collapsed into one pass/fail row.

serialized private handles and publisher-local digest agreement are insufficient.
