* DESIGN S2 objective and trust boundary
:PROPERTIES:
:CUSTOM_ID: library-construction-scope-handoff
:STATUS: Existing-file/field/call/normalization design only; no implementation or acceptance execution
:END:

S2 constructs and publishes one coherent Library object graph per actual successful
linked Scope: Generic -> Rust -> Integration, two independent policy definitions,
typed Config and complete exports/deferred callables. Core retains the checked
publication, the consumer-specific required-edge candidate and the final admitted
Scope candidate at their actual boundaries. A validator returning a different
receiver/function must not lose that returned value on the path to consumers.

This refines 10.43 using S1's complete roles/fields and S0's dirty source/load/
recovery limits. It adds no linker, constructor framework, global singleton,
family cache, version resolver, generated schema layer or compatibility facade.
S2 publishes reusable meaning and actual callable expectations; it neither
captures a project C nor executes methods, issues W, prepares authoritative Q/R,
approves a review or delivers anything.

The 75 selected current implementation/build/runner files still match S0's
recorded bytes at this inspection. Linked Core remains the dirty checkout at
52130d2d338b09622a3f55e37987ddc0375b6187; project HEAD remains
8044732d505f84e373119a70f947df00e1767300. Source inspection supplies no fresh
compiled/loading/acceptance result. S0 BS01-BS09 and the restart-two timeout remain
open at their existing scopes.

Role shape inheritance is not inheritance of concrete role identity constraints.
Rust's expected value must not be checked through Generic's fixed identity or
parent=false Contract; Integration must not inherit Rust's fixed-role/Generic-parent
constraint. Policy values share common declaration/policy shape while retaining
their distinct expected identities/applicability; neither derives from a model
or implies actual project policy adoption/appointments/approval.

The family read is actual checked Scope -> selected expected role Contract ->
its admitted declaration-contract -> contract-version. BackpressureDeclarationContract
in abstract/types.ss owns the one target V1 symbol; no object, Config, interface,
Profile, generator, Org or D2 copies that field or parses a generation from a
revision/Namespace. Existing semantic tokens above remain opaque baselines;
construction/source edits do not automatically advance them. Actual role/source/
owner guards prevent copied metadata or restored mutable state from authorizing use.

Preserve inherited meaning, not merely set membership. Conflicting duplicates,
dropped duties/input roles, wrong state-map endpoints and inconsistent premises
refuse the effective value. Exact duplicate authored rows are corrected at their
owner, not silently merged into a new accepted definition during use. The final
Rust map uses waiting->waiting, queued->queued, cpu-running->active,
result-pending->returned, cleanup->cleanup and released->released. Integration's
observed QNT running/done domains remain separately declared.

* SPECIFIED Config and exact published Scope
:PROPERTIES:
:CUSTOM_ID: s2-config-and-scope-exports
:END:

Generic Config.entry references the authored BackpressureModel and is validated
under the closed BackpressureConfigContract. The interface consumes the returned
checked Config.entry and its expected role/source association; it must not call
validate then read the original raw Config. This is an explicit Library boundary,
not an invented automatic Core config-contract field. Rust Config is the closed
no-options value under RustResourcesConfigContract. Neither Config selects a
project, policy, parent, method result or arbitrary constructor/validator.

| Export / field pair | Generic Scope | Rust Scope and checked association |
|---------------------+---------------+------------------------------------|
| entry / entry-contract | Selected checked Generic / BackpressureModelContract | Checked Rust / RustResourceModelContract |
| declaration-contract | Sole admitted family owner | Same family associated with actual required Generic and every exported role |
| integration-entry / integration-contract | Not advertised | Checked Integration whose parent is this exported checked Rust |
| review-policy / review-policy-contract | No bounded Rust policy | Checked bounded policy and its own expected descriptor |
| design-review-policy / design-review-policy-contract | No Rust case design-policy export; generic criteria have their own supported capability meaning | Distinct checked design policy and its own expected descriptor; actual authored revision/applicability/content/history/delivery requirements |
| profile-contract | BackpressureProfileContract | ResourceProfileContract |
| six-case-profile-contract / integration-profile-contract | Not advertised | ResourceSixCaseProfileContract / ResourceIntegrationProfileContract |
| context-contract | Not advertised by this Generic Scope | ResourceContextContract with complete S1 expected input/selection/occurrence fields; no always-true placeholder |
| methods / method-contracts | Real supported generic functions / actual expected Function Types | Real supported Rust/integration/content operations / expected exact Function Types, associated with selected declarations and real source-qualified implementation owners |

The complete Rust Scope advertised here requires both policies and their real
mandatory exports. Missing design revision/criterion/callable support cannot be
hidden by dropping that export, switching to bounded policy or relabeling required
support optional. An independently supported narrower publication needs an explicit
expected Contract/capability design first; this task creates none. Independently
selected Generic-only routes retain their existing provider/demand isolation.

Validation of a Function must preserve its returned wrapper and exact input/
output/keyword/arity expectations. Method bodies are real before exposure, but
publication executes none. Merely deferring external calls does not prove every
imported parser/tool/initializer is cold; actual source/compiled import/initializer
footprints remain S0/S4 qualification inputs.

|-----------------------+--------------------------------------|

Moving labels into objects without making the actual renderer consume declared

no general transition DSL or prose-to-proof service is introduced.

* SPECIFIED Core admission and checked-value handoff
:PROPERTIES:
:CUSTOM_ID: s2-core-candidate-handoff
:END:

The following are logical existing-field paths and proposed migrations, not an
implemented replacement API. Core owns these records; Library does not maintain
another admission/candidate cache.

| Boundary / actual call | Required retained result and next read |
|------------------------+----------------------------------------|
| Publication / admit-module-publication! -> publication/eligible | Existing correct behavior: evidence.candidate is checked-publication, owner/source checks and dependency projection use it, linked publication stores it. Preserve evidence/currentness/source association |
| Provider produced Scope / recursive link | base-record.scope is the provider's final admitted Scope candidate and base-record.scope-evidence describes that same subject. Original provider record remains coherent in its own cache |
| Optional realization / dependency-scope | Derive actual effective input under the current realization/source/package guards. It is an input to this consumer edge's expected requirement Contract, not automatic evidence of admission |
| Required edge / admit-module-value!(requirement.contract, effective input, context) | Retain actual requirement-evidence; its candidate is the consumer binding. Construct bindings.alias from records.alias.requirement-evidence.candidate, not records.alias.provider.scope |
| Deferred factory / baseline.link(bindings) | Generated core.link/core.exports sees actual checked required-edge aliases. Build/admit actual child graph and wrappers from that binding; no direct raw parent/global import |
| Export protocol / bind-exports | Preserve actual .bind-publication owner/selection/export/currentness behavior on the produced Scope before final Scope admission; its returned value is the admission input |
| Final Scope / admit-module-value!(baseline.scope-contract, bound Scope, context) | Retain scope-evidence.candidate as linked record.scope; record.scope-evidence, exports/source/owner/currentness and cache subject must agree |
| Final guard / current!('scope-linked) -> cache insert -> resolve | No usable linked Scope is exposed before actual admission/final currentness passes. Return that same admitted record Scope under existing selection/source/failure semantics |

For the required-edge record, provider must retain the actual original base-record
and its original Scope/evidence/source association. requirement-evidence records
the consumer-local accepted receiver. The existing realization context retains
its source/selection association. If an effective raw input needs diagnostic
retention, label it explicitly as input; never overwrite provider.scope while
leaving provider.scope-evidence describing another receiver. No redundant public
required-scope mirror is needed when the authoritative returned candidate already
lives in requirement-evidence. Audit/update every direct record consumer at Core
when applying this migration; do not keep a second old binding route.

A required-edge normalization must not mutate/replace the provider's cached
produced Scope or contaminate another consumer's differently admitted view.
Conversely, final produced-Scope normalization belongs to that provider's record
and is reused only under its actual valid source/context/currentness. Realization
and requirement admission are not skipped when a cached provider exists.

Keep both original provider provenance and consumer-specific evidence reachable
at their actual owner. A copied candidate/identity/evidence-shaped object supplied
by a caller is not an accepted required edge. Source/style/descriptor/policy/read
and realized-build guards remain active around actual getter/validator/factory/
.bind-publication calls; no broader read cache or discarded final guard is added
for apparent speed. Existing publication-tail optimization is retained only within
its current qualified closed window, never across a new effect/author callback.

* SPECIFIED Construct, normalize and expose one coherent graph
:PROPERTIES:
:CUSTOM_ID: s2-construction-call-order
:END:

| Stage / responsible owner | Input -> actual checked output and invariant |
|----------------------------+---------------------------------------------|
| 1 / Generic objects + Config/interface | Authored Generic and closed selected Config -> actual validated Config/Generic references, full Generic Scope and retained Core Scope evidence |
| 2 / Core required edge for Rust Parent | Actual produced/realized Generic Scope -> requirement-evidence.candidate; consume its entry, role/family/source associations |
| 3 / Rust object owner | That exact admitted Generic entry -> full Rust definition, validate/admit under RustResourceModelContract, retain returned Rust |
| 4 / Integration owner | Returned Rust -> full Integration mapping/delta/case definition, validate/admit under BackpressureIntegrationContract, retain returned Integration |
| 5 / Both policy owners | Actual applicable checked role/family references -> two separate checked policy values with their own expected descriptors and semantic revisions; parent=false |
| 6 / Implementation/interface assembly | These checked declarations plus real deferred operations -> full effective Scope exports and returned typed Function wrappers; no invocation |
| 7 / Core export binding + final admission | Produced/bound Scope -> final scope-evidence.candidate with coherent checked descendants/parents/policies/callables/source association |
| 8 / Consumer link/S3 | Final guarded cached record -> exact consumer-visible Scope; further requirement normalization produces its own retained edge candidate, not a raw reuse |

Do not assume validate is identity-preserving, idempotent or wrapper-free. A
returned checked Generic/Rust can differ from the authored receiver. Construct
its descendant using that checked predecessor, and validate cross-export relations
on the final effective checked graph. If normalization affects nested references,
it must preserve/rebind them coherently as part of the qualified normalizer before
acceptance; changing one parent field after admission invalidates that evidence.
Independent revalidation/cloning of each component that detaches parent references
or wraps callables under stale evidence cannot be accepted.

Within a constructed Rust Scope, Rust.parent refers to its actual required-edge
checked Generic entry; Integration.parent refers to the returned Rust exported
there. A later Scenario's separate Generic requirement may have a different
consumer-local normalized view. Corroborate its actual provider/source/family and
qualified normalization association with Rust's recorded parent; do not substitute
it into an already admitted Rust, require raw eq? across all consumer views or
accept equal printed identity strings as lineage proof. Unsupported/incompatible
normalization refuses that route; no optimistic semantic equivalence is invented.

Opaque parent/descriptor association fields do not recursively execute one
another's Contracts. Reuse S1 effective value shapes and actual contextual
relationship checks; source-qualified checked references need no objects -> Types
-> objects self-validation loop. Construction is once per successful actual
linked Scope, not a new global singleton guarantee. New/failed contexts can
construct other instances, with their own evidence and guards.

* SPECIFIED Failure, cache, currentness and direct migration
:PROPERTIES:
:CUSTOM_ID: s2-failure-and-migration
:END:

| Event | Required state and boundary |
|-------+-----------------------------|
| Wrong/missing Config/role/parent/policy/export/semantic revision | Stop affected construction/admission; publish no successful child or Scope with placeholders. Independent previously accepted provider evidence remains historical/valid only at its own current scope |
| Requirement refuses or source/realization changes | No child factory using raw fallback; no alias bound from a discarded candidate. Preserve actual diagnostic/source occurrence; existing failed-session policy still applies |
| Child graph/Function/final Scope normalization fails | No partially constructed current Scope/cache entry. Already admitted upstream provider is not globally rolled back or relabeled as the failed child |
| Final source/currentness check fails | No new successful cache insertion or current return for that route; actual known previous values retain only their original identity, not successor eligibility |
| Public presentation/export fails after actual accepted link | Preserve actual owner/evidence state and report unavailable export; no claim that the real accepted operation or an unrelated owner was rolled back |
| Source, descriptor, policy, parent, Config or implementation changes later | Re-evaluate affected selection/link/currentness under actual guards and input closure; do not return stale cached graph because identity/version/fields look equal |
| Independent consumer or new source context | Required-edge normalization/evidence stays local to that actual consumer; no global cached Parent/definition transplanted by a helper |

Keep existing active-cycle guards, current-source/selection checks and failed
context behavior at Core. No cross-owner transaction or rollback is promised;
Library/Config evaluation may have already performed real reads/composition.
S2's declaration path performs no project/tool scans or method/authority effects,
but cannot retroactively undo unrelated arbitrary effects a malformed extension
attempted. Such a route is refused, not qualified by a fake rollback receipt.

Implementation order is S1 expected Types/actual supported definitions -> Core
normalized provider/edge/final handoff controls -> Generic objects/Config/exports
-> Rust/Integration/policies and sole semantic declarations -> deferred consumers/
Function wrappers/complete exports -> coordinated active caller/test migration.
Actual implementation work can be grouped to avoid publishing incompatible halves;
public exposure waits for all its real requirements. Remove generic-entry and
resource-slice-entry active aliases directly; retain historical artifacts in their
original meaning without maintaining two accepted current paths.
