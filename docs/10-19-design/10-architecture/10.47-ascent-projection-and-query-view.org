* DESIGN WP06 objective and retained owners
:PROPERTIES:
:CUSTOM_ID: ascent-projection-and-query-view
:STATUS: Target relation/call/transaction design only; no implementation, Session run or Q issuance
:END:

WP06 projects one actual C and its required investigation inventory together
with actual applications A, attempts E, private issued W and qualified current
uses. ASCENT derives finite scoped consequences from accepted inputs. A completed
owned query view Q binds that exact accepted program/source/result/request basis
for Aitia; it does not mean all duties passed or confer review authority.

Library publishes domain/catalog/criterion/coverage semantics. Scenario binds C
and actual input/result/use associations. The existing ResourceEvidence program
owns domain projection/rules/query construction, ASCENT Session owns source
transactions and evaluation, and Aitia owns verification and disposition. No
second fact store, rule evaluator, transaction manager, result registry, version
service or approval engine is introduced. All relation names/Contracts below
are target responsibilities, not implemented exports or a new persisted schema.

The declaration generation remains read from the one Contract owner specified
in WP01; Q references it with the actual selected role/policy/source association.
Same V1, semantic revision, path, result label or query timestamp is not sufficient
to identify an accepted program, source cut, execution, qualified use or Q.

The target operation boundary is prepare-projection(C, request, actual outcomes,
qualified uses) -> checked candidate; commit-projection(owner, candidate) ->
accepted projection/result or failed-attempt diagnostic; query-view(owner,
accepted projection, checked query request) -> owned Q or refusal. These are
responsibility names for refactoring existing operations, not runnable APIs here.
The owner is created for its actual checked program/provider/C association.

Request fields specify supported selection of claims, evidence-source cuts and
query purpose. They cannot supply raw relation rows, arbitrary predicates/receipts,
replacement validators, program/rule paths, source identities or an Aitia policy.
The trusted adapter determines exact accepted uses and projection fields. It may
retain private operation/result association metadata and previously published Q;
it must not maintain a second mutable mirror of Session facts. Owned Q artifacts
are observations of committed state, not a competing fact database.

* SPECIFIED Identity, input ownership and relation fields
:PROPERTIES:
:CUSTOM_ID: ascent-projection-relation-fields
:END:

Keys distinguish occurrence from content and from execution:
C is an acquired use; D a required duty instance; K a required coverage unit;
A a concrete application; E an actual attempt; W an original private issued result;
U a fresh target use; B an exact semantic/input comparison basis; G an actual
correlated upstream run/derivation group. K exists even with no A. One Rust-suite
A/E can yield six scoped W/claims; SI/TM have their own A/E while referring to
the exact original Rust group G. Never force all evidence into one run or join
it solely by case/obligation/method names. Fresh cross-C use preserves W's original
C0/A0/E0 and must have an actual target C/A/U association.

All relation fields are primitive finite enums, bounded exact integers or owned
nonempty reference strings under expected Types; actual definitions/handles and
artifacts remain accessed through their qualified owners. Copy strings on ingress
and presentation; reject mutable nested objects, callbacks, hash tables and
unqualified opaque values. Do not intern arbitrary input IDs as symbols. Known
relation/enum symbols are declared by the program. A digest in a cell represents
a checked binding only because of its actual producer/subject/role association.

The table specifies declared source relation responsibilities. Refactor them as
normal define-evidence relations and expected field Contracts, not a second generic
relational schema service. Large bound values/ordered artifacts are referenced;
expand collections only under a supported finite typed role/index rule.

Required keys are functional at the declared scope: C/selection; C/D/K definition;
C/A identity; C/A/K claim/basis; C/A/E group; C/A/K/role expected binding; W identity/origin;
W/role actual binding; U target/verification. Conflicting values refuse the affected
candidate transaction, preserving prior accepted state and diagnostics. Exact
repeated row deliveries may normalize idempotently at this declared set boundary;
distinct actual E/W/U never collapse because their content matches. Preserve
intake/origin references under their actual owner, not invented duplicate facts.

A capability's required role set is validated independently. The methods/content
checks in this slice all require material input roles; an empty footprint is
malformed and cannot be admitted by negation. Optional inputs become explicit
supported role bindings when selected; absent unselected optional roles do not
create spurious required gaps. Future genuine zero-input claims require their own
explicit supported criterion/meaning, not an accidental empty map. Invalid A/U
may be retained as diagnostics, but never as qualified application/use facts.

One prepared A can have several actual E attempts. Their distinct G/W/U origins
remain distinct even when their input basis B is equal; G is not a mutable slot
on a shared application_claim row. For derived applications the expected upstream
binding constrains G; for a Rust attempt its actual run establishes G. Current
use eligibility is explicitly selected by the trusted verifier/source cut and
replaced as a whole. No rule picks the largest ID/timestamp or treats an older
failed check as a permanent contradiction of a later actually qualified use.
Withdrawal/revocation must still remove every affected eligible U at that cut.

For qualified reuse, compare target expected bindings to the original actual W
footprint at the supported meaning. Any admitted normalization/compatibility map
is itself an explicit verified semantic/input dependency; it cannot overwrite
W's original fields or omit inconvenient roles. No cross-C equality test alone
is sufficient, and no C0=C requirement may incorrectly prohibit genuine fresh use.

The old project sources migrate directly; historical query files retain their
old names/semantics rather than being reinterpreted under the new declarations:

Rules are finite, typed, safe and stratified under actual ASCENT admission.
Positive candidate/blocked/applicable relations precede any dependent negation;
no rule defines applicability as the negation of its own failure. Predicates and
comparators are qualified pure computations on accepted primitive values: no
clock, environment, filesystem, network, hidden mutable classifier or arbitrary
callback inside rule evaluation. Hashes are references to already qualified
inputs, not an instruction for Datalog to read those files.

The core applicability condition is a conjunction: the required K and capability
are valid; actual A targets it; U binds this C/A/K/W/B; original W meaning/strength
is sufficient; all independent required and complete expected/actual input roles
match; required upstream uses share the actual supported G; and current qualified
eligibility was verified at this source cut. Matching one row or a receipt string
alone never establishes the conjunction. Structural/type/identity collisions
refuse admission before inference; supported typed gaps can be inferred/reported.

Coverage, property support and control correctness are different questions.
M06 harness/control success can provide the required negative-control observation
while its ownership W remains counter. Lean proved negation remains a budget
counter; QNT unfinished violation retains its qualified reachability meaning.
A design review may require that such known unsafe alternatives are documented
and checked, rather than demand ownership support from them. Its actual policy
must express that criterion; neither this program nor a count silently resolves
or suppresses the counter. Aitia applies review/disposition policy later.

Support does not erase counter. A counter-only unit is observed and may be
pending_support; it is not missing_observation. A mechanically supported content
unit does not fill an absent semantic-review unit. Applicable contrary findings
from all required investigation sources remain visible, including across attempts
where the actual broader duty requires them. Comparison/aggregation rules state
which propositions they compare; they cannot choose a favorable run for the
whole project or turn run-local support into universal refinement.

Alternative methods or independent repeats only combine when the selected policy
explicitly permits that coverage. Correlated RL/SI/TM sets bind one actual upstream
Rust group; combining RL from run X with SI/TM from Y is not a complete same-run
slice. If a required alternative/role cannot be supplied, keep a gap rather than
shrink the demand. Unknown domain/unsupported coverage remains explicit even if
all known rows have a finite completed result.

* SPECIFIED Candidate preparation, commit and rollback
:PROPERTIES:
:CUSTOM_ID: ascent-projection-transactions
:END:

Use one C-bound serialized owner of the actual admitted program/Session. A new C
normally opens a new target owner; retained W/history can be referenced through
fresh use. Any supported Session rebind must atomically replace the complete
C-sensitive source inventory and be qualified explicitly. Changed relation schema,
rule/predicate/provider semantics or actual program association requires a new
qualified program/Session, not replacing facts under a new rules-path label.

1. Resolve checked Scopes/C and actual project rule/catalog/policy/provider/source
   closure. Derive required_duty/unit/role independently of supplied outcomes;
   validate exact request scope and complete source-relation inventory, including
   explicitly empty sources. Refuse a malformed program/required catalog rather
   than mint an apparently successful empty investigation.
2. Acquire actual producer-recognized W and fresh use/status observations through
   their bound operations. Preserve original W/E and history, failed attempts,
   missing A and required content gaps. Prepare owned primitive rows and validate
   functional identities/domain/upstream associations. Invalid use is excluded
   with its real diagnostic; a typed missing/counter/conflict is not a reason to
   delete the required duty or reject a truthful negative view.
3. Prepare one consistent source batch for all dependent facts: required inventory,
   applications/inputs/attempts, witnesses/history, current uses/status, traces and
   gaps. Replacing current eligibility must remove stale/withdrawn U, not only
   append favorable uses or keep an old checked source by omission. Source history
   is read from the actual owner/accepted result or qualified inputs; no parallel
   mutable fact cache or caller-controlled union defines truth.
4. Invoke existing gerbil-ascent-session-replace-sources! with a trusted
   accept-result callback under the actual supported execution-control/limit
   route. Callback receives the prospective finished result. Validate exact
   requested program/owned source association, all required output relation
   coverage and source/use/currentness checks, and detach candidate rows while
   still bounded. Return exact #t only on conformance. No callback-supplied user
   predicates, Session reentry, external Q publication or review submission.
5. On successful return, Session's final acceptance/adoption has committed that
   exact result/source cut. Bind accepted projection metadata to that actual
   returned result and its owner; only then publish owned Q for the checked
   request. A completed result containing pending/counter/conflict is eligible
   as an honest Q. Acceptance verifies conformance, not all-green readiness.

The callback compares source rows visible through that actual result with the
prepared complete batch under the admitted program's field/set semantics. Its
association is supplied by the trusted serialized owner that constructed the
Session, not by serializing a private source-snapshot or inventing an exposed
commit-ID accessor. It may privately prepare an owned candidate view; that view
is never exposed as accepted before the actual call commits. Query requests do
not invoke another Session operation from inside accept-result.

| Failure/transition | Required retained state and externally visible result |
|--------------------+-------------------------------------------------------|
| Malformed field/key/source/required inventory before batch | No source change. Retain request/diagnostic; previous Q remains its old association |
| Duplicate replacement relation, field/provider/predicate failure, budget/error or rejection before acceptance | Existing prospective Session boundary retains prior accepted sources/result. No candidate Q/accepted revision is published |
| Callback false, truthy non-#t, exception or Session reentry | Batch refuses under existing owner; no prospective Q/rows leak as accepted. Reentry guards do not replace serialization of independent writers |
| Timeout/partial evaluation or interrupted unknown completion | Preserve actual diagnostic/partial result at its real scope; no complete Q for the requested cut. Do not relabel the last finished result as this request's answer |
| Final Session acceptance already committed, later presentation/export/file write fails | Do not claim Session rollback. Retain actual committed association; later recover/read/freeze that exact completed result through the real owner, or report unavailable publication. No fabricated duplicate commit or fresh method execution |
| Failed update while old evidence/source has since become stale | Old Q remains immutable history; source rollback does not restore external file/role/receipt validity. Block current use until actual fresh verification succeeds |
| New counter, withdrawn use or history projected into the technical/query source cut | Publish a new Q with required duties, diagnostics/history and changed applicability intact. Old Q is not edited. A purely external authority-status change follows WP08 current H/use without a new technical Q/R unless its declared query/input/coverage meaning changes |

Retained/persistent Session snapshots are in-process accepted values, not an
automatic durable crash transaction with artifact files. If the host/process is
lost before an observable terminal association, completion/publication remains
unknown at that boundary; a surviving file cannot reconstruct private acceptance.
A supported recovery must genuinely re-admit the program/source/evidence/use
basis and record any new evaluation as that operation. If the original accepted
origin cannot be established, retain the uncertainty rather than invent a commit,
rollback receipt or portable private authority.

Clue exchange/trajectory attestation may perform genuine operations before the
project batch. Those operations are not rolled back by a failed project Session
transaction. Retain their actual origin and retry idempotently under supported
identities; do not claim distributed atomicity, forge an accepted row or delete
history to align owners. Attempts/diagnostic files also remain actual artifacts.

All stages, including row validation, callback materialization and Q encoding,
need declared finite bounds; the current 4096 program labels are not automatically
sufficient for expanded content/trace inventories. Derive supported limits from
actual cardinality/role/domain constraints and qualify them under fixed acceptance
budgets. Use existing ASCENT execution control where actually supported; a later
run-timeout on a clean cached result cannot enforce a deadline for the batch
that already ran. Unsupported deadline/resource enforcement remains a gap at its
actual owner, not a new project watchdog engine or a silent limit increase.
