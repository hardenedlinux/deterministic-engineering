* Initial ownership failure (retained)

Before this refactor, =init.ss= selected one =parser= Module under =modules/=. That Module's
=objects.ss= imports =build-modules.ss= and exports the same whole-library catalog.
The root =build.ss= then appends the catalog and three explicit FFI specs to the
init-owned =std-make-spec=. Core really does own one selection epoch and the
normalized compiler handoff, but the retained whole-package roots remain the
practical membership authority. Init therefore does not organize the actual
compiler/runtime/language subsystems or control their membership separately.

Changing only =:load-modules "./modules"= to ="./src"= is insufficient. The
source loader discovers declared Module leaves, not arbitrary Scheme files;
a directory with =interface.ss= is a leaf, and its private children are not
additional namespace branches. Current =src/modules/parser/interface.ss= is a
business API module, not proof that its directory is already a Yuanxu Module.
Directory placement, native Scheme module identity and Yuanxu publication
identity are separate concepts and must remain explicitly related.

* Native construction and build chain

The intended chain is:

#+begin_example
init.ss: load/choose source-directory Modules
  -> one Core source context and selected dependency Graph
  -> guarded native role sources and actual Scheme import closure
  -> owner-bound additional Build projections (notably FFI)
  -> the same init-owned std-make-spec
  -> Core defbuild-script
  -> Gerbil std/make and the default compiler
#+end_example

The implemented init uses =mode: explicit= to select the nine subsystem
publications under =./src=. Core's =mode: auto= discovers eligible Modules on
demand; an empty auto window does not itself select all Modules for compilation. Additional windows or explicit selections for language Libraries are
part of the same init epoch. Mount names organize access; they do not create
publication identity or permit duplicate identities. Auto mode discovers
eligible Module declarations; it is not a raw =src/**/*.ss= build glob.

Each subsystem's roles must have real responsibilities:

- Types declare its actual Scope/value/function contracts using existing POO/Core types.
- Objects expose existing implementation functions/prototypes, rather than a private source-file inventory.
- Config supplies genuine settings/defaults consumed by that subsystem; no dummy settings.
- Interface declares identity, real Scope, dependency contracts and selected projections.
- Build, where needed, declares owner-relative extra native entries and their options. It does not execute another compiler loop.

Core already derives role sources and their observed native import dependencies
in =module-system/source/build.ss=. Its =BuildContributionContract= admits
=module/build= values with owner-relative =roots=, including =gxc:= options.
=building/build-projection.ss= and =building/interface.ss= retain the selected
source guards and exact std/make consumer handoff. Reuse those mechanisms.
Do not put an =all-files= scan or another whole-package catalog into every Module.
Do not export the phase-bound Build value as a runtime Scope service.

The final root =build.ss= must consume the init projection, not select files by
itself. Remove =modules/parser= as a catalog-forwarding owner and retire the
production =build-modules.ss= list after native coverage is demonstrated.
A one-time migration comparison may read the old catalog as historical input;
that comparison is not the new build driver.

Core selection lowers required Modules into its existing dependency resolver,
which reports =dependency-cycle=. Hiding these edges behind an empty
=requires:= object, or retaining all files unconditionally, is not a valid fix.

Classify the actual imports before assigning final Module requirements:

1. Shared grammar, IR, value contracts and pure utilities belong below both
   compilation and execution. Extract or reassign them only after checking
   their actual native import closure and current callers.
2. Compiler/generator code consumes that shared contract, not the assembled
   runtime service. Runtime executes an already constructed machine/plan.
3. Language assembly/integration binds compiler output to execution. Move the
   current reverse composition responsibilities to that owner.
4. Syntax-phase/native compiler imports and runtime Scope dependencies are
   distinct edges. Keep the former in the native closure and declare the
   latter as actual Module requirements; do not manufacture Scope cycles
   by mechanically copying every source import into requires.

These are target responsibilities. The initial native interface/SCC inventory above is complete for its 259
inputs. Phase-specific Scope/API classification, ownership dispositions and
exact file moves remain open; no dependency split is claimed implemented.

* Facades, language Libraries and FFI

The old catalog also owns root public facades, =language-support/= adapters and
=languages/= entries. They must not disappear when the src window changes.
Assign every currently supported facade to an actual Module API/import closure;
use separate declared language Module selection where appropriate. Native role
imports can provide a real public facade dependency closure without a second
file discovery pass. Any required compatibility facade remains a thin Gerbil
re-export with its actual source association, not an alias publication or a
second build selection.

Keep public Scheme import paths and C ABI stable by default while reorganizing
internal ownership. An actual incompatible public API change must update its
known consumers and tests explicitly. Unsupported/unused old catalog entries
are dispositioned in an audit, not silently dropped to pass compilation.

The three FFI entries remain =language-abi=, =language-abi-context= and
=rust-aot-abi=. Their owner declares include paths and platform link arguments
once in its Build projection. Avoid enrolling the same C entry through an
unoptioned role import and again through a differently optioned Build root:
Core rightly refuses conflicting contributions. Runtime ABI contracts can
remain available through pure interfaces without evaluating C declarations
while simply enumerating the Module namespace.

** Scope signature refinement: concrete domains and parametric services

Named Records alone are insufficient when their method inputs and results are
all =Any=. The refactor gives each actual service an explicit boundary:

| Service | Input/result boundary | Semantic owner |
|---------+-----------------------+----------------|
| Compiler | Structural Grammar Record or schema-bound GrammarIR -> GrammarIR | Existing normalizer retains composition checks; source/compiled objects must interoperate |
| Graph query constructor | Existing GraphQueryViewContract -> GraphQueryContextContract | Existing graph view/context admission and ancestry checks |
| Artifact roundtrip | ParseArtifact -> String | Existing structural artifact validator, not a second artifact checker |
| Host initialization | No arguments -> Unit | Existing compiler-host policy |
| Compiler options | No arguments -> List String | Existing compiler profile |
| Build-spec adjustment | BuildSpecification -> BuildSpecification | Gerbil std/make owns instruction semantics |
| Native link options | List String -> String | Existing selected-object provenance check |
| ABI / language metadata | UInt ABI values; Exactly the existing schema declarations | Existing schema.ss remains the only metadata source |
| Test-form admission | Arbitrary syntax datum, List Symbol, optional List Symbol -> Bool | Existing syntax admission walk |
| Text lines | String -> List String | Existing string implementation |
| Whitespace | Character -> Bool | Native char? Type |
| Generic lists | list-operations-for(RowType, KeyType) -> TypeValuePair | Native Record/Function input, callback and output validation; no default domain |

=ListOperationsScopeOf= connects the row list, inserted row, key callback and
conflict callback using the same caller-selected types. The published Utilities
Scope contains concrete string services and an explicit =list-operations-for=
factory. It accepts two native Types and returns the existing POO =TypeValuePair=:
the concrete operations Type paired with a value validated by that Type. No
=Any/Any= default or unconstrained list methods are published.

Concrete row representations may use =defstruct=. Their owner defines a native
POO Type using the struct predicate and supplies it, together with the Key Type,
to this factory. A struct-row/Symbol-key test exercises admission, callback key
validation and rejection of an unrelated string row. The Type parameter carries
the caller's actual struct predicate; the utility does not invent a universal
nominal struct identity across source/compiled worlds. Native =TypeValuePair=
validation also rejects a factory result whose value does not match its Type.
No alternate Type engine or function-wrapper implementation is introduced.

Remaining =Any= occurrences have explicit reasons: membership predicates accept
invalid candidates and return false; test syntax can be an arbitrary Scheme
datum; native std/make option
payloads and heterogeneous IR section bodies remain owned by their existing
consumers. These are not evidence of semantic validation. IR typing checks the canonical schema and symbolic grammar identity as well as
symbol-keyed rows; it does not certify grammar correctness; BuildSpecification typing does not certify
a native instruction or compiler invocation.

Validation must exercise real normalized Scope functions, reject native Type
mismatches before target effects, check callback and output mismatches, preserve
optional-argument checking, and retain compiled Grammar/artifact interoperability.
An arbitrary exception from the implementation does not count as Type rejection.
The type-focused tests therefore recognize native =TypeError= specifically.

The explicit list-service factory belongs to =src/utilities/lists.ss=. Its
=objects.ss= role publishes only the existing implementation binding; executable
construction does not move into the declaration role. An initial misplaced
helper is refused by the existing Interface authoring Contract, with the failure
retained as =parser-explicit-row-types-cohort22.log=; that guard is unchanged.
