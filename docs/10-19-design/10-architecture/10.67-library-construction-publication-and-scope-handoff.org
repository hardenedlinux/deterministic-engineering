* SPECIFIED One coherent publication and its limits
:PROPERTIES:
:CUSTOM_ID: p2-construction-publication
:STATUS: Source/design and static documentation only; no implementation, acceptance run or delivery
:END:

P2 joins complete P1 expectations to real construction and deferred operation
bodies, then to Core's actual checked Scope handoffs. The publication unit contains
the returned Generic/Rust/Integration definitions, both distinct policies, the
single mapping/delta meaning and real typed method bindings. A field-complete
Scope with placeholder bodies or discarded normalized candidates is not publishable.

This chapter consolidates 10.55 with 10.65-10.66; it does not introduce another
family factory, schema, admission cache, loader or execution framework. POO objects,
prototype composition, explicit required aliases, core.exports lowering, POO
Function wrappers and Core contextual admission remain the construction path.
Public module publication here means a qualified local source/Scope exposure;
it is not project approval, Library distribution or receiver adoption.

P2 defines before C exists, and executes no Rust/QNT/Lean/SysML analysis while
constructing declarations. Future calls consume actual recognized C and explicit
Host inputs under P3/P4. Method binding before exposure and method execution after
capture are separate boundaries. This design task performs neither.

* SPECIFIED Real operation binding before exposure
:PROPERTIES:
:CUSTOM_ID: p2-real-method-bindings
:END:

P2 publishes real callable values against P1 Function Types. Actual implementations
may be pure functions or deferred effect operations over explicit arguments; they
are not procedure? promises, successful dummy validators, callbacks supplied by
Profile or descriptors with an unimplemented body.

| Binding group / actual owner | Before publication / actual call boundary |
|------------------------------+-------------------------------------------|
| Generic declaration/parameter/model helpers | Real supported pure functions over checked Generic and expected data. Generic-only demand does not initialize Rust/Integration or unrelated providers |
| Rust/QNT/Lean/SysML preparation/execute/observe | Bind actual selected capability/Contract/source to returned checked model/Integration/premises. Calls later consume recognized same C/A and actual explicit tools/Host/input origin; P2 neither scans a repo nor launches these tools |
| Content observers and reference closure | Bind real supported architecture/Org/decision parsing/semantic observation/ref-closure operations and finite demand contracts. Missing project content is a future typed gap; missing implementation is not a gap-producing placeholder body |
| Private result issuance/current use | Actual qualified producer/issuer and source-read/status boundaries at P4 owners, with immutable W and fresh target use. Public record getters/shape checks cannot mint issuance or make C authentic |
| ResourceEvidence registration/projection | Keep generic rule/Session owner at ASCENT, actual application Clue/history capability at supported Flow owner under P0. Real verifier is Host-bound; no Agent attestations or copied runtime store |
| Review/Host adapters if advertised by selected policy | Actual qualified Aitia/shared Host operation, expected purpose/facts/action/role/status signature and source association. Policy-neutral declarations do not appoint users or execute review |

Validate each callable under its exact argument/keyword/result/exception/limit and
claim/domain Contract; retain the returned wrapper in methods and its corresponding
method-contracts entry. A real implementation raising an honest unsupported-domain
or missing-input diagnostic under its declared capability is different from a stub
that pretends all advertised methods exist. Required policy capability cannot be
satisfied by unconditional unsupported/pass/empty results.

Bind operations after their referenced model/policy values have returned from
admission. They close over those actual checked definitions or consume the exact
explicit selected reference; they do not capture pre-normalized globals. Functions
must not close over a future Scenario capture or call init to find their own Scope.
If final root normalization would replace a captured definition, it must also
provide a qualified coherent real rebinding before acceptance, or refuse. Rewriting
a parent field or wrapping a method after Scope admission invalidates that evidence.

No ordinary external operation runs during declaration/method/Scope validation.
Imported initializer/expansion effects are a separate P0 source/build/cold-load
qualification concern: syntactically deferred calls do not prove inert imports.
Binding availability and actual later execution provenance remain distinct evidence.

Wrong Config/parent/policy/revision/mapping/body/wrapper/required edge or stale source
aborts that affected construction; no successful partial Scope/cache entry or raw
fallback is published. Already accepted upstream provider evidence is not undone
by a later child failure. If an export/save fails after genuine issuance, report
that later failure; do not pretend Core rolled back an issued receipt or external
effect. Existing sticky failed-session rules remain, not an automatic retry route.

Changed definition/premise/mapping/policy/body/source requires new eligible source/

revision labels need not change for source bytes to invalidate old currentness.
Never mutate an old admitted graph, erase its negative findings or revive revoked
credentials when old bytes return. P2 does not compute empirical causal effects,
guarantee minimal invalidation or introduce global invalidation/authority service.
