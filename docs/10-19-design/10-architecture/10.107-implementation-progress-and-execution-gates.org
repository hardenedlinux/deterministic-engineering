* Parser prefix policy and publication-wrapper removal (2026-10-25)
:PROPERTIES:
:CUSTOM_ID: implementation107-parser-prefix-policy-removal
:END:

** Implemented scope and authority boundary

Following the user's confirmation, remove the source of the redundant input
policy rather than moving it into Core. =package-inputs.ss=,
=library-publication.ss=, =preparation-snapshot.ss=, =preparation-cache.ss= and the
now-unused =build-environment.ss= are deleted from Parser and its library catalog.
Their dedicated tests are retired with the implementation. Compiler process,
Core projection, FFI, worker failure, idle/silence and actual language tests remain.

The separate =build-qualified-library.ss= is deleted. =qualify-library= delegates
to the existing =build.ss=; optional/helper builds invoke their existing standard
Gerbil entries without =publication-build-main=. =qualify.ss run= retains its
actual process supervisor, budgets, output checks and failure propagation but
no longer presents a Parser receipt as authorization to run. Its obsolete
=--library-write= flag and workflow callers are removed together.

Conformance preparation invokes the existing =compile-static-conformance!= and
native link entry. The prefix-wide copied cache and =scripts/preparation-cache.ss=
are removed; the small source-only test classification remains in the existing
=scripts/test-plan.ss= declaration owner. No replacement cache, graph registry,
whole-prefix observer, signer or scheduler is introduced. The failure archiver
continues to preserve failed lib/bin outputs and original status, but stops
expecting the removed publication record.

Ordinary compiler completion is not review/delivery authorization. This change
retires Parser's own whole-library issuance promise; it does not replace that
promise with a weaker receipt. Core/Gerbil own the actual selected-source guards,
normalized build spec, compilation and required-product checks. A higher-level
consumer needing evidence must bind its actual capture, source, command and test
result through the existing evidence owner, rather than trust a Parser marker.
No new Core API is introduced for the removed policy.

* Parser build responsibility consolidation (2026-10-25)
:PROPERTIES:
:CUSTOM_ID: implementation107-parser-build-consolidation

** Architecture and first implementation slice

Gerbil is the default compiler and standard build toolchain. References to a
separate project-owned SDK layer are withdrawn. Existing toolchain environment
variable names, such as Apple's =SDKROOT= or release-provider inputs, remain
external interfaces; they do not define a new architectural owner.

The build path remains Parser declarations -> =yuanxu!= / =init= -> the same
=std-make-spec= -> Core =defbuild-script= -> Gerbil =std/make= / compiler.
No new builder, dependency resolver, scheduler or compiler implementation is
introduced. Two workers and the existing heap limits remain; the earlier
user-authorized removal of Parser's 180-second build cutoff remains in force.
Core's separate 180-second build boundary is unchanged.

The first slice removes Parser's unused =loader-products.ss=, its sole catalog
entry and its dedicated test suite. Production had no caller. These tests only
exercised the removed post-build wrapper-deletion mechanism; runtime module
loading tests and the real runtime loader remain. All current build products
must still be checked by the existing owner.

Parser's duplicate byte/text drain loop moves into the existing Core Ops
=copy-process-output= function. Its four positional arguments and default line
mode are retained. Optional =mode:= is limited to =lines=, =text= and =bytes=;
chunk modes refuse line-progress callbacks. Real data is forwarded in bounded
chunks before newline or EOF. Gerbil ports own text decoding; =run-process=
continues to own process spawn, wait and failure propagation. Parser retains a
thin invocation adapter, its actual compiler options and FFI configuration.

** Correction: remove prefix-wide policy at its source

The =package-inputs.ss= wrapper is not a Parser responsibility. Its original
purpose was to exclude reverse-dependent products from the whole-prefix input
snapshot in =library-publication-inputs=. The snapshot first treated unrelated
installed library files as inputs; the policy then enumerated every package,
validated metadata caches, inferred namespace/path ownership, computed reverse
consumers and intercepted imports to compensate. Calling Gerbil's native graph
functions does not make this additional Parser policy necessary.

The target is to remove that whole-prefix snapshot and the compensating policy
together, not merely make the policy lazy, rename it or move the complete file
into Core. Ordinary builds consume declared module/FFI specifications through
=std-make-spec= and =defbuild-script=. Verification consumes the framework's
existing selected-source/dependency/product information; genuine external
non-Scheme inputs remain explicit declarations. If an existing framework API
cannot provide a required observation, identify that precise missing contract
before proposing an addition. Parser does not acquire a general package-policy,
namespace-ownership or publication authority role.

Acceptance must preserve the actual obligations rather than the removed
algorithm: a selected source, dependency, compiler or required FFI-input change
invalidates affected verification; a missing required product or failed build
refuses; unrelated downstream outputs do not become upstream compiler inputs.
Import/source-owner boundaries are checked through existing framework owners,
not a second Parser expander admission policy. Tests devoted solely to the
removed implementation are retired or replaced by these boundary checks.
The current =772689f= qualification run verifies the preceding first slice;
its successful completion would not approve retaining this policy architecture.
