* Unified target and current-source limits
:PROPERTIES:
:CUSTOM_ID: a1-scope
:END:

A1 unifies effective declarations for the organization/formation slice and the
existing backpressure Library family. It retains 10.77's complete field, origin,
strength, policy and downstream request obligations. It refines their declaration
ownership and binding to the actual four owners; it does not reduce them to a new
small schema. All names marked target below are proposed descriptors/slots in the
existing files, not currently implemented exports. No directory change, executable
implementation, acceptance run or automatic orchestration is performed here.

Public extensible values remain ordinary POO objects and Type/ObjectContract
refinements. Core contextual Contracts add admission evidence and responsibilities;
ASCENT evaluates the domain program; Aitia retains its independent CLOS/request
owners. No parallel validation DSL, object registry, decoder-dispatch schema,
version manager or copied Aitia enum is introduced.

* Sole generation source and inheritance graph
:PROPERTIES:
:CUSTOM_ID: a1-generation-inheritance
:END:

This is an explicit ownership refinement of 10.77's backpressure-only source path.
For the unified repository Library, target LibraryDeclarationContract in existing
library/project-organization/types.ss owns the sole authored contract-version=V1.
BackpressureDeclarationContract and OrganizationDeclarationContract inherit that
metadata through ordinary POO descriptor composition. Backpressure keeps its fixed
family identity/constraints; organization gets its own. Neither family copies a V1
literal, introduces an independently adjustable generation nor inherits the other
family's concrete model constraints. The old proposed literal location in abstract/
types.ss is replaced, not maintained in parallel. This move is design only.

The sole read remains admitted Scope -> trusted expected role descriptor -> its
admitted family declaration -> inherited contract-version. The expected declaration
and actual source-qualified owner association must agree; a candidate object naming
V1 or a matching descriptor identity cannot select its own generation authority.
The common base constrains generation and common fields, not one concrete family's
identity. Each family refinement fixes that identity at its own expected descriptor.

| Level | Inheritance / association | Constraint boundary |
|-------+--------------------------+---------------------|
| Neutral Library declaration | LibraryDeclarationContract; sole V1 constraint | Own common descriptor metadata/value expectations, not a BackpressureModel identity or parent=false constraint on every child |
| Family declarations | OrganizationDeclarationContract and BackpressureDeclarationContract are siblings over that neutral base | Distinct fixed family/source ownership. Compatibility is explicit; equal generation does not imply interchangeable models, policies or APIs |
| Model shape | Common ModelDeclaration value shape | identity/role/family/contract/immediate-parent/revision plus declared meaning, requirements, capabilities and references; no concrete model fixed identity here |
| Concrete model Contracts | OrganizationModelContract; BackpressureModelContract, RustResourceModelContract and BackpressureIntegrationContract refine the appropriate shared shapes | Backpressure concrete Contracts remain siblings for fixed identity/parent checks; do not inherit Generic's fixed identity/parent=false on Rust |
| Actual backpressure values | Generic -> Rust -> Integration immediate published parent association | Actual prototype composition and parent links agree, preserving inherited duties/premises/input demand and allowed refinements. Skipping Rust is not shape reuse |
| Policies | Coding/design-policy Contracts are siblings over common policy shape; parent=false | Distinct identity/applicability/semantic revision. Policy combination is not model ancestry, evidence or a role grant |
| Profile values | Formation and resource Profile refinements share qualified references and selection fields | Effective inherited field maps and constraints conjoin. Closed checks run after deriving the supported full map, not on a parent's partial field list |
| Scenario values | Project-bound acquisition/C/operation refinements compose imported data Types | Actual issuer/source recognition is an operation boundary, not a field flag, prototype match or function tag |

Each published definition's revision is its authored semantic revision. Retain existing
opaque ownership-budget/v1, backpressure/v3 and backpressure-integration/v1 strings
as semantic revision values; they do not create V2/V3 Library generations. Organization
model/catalog/LR semantics, SysML method and each policy require their own actual
source-authored nonempty revisions before full publication. Do not invent revision
counters here. Missing authored revisions remain missing inputs to implementation.
Git SHA, dirty source cut, compiled identity, document revision, origin lease and
native wire tags remain separate. Org/D2 only reference/display these meanings;
no version suffix enters Namespace, filenames, model family identity or Module ID.

Model element kinds and supported SysML name forms are fixed by the selected catalog
and projection capability, not an unbounded string-to-code dispatch. Runtime modes,
resource bounds and input role multiplicities are narrowed by the selected method
and policy. Candidate/element/product/duty identity spaces are open typed identities
within published references; do not encode LIB-C01 or D01--D10 as a global enum.

Whole-value constraints reject unsupported cross-domain pairs even if every tag is
individually valid. Identity-preserving and nonidentity validators obey the same
call boundary. Well-formed incomplete/historical/negative variants remain expressible;
unknown input, missing evidence and unsupported operation are not positive success.

Concrete retention seams are: Library Config -> checked definition -> complete Scope;
Module implementation -> checked bound Function -> Scope; Profile request -> admitted
selection and one normalized parameter child; Scenario preparation -> normalized
immutable basis -> actual recognized C; C-bound reason result -> selected checked
plan -> projection request -> validated candidate. Every arrow retains the returned
value and its real association. A1 defines these expectations; A2 and later owners
implement the actual calls, capture, execution and promotion.

The existing names inputs/run/render cannot remain three unrelated procedures. A1
requires their direct migration to coherent signatures: preparation consumes admitted
Library/Module Scopes, Profile and actual input bindings; reasoning consumes the same
admitted C/projection input; rendering consumes a checked C/result/candidate/plan
request. The precise exported operation spelling can stay at the existing interface;
it does not justify a public raw-alist route bypassing checked values. Raw ASCENT
batches remain a private projection detail. If renamed, migrate all callers together,
without keeping a second unbound current API as a compatibility facade.

Function Types check inputs/outputs and retain wrappers while deferring method bodies;
a declaration check must not launch Rust/QNT/Lean/SysML or an ASCENT workload. Real
implementation source binding requires the actual selected provider owner; a callback
with the right arity does not establish its semantics. Missing required implementation
or authored revision blocks complete publication; model it as missing capability only
when the explicitly selected reduced design activity permits that absence.

Original acquisition/origin, expiring receipt and later re-verification/current use
retain 10.77's separate associations and interval semantics. No C mutation, second
capture, refreshed timestamp or output appended to its own canonical basis repairs
provenance. Normalizing a value does not authorize changing its sealed meaning.
A0's source/build/load/return-retention repairs must qualify actual use; A1 field
checks cannot hide them or reissue authority at a project-local wrapper.
