* Scope and source observation
:PROPERTIES:
:CUSTOM_ID: a0-scope-observation
:END:

A0 establishes one explicitly selected dependency cohort and preserves each accepted
normalized value across Core linking. It does not make the Project a package
manager, change Library generation, or infer loaded code from a filesystem path.
This chapter refines 10.81 A0 against actual current source and artifact files.
All repairs and acceptance controls below are proposed. No implementation, package
operation, compiler, Gerbil process, runtime acceptance, recovery or orchestration
is executed here. D2 rendering and Org checks are documentation operations only.

actual process loading and Core publication admission; none substitutes for another.

* Value normalization and the three broken handoffs
:PROPERTIES:
:CUSTOM_ID: a0-normalized-handoffs
:END:

Both Core checkouts have the same relevant control-flow shape despite renamed APIs.
POO owns ordinary value Type validation. In isolated POO, mop.ss provides validate
and ObjectContract./object-contract-validation.ss preserve checked receivers and
wrapped fields; type-validation.ss returns complete normalized containers. Core
owns evidence-bearing contextual admission, not another copy of those field rules.

Current Core types.ss contract-admit-evidence first calls validate on value-contract,
then classifies that normalized candidate and checks responsibilities/obligations.
yuanxu-contract-validate returns accepted evidence.candidate. Isolated Core has the
same protocol under poo-flow-* names. admit-module-value! returns accepted evidence,
not the normalized subject directly. Callers must extract its candidate deliberately.

Use these design symbols only as prose, not a new public protocol: K0 raw Context,
EK Context evidence, K1=EK.candidate; SP provider's admitted Scope; SX effective
Scope after optional package realization; ED consumer-edge evidence; SD=ED.candidate;
S0 linked/export-bound Scope; ES final Scope evidence; S1=ES.candidate.

| Boundary / current source | Current behavior | Required target handoff |
|---------------------------+------------------+-------------------------|
| Context: Core source/link.ss link-module-context, context-admission stage | Calls admit-module-value!(ModuleScopeContextContract,K0,K0), discards evidence, then closes over K0 and its generation, selected IDs, current?/locate/read callbacks and namespace | Retain EK and use K1 for subsequent Context reads, guards, graph selection, admission context, recursive build relinking and returned context. Preserve the actual origin/currentness association; normalization cannot silently grant new provider or source authority |
| Publication: source/admission.ss admit-module-publication! and link.ss publication/eligible | Already extracts accepted publication candidate before identity/source-owner checking and linked-publication construction | Keep this correct pattern, SourceRef ownership/currentness checks and native read issuance. Do not regress it into a boolean check or rebuild a publication from raw input |
| Dependency: link.ss link, requirements -> records -> bindings | Computes SX from base record and optional dependency-scope realization; admits the consumer requirement; stores requirement-evidence, but bindings reads provider.scope=SX | Keep ED with provider provenance and make only that consumer alias bind SD. Do not replace or mutate provider's globally cached SP with a consumer-specific wrapper; two consumers can have different normalized views |
| Final Scope: link.ss scope-factory/scope-admission -> record -> cache -> resolve-scope | Admits S0, stores ES, but record.scope=S0; callers and future dependents receive S0 | Store record.scope=S1 paired with ES; namespace/resolve/dependency consumers must receive S1. Keep publication and dependency records alongside it, run current! before publishing the cache entry, and preserve failure/refusal behavior |

The current default ModuleScopeContextContract is predicate-only and normally
identity-preserving. The discarded Context return is a protocol/extensibility gap;
this audit does not claim an observed nonidentity default-Context failure. Scope
Contracts can use value-contract normalization, so retaining a successful predicate
or an accepted? boolean cannot justify retaining their original receiver.

A precise dependency record can retain its provider, requirement-evidence and
consumer checked scope, or derive the checked scope from requirement-evidence at
the bindings boundary. The implementation must choose one coherent representation;
this design does not require another global cache. Never normalize the alias again
just to reconstruct SD: a second validation may make another function wrapper or
invoke callbacks twice. Exactly once means once for each actual admission boundary,
not once for the entire graph or no future currentness recheck.

For Context, merely rebinding a local variable is insufficient if callbacks, original-graph,
realization or source read guards still describe K0 while K1 changes generation or
selection. Core must preserve compatible provenance or reject/reprepare under the
original owner. Capture source reads and Contract policy dependencies using existing
observation/issuance mechanisms; do not certify copied callbacks with field equality.
Context admission bootstrap uses the original expected owner association; later
admissions use K1 without fabricating fresh authorization. Keep EK's original
candidate/context association intact; do not edit an already-issued receipt to make
it appear issued under K1. Subsequent edge/final admissions carry their actual K1
context and their own accepted candidates. Expose no new arbitrary
runtime Contract replacement or authority hook to make a test pass.

For dependency realization, validate the actual SX selected for that alias, not the
pre-realization SP, then pass SD to the consumer's link function. Keep realized
package/source guards and raw provider provenance distinct from the consumer receipt.
A rejection at any boundary cannot publish an accepted record, poison another
consumer's provider view or leave a partially successful Scope accessible. Preserve
upstream session poisoning/cache refusal and lazy sibling behavior.

A0.2 tests belong at Core's existing t/module-scope-link-test.ss and Contract tests;
POO wrapper/receiver tests remain with POO. The present link tests use predicate
Contracts and do not establish nonidentity handoff. A Context normalization fixture
must exercise the owner-controlled Context admission path or a factored private
helper with the real Contract algebra. Do not add a generic public replace-Contract
switch or patch production policy from the Project merely for test injection.

Required normalization controls include: one transforming provider Scope Contract;
a distinct consumer requirement normalizer; two aliases/consumers with different
wrappers; identity-preserving control; Context normalization with origin-compatible
callbacks and a conflicting-origin refusal; final-Scope normalized callable behavior;
selected package realization before edge admission; and rejection before consumer
factory execution. Verify semantic behavior, retained subject and admission counts
at each boundary. Rechecks of currentness must still occur after effects. The controls
must distinguish different objects with equal visible fields, rather than allowing
structural equality to hide a discarded checked receiver.

Existing Project t/project-formation-entry-test.ss exercises real Scope linking;
t/project-formation-test.ss checks application consequences. Preserve both, and keep
the pure module probe labelled separately. Matching rows from their shared code is
route parity, not the independent witness for normalization or ASCENT semantics.
No test implementation is added here. Source/API static checks may inform planning
but cannot close runtime, compiled-load or restart acceptance.
