* DESIGN Objective and retained authority
:PROPERTIES:
:CUSTOM_ID: s4a-method-execution-issuance
:STATUS: Existing-file/field/call design only; no implementation, acceptance or delivery
:END:

S4a consumes S3's actual recognized C, prepares method application A, retains each
real attempt E, issues scoped W only from accepted observations, and produces
fresh qualified use records for actual target applications. Rust, QNT, Lean and
SysML share C and common owner mechanics, not one undifferentiated pass flag or
one claim. Outputs never mutate C. Missing results leave independent duties open.

Library Types/declarations own reusable method meaning; trusted method operations
own interpretation and private issuance; Core Ops owns actual process execution;
Scenario owns project/C association; ASCENT owns accepted projection; Aitia owns
review/authority. No new executor, scheduler, signature service, public evidence
constructor or result registry is introduced. Public extensible records remain
POO values; compact private handles stay producer-owned implementation details.

The 75 selected project implementation/build/runner inputs match S0 and S3 at
inspection. Project HEAD remains 8044732d505f84e373119a70f947df00e1767300; linked
dirty Core HEAD remains 52130d2d338b09622a3f55e37987ddc0375b6187. Source inspection
is not current compilation/loading or execution evidence. WP00, BS01-BS09, S3
acquisition/origin qualification and the historical recovery timeout remain open.

* SPECIFIED A/E/Observation/W/use fields and relational invariants
:PROPERTIES:
:CUSTOM_ID: s4a-record-fields
:END:

| Subject | Required effective fields / boundary |
|---------+--------------------------------------|
| A / ResourceMethodApplicationContract | identity, C, capability and expected operation/Contract/owner, subject, claim or declared claim-set, case/cut/theorem/path, mode/domain/parameters/strength, expected-inputs, derivation/upstream references, execution/interpretation policy and relevant source/load associations |
| A.expected-inputs | Independently required role -> qualified captured or actual upstream binding, with cardinality/type/subject/domain constraints. Missing, extra, duplicate, conflicting or vacuous required roles refuse the affected executable application |
| E / ResourceMethodAttemptContract | identity, actual A, run/derivation group G, ordered preflight/derive/build/probe/run/check steps, actual command results, effective limits, owned raw inputs/outputs/logs, execution/interpretation findings and terminal or explicit incomplete state |
| E.commands | Actual Core operation/result and used launch descriptor references; effective executable/wrapper argv, resolved cwd/environment policy/basis, stream/log routing, limits, normalized status, raw wait-status, elapsed observations and available interruption cause evidence |
| Observation / ResourceMethodObservationContract | Actual C/A/E/G, subject/claim/basis, observed input/derivation/artifact inventory, exact proposition/target/domain, execution/validation/semantic/control dimensions, observer/loaded-source identity, diagnostics and premise/strength limits |
| W / private resource-result + owner-bound output Contract | Immutable original C/A/E/G/subject/claim/facet, scoped conclusion, actual footprint/artifacts/accepted observation and selected issuer association. Public record/hash/reference is presentation only |
| use / ResourceEvidenceUseContract | Original W/origin, target C/A/claim/basis, actual verifier/source/artifact/issuer checks, comparison of subject/domain/strength/policy demands, fresh verification association and limitations. WP06 denotes the actual qualified occurrence U |

A identifies an application; retries of it have distinct E/G. One Rust suite A/E
can yield six separately scoped W sharing that actual group. SI/TM bind exact
facets and raw observation of that Rust group, not merely equal filenames/digests.
The claim binding is not overwritten by the latest attempt. Missing A remains a
projection gap; preflight after a real A can retain E with no command started.
A request refused before A exists does not invent an executed E.

Normalize inputs and retain returned checked A/E/observations/use and operation
wrappers before contextual checks. Normalizers must preserve or re-establish
real owner association; copying fields or returning an unrelated object cannot
mint origin. Final E retains an actual attempt's failure/unknown completion even
when no W is issued. No mutable global last-result or success-only result list
is the authoritative attempt history.

The sole generation read remains the checked Library declaration Contract at
S1/S2, not another method/record/Namespace version. Existing serialized historical
schema tokens keep their original meaning and are not upgraded or relabeled.
Semantic revision or V1 equality alone establishes neither issuer nor execution.

* SPECIFIED Complete input basis and actual execution origin
:PROPERTIES:
:CUSTOM_ID: s4a-footprint-and-launch
:END:

A's full C association and its precise consumed footprint are distinct. Required
roles derive from capability/claim before results exist. Bind semantic inputs,
execution tool/runtime inputs, validation inputs, actual reader/runner/observer/
issuer/source/load dependencies, and supported domain/premises. Every role has an
actual qualified input/derived association; a supplied manifest cannot define
its own completeness. Shared dependencies remain shared honestly.

| Boundary | Input -> retained association / refusal |
|----------+----------------------------------------|
| Prepare / Scenario + selected Library operation | Actual recognized C + bounded request + qualified upstream W/use + execution destination -> returned checked A or explicit gap/refusal. No root/Profile/tool/policy/mapping overrides or caller ProcessScript/observer |
| Derive / actual selected method | Owned C/upstream inputs -> exact copied/generated model/theorem/build input, recipe/source/parameters and owned bytes. Derived products are execution inputs of A/E, not additions to C |
| Preflight / qualified source and Ops owner | Check supported environment/destination/config/limit domains and actual operation association. Hidden relevant input outside C/qualified captured domain blocks launch and requires proper recapture |
| Execute / Core Ops | Used prepared launch value -> actual process/result; retain the exact effective value after environment resolution and the invocation association. Never attach a separately reconstructed preview as launch proof |
| Interpret / bound observer | Exact E and required raw artifacts/targets -> accepted scoped observation or retained rejection/incomplete finding. Tool output, independent oracle and expected control remain separate inputs/dimensions |
| Issue / trusted producer | Accepted observation + real E and complete required closure -> private W. No public issue(JSON), supplied checked flag or copied receipt/issuer name |
| Revalidate / actual verifier | Original W/artifacts + target C/A -> fresh qualified use, or explicit refusal/gap retaining historical W. Actual new check invocations have their own origin, never claim a workload rerun |
| Exchange / WP06 | Same C/A/E/G/W/use -> actual required-unit K association and later Session/Q. K is not retroactively appended to issued W; trusted adapter performs exact target binding |

Core Ops needs a retained launch descriptor associated with the exact value used
by execute-script, including post-merge environment and actual routing. Configure
and validate explicit environment-policy at its Types/Config/ProcessScript owner:
qualified inherit is possible only with actual relevant inherited inputs bound;
replace requires actual implementation of replacement, not current override merge.
No Library-side clearing/sampling assertion can claim isolation that Ops lacks.
Sensitive environment material stays owner-controlled; portable diagnostics expose
only the qualified representation needed for verification, not arbitrary secrets.

Bind actual tool binary, interpreter/wrapper/backend/import chain, actual executable
produced by a specific build, relevant system linkage/config/cache, and actual
selected loaded method/observer/issuer. CLI version text, Cargo.lock/offline flags
or recursive source enumeration alone do not close all reads. Metadata-discovered
registry inputs must already be in a qualified captured domain; discovering them
after launch cannot bless the earlier C. Unsupported closure blocks stronger claims.

Methods use owned bytes/qualified immutable inputs, never hash then reopen ambient
paths. Output placement can affect Cargo ancestor configuration, plugin resolution
or cache/backend behavior: bind these before launch under the existing request
and captured domain, or require new C. Generated outputs do not hash themselves
into their own capture. Local before/after checks do not eliminate all exec-file
or change-and-restore races; stronger custody/snapshot claims require an actually
qualified facility, otherwise the claim/use remains bounded or unsupported.

Tool conclusion is interpreted before comparing the independent oracle or desired
control label. Disagreement preserves actual output/mismatch and blocks target
issuance; do not coerce it into the expected pass/fail. A narrower useful result
requires an explicitly declared supported claim, not an invented favorable subset.
The finite model and conditional arithmetic proof do not establish real source
correspondence; SysML cut checks and mapped path checks do not close that gap alone.

| Independent result dimension | Required state distinction |
|------------------------------+----------------------------|
| execution | Not started/refused, completed, tool failure, deadline/idle timeout, cancellation, drift, interrupted/unknown completion with actual cause evidence |

| semantic | Holds, refuted or undetermined at declared scope/strength/premises; qualified holds/refuted alone may become W support/counter |
| control | Expected safe/unsafe behavior met or failed independently of semantic polarity; harness success can yield counter evidence |
| current applicability | Historical original versus fresh eligible use for target C/A; never rewrite original execution or conclusion |

* SPECIFIED Failure retention, limits and interruption
:PROPERTIES:
:CUSTOM_ID: s4a-failure-and-limits
:END:

Retain actual attempt/step/output references as available before presenting success.
A timeout, malformed artifact, incomplete closure, observer mismatch or missing
terminal observation yields diagnostic E/Observation and no qualified target W.
One failed tool step does not erase preceding steps or other independently issued
results. Retry has a new E; a missing Rust facet cannot complete the declared suite.
A narrower partial claim requires a published capability. SI already accepted
under its own complete basis is not erased by a later TM timeout.

Current command timeout 45 is per command. Target execution-policy binds positive
finite per-command and aggregate attempt budgets, remaining time, idle/cancellation
limits and actual enforceable scope. Pure field presence is not enforcement.
Core owns actual mechanisms; Library supplies policy constraints, not another
watchdog. Preserve raw wait-status and observed timeout/cancellation findings:
124/137 alone cannot determine exact cause or every descendant's termination.
Host SIGKILL cannot execute cleanup; missing terminal receipt remains unknown,
not inferred completed from a log/artifact or invented during recovery.

Keep S0/WP00 fixed 2 GiB/180-second acceptance limits. Per-method limits are
validated at their actual supported scope, not automatically equated with the
acceptance watchdog. No budget widening, synthetic progress, swallowed status or
unchanged failed recovery rerun can close a gate. Retained owned evidence need
not imply cross-crash durable attempt storage; durability/recovery guarantees
require the actual existing custody owner to be qualified at that strength.

* SPECIFIED Invalidation and qualified reuse
:PROPERTIES:
:CUSTOM_ID: s4a-invalidation-reuse
:END:

| Actual change / missing basis | Required action and retained distinction |
|-------------------------------+------------------------------------------|
| Project documents/roles/policy change; method basis unchanged | New C/Q/R as affected. Original W can serve only through fresh qualified target use and adequate claim/domain/premises, never a new execution |
| Rust source/compiler/config/runtime/payload/protocol or actual run changes | New affected Rust E/W and dependent SI/TM application/run associations. Unaffected complete abstract QNT/Lean bases need no automatic rerun |
| Mapping/renderer/delta changes | Re-derive/recheck affected SI/TM; retained telemetry may support an actually qualified regeneration path. New derivation/check origin does not rewrite original generated artifacts |
| Method-specific QNT/SysML/Lean tool/checker change | Invalidate actual consumers only after real import/initializer/compiled closure separation. Current monolithic dependencies remain broad |
| Shared Types/descriptor/issuer/observer/Core/load/trust change | Fresh actual association/meaning qualification, potentially new C. Retained artifacts can establish only what the actual new supported verification performs |
| Artifact absent/changed, foreign or unavailable issuer, unqualified origin | No affected current use; retain history/gap. Recovered/downloaded/signed bytes do not reconstruct a private W or an unobserved execution |
| Stronger purpose/claim/domain/coverage request | Re-evaluate target required units/strength and current prerequisites; finite/control evidence cannot be relabeled broader refinement/project evidence |
| Rule/query/history/status change only | WP06+ refresh affected Q/R/current authority. Preserve C/W when captured meaning is unchanged; withdrawal may immediately block use without rerunning unrelated methods |

Qualified use compares complete expected/actual input roles, acquired/derived/artifact
basis, actual producer/observer/source/load association, subject/claim/domain/strength
and target requirements. Equal digests, revision strings or V1 do not suffice.
Original W always retains original C/A/E/G; fresh U targets C/A/K through the actual
adapter. A changed run origin cannot be merged with old facets into one group.
Opposite comparable findings remain available; a new successful attempt does not
erase counter evidence, failure history or independently required repeat coverage.

Local private handles are not portable. Cross-process/host verification uses actual
qualified source/custody/attestation mechanisms at declared trust strength. A
verified foreign assertion yields a new local observation with its actual verifier
origin, not a reconstructed old private W or proof the workload was rerun. Without
that route, retain inspectable artifacts and an unsupported-use gap, or perform
a real new method. A signature authenticates an assertion, not its truth.
