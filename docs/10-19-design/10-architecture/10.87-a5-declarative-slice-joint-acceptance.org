* Scope, three verdicts and execution prohibition
:PROPERTIES:
:CUSTOM_ID: a5-scope-verdicts
:END:

A5 unifies A0--A4 into an acceptance plan for the actual DE-CASE-01 declarative
Project -> admitted Library/Module Scopes -> Profile selection -> Scenario capture C
-> ASCENT accepted consequence view -> SysML candidate/validation -> explicit Project
publication. Org, architecture and decision obligations remain associated with that
chain. This is not the full Aitia authorization/delivery/receiver qualification of
10.74 and does not silently waive those later obligations.

All controls, evidence layouts and future calls below are specified only. No code,
model, package, build, cold start, recovery, capture, inference, validator, acceptance,
publication or automatic orchestration is run or changed here. Org/D2 rendering and
static documentation checks are the only verification performed for this update.
No fixture, report or checklist issues C, build authority, Q, role grants or decisions.

| Verdict | Passing means | What it does not mean |
|---------+---------------+-----------------------|
| Mechanism/control and lane correctness | Each advertised source/compiled/cold/recovery path and positive/negative control exhibits its independently expected behavior with complete termination and evidence | A correct refusal does not establish the positive case or operational readiness |
| Actual DE-CASE-01 positive completion | Every mandatory gate of the preselected case activity closes on compatible real sources, recognized C, accepted view, valid model and explicitly completed publication/product conditions | Test identities, partial captures or design publication do not establish real Aitia review, Library delivery or receiver adoption |
| Research comparison | A predeclared matched study supports, refutes or leaves uncertain a hypothesis about architecture/review quality, reuse, cost or complexity | Comparative advantage cannot compensate for correctness failure; correctness requires no measured advantage |

Current status is planned/unexecuted for this unified acceptance. A0--A4 controls
are target criteria, not historical test counts. Selected partial/gap-bearing variants
can qualify their declared behavior; they cannot be relabelled a complete activity
after failure. Publication may retain assurance gaps only if the actual preselected
policy permits that bounded design activity and all its mandatory publication
conditions are met. It never infers permission from declared_ready or a model file.

Lane identity includes actual source/build/load/observer/configuration/tool conditions,
not just a label. A0 records the currently mixed formation route; it is not already
a pure-source or complete compiled/cold lane. Do not clear user/shared caches to
manufacture a cold test; use owned isolated test roots and explicit prerequisites.

Within one run, report, inference, model and publication share the same original C
and its recognized acquisition. Across processes/lanes, each actual acquisition may
have a different C and private origin. Compare independently specified semantic
meaning and stable model identities while preserving those differences. Never forge
one C across lanes or require process-local issuer state to survive by serialization.
Byte parity is required only for identical admitted model inputs under the selected
method's deterministic contract; differing captured metadata needs declared semantic
comparison rather than edited receipts.

Compiled artifact recovery and capture-origin recovery are different gates. Core's
build recovery does not restore Scenario private acquisition/verification provenance.
If the selected activity requires continuing the same C after process loss, qualify
an actual supported original-origin recovery protocol; otherwise that lane remains
open. A declared fresh acquisition can qualify a separate restart route with new C,
not the unsupported same-C continuation. Root publication crash recovery is a third
independent effect-owner requirement.

:PROPERTIES:
:CUSTOM_ID: a5-recovery-boundaries
:END:

| Intended interruption boundary | Required state/oracle after failure or restart |
|--------------------------------+---------------------------------------------|
| Before acquisition completes / basis admission | Keep attempt and exact missing/unstable inputs; no recognized partial C escapes. A permitted gap-bearing C requires a completed supported variant, not an interrupted draft |
| After Core origin issuance, before final C admission | Preserve issuance/admission failure where retained; claim no rollback of the already-issued receipt. Process loss does not recreate its private association; fresh acquisition has new occurrence |
| ASCENT prospective result / callback / final checkpoint | No new accepted view before final native acceptance; retained native prior result/source remains under its actual rollback contract. External invalidation still blocks old current use |
| After native adoption, before frozen application-view admission | No half-view exposed; record native success plus application failure, not native rollback. New-process continuation must qualify its actual C/result origin, not import a public snapshot as authority |
| During model staging or validation | Retain partial candidate/logs, prior published root unchanged; failed/interrupted validation does not produce accepted validation or publication permission |
| During explicit root replacement / before completion record | Inspect actual permitted target transition under qualified effect ownership; completed versus interrupted/unknown outcome must reflect actual bytes and closure. No unconditional retry/restore that overwrites a newer target |

Interruption tests, when later implemented, must target the owned process and exact
checkpoint, retain intended signal/action versus actual PID/wait status/cause, and
verify state independently. A watchdog exit, signal 9, partial marker or unrelated
process death does not prove the intended injection occurred. Ordinary successful
runs require natural complete exits. Never reinterpret a timeout as a controlled
interruption merely to qualify recovery.

* Separate research comparison
:PROPERTIES:
:CUSTOM_ID: a5-research
:END:

Reuse 10.74's separation of correctness and research. The paper discussed in earlier
chapters is a research object to examine and improve upon, not a requirement source
or authority that proves this design superior. A paper-derived comparator needs a
faithful implemented interpretation and explicit assumptions; no invented weakened
baseline or new claim about the paper is made here.

| Hypothesis / variant comparison | Predeclared experiment and useful observations |
|---------------------------------+----------------------------------------------|
| Declarative composition versus manually maintained structural layout | Same confirmed intent, initial repo/input corpus, independent requirements and perturbations; compare actual supported LLM/manual/template/declarative variants, role/obligation/reference coverage, false claims, unresolved conflicts and reviewer effort |
| ASCENT feedback improves proposals | Compare matched supported proposal workflows with/without explicit consequence feedback; fixed prompts/tool access/model settings/budgets/order where applicable, retained proposal history and independent architecture/content assessment |
| Qualified selective reuse versus full revalidation | Only if actually implemented: same exogenous source/premise/status changes and gold affected scope; compare missed invalidations, false blocking, recheck work, latency/memory and trust/implementation complexity. Conservative full revalidation remains valid |
| Typed catalog/identity/closure reduces model repair | Matched namespace/collision/catalog/dirty-input perturbations and semantic gold; compare wrong-target links, silent merges/dropped duties, failed validation, edit/review time and artifact stability |

Each variant/run has its actual source, acquisition/C, execution and origin; matching
exogenous inputs does not make those C identities equal. Within each run enforce the
same-C lineage. Compare semantic meaning through independent declared mappings and
retain original identities. Variants that intentionally omit mechanisms cannot pass
the full Library's correctness contract; they may still be study baselines with their
limitations explicitly scored, never accepted as production alternatives by speed alone.

Predeclare independent gold/known perturbations, required outcomes, sample/case and
repeat plan, order/randomization, cold/warm and contention conditions, budget accounting
and uncertainty analysis before running. Keep failed/time-limited variants and missing
observations in results. Report actual resource/work/review measurements only, no
fabricated effort scores or speedup from one contaminated run. Do not tune the gold
or remove hard failures after seeing results.

Any claimed better architecture, lower review cost or causal robustness needs that
study; source parity, finite ASCENT consequences, SysML syntax or deterministic bytes
are insufficient. A correct mechanism with no advantage, or a refuted research
hypothesis, is a valid outcome. Faster behavior never excuses false-current use,
lost negatives, forged origin or unjustified publication.
