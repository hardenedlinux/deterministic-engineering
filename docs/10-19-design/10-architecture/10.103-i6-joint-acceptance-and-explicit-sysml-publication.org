* Scope, activity and three independent verdicts
:PROPERTIES:
:CUSTOM_ID: i6-unified-scope
:END:

This unifies 10.95 with 10.97--10.102: joint acceptance of the complete declarative
slice, including its separately requested SysML publication effect and independently
qualified cold/recovery paths. It specifies I6's design and prerequisites; 10.96's
I7 remains the later execution and separate research comparison. No renumbering or
implicit authorization to execute I7 is introduced.

#+begin_example
Declared Project -> actual source/load -> retained Core K1 / SD / S1
 -> actual Library/Module + checked Profile/Scenario -> original acquisition C
 -> actual Program + complete projection -> recognized frozen accepted view
 -> captured candidate/plan/catalog/mapping -> exact candidate O/support
 -> actual independent validation + current-use qualification
 -> separate explicit Project request -> protected expected B -> O
 -> actual poststate/product closure -> mechanism / case / research verdicts
#+end_example

Only source inspection and Org/D2 editing/rendering occur here. No implementation,
package/model change, directory reorganization, build/load/test/acceptance, acquisition,
inference, model materialization/validation, publication, restoration or orchestration
extension is performed. Static document checks do not qualify runtime behavior.
The controls and calls below are proposed, not completed execution receipts.

| Verdict | Required meaning |
|---------+------------------|
| Mechanism/lane correctness | Independently expected positive/negative semantics, real selected source/load identities, exact nonzero inventory and bounded full completion. Correct refusal can pass a refusal control |
| Positive DE-CASE-01 activity completion | Every mandatory selected stage, lane, cross-stage association and product/content duty closes. Candidate-only, correct refusal or a focused probe cannot establish a broader activity |
| Research comparison | Separately predeclared matched protocol supports/refutes/leaves uncertain a hypothesis. Better Agent proposals, causal explanations, reuse or cost are not correctness requirements |

Before execution, select candidate-only, explicitly permitted root-only publication,
or an actually supported broader product activity. These describe scope, not new
purpose/action literals. Default investigation remains candidate production. Profile
choice does not grant publication; real intent/policy/mandate conditions still apply.
Do not narrow an activity after failure to make its report pass, or treat an expected
negative-property control as positive architecture validation.

Library publishes meaning and obligations; Project declares providers and activity;
Profile selects; Scenario captures actual input and owns expected acquisition/current
origin checks; Module owns reasoning/materialization/validation bindings; real tool/
evidence owners issue their outcomes; Project's actual effect owner performs a
separate permitted transition. ASCENT neither writes files nor grants authority.
Org/D2 organize the required products without becoming a version source or issuer.

* Explicit publication request and protected B -> O
:PROPERTIES:
:CUSTOM_ID: i6-unified-publication
:END:

Publication is an explicit Project operation at the existing runner/output boundary
using its actual supported effect owner. If publicly exposed, use existing owner
Types/interface and POO Function/source binding. Current implementation has no
qualified generic model publisher, filesystem CAS or replay/recovery protocol.
Missing capability blocks the corresponding promise; a proposed callback/path is
not an implementation or grant.

| Request/observation field group | Required meaning |
|--------------------------------+------------------|
| Activity/intent/authority | Actual explicit Project/user publication intent, preselected permitted products/policy, responsible role/mandate if required; Profile selection alone is not authorization |
| Original chain | Recognized C/origin/immutable basis, exact actual view/Program/source/selection/candidate/plan/catalog/mapping/generator and required validation/use/checks |
| Exact proposed effect | Owned immutable O/support, actual target worktree/path/object and permitted write set; actual/target meaning and projection limits retained |
| Expected prior state | Captured root B plus relevant directory/support/source state, or genuinely captured qualified absence for supported creation; no force/overwrite default |
| Guarantees/limits | Actual target/support exclusion/check-and-replace owner, stability/time interval, cancellation/process ownership, crash/durability and multi-file promise only where qualified |
| Attempt/outcome | Actual operation/source/request association, guards, observed old/new/support, transition/completion/postchecks and failure/current-use state; report fields are observations, not credentials |

1. Generate and validate exact O outside original captured input I = B + supporting
   basis. Freeze inventory/trace before future receipts; no self-digest or appended
   output/effect inside original C. Keep candidate staging separate from root.
2. Prepare a separate explicit request. Inspection/dry preparation has no effect.
   Binding/content/tool/policy conditions must actually close; structurally_covered,
   declared_ready, finished, FORMATION-OK or exit zero is insufficient.
3. Resolve actual target/worktree/object and expected B/support inside the protected
   domain, including relevant symlink/hardlink/case/parent-directory substitutions.
   Establish actual origin/use/time/policy/mandate/premise checks. An old realpath or
   preceding hash comparison is not a protected target identity.
4. Establish actual qualified exclusion/check-and-replace and immutable staged-byte
   protection. Hash-then-write/rename has a race. An advisory lock covers only the
   cooperating writers it actually excludes; noncooperating writers remain outside
   that claim. Qualify a supported primitive or leave the broader promise blocked.
5. Perform only B -> exact O with required support S stable over the promised
   interval. Atomic root replacement, durability and multi-file consistency are
   separate properties; one cannot imply the others.
6. Observe actual O/target/support and required current-use checks at the actual
   supported cut. Original C keeps B. Postchecks must recognize the permitted output
   transition while continuing to guard unchanged S and original provenance. Neither
   a whole-old-basis comparison that rejects intended O nor a blanket stale-origin
   bypass is correct. If currentness APIs cannot express that separation, keep the
   effect gate open and repair the actual owner; do not add an ad hoc bypass.
7. Record effect occurrence separately from valid completed publication and later
   current reliance. A failed postcheck/log/eligibility observation after replacement
   cannot make a completed write disappear. Retain actual state/unknown outcome;
   do not overwrite concurrent state to repair the report or claim false rollback.

Local filesystem sequencing cannot make remote mandate/revocation/premise checks
atomic with rename. Require actually supported guard/lease/trusted time semantics,
or state a weaker observed interval and leave stronger activity incomplete. Core's
fixed supplied-time verification view is not a moving clock or a remote lease.

A root-only activity does not publish companion/Org/D2 atomically or discharge their
mandatory content obligations. Broader product effects need a real qualified visibility/
transaction protocol. Git commit/push, Aitia review, Library delivery and receiver
adoption remain independent; no purpose/action domain is expanded to grant them.

Core's build handoff data checks do not authenticate an arbitrary input port/packet;
actual expected parent channel or approved source association is separately required.
Managed failed restoration invalidates the receiver; no silent source fallback into a
compiled lane. A no-op/recursive restoration is not positive recovery. Flow product
transport is included only when selected and its migrated fixtures/recipes qualify.

Any durable operation association required for replay/crash promises belongs at the
actual effect owner. The current report writer is not that protocol; no local ledger,
issuer registry or persisted success bit is invented. New attempts preserve earlier
failures and conduct real current checks. Original-C/view recovery, fresh new-C
restart and build recovery cannot repair an unknown publication outcome.
