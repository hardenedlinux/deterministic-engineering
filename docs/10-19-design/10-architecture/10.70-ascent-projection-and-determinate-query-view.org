* SPECIFIED Determinate Q is an exact answer, not universal success
:PROPERTIES:
:CUSTOM_ID: p5-projection-query-view
:STATUS: Source/design and static documentation only; no implementation, ASCENT evaluation, acceptance, review submission or delivery
:END:

P5 consumes the same genuine C and actual A/E/G/W/use/observations to produce an
owned, complete finite query view Q at an exact accepted projection cut. Mandatory
duties and coverage units exist independently of outcomes. A definite Q can retain
missing inputs, unavailable methods, counterevidence, conflict and unestablished
current use; determinacy never means every duty holds or an action is authorized.

The application projection remains modules/resource-evidence. ASCENT owns generic
Program/Session evaluation and accepted source/result mechanics; actual Flow Clue/
history and Library evidence/Host owners retain their own origins and effects.
This design uses existing POO/Core/ASCENT mechanisms, not another fact store,
inference engine, generic invalidation registry or review-policy authority.

This chapter consolidates 10.59 against P0-P4. It retains that chapter's complete
source/derived relation vocabulary and adds no alternate claim schema. Candidate
transaction, Session acceptance, Q publication and fresh external use are distinct
boundaries. Scope/type conformance or a JSON/hash cannot supply private acceptance.

* SPECIFIED Independent required inventory and exact input relations
:PROPERTIES:
:CUSTOM_ID: p5-required-inventory-and-relations
:END:

Retain the full [[file:10.59-ascent-projection-and-query-view.org::#s5-source-relations][10.59 source relation fields]]. C is capture occurrence; D required duty;
K independently required coverage unit; A application; E attempt; G actual group;
W immutable original result; U fresh target use; B exact qualified basis. K exists
before any A/W, and no later target binding mutates W.

| Relation family / required source names | Qualified source and exact join invariant |
|-----------------------------------------+-------------------------------------------|
| capture; required_duty; required_unit; required_role | Actual C/selection/project/revision/scope/purpose and complete Library/project demand. D/K keys include subject/claim/capability/domain/strength/coverage meaning and complete input roles. No observed outcome or available method defines membership |
| application; application_claim; expected_input | Actual prepared A for same C, exact K/subject/claim/B and each expected role binding. No latest application slot or globally keyed usage/role map |
| attempt | Actual C/A/E/G/execution/interpretation/diagnostic; failures remain even without W. Missing A is a missing-application finding, not a fabricated attempt |
| witness; witness_input | Recognized original W/C0/A0/E0/G/subject/claim/B/strength/conclusion/issuer and complete real role footprint. Original basis may differ from target C through qualified reuse |
| qualified_use; use_status; upstream_use | Genuine U plus exact target C/A/K/W/B/verification/status/finding and required upstream W/G/role. Exact check identity prevents an old failed verification from joining a newer U or vice versa |
| comparison_group; control_observation | Trusted comparable proposition/subject/domain/strength/basis group, plus actual independent control expectation/result/finding. Control never rewrites property polarity |
| projection_gap; historical_reference; trace_link | Exact typed target/subject/category/source/origin and required product/model/decision/duty/input/premise/check/impact/evidence trace. Historical assertion is not current W/use |

Derive finite inventory from actual selected definitions/parameters/policy and project
demand before offered outcomes. Unsupported factor or missing duty/required-role
definition is a retained explicit gap where supported, or malformed mandatory catalog
refusal. Never drop the duty and its evidence together. No raw fact input can waive
required content/independence/premise work or select another policy.

Project matching of an already qualified P4 U to K is an actual checked target
association: verify C/A/subject/claim/domain/strength/basis/input-role/coverage
compatibility at the trusted adapter. If original U did not assert K, do not pretend
it did; the projected association includes that real binding/verification lineage.
Do not rewrite U/W or create a qualified-use row from a public checked flag.

All cells are admitted finite enum symbols, bounded exact integers or owned bounded
nonempty reference strings. Complex uncertainty, artifacts and ordered traces use
exact qualified references or declared bounded ordinal rows, not arbitrary host
objects/JSON/functions/floats/NaN. Copy string cells and row/list spines at application
ingress; Session's shallow row copies alone do not own mutable nested data. Enum
roles are fixed; never intern arbitrary witness/premise/record IDs into symbols.

Enforce 10.59 functional keys for C selection; C/D/K definitions; C/A identity and
claim/basis; C/A/E/G; C/A/K/role binding; original W identity/role footprint; complete
U target/verification. Incompatible duplicate keys refuse the candidate transaction.
Exact duplicate set rows may deduplicate, but distinct E/W/U or trace ordinals remain.
Qualified compatibility maps are themselves admitted inputs; hash/equal-name/C0=C
tests alone establish neither reuse nor common execution origin.

* SPECIFIED Derived missing, support, counter, conflict and coverage
:PROPERTIES:
:CUSTOM_ID: p5-derived-meaning-and-coverage
:END:

Retain 10.59's missing_application, missing_expected, missing_input, extra_input,
mismatch, blocked_use, applicable, support, counter, observed, missing_observation,
pending_support, counter_present, conflict, missing_unit, duty_coverage, duty_finding
and explanation_edge relations. The following invariants constrain those actual
rules and output semantics, rather than introduce a second evaluator.

| Derived meaning | Required rule/interpretation boundary |
|-----------------+---------------------------------------|
| Missing application/input/observation | Root in independently present required K/roles even with no A/W. Missing observed support is not false property or an absent requirement |
| applicable/use | Positive conjunction of admitted required inventory/A/claim/U, complete nonvacuous required/expected/actual role bindings, subject/domain/strength/premises/upstream and actual eligible cut. Merely no mismatch row is insufficient |
| support/counter | Applicable holds/refuted W with original E0/W and actual U retained. Counter-only unit is observed but lacks positive support |
| conflict | Both opposed comparable qualified conclusions retained with group/use/origin. Different actual-target, run-local/domain/strength or integrity/adequacy meanings are not blindly contradictory |
| Coverage | Actual all/alternative/correlated/repeat policy, independently defined units/group multiplicities and distinct origins. Correlated RL/SI/TM requires exact original Rust G; repeated rows are not independent repeats |
| Negative-control duty | Policy may require observing/documenting an unsafe alternative or refutation. Fulfilled observation/control duty does not turn its property counter into support or authorize exception |
| Explanation | Finite path to every required unit, missing role, blocking condition, E/W/U/check/premise/impact and product/source/trace association. Counts without required named rows/lineage cannot complete Q |

Use actual ASCENT finite safe stratified rule admission. Pure predicates compare
accepted primitive values only: no IO, clock, network, live guard, supplied callback
or empirical estimator inside Datalog. Actual producer/source/premise/status checks
occur outside evaluation and enter as exact qualified findings at declared cuts.
Unknown/violated/refuted/stale/conflicted findings remain distinct as P1/P4 require.

An intentionally empty material-role demand needs the independently checked
no-demand basis permitted by its actual capability Contract. Missing catalog/role
data must never be interpreted as that exception. Set deduplication applies only
to relations actually admitted with those set semantics; unsupported bag/order
semantics cannot be silently converted to sets by the application codec.

One favorable alternative cannot erase other required independent work, original
counter or unresolved conflict. M06 harness success remains ownership counter; Lean
negation remains counter to the positive bound; mapped unfinished polarity remains
its reachability assertion. Majority green, latest-looking revision and graph
reachability do not adjudicate semantics, empirical causality or project authority.

* SPECIFIED Candidate preparation, serialization and accepted cut
:PROPERTIES:
:CUSTOM_ID: p5-transaction-and-owner
:END:

Use the synchronous Session route behind an actual qualified single-writer project
operation owner. Existing Host serialization must be bound/qualified at that boundary;
if unavailable, do not advertise a concurrent route. Session reentry rejection is
not a multi-writer lock. Do not substitute current actor-session: its pure-positive
Set admission and batch surface do not qualify this stratified-negation/accept-result
program. No new scheduler or private parallel fact database is proposed.

| Stage | Actual input/output and publication boundary |
|-------+----------------------------------------------|
| Open | Actual admitted program/Scope/C/catalog/predicate/provider/codec/load association and supported limits -> private owner/Session. No raw supplied Session accepted as Evidence owner |
| Prepare | Normalize request and real outcomes/uses/findings, independently expand D/K/roles, deep-own primitive facts, check keys/footprint/comparability. Candidate binds exact owner/C/program and actual accepted predecessor association |
| Refresh before commit | Check actual owner/current predecessor/source/use support under declared cuts. Stale concurrently prepared candidate refuses or is genuinely reprepared; no invented public Session CAS/commit-ID API |
| Complete batch | Include every application-controlled dependent source and explicit empty relation: inventory/application/input/attempt/W/use/status/history/gap/control/trace. Full current eligibility replaces prior eligibility; omitting a relation cannot retain withdrawn U accidentally |
| Evaluate | Call existing gerbil-ascent-session-replace-sources! with actual qualified execution-control. Session checks replacement names/types, prepares prospective cut and requires finished result |
| Trusted accept-result | Compare prospective source sets/fields to complete prepared batch; require expected program/output inventories, complete bounded extraction and exact eligibility/finding cut. Return exact #t only on conformance. No Session reentry, external publication, method run or candidate predicate |
| Final Session acceptance | Actual ascent-accept-publication! checkpoint precedes engine/source/result adoption. Only successful return supplies accepted-result/projection association; callback-observed prospective data is not published Q |
| Freeze Q | Bind actual returned finished result and accepted metadata, extract complete required rows/explanations, own and canonicalize under request/limits, then admit/expose returned Q. No lazy live Session getter pretending to be frozen |

The project retains only actual accepted projection/result metadata and immutable
owned view values, not a second mutable source mirror. Historical W/history rows
come from recognized original/accepted owners under their exact scope, not a shadow
union of whatever public old Q happened to contain. Current uses/status are fresh
whole-cut inputs, never unioned historical eligibility.

All controlled source names must be declared and included even when empty. Session
itself preserves unnamed sources; application completeness is not supplied by that
API. Unsupported mutable provider/predicate behavior refuses qualification rather
than being excused by finished=true. Prepared copies and callback output stay private
until actual final acceptance; caller-supplied truthy values/accept callbacks refuse.

Private bounded row copies prepared by accept-result may be retained for freezing
only after associating the actual successful returned result with that very
prospective result. This inspected synchronous Session returns the same result;
another route must qualify its actual return association rather than invent a
commit getter or infer it from matching counts. No callback buffer updates accepted
owner metadata before the final Session acceptance point.

Execution-control must bound the actual evaluation and final acceptance, with finite
row preparation, callback materialization/extraction and canonical export budgets
also qualified. A zero-timeout read of a cached result does not bound earlier work.
Existing 4096 fact labels or engine finished status alone prove neither expanded
cardinality support nor whole-operation completion. Source/use checks define an
observed cut, not atomic global source/role/clock consistency.

* SPECIFIED Rollback, live invalidation and publication failure
:PROPERTIES:
:CUSTOM_ID: p5-rollback-and-live-use
:END:

| Event | Preserved state / required owner behavior |
|-------+-------------------------------------------|
| Malformed field/functional key/mandatory inventory or forged association | Reject candidate before mutation; retain intake diagnostic and prior accepted association. Do not turn a forged W into a genuine negative E/W |
| Validation/provider/predicate/budget/evaluation failure | No partial accepted batch/Q; Session retains prior accepted source/result under its qualified recovery semantics. Retain actual candidate-attempt diagnostic |
| Callback false, non-#t, exception, reentry or final checkpoint refusal | Prospective result not adopted; no leaked candidate Q. Actual negative/failure retained at its owner |
| Old Q after failed candidate | Old Q remains genuine only for its original accepted request/cut. It is not the failed new request's answer; any reuse needs actual current source/use/required-scope checks |
| Known external W/U/source/premise/role/receipt drift | Actual producer/source/Host use guard blocks affected use independently of Session. Rollback cannot reinstate validity; old Q remains immutable history once invalid for current use |
| Clue/history/producer effects precede batch failure | Those original accepted effects remain at real owners. No cross-owner rollback, deletion of counters or fiction that method execution never occurred |
| Session accepted, then Q admission/extraction/export/save fails | Session stays committed. Retain exact accepted return/metadata; freeze the same accepted result if supported or report view publication unavailable. Do not rerun/duplicate commit or claim rollback |
| Host loss/cancelled unknown boundary | Report what actual owner observed; no automatic durable transaction from in-process snapshots. Recovery re-admits actual program/source/producer/use; new evaluation is recorded as new |
| Later changed query input/meaning | New accepted projection and/or Q as actually required; prior Q never edited. Captured meaning change requires P3 new C; unchanged technical basis with later status may keep historical Q/R while fresh use blocks |

The live guard is an actual source/issuer/Host operation and current-use boundary,
not another mutable invalidation table, public current? flag or promise that Session
facts are globally current. It can expose exact qualified status/gaps in a new Q when
accepted, but must not wait for that transaction before blocking known-invalid use.
Pure accept-result does not query external clocks/files; actual Host/source checks
and final execution control retain their distinct qualified cuts and limitations.
After accepted return, any newly observed drift still blocks current Q use. No
stronger check/effect atomicity than the actual effect owner supplies is claimed.

:END:

| ResourceQueryViewContract field group | Required immutable association |
|--------------------------------------+--------------------------------|
| identity/owner/origin | Actual accepted projection/returned result and source-qualified project owner; separate publication occurrence and reproducible logical content reference |

ResourceQueryRequestContract selects only supported operation purposes/filters and
full expected output inventory from the actual Evidence policy. Narrow inspection
is explicitly scoped; it cannot be relabelled full policy-required Aitia input.
All expected relation names and empty sets must be present. A complete Q accounting
for missing content is allowed; incomplete provenance/extraction cannot be filled
with empty arrays to appear complete. Engine finished is necessary, not sufficient.

The actual ResourceEvidence owner creates a private accepted-projection/Q association
from successful Session return and complete normalized view, with no public
freeze/sign-any-rows constructor. POO Q is the owned presentation of that actual
association; Types/hash/owner strings alone do not mint it. Qualify this at the
existing owner using private runtime support/real source and call association, not
a global Q/commit/nonce registry or shadow Session. A qualified normalized presentation
may denote the same original publication; it does not create a new evaluation or
transfer private acceptance to another owner/process.

The applicability field group freezes only its original cut/limits and any actual
prior findings included at formation. Later Q-use observations are separate outputs
bound to that exact Q, not appended fields or an input to their own Q identity.
Recognizing original accepted Q, matching a requested full scope and establishing
current eligibility are three independent checks.

Canonical encoding is pure at the Evidence owner. Preserve scalar type tags,
field boundaries/lengths, declared set semantics and sorted set rows, explicit
named empties and exact-repeat deduplication; distinct E/W/U remain distinct.
Ordered traces retain ordinals/exact artifact refs. Symbol versus string, exact
integer versus textual number, byte/unicode content and original negative/limit
fields cannot collapse through printing/coercion/iteration order. Own public string
cells and collection spines; getters cannot leak mutable Session/result aliases.

Fixed accepted primitive sources/program/request/codec yield the same finite
consequences and logical content reference under qualification. Actual capture,
execution, publication occurrence, clocks or scheduling need not be deterministic.
Do not include newly sampled time in logical identity or erase real occurrence
IDs to force equal content. Codec/normalization change is a real interpretation
input; identical row counts/digests without that basis prove no equivalence.
