* Retired acquisition interface discovered by the consumer
:PROPERTIES:
:CUSTOM_ID: cohort139-acquisition
:END:

Parent retired the Python prepare-native command when native acquisition returned
to Gerbil. Aitia still called that removed command. Changing only dependency
revisions would therefore leave a real API incompatibility before compilation.

Aitia's existing native dependency entry now delegates source-only acquisition
to the SDK's actual pkg-fetch procedure. The pinned v0.19 SDK does not export
that procedure as a public script API; an explicit native SPI binding names the
real SDK owner. It does not reproduce clone, checkout or tag-file implementation.
A missing SDK procedure remains an error, not a fallback implementation.

The same entry accepts a declared repository and exactly one pin from its owning
gerbil.pkg. Source registration may create SDK prefix directories and native tag
metadata. It must not create a package manifest or compiled package products.
Native pkg-build remains the owner of real manifest generation and complete
package compilation. Parent demand compilation remains a separate existing entry.

#+NAME: cohort139-cold-sequence

* Source-grounded Linux executor correction
:PROPERTIES:
:CUSTOM_ID: cohort139-native-executor
:END:

The selected Linux SDK archive contains the deferred compiler implementation:
add-compile-job! constructs a thread for each job and stores it; only
execute-pending-compile-jobs! starts the accumulated threads. The configured
capacity limits running backend work, but it does not overlap that work with
front-end generation. Source inspection confirms that a correct capacity handoff
alone cannot change this scheduling boundary.

POO's own successful build at the same source selected an uncached package and
completed in 247.81 seconds under its 300-second producer limit. Its log contains
503 backend job events including the later benchmark entry. Thus its green
producer run never established the consumer's 180-second limit. The failed Aitia
run used the same Linux release and retained capacity four; the deadline remains
unchanged.

The SDK repository already owns a platform-independent streaming executor patch.
Its release workflow applied it only on Darwin. Existing SDK PR #58 now applies
that same native patch to Linux too, with no consumer scheduler or compatibility
copy. The hunk applies to the real selected 2591dcd release source. This is a
candidate SDK cohort change, not permission to claim compatibility with Aitia.
The new SDK must pass its installed tool-entry and executor checks before any
consumer selects its immutable archive and real SHA-256.

The strengthened executor oracle requires an actual worker message before drain
is requested. Prior capture/drain/error/reopen checks alone could pass under the
old deferred implementation. Existing assertions remain, including raised #f,
nested work, restored submission parameterization and reopening after failure.
Explicit capacities one and three are bounded contract probes; production
capacity remains machine-derived. Local native contract invocations passed for
one, three and default machine capacity. This is a behavioral receipt for the
available Darwin executor, not executed Linux SDK qualification.

The release correction is tracked by
[[https://github.com/tao3k/gerbil-bazel/actions/runs/40940039859][SDK producer run 40940039859]]. It retains a distinct trust boundary: SDK
publication, package cold build, complete Aitia CI and root admission must each
finish successfully. A later or differently configured SDK is never selected
solely because its release date is newer.

Core's source-bound replay check also completed: all-source typechecking and all
11 selected replay/topology cases, including matched faults, passed with the
actual POO source owners. Incremental Core completion took 56.65 seconds after
the failed cold attempt. The subsequent initial Parser build also reached its
180-second limit. Neither incremental Core completion nor partial Parser output
is cold admission or full consumer acceptance.
