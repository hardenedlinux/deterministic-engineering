* Public contract
:PROPERTIES:
:CUSTOM_ID: unified-engineering-config
:OWNER: deterministic-engineering/config.ss
:MERGE_OWNER: :yuanxu/configuration/json::config-defaults
:SCHEMA_OWNER: library/source-contract-profiles/types.ss
:END:

The single downstream interface is
=programs.deterministic-engineering.languages.<language>.{enable,settings}=.
The current executable language keys are =c= and =cpp=. The maintained root
[[file:../../../config.ss][Config]] contains defaults; [[file:../../../examples/programs.ss][the user Example]] contains ordinary
assigned overrides. No separate enabled/disabled Example or user-authored ancestry
is needed. This supersedes the earlier flat method-only Example interface in
[[file:10.148-flat-declarative-library-boundary.org][10.148]]. Low-level method declarations remain reusable Library capabilities.

#+NAME: unified-engineering-config-fields
| Field | Default | Contract |
|-------+---------+----------|
| languages.c.enable | false | Boolean |
| languages.c.settings.profile | capacity-body | Maintained Profile belonging to C |
| languages.c.settings.timeout | 45 | Integer from 1 through 45 seconds |
| languages.cpp.enable | false | Boolean |
| languages.cpp.settings.profile | lifetime-body | Maintained Profile belonging to C++ |
| languages.cpp.settings.timeout | 45 | Integer from 1 through 45 seconds |

Unknown fields, unsupported language keys, wrong structures and invalid budgets
refuse through native sealed Record Types. Profile names resolve against the
existing Profile values. Language projection verifies the selected Profile's
actual language identity; it does not trust a caller-supplied language label.
That semantic check occurs when the projection is demanded, before tool execution.
Mandatory method safety flags cannot be removed through language settings.

* Native composition
:PROPERTIES:
:CUSTOM_ID: unified-config-composition
:END:

Yuanxu =config-defaults= recursively combines object/object fields using native POO
prototype parents. Omitted values inherit defaults. Scalars, lists and explicit
false replace the corresponding value; they are not interpreted as absence.
There is no repository-local recursive merge, option registry or configuration
loader. Native Types admit the final merged value.

#+NAME: unified-merge-gold
| Supplied value | Result |
|----------------+--------|
| Empty object | Both languages remain disabled with their maintained Profiles and 45-second deadlines |
| C enable true and timeout 25 only | C uses timeout 25 and its default capacity-body Profile; C++ remains disabled |
| C enable false over an enabled contribution | False remains false; neither C++ values nor historical evidence are deleted |
| Unknown settings.timout | Refuse rather than silently retaining the default timeout |
| Timeout 0 or 46 | Refuse; no execution budget is widened |
| C selects lifetime-native | Refuse the language/Profile mismatch |

A downstream Module can assign its complete configuration with ordinary native
composition. The following is Module authoring, not extra syntax users must copy
into the Example:

#+BEGIN_SRC scheme :eval never
(import :clan/poo/object
        (only-in :yuanxu/configuration/json config-defaults)
        (prefix-in :deterministic-engineering/config defaults-)
        (prefix-in "project-values.ss" project-))

(.def (Config @ (config-defaults defaults-Config project-Config)))
#+END_SRC

The existing Profile Scope also exports a pure =configure= operation that combines
an override with that Scope's final Config and validates the result. Derived
language projections read the final receiver. They do not freeze a parent's
settings before downstream composition.

* Existing Library responsibilities
| Owner | Responsibility |
|-------+----------------|
| Root config.ss | One maintained programs/languages defaults tree |
| source-contract-profiles Config Type | Sealed configuration structure |
| Existing Profile values | Actual source units, language strategy, harness, obligations and expected property labels |
| Language projection | Select the existing Profile, enforce its language identity and derive the configured method scope |
| source-contracts | Native generic verification plans and protected method policy |
| Development/consuming host | Capture actual sources/tools, execute declared steps, register actual results and query ASCENT |
| External application owner | Authorization and actual application effects |

A downstream maintained POO contribution can extend the existing =profiles=
object and select its new Symbol in language Settings. The projection reads the
final receiver's Profile map; there is no parallel dispatch table. The native
consumer control adds a project-specific capacity Profile and checks that final
selection sees it. Adding a new language still requires a maintained language
contract and actual supported method/subject mapping.

The generic =plan-library= remains a reusable method capability for Library
composition and tests. User-configured use goes through =languages.c= or
=languages.cpp= and its selected Profile/method scope. Disabling that projection
refuses its plan; it is not a global prohibition on every standalone use of the
underlying Library or a grant/revocation of application authority.

Plans contain their effective command timeout. The host executes that declared
value, and the method evidence identity includes the complete plan. A changed
budget cannot silently reuse a result under an identical method fingerprint.
The native process heap/build/test ceilings and all mandatory safety flags remain
unchanged. The low-level method Config also delegates nested default composition
to the same Yuanxu primitive.

* Concrete language engineering
| Language | Actual assets | Selected methods and evidence |
|----------+---------------+-------------------------------|
| C | languages-engineering/c/numeric/bounded-capacity | Capacity arithmetic, parser/pool callers, failure-state framing; CBMC body/enforced-contract/caller checks or native executable |
| C++ | languages-engineering/cpp/memory/resource-lifetime | Unique ownership, transfer/refusal, idempotent cleanup and destructor assertions; CBMC or native executable |

Profiles reuse the maintained source declarations. The interface does not invent
new Rust/Go engines, duplicate Modules or add a platform Runtime. Additional
languages require their maintained Types, Profiles, source mappings and actual
verification evidence before being advertised by the interface.

* Qualification and limits
:PROPERTIES:
:CUSTOM_ID: unified-config-qualification
:STATUS: local-native-qualified-remote-ci-open
:END:

The configuration suite checks the actual Example, inherited sibling defaults,
explicit false, nested override values and unknown-field rejection. The real
native-owner case uses the same Module/Profile/Scenario framework and actual
maintained sources. It runs C and C++, registers their privately issued native
observations in ASCENT, checks support, switches only C off and checks historical
retention plus the still-enabled C++ plan. No fixture result is registered.

Qualification requires natural process exit in addition to case/Module/Harness
markers. The root build and compiled public Config import have separate native
package gates. All command/heap/process fences remain in force.

The native source owner still guards its captured source files. A changed shared
configuration file can make an old owner non-current even if C++ values happen to
be unchanged. Preserving the C++ settings and frozen evidence does not establish
automatic transfer of an old receipt into a new owner or field-level publication
currentness. Likewise, disabled settings do not establish namespace absence,
zero compiler demand, arbitrary helper hot reload or whole-environment attestation.
Cold dependency installation, the candidate upstream cohort and complete remote
CI remain separate unqualified gates until actually verified.

** Source-bound view migration
:PROPERTIES:
:CUSTOM_ID: current-declaration-views
:END:

Views 90.02, 90.132, 90.133 and 90.138 reference the maintained flat Library
Modules. The formation view describes =design-only= declarations and input
requirements; it does not describe the removed capture executor. A Scenario
declares bindings, while the consuming host acquires inputs and executes tools.
The original evidence-loop subjects and feedback associations remain intact.

The existing TypeScript renderer checks maintained source excerpts before
export. Published image receipts bind the D2 declarations, composition sources
and referenced Scheme files. Regeneration updates the images and their source
digests together; stale receipts must fail the example regression. Native
ASCENT evidence and application authorization are not issued by these views.
PNG export uses the existing lossless compression path. The separate raster
comparison checks decoded PNG/WebP pixels against each source image; compressed
output is not substituted beneath an unchanged image digest.

** Native package startup and build-projection acceptance
:PROPERTIES:
:CUSTOM_ID: package-startup-projection
:ENTRY_OWNER: Justfile::test-file
:CONSUMER: t/project-formation-build-test.ss
:END:

The native test entry is =gerbil env gxtest=. Package environment selection must
precede test-tool initialization. With this selected SDK/cohort, plain
=gerbil test= failed while expanding Core's generated POO import, even after a
native Core clean/rebuild. Establishing =GERBIL_PATH= before process startup
removed that import failure; the maintained entry delegates that selection to
Gerbil's =env= command rather than constructing another load path or resolver.
The independent compiled POO consumer also imports successfully. This evidence
does not establish a general POO export defect or a stale-product-only cause.

The real compiled-root consumer checks the maintained formation Profile target,
one canonical =(gxc: "config")= row, identical specification identity on repeated
reads and refusal to change retained roots within one init epoch. Config is
already selected through the Profile dependency graph; it must not also appear
as a duplicate ordinary retained target. The separate native root source build
passes; switching the consumer to its public compiled import does not substitute
for that source build. The removed =profiles/library-formation= path is no longer
an asserted product.

All test markers and error scanning remain mandatory. The 120-second test fence,
180-second build fence, per-process 2 GiB heap and machine-derived compiler
concurrency are unchanged. A zero-exit incremental package build was insufficient
to repair the startup failure and is not treated as consumer acceptance.

A real native Core clean followed by a rebuild exceeded 180 seconds (exit 124).
The subsequent incremental recovery completed and the root source build passed;
neither result converts the failed cold rebuild into a pass. Complete cold
dependency installation remains open. Remote Linux rendering failed during
Chromium system-dependency installation with Ubuntu mirror DNS errors; macOS
passed at 4f43d48. Those infrastructure observations do not qualify Linux tests.
