#+TITLE: Gerbil PR1515: Typed Markup Research and Parser Improvement Checklist
#+LANGUAGE: en
#+STARTUP: overview

* Decision and scope

Reuse Gerbil's Djot/XML/HTML capabilities through their public APIs when they are
actually published by the selected compiler distribution. Investigate transferable
scanner, representation and output techniques inside the existing Parser engine.
Do not build a second markup framework, parser registry, source resolver or test
runner. This document is a research and implementation plan, not implementation
acceptance or permission to replace the current compiler.

The highest-value first slice is: establish the actual stdlib capability, choose
an explicitly semantic Djot adapter, qualify its typed HTML output, then measure
one bounded byte-class scanning improvement against the current scalar path.
A lossless Djot frontend is a separate deliverable with stronger obligations.

* What PR1515 changes

- Typed XML nodes, checked public constructors, a byte-oriented XML scanner and
  byte-buffer emitter; HTML reuses XML element/attribute/text representations.
- A WHATWG-oriented HTML tokenizer/tree builder, fragment context support, static
  atom tables and generated named-character-reference data.
- Djot semantic AST to typed HTML fragment conversion. =djot->sxml= is removed,
  =djot->html-fragment= is introduced, and HTML string output is intended to remain
  byte-identical. =write-djot-html= uses the new HTML writer.
- TAL reader/compiler/runtime and S3 XML consumers move to typed markup APIs;
  old SXML remains under the deprecated =:std/text/markup/sxml= interface.

The diff does not change =djot/{ast,parse,block,inline,attributes}.ss=. Those files
are useful baseline context, but their algorithms are not innovations of this PR.
The PR's Djot speedups primarily concern representation/rendering/output, not a
replacement of its block or inline parsing algorithm and not an LR-table advance.

The author reports median Djot parse+render speedup4.4x and render speedup7.7x,
plus302 byte-identical fixtures,7045 tokenizer cases and1963 tree cases with four
selectedcontent skips. These are upstream claims. Their external conformance
runner and complete comparative benchmark corpus are not contained in this PR.
The reported old-implementation crashes are excluded from speedup samples; our
correctness inventory must retain equivalent failing inputs explicitly.

Upstream's sentinel scans own a buffer ending in NUL; loops distinguish embedded
NUL from EOF by index. Parser's generic byte-span API receives borrowed bounded
ranges. Its input must not be mutated to install a sentinel, nor scanned past
=until=. Unchecked primitives require a verified internal ownership/bounds
invariant; they are not a mechanical replacement for checked vector reads.

* Semantic boundaries that constrain the plan

1. Djot source ranges are zero-based half-open character offsets, with one-based
   line/column; CRLF is one line ending but two characters. Parser artifacts use
   UTF-8 byte coverage. Reuse/extend the existing source-index mapping and test
   multilingual/astral/combining input. Do not relabel character offsets as bytes.
2. A Djot semantic AST, normalized HTML tree, or XML tree is not a lossless CST.
   HTML inserts/repairs nodes; XML defaults discard whitespace/comments; Djot
   source locations are optional. Original input and digests remain authoritative.
3. Reader acceptance is not resumable parsing: XML/HTML input helpers read the
   whole source to EOF into growing storage; =read-djot= also reads/decode-all.
   Chunked Writer output is not streaming parsing or incremental-edit support.
4. HTML recovery does not provide our fail-closed accepted/rejected diagnostics.
   HTML builder parse errors are not reported. Its scope-window512 truncates
   search semantics beyond the window; Djot render depth512 rejects containers.
   These are explicit policies, not exact replacements for general LR searches.
5. Typed structs remain mutable. Upstream writers read untrusted slots and recheck
   after callbacks; constructor validity does not certify later contents. Circular
   lists are not detected, and Writer paths may already have emitted chunks when
   a later error occurs. Direct port paths may instead materialize full output.
6. =write-djot-html= builds the typed HTML tree before starting the Writer, avoiding
   output for a rendering error, but that does not make arbitrary IO failure or
   sink mutation atomic. A future fused renderer must preserve its promised error
   boundary or expose a separately chosen weaker contract.
7. =html-raw= is raw unsanitized markup, and browser-style parsing is not a
   sanitizer. Any document delivery policy must explicitly choose raw markup/URL
   handling. This study does not replace Org as the repository's document source.

* Implementation checklist

Checked boxes below must be supported by a source or execution receipt. Proposed
file locations are responsibilities to implement, not claims of current APIs.

** M0 — Capability and source alignment (first blocker)

Owner: compiler/package maintainers. Inputs: pinned PR, active compiler identity,
stdlib publication and current native package declarations.

- [ ] Identify the normal upstream release/PR chain that publishes the needed
  stdlib modules; record actual source, checkout, compiler, build and load origins.
- [ ] Resolve the observed absent =:std/text/markup/djot= through that publication
  chain. Keep one inherited dependency source; do not vendor the74-file change.
- [ ] Verify =string->djot=, =read-djot=, =djot->html-fragment=, =djot->html= and
  =write-djot-html=, typed XML/HTML APIs, and the removed =djot->sxml= boundary.
- [ ] Qualify native compile, import, cold start and restart with declared two
  build workers,2GiB build/3GiB full-test ceilings and existing test budgets.

Acceptance: real stdlib imports and sample parse/render work from the selected
installed artifacts; missing module, wrong revision, old SXML entry and changed
compiler source are refused or explicitly diagnosed. A compiler language-version
string alone does not close this gate. No Gerbil/SDK modification is made by
this research task.

** M1 — Semantic corpus and baseline (depends M0 for execution)

Owner: language/verification maintainers; =languages/<markup>/fixtures.ss= and
existing =language-test-support=, qualification and ASP benchmark facilities.

- [ ] Pin official Djot fixture source and complete expected outputs; record302
  as an upstream expectation to reconcile, not a hard-coded successful count.
- [ ] Pin html5lib/WPT corpus revisions, retain skips and obtain/audit the missing
  external harness before claiming its7045/1963 results locally.
- [ ] Establish separate parse, typed-node conversion, write, complete
  parse+render, read+parse, artifact publication and edit/reuse measurements.
- [ ] Include source/string/bytes/port/Reader and output/string/bytes/Writer
  variants, malformed input, invalid UTF-8, embedded NUL, deep/wide trees,
  entity-heavy text, large attributes and multi-megabyte source.

Acceptance: immutable corpus hashes, complete positive/negative inventory and
baseline outputs/costs; excluded crashes/skips are visible. Correctness and
performance sample eligibility are reported independently.

** M2 — First std Djot integration slice (depends M0–M1)

Owner: Parser language/API maintainers. Use existing =language-support/entry.ss=,
=src/language/source-descriptor.ss=, =src/compiler/source-language.ss= and Module selection.

- [ ] Inventory existing adapter/result contracts before adding a binding. Expose
  a named semantic Djot capability with actual stdlib method/source bindings.
- [ ] Keep typed Djot/XML/HTML values native; use specific defstruct/Record/POO
  family contracts where the adapter adds domain data, not =ScopeOf Any Any=.
- [ ] Specify original-source retention, byte/character mapping and normalized
  output identity. State result kind before selecting artifact publication.
- [ ] If a lossless Djot pack is required, implement its real lexical/structural
  coverage in the existing compiler IR and use std Djot as a semantic oracle;
  preserve complete byte coverage, trivia, diagnostics and incremental state.

Acceptance: named semantic input/output contract, Unicode range agreement and
byte-identical expected HTML. Missing source locations and a normalized-only AST
cannot satisfy a lossless ParseArtifact obligation. Existing eight packs retain
behavior and actual normalized Contract results are consumed.

** M3 — Boundary and callback ownership (depends M1–M2)

Owner: runtime/adapter maintainers; current =token.ss=, =artifact.ss=,
=source-scanner.ss= and the native markup adapter.

- [ ] Audit validation at publication/use boundaries; keep existing Grammar and
  Function contracts and avoid adding duplicate descriptor/field checks.
- [ ] Separate checked public construction from internal kernels. For external
  mutable nodes, choose snapshots/borrowing rules and defend against callbacks
  invalidating cached fields; do not rely on erased typed-slot checks.
- [ ] Keep request-local render/reference/note/intern state out of public ASTs
  and reusable prepared backends; define cache invalidation by actual inputs.

Acceptance: mutated slots/strings/lists, wrong-family nodes, cross-request state,
re-entrant writers, exceptions and sink failure cannot corrupt retained artifacts;
error category, partial-output policy and cleanup order remain explicit.

** M4 — First algorithm experiment: finite byte-class bulk scanning (depends M1, M3)

Owner: compiler/scanner maintainers; =runtime/byte-spans.ss=,
=runtime/contextual-scanner.ss=, =runtime/scan/regular.ss= and existing lexical IR.

- [ ] Profile predicate calls, checks, UTF-8 work and bytes traversed before
  choosing a kernel. Account for existing first-character indexes.
- [ ] Prepare class tables through existing compiler/POO method selection, once
  per compatible plan; retain scalar fallback for arbitrary/contextual predicates.
- [ ] Prototype bounded four-byte traversal without a sentinel write or access
  past a borrowed span. Keep invalid UTF-8 handling and lexical-mode semantics.
- [ ] Compare complete token/event vectors with the current scalar implementation.

Acceptance: exact scalar agreement for all256 byte values and every short tail,
empty/interior/end spans, NUL, high bytes and malformed sequences; grammar-specific
longest-match/order semantics unchanged. A component-only win is not a parser win.

** M5 — Copy/materialization and typed output (depends M1, M3; optional after M4)

Owner: runtime and document consumers; =source-scanner.ss=, =token.ss=,
=source-index.ss=, =event-program.ss=, =event-reduce.ss=, =artifact.ss=.

- [ ] Measure substring allocation/UTF-8 recounting and repeated materialization;
  distinguish source-backed spans from the public lexeme-bearing token protocol.
- [ ] Reuse existing persistent blocks, indexes and cursors. Compare any private
  transient builder against retained branches/snapshots, never replace them globally.
- [ ] Reuse std typed HTML/XML writers; measure avoiding intermediate SXML and
  repeated string/output conversions before considering producer-consumer fusion.
- [ ] Define validation-before-write versus partial streaming output separately.
  Inventory native artifact publication before selecting staging/atomic publication.

Acceptance: old token APIs/IDs/digests, UTF-8 ranges, roundtrip, failed-branch silence,
old snapshots, inverse edits and publication closures remain correct. A sink error
must not falsely publish a completed artifact. Fusion is rejected if it weakens
these obligations or only shifts work outside the measured interval.

** M6 — Optional vocabulary/index optimization (depends M1, M3 and profiling)

Owner: contextual-IR and language maintainers; =compiler/contextual-scanner-ir.ss=,
=runtime/contextual-scanner.ss= and language-specific declarations.

- [ ] Measure dynamic-name lookup separately from already-interned grammar kinds.
- [ ] Evaluate bounded request-local name indexes or generated tries only for a
  demonstrated vocabulary cost; do not add a global symbol/name cache.
- [ ] If using generated tables, track source hash, generator, options and outputs
  with existing Module/build input declarations. Audit upstream data licensing.

Acceptance: same-name identity, collision/overflow behavior, hostile name sets,
attribute order and longest-prefix matching remain deterministic. Changed source
or generator invalidates reuse. No runtime network access or handwritten entity
registry is introduced.

** M7 — Resource policy and failure semantics (depends M2–M6 as applicable)

Owner: policy/runtime maintainers; reuse current Core/Flow resource/Fixture policy.

- [ ] Select explicit input/tree/depth/output limits for the intended consumer.
  Record upstream whole-input buffering, unchecked circular lists and scope-window
  behavior; do not copy512 or64KiB as universal policy constants.
- [ ] Keep HTML recovery, strict parsing, resource exhaustion and unsupported
  constructs distinct; expose them through existing result/diagnostic mechanisms.
- [ ] Select raw HTML/URL handling explicitly; type validity is not sanitization.

Acceptance: deep trees beyond the chosen limit, cyclic external values, oversized
input/output, invalid namespaces, mutation and failed IO are finite, diagnosed
outcomes. A truncated scope search must not silently certify strict grammar or
language semantics.

** M8 — Mathematical and source correspondence (depends selected M4–M7 experiment)

Owner: formal/verification maintainers; existing =formal/ParserEngine= and LeanPoo.

- [ ] State and prove the selected pure obligation: scalar/bulk scan agreement,
  range preservation, ordered concatenation, capacity bounds or snapshot isolation.
- [ ] Reuse current prepared-method and event-sequence laws; do not duplicate POO
  inheritance/dispatch machinery or derive implementation correctness from typings.
- [ ] Bind source witnesses, full input footprint and native controls to the exact
  implementation. A proof over an abstract kernel does not verify unsafe machine
  reads, callback lifetime, allocations or actual compiler optimization.

Acceptance: native positive/negative and source-correspondence evidence remains
separate from Lean results. Any unclosed correspondence or host premise is listed.

** M9 — Comparative selection and release gate (depends M1 plus chosen changes)

Owner: benchmark/CI maintainers; native CLI/just + existing ASP benchmarks.

- [ ] Register candidate, baseline, actual compiler/options, output semantics,
  corpus/source hashes, worker/memory policy and useful improvement/regression
  criteria before measurements. Keep cold and warm samples distinct.
- [ ] Use repeated matched batches with dispersion/confidence reporting; include
  decode, parse, projection, write, complete path, retained memory, allocations,
  GC and source/edit distributions. Report cost per input/output byte where useful.
- [ ] Retain failures and negative controls. Counterbalance run order; CPU pinning
  is recorded when available, otherwise report uncontrolled host scheduling.
- [ ] Keep native test files declarative; CI/development invokes gerbil test/build.
  Run focused source/compiled tests, native production catalog, full Parser cases,
  restart and Linux/macOS exact-head CI without a new private executor.
- [ ] Select or reject each experiment using the preregistered complete-path and
  resource criteria; component gains and upstream ratios cannot substitute for it.

Acceptance: useful measured improvement with no semantic/control regression;
otherwise retain the simpler current kernel and document the rejected hypothesis.
Only actual implemented/verified capabilities may be published by Library and
selected/captured downstream. Org and D2 describe those results; they are not a
second version source or an implementation acceptance certificate.

* Dependency order and current open decisions

=M0 -> M1 -> M2 -> M3= establishes capability, semantics and ownership.
=M1 + M3 -> M4= is the first general engine optimization experiment.
=M5= may follow in parallel as a separate measured hypothesis; =M6= is conditional.
=M7/M8= apply to each selected candidate; =M9= closes its evidence and adoption.

Open: installed stdlib release/publication alignment; exact std Djot API source;
semantic adapter versus actual lossless frontend requirement; external conformance
runner/corpora; profiling attribution; meaningful gain/regression thresholds;
consumer raw-markup/partial-output/resource policy; source-to-proof correspondence.
No unchecked item is implemented or qualified by this research document.
