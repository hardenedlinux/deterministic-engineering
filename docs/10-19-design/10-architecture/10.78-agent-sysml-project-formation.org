* Proposed main path: conversation to the repository's architecture layout
:PROPERTIES:
:CUSTOM_ID: agent-project-formation
:STATUS: Authored SysML organization and workflow model; static language diagnostics only; orchestrator not implemented
:END:

The entry is a user creating a repo and discussing intent with an LLM. After actual
confirmation of goals/constraints, the LLM generates a candidate architecture. ASCENT
reasons over that proposed structure under selected real Library rules; the resulting
selection/coverage/gaps guide SysML Library selection and project-specific formation.
The repo receives its own SysML architecture/document organization, with linked Org
rationale and D2 views. This connects the LLM to the model lifecycle; it is not merely
a retrospective file inventory or automatic directory rearrangement.

The primary conceptual sequence in the authored model is:

#+begin_example
Repo + conversation -> confirmed intent -> LLM candidate
  -> ASCENT design reasoning -> selected SysML Library definitions
  -> current repo SysML layout -> linked Org products and D2 views
                     ^                         |
                     +-- gaps/conflicts/revision+
#+end_example

The existing DE-CASE-01 inventory is a concrete model instance for this path, not a
claim that an actual LLM/ASCENT/bootstrap workflow has run. The authored action
definition models the successful ordering; rejection/unknown/feedback conditions are
specified below, not silently interpreted as a successful transition. No property
satisfaction, actual implementation, review disposition or delivery is asserted.

* Step inputs, outputs and actual owner boundaries
:PROPERTIES:
:CUSTOM_ID: formation-step-contracts
:END:

| Stage / model subject | Required input -> output artifact | Boundary and feedback |
|-----------------------+----------------------------------+-----------------------|
| Repo + discussion | Actual repo/dirty source occurrence, user goals/non-goals/context -> identified intent draft | LLM asks/records open questions; a generated summary is not evidence of human confirmation |
| Confirm / DE-WF-INTENT | Actual confirmed scope/constraints and remaining unknowns -> confirmed intent basis | Permission is bounded model drafting, not appointment, deployment, delivery or acceptance authority. Changed material goals require reconfirmation |
| Generate / DE-WF-CANDIDATE | Confirmed intent, actual repo observations and supported Library catalog -> candidate architecture: elements/interfaces/data flow, requirements, alternatives, assumptions, proposed roles/products and explicit gaps | LLM may propose several candidates. Every proposed versus source-observed assertion remains labeled; generated code/text/model cannot self-attest truth |
| Reason / DE-WF-REASONING | Candidate facts + actual qualified applicability/requirement/role/closure constraints and independent demand -> finite deterministic selection/coverage/conflict/gap view | ASCENT applies actual rules; it cannot invent network/GC/distributed knowledge or empirical causality. Inconsistent/unsupported inputs return feedback, never a favorable-only view |
| Select / DE-WF-SELECTION | Actual reasoning basis + checked Library/SysML definitions/parameters/constraints -> exact model/Integration/two-policy/definition selection and rationale | Profile selects supported intent; Scenario binds actual project inputs. Required unavailable definition remains an open domain obligation, not an invented Library capability |
| Form / DE-WF-LAYOUT | Selected definitions + actual repo facts/confirmed intent -> repo-specific SysML architecture and document-role layout, source and Org locators | New project occurrence has its own identities/capture. Preserve actual versus target, pending evidence and unresolved real roles. No serialized runtime Scope/private receipt is trusted |
| Views / products D01-D10 | Identified model structure and exact Org rationale/content -> documentation navigation and selected D2 diagrams | Views do not rewrite model relationships or issue evidence. Later code/method/QNT/Lean/content checks consume real project basis through P3-P9, not generated success flags |

Library definitions must be inspectable before reasoning: their supported descriptors,
applicability rules and required duties constrain the candidate. The main sequence's
SysML Library step is actual selection/instantiation after reasoning, not hiding the
rules until then. The return edge carries missing concepts to LLM/user for explanation,
revision or genuine Library authoring; no guessed threshold becomes a trusted rule.

Scheme remains the intended checked POO/Yuanxu runtime entry/orchestration boundary
for prepared candidate values and actual operations. The conversational LLM is the
proposal author outside that trust boundary. This model adds no replacement loader,
reasoner, framework schema or public callback that can approve arbitrary proposals.

* Structural organization and each source of meaning
:PROPERTIES:
:CUSTOM_ID: organization-ownership
:END:

| Owner | What it owns / what other artifacts reference |
|-------+-----------------------------------------------|
| POO/Yuanxu Library declaration | Contract identity, sole contract-version V1, model/policy/parameter/method definitions and actual checked publication. SysML refers to these; it does not mint a second runtime declaration/version |
| SysML Library | Reusable architecture/part/interface/requirement/allocation/view definitions and supported interpretation associated with those declarations. Domain coverage must actually exist; the standard SysML library alone is not network/distributed knowledge |
| Current repo SysML model | Repo-specific identified architecture and organization relationships. This first file explicitly authors dependencies/trace allocations and workflow order, keeping documented baseline and proposed targets separate |
| Org | Authoritative prose requirements, rationale, alternatives, status, reviewer discussions and exact source locators. Prose clauses remain here; a dependency arrow does not replace their meaning |
| D2/SVG | Selected presentation of named model nodes/relationships; updated and inspected together. This first projection is maintained explicitly, not an implemented automatic model-to-D2 service |
| ASCENT | Qualified deterministic consequence/coverage view for actual input facts and rules. Early design-reasoning view is distinct from later evidence-backed Q; mapping into an actual Program/Session remains implementation work |
| Aitia / receiver | Independent content/context/currentness, accepted authority and own receiver/project use. Authored workflow, structural checks or user intent confirmation cannot supply these outcomes |

An assertion has one owner per meaning: relationship structure in SysML, rationale
and prose clause at its Org selector, runtime declaration at Library, observed evidence
at its issuer. Conflicts are retained for resolution, not silently resolved by whichever
file changed last. There is no format that owns all truth and no blanket conversion
of every hyperlink into a required dependency. Exact demand/reference closure still
comes from adopted policies and actual capture.

This refines DE-D02's model/view organization direction without claiming an authorized
replacement decision. Earlier Org/D2 baseline remains historical content; current
structural counterpart and open synchronization limits are declared here. No directory
or earlier signed/hash-bound dossier is changed. Migrating every past table or generating
all views requires a separately qualified adapter; this first model is a bounded start.

* OpenSysML use and actual static diagnostics
:PROPERTIES:
:CUSTOM_ID: model-diagnostics
:END:

OpenSysML supplies SysML v2 language diagnostics/model services; it is not another
LLM. Research checkout .data/OpenSysML remains at
188f222055755fa9deca1c1095e0727ed46f0628. Actual PATH executable used for this model
is /opt/homebrew/bin/sysml, reporting v0.10.1, commit
1c45b6e1749fc8adc9b82d4af22fbe180b56a0e2. These are different source/binary identities;
no claim that this development checkout built the executable is made.

The authored model passed static diagnostics with this actual invocation:

#+begin_example
timeout --signal=TERM --kill-after=5s 30s sysml -no-record-cache -strict -validate \
  docs/10-19-design/10-architecture/10.78-case-organization.sysml
#+end_example

Result: package DECaseOrganization, no errors, exit 0. No object-specific validation,
verification case execution, LLM generation, ASCENT program, property satisfaction,
Aitia review, acceptance or delivery was run. Initial diagnostics rejected an unquoted
reserved name and package paths using dot instead of ::; those authoring errors were
corrected in the final model. This result proves only the supported static diagnostic
scope, not lossless modeling, domain adequacy, actual role authority or automation.
