* SPECIFIED One evidence path, distinct methods and assertions
:PROPERTIES:
:CUSTOM_ID: p4-unified-execution-evidence
:STATUS: Source/design and static documentation only; no implementation, method/observer execution, acceptance or delivery
:END:

P4 consumes the same genuine P3 capture C for Rust, QNT, Lean, SysML and content
operations. Each supported question prepares its own A, retains every actual E and
interpretation Observation, issues original private W only for a qualified holds
or refuted claim, and establishes fresh target use U separately. Tool completion,
schema validation, property conclusion, control success and current applicability
are independent dimensions. No single pass flag represents this chain.

This consolidates 10.57-10.58 against P0-P3's actual owners, full effective fields,
real bindings and origin protocol. It does not create another runner, oracle,
capture, evidence registry or policy engine. Existing POO Types/Functions/Core Ops,
Library private result mechanisms and real observer/issuer owners remain the route.
Same C does not require every method to read every input or share one E. Shared
inputs and actual loaded dependencies remain shared honestly.

P5 still owns independent required units K, accepted Session facts and definite Q;
P6-P8 own review, authority and recipient conditions. P4 observations/receipts cannot
grant those actions. A capture-origin receipt is not W, a process receipt is not
a semantic result, and a W presentation is not portable private issuance.

* SPECIFIED Preparation, derivation and complete actual footprint
:PROPERTIES:
:CUSTOM_ID: p4-footprint-and-derivation
:END:

A binds the complete C occurrence and a precise independently demanded input
contract. Actual consumed footprint can be narrower than C only if complete and
qualified: include semantic inputs, tools/runtime/import/link/cache/config/environment,
reader/runner/parser/observer/oracle/issuer source and actual loaded dependencies,
premise/status domains and actual validation dependencies. Candidate manifests,
CLI versions, lockfiles or recursive source enumeration alone cannot define closure.

| Input/derivation stage | Required binding / refusal |
|------------------------+----------------------------|
| Prepare A | Same recognized C plus supported request/target/destination and qualified upstream W/use; derive roles before results. Reject unsupported subject/mode or independent overriding semantic input |
| Bound original inputs | Owned C bytes/values or genuinely qualified immutable source domain, with exact subject/role and real acquisition support. No hash-then-ambient-reopen or caller true/current callback |
| Planned derivation | A fixes recipe/source/parameters, required typed outputs and step dependencies. It does not pretend future generated bytes/digests already exist |
| Actual derivation E | Real copied/generated theorem/model/package/build inputs with original-to-copy/recipe/tool/source/actual bytes and interpretation limits. Retain actual step outputs; do not append them into C |
| Downstream build/run step | Before launch, bind actual derived input/product/executable and producing step/result. Output role and complete derivation satisfy A's expectation; changed bound semantic recipe/claim requires new A, not an in-place rewrite |
| Transitive/environment discovery | Must resolve within a genuinely captured supported domain before dependent launch. New unbound source/config/dependency requires proper acquisition/new C; discovering it after a run does not retroactively qualify that run |
| Output/destination behavior | Bind paths/base/retention/stream routing and relevant ancestor config/plugin/cache resolution. A destination is not always semantically inert; unqualified changes block use |

Retain logical roles when identical bytes serve Library/reference/project inputs;
deduplicate storage only. Bind actual built binary to the actual build invocation
and actual launched executable, not a previously existing target file. Actual wrapper/
interpreter/backend/tool libraries/FFI and loaded method/observer/issuer matter.
Before/after digests do not prove atomic exec-file custody or exclude all ABA races;
unsupported stronger claims remain bounded/unsupported rather than silently assumed.

No method invents a favorable narrowed claim after failure. A narrower valid result
needs a published supported capability and its own exact application/interpretation.
Missing closure for the requested property remains a diagnostic; not all missing
inputs can be downgraded into an apparently qualified provenance-only property W.

* SPECIFIED Actual launch, attempts and failure retention at Ops
:PROPERTIES:
:CUSTOM_ID: p4-launch-and-attempts
:END:

Core Ops must retain a source-qualified invocation association to the exact final
prepared value used by execute-script, after environment resolution and any real
wrapper preparation. This target belongs in existing Ops Types/ProcessScript/result
and execution path; field spelling/implementation is not a newly available API.
At minimum retain executable/wrapper argv, resolved cwd, effective environment policy/
basis, stream/log routing, total/idle/progress/cancellation settings, actual process/
result association, normalized and raw wait status, elapsed observation and limits.
Do not export sensitive environment values merely to make portable diagnostics.

The target actual-call association is a private invocation/result carrier at the
existing Ops owner, constructed only by its real execution path, not a public
receipt field supplied by callers. It retains the frozen effective launch, actual
call/result or failed/unknown terminal observations, source/owner instance and
limits. The public POO receipt projects that occurrence through an opaque genuine
owner association; its expected projection/recognition operation is source-bound
at Ops. E retains that original association as well as visible diagnostics.
Copying status/argv/log fields cannot create a new invocation; a qualified presentation
of the same original occurrence still denotes that original run, never a rerun.
Implement this in existing Ops fields/private runtime support, with no parallel
global invocation/signature registry or Library-side receipt issuer.

Create/retain the attempt association before the execution boundary and finalize
observed failures on supported unwind paths. A host kill may prevent durable
finalization; retain what actually exists and report unknown completion instead
of synthesizing a terminal receipt. Actual launch association proves what Ops
submitted and observed at its boundary; additional custody/measurement support is
needed to establish atomic executable identity or every hidden OS/runtime read.
No carrier or private-kind tag alone supplies those stronger guarantees.

An explicit qualified inherit policy records actual relevant inherited inputs;
replace requires real replacement behavior. Current run-script merges overrides
into inherited environment, so clearing an outer field or saving preview-script
output cannot establish isolation or what actually ran. Candidate ProcessScript or
an unrelated earlier preview is not trusted execution proof.

| Stage | Required retained attempt evidence |
|-------+------------------------------------|
| Preflight/refusal | Actual A/request/source checks, diagnostics and no invented run. Preparation is not execution |
| Actual external execution | Used launch + actual Core call/result/artifact origins. Tool failure, nonzero exit or check-status exception remain attempts; requested argv alone does not establish the call |
| Actual pure observer | Real source-bound Function call/input/output/parser/closure/context association, limits and diagnostics. E may have no shell commands; do not fabricate a process/command or human reasoning trace |
| Timeout/cancellation/host interruption | Record actual timeout/progress/wait/cleanup observations and known-versus-unknown completion/cause. Retain partial outputs, late outcomes and uncertainty; no assertion that every descendant stopped without actual evidence |
| Retry / recheck | New actual E/call origin. Earlier failed/unknown E remains; a validation-only recheck is not the original workload rerun |
| Issue/export boundary | Genuine W issuance may precede failed presentation save. Retain issuer/attempt/failure; no fabricated Core rollback or silent replacement of original records |

The declared attempt/result interfaces need failure paths before publication;
success-only result arrays/global last-result cannot be authoritative history.
One failed step does not erase unrelated qualified observations. Conversely, a
successful tool probe/build does not qualify the dependent run or complete suite.
Current default method command bound is 45 s; any future selected budgets/heap/
parallel aggregate policy must be explicit under existing owner limits, not widened
to convert failures into acceptance. No execution is performed in this design work.

* SPECIFIED Content observation and finite reference closure
:PROPERTIES:
:CUSTOM_ID: p4-content-and-reference-closure
:END:

Content operations use the same A/E/Observation/private W/use path, refined by
EngineeringProductContract, ContentLocatorContract, ContentReferenceContract,
ContentCriterionContract, ContentFindingContract and ContentReviewFindingContract.
Required products/claims/relations/strength/independence come from actual selected
policy and project demand, not offered files, report counts or document callbacks.

1. Parse C-owned model/Org/decision bytes as inert data with exact parser/recipe/full-
   file/selector/span/source basis. Execute no Babel/eval/shell/export filter or prose
   instruction. Supported authored bindings retain their actual origin; unsupported
   macro/table/selector forms are gaps, not guessed semantic truths.
2. Root finite typed demands at required product/claim/relation roles. Resolve from
   actual artifact/base/subject/revision, not cwd/title/first suffix. Duplicate anchors,
   incompatible authoritative candidates or wrong subject refuse the ambiguous target
   and retain candidates. One section may fulfill several actual roles without copying
   its body into a second authoritative document.
3. Preserve each incoming demand/referring span when targets are shared. Track qualified
   artifact/subject/revision/selector and finite budgets; cross-reference cycles may
   terminate with retained edges, while decision supersession must be acyclic. Context-
   only links do not become required proof, and omitted required links cannot be
   reclassified as optional to complete the closure.
4. Resolve only acquired targets or a genuinely qualified immutable domain inside C.
   New ambient required target -> new acquisition/C or explicit gap. Remote context URL
   is not fetched as evidence; inaccessible mandatory target remains unfulfilled.
5. Historical reports delegate only bounded expected leaf roles for exact schema/subject.
   Use independent required role-to-leaf mapping, exact retained bytes and actual origin.
   Catalog/array/accepted flag cannot define completeness or supply current private W.
6. Interpret supported structural/architecture/decision/trace/premise criteria separately
   from syntax/integrity. Substantive semantic findings bind actual attributed reviewer/
   qualified operation/role/independence/input spans/conclusion/limits. No invented human
   execution, signature-implies-truth or observer-as-review-approval inference.

A complete qualified search can refute an exact locator/unique-selector/completeness
claim. Inaccessible source, timeout or parser failure cannot refute unrelated
architecture truth. Both scoped qualified contrary findings remain; P5 compares
actual subject/proposition/domain/strength/basis before classifying conflict.
Actual-versus-target or integrity-versus-adequacy assertions are not automatically
contradictions. Missing/ambiguous/conflicted/unsupported/stale findings remain exact.

The historical 10.34 catalog and 10.58's coding/historical integration reader scopes
stay intact. Draft dossier input, observed findings, later Q/R and assembled output
are separate stages. An observer result used to discharge current Q enters P5 and
new Q/R as needed; it cannot become its own C/dossier input by recursive hashing.

* SPECIFIED Issuance, result dimensions and fresh target use
:PROPERTIES:
:CUSTOM_ID: p4-issuance-and-results
:END:

| Dimension | Required independent meanings |
|-----------+-------------------------------|
| execution | not-started/refused/completed/tool-failure/timeout/cancelled/drift/interrupted/unknown-completion, with actual cause support |
| validation | accepted/rejected/incomplete for exact artifact/schema/target/input/observer basis |
| semantic | holds/refuted/undetermined for exact claim/polarity/subject/domain/premises/strength |
| control | met/failed/not-applicable with explicit no-control basis; successful negative control can yield refuted property |
| current applicability | eligible/ineligible/unestablished for fresh actual target operation/cut, distinct from original historical W |

Common trusted issuance checks recognized C/A/E, actual implementation/observer/
issuer source and call association, independently required input/artifact closure,
semantic interpretation and actual supported domain. Only qualified holds/refuted
observations issue their precisely scoped original private W. Failed/incomplete/
unsupported observations remain retained findings/E; an honest gap is not silently
converted into property W. Qualified negative W is retained even when another unit
passes or the control expects failure.

Keep issuance at the existing private producer/result owner; actual Core Ops invocation
and P3 origin association are prerequisites, not editable JSON fields. Reuse Core
verification only for its exact trusted-operation assertion where required, with
expected adapter/source/clock bound by actual operation. It neither supplies missing
method execution nor authenticates arbitrary reports. A public verify/issue endpoint
for submitted success records, copied receipt/private flag or caller observer refuses.
No duplicate receipt/nonce/W registry is introduced beside actual owner mechanisms.

W preserves original C0/A0/E0/G/basis/strength/conclusion/artifacts/issuer forever.
Fresh use U compares target C/A and independently required claim/input/domain/premise/
strength conditions, revalidates actual artifacts/issuer/validator/source/status/time
as demanded, and records its new check origin/limits. A later K is a P5 target binding
from actual recognized use, not an addition to original W. A fresh check can establish
continued eligibility without saying that Rust/QNT/Lean/SysML or a reviewer reran.

Do not require every observer to wait for unrelated tool suites: mechanical Org
closure may run independently with its own complete prerequisites. A SysML/TM check
requiring original Rust results must wait for that actual qualified upstream input.
A narrower completed unit may stand under its own supported Contract while the
required whole suite remains pending. No green count fills absent facets or criteria.

| Changed semantic inputs, derivation, mapping/delta, dependency/tool/binary/environment | New affected A/E/observation/W or unsupported gap as required; preserve original. Captured meaning changes require acquisition/new C, not patching C |

| Changed policy/criterion/role/history/status or query meaning | Re-evaluate actual applicability/review/authority and Q/R where demanded; do not rerun unrelated methods simply to refresh explanation, erase denials or revive revoked seals |
| Missing artifact, foreign process, restart or receiver | Qualified local verification yields a new local observation and original-assertion lineage, or an unsupported gap. Do not reconstruct old private W/E/G or inherited authority from serialized handles/signatures |

Evidence strength is P1's scoped multidimensional contract, not a universal rank.
Provenance-only verification supports only that provenance assertion. Property use
requires actual qualified semantic trust/strength/premise mapping and accessible
evidence or new required work. Formal/model traces do not estimate empirical effects;
causal claims need actual supported identification/data/measurement/uncertainty/
transport findings, otherwise remain undetermined. No estimator is implemented here.

Conservative full revalidation is correct when scope/evidence requires it. Minimal
invalidation/cost advantage is a research hypothesis unless an actual selected
qualified capability explicitly promises bounded selective behavior. A broad eager
assembly cannot advertise independent narrow footprints by omitting actual shared
imports/initializers. Use existing pure Core dependency algorithms over qualified
inputs, not a new truth/invalidation registry.
