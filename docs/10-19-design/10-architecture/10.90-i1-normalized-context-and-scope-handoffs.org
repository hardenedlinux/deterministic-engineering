* Scope, prerequisites and verdict
:PROPERTIES:
:CUSTOM_ID: i1-scope
:END:

I1 makes the existing Core admission result authoritative at three call boundaries:
Context K1, consumer dependency Scope SD and final provider Scope S1. This is a
complete target handoff plan, not a new Type system, loader, evidence issuer or
global Scope cache. Native POO validates values; Core admits them in context and
must consume the exact returned candidate.

The inspected code still drops these three candidates. The normalized publication
candidate path already exists and must be preserved. The default Context Contract
is predicate-only and normally preserves identity: its discarded result is an
extensibility/protocol defect, not an observed default nonidentity runtime failure.

I0 has not established an immutable compatible POO/Core/ASCENT/product tuple.
I1 design can be reviewed now; executable qualification must wait for that actual
source/API/bootstrap closure. There is no implementation, build, load, cold start,
recovery, inference, acceptance, publication or orchestration execution in this
update. Only Org/D2 document checks and rendering are performed.

* Exact values, fields and evidence associations
:PROPERTIES:
:CUSTOM_ID: i1-values
:END:

K0/EK/K1, SP/SX/ED/SD and S0/ES/S1 are explanatory symbols only. They do not
introduce public wire records or additional version domains.

| Symbol / actual field | Meaning and retained association |
|------------------------+----------------------------------|
| K0 | Actual source Context supplied to link-module-context; original bootstrap owner/read/currentness association |
| EK | Accepted admit-module-value!(ModuleScopeContextContract,K0,K0) result; retain original candidate/classification/Contract/context evidence unchanged |
| K1 = EK.candidate | Effective Context for all subsequent context reads and admissions; EK.context remains its actual original K0 association |
| SP = base-record.scope | Provider's already admitted final S1 in its generation-local record; shared provider provenance and identity are not consumer policy |
| SX = dependency-scope(owner,alias,provider-id,SP) | Effective alias input after optional actual package realization; may equal SP, or come from the exact matching realized request |
| ED = requirement-evidence | Consumer alias admission under its actual requirement.contract and K1, with candidate SX normalized to SD |
| SD = ED.candidate | Exact view bound to that consumer alias; not a replacement of the provider cache or a globally reusable requirement result |
| S0 = scope-value | Consumer link(bindings) output after opt-in bind-exports; actual subject submitted to final scope-contract |
| ES = scope-evidence | Final accepted evidence for S0 under that publication's actual scope-contract and K1 |
| S1 = ES.candidate = final record.scope | Actual final checked receiver returned through all public Scope resolution paths and used as SP for future edges |

Retention rules:

1. Consume the exact returned object, including wrapped Function fields and normalized
   children. Do not copy raw siblings back over it or substitute an equal-looking
   object. Nonidentity controls compare the actual candidate association as well as
   semantic behavior, including preforced parent caches and inherited fields.
2. One value validation per actual admission boundary. Extracting ED.candidate or
   ES.candidate is not another admission. A new edge, new generation, explicit package
   relink or fresh process has its own real admission and evidence; this is not a
   whole-graph exactly-once guarantee. Fresh currentness checks remain mandatory.
3. Evidence context is factual history. Do not rewrite EK.context to K1, replace
   ED.candidate after issuance, or serialize private authority to fake continuity.
4. Retain existing private lexical/record associations. EK can remain privately
   held by the linker session; no new public credential slot or global registry is
   needed. Existing dependency records already contain provider and requirement-evidence.

* Context K1: bootstrap, closures and package relinking
:PROPERTIES:
:CUSTOM_ID: i1-context
:END:

In source/link.ss, retain EK before generation-value, caches, paired reader guards
and selection-value closures are formed. The original K0 is used for the actual
Context admission bootstrap. All later Context-dependent behavior uses K1.

| Existing read/call | Required target use / provenance guard |
|--------------------+---------------------------------------|
| generation-value, module-ids, selected, denied-modules, optional eligible? and init-source | Read K1; graph demand/eligibility, record generation and source diagnostics describe that same Context. Normalization cannot enlarge source permission on its own |
| check-current!, locate, read-publication, publication-preparation and publication-inputs | Use K1 callbacks/metadata and their actual qualified source association; preserve source/Contract/policy observation and package boundary checks |
| resolve-selection-graph/select-module-graph, publication/eligible, requirement and final admissions | Pass K1 as actual context after bootstrap; keep checked publication SourceRef/owner/currentness and original evidence associations |
| namespace construction, selected-graph, selected-records, dependency-order, .selected-record | Resolve K1 roots/namespace and actual generation consistently; no raw K0 branch left in a later closure |
| selection-value.context, sources-current, package-current, admit-current, prepare-publication | Retain K1 and guards that genuinely describe its source/selection/package closure; do not reconstruct from Profile or Config |
| .with-packages -> link-module-context | Re-enter using the effective Context and actual package result/original Graph association. A new admission retains its own returned Context; preserve real build-graph identity check and guarded package handoff |

The public yuanxu-load-modules directory route also creates reader-ref, original-current?,
read-located/candidate-read and candidate-location guards before link-module-context.
A local K1 rename does not retarget these private native closures. Admission must
preserve their actual owner/generation/selected-source association or reject and
reprepare through that owner. Never infer source authority from copied callback
fields, equal generation text or a generally accepted Context shape.

Caller-supplied object Contexts remain a distinct supported input route. Passing
ModuleScopeContextContract establishes that route's shape/obligations; it does not
turn arbitrary callbacks into native filesystem producer observations. Keep this
trust boundary explicit in fixtures and downstream C provenance.

For the unchanged native paired Context, keep the existing closed-prefix optimization
and lazy reader creation. A normalized wrapper must not inherit the closed-prefix
privilege merely because its fields look equivalent. If actual owner association
supports the ordinary guarded path, use that path; if it does not, refuse/reprepare.
No arbitrary author/MOP callback may run inside a reused pure filesystem window.
Do not broaden observation caches, eager-demand the native reader or probe siblings
to make normalization appear current.

Package relinking currently shares publications/prepared metadata while constructing
a fresh linker cache. The target preserves that distinction. Reuse requires the
retained publication/preparation evidence and source guards to remain compatible
with the newly admitted effective Context and original selected Graph. Otherwise
re-admit/reprepare at the original owner or refuse; never relabel old evidence with
a new Context. Package realization changes dependency Scope bindings, not selected
source publication identities. It does not mutate the old selection's records.

The production default ModuleScopeContextContract remains fixed by its Core owner;
this plan does not expose a runtime Contract-replacement parameter. A nonidentity
Context control needs an owner-scoped expected normalizing value Contract exercising
the same production handoff. The concrete internal fixture arrangement remains to
be designed in the Core test owner; a mocked admit-module-value! return is insufficient.
Do not claim this control passes using only the identity-preserving default.

* Dependency SD and final S1: consumer isolation
:PROPERTIES:
:CUSTOM_ID: i1-scopes
:END:

Use the existing dependency-record representation directly:

| Existing source/link.ss seam | Target retained value and call ordering |
|------------------------------+-----------------------------------------|
| requirements alias loop | Resolve actual provider record; select actual SX through dependency-scope with exact owner/alias/provider-id and realized packages guards |
| record used as provider provenance | Keep current effective provider record behavior: base record if SX=SP, otherwise an alias-local persistent child with scope=SX. Do not mutate the base record, publication or source evidence |
| records[alias].requirement-evidence | Retain ED from admitting SX with requirement.contract and K1; no redundant checked-scope slot is required |
| bindings[alias] | Read records[alias].requirement-evidence.candidate = SD; stop reading records[alias].provider.scope as the authoritative consumer value |
| baseline.link(bindings) then bind-exports | Consumer factory sees SD values. Finish existing opt-in .bind-publication export binding before final admission; S0 includes those actual bound exports |
| scope-admission | Admit S0 under actual baseline.scope-contract and K1, retain ES and S1. Do not bind exports again after normalization or validate S1 again to reconstruct a wrapper |
| final record construction/cache | Keep identity, generation, source, publication, publication-evidence, dependency-records and scope-evidence fields; set scope to S1. current!('scope-linked') still precedes cache insertion |
| resolve / modules resolver / module-view thunk / .selected-record / selected-records | Return or reference that same record.scope S1. module-view must preserve normalized underlying resolution; no parallel raw-Scope fallback |

The actual building/interface.ss module-view returns a facade with identity,
scope=(scope!) and tests. Thus a namespace leaf can be a facade; its scope must be
S1, not the facade itself equal to S1. Preserve lazy test-source behavior. Direct
selected records expose S1 through their scope field. Cached immutable POO slots
are not live filesystem/currentness IO: selected Graph/consumer boundaries must
call their existing admit-current before publication/use; do not claim every
cached field access independently refreshes authority.

A shared provider P can serve A.Left and B.Right with different requirement Contracts.
P's cached SP remains the same provider S1. A receives SDA and B receives SDB from
their own actual ED; even equal Contract names do not authorize sharing ED by name.
Two aliases of one consumer likewise remain distinct edge admissions. An alias-local
realized SX is admitted before reaching its consumer, never replaced by pre-realization
SP simply because the provider was already valid.

Provider final admission and consumer edge admission are different boundaries;
therefore the provider is not rebuilt for each edge, while each actual edge can
normalize/check its own view. Repeated warm resolution of the same admitted record
must not rerun its factory or produce new wrappers through gratuitous revalidation.
It must still execute the required source/Contract/package freshness guard.

Retaining candidates alone does not establish currentness of all normalization
inputs. Audit the actual EK/ED/ES Contract, value-contract, policy and wrapper/source
reads against existing source observation and publication metadata-current guards.
Retain required dependencies at their existing owner and refuse unsupported/open
coverage. A freshness replay must not repeat classification/value normalization
just to rebuild SD/S1. Mutation controls must demonstrate the coverage; the mere
presence of linked-publication-metadata-current is not a proof it covers every
newly normalized field or author callback.

A rejecting edge/factory/final Contract must not insert an accepted consumer record.
Existing resolve catches poison the linker session; do not promise that other
providers remain publicly usable in that same poisoned session. Consumer isolation
means no mutation/leakage of provider or sibling edge values, not bypass of failure
fencing. Compare unaffected behavior in an independently admitted fresh session;
retained diagnostic/historical references are not permission for current use.

* Compilation, loading, cold start and recovery lanes
:PROPERTIES:
:CUSTOM_ID: i1-lanes
:END:

Every advertised lane must demonstrate its own K1/SD/S1 behavior with the selected
actual cohort and independent semantic oracle. Object identities are process-local;
cross-process lanes establish their own admitted receivers/evidence and compare
meaning and source/Contract associations, not pointer equality across processes.

| Complete compiled build | Native selected graph includes supported Core, actual POO/ASCENT and Project roots, macro/runtime phases and selected optional native/product dependencies; exact compiler/tool/flags and source/output association | object/mop-only build or matching wrapper is insufficient; omitted root, stale .ssi/.ssxi where produced, named ~ section, native image or changed compiler source refuses |
| Fresh-process actual loads | Observe actual expander/runtime/native resolutions and current artifact/source admission, then exercise same-process exact candidates through namespace/module-view/dependent consumer paths | Current source filenames or a build receipt do not prove those bytes were loaded; unexpected fallback to old compiled Evidence/Core or source invalidates the claimed lane |
| Cold process and empty-artifact bootstrap | Name whether fresh process only or absent selected artifacts; bootstrap actual prelude before init macros, build selected closure and naturally/intentionally complete process | Hot cached outputs are not absent-artifact qualification; opt-in suite with no actual cases is not a pass; OS cache coldness is not inferred |

| Fresh-process selected restoration | New process acquires current selected graph; explicitly chosen .restore-build establishes receiver-local issuance and all source/tool/artifact guards; rerun relevant normalization controls on actual new selection | No-op/recursive/failed restore must refuse/invalidate, never silently become a compiled pass via source loading. Restored machine code does not restore old EK/ED/ES or C authority |

Core artifacts.ss already distinguishes ordinary source publication from a managed
compiled graph. An unissued ordinary source graph may remain inert; an explicitly
selected recovery that failed is invalidated and must not fall back to source-only
success. Keep these states separate in result reporting.

The exported accept-build-artifact-handoff! checks packet/projection/current
source/artifact associations, but does not by itself authenticate an arbitrary
input port as the supervised parent. The calling owner must establish the actual
parent channel or selected approved-source restoration and its guards. Identical
public packet bytes are not self-authenticating; do not claim that the helper alone
rejects an otherwise matching disk copy. An unapproved packet must be refused at
the owner/entry boundary. This is a call-boundary obligation, not a reason to add
a new credential registry or duplicate the artifact implementation.

Build restoration, original Scenario-C provenance continuation and filesystem SysML
publication recovery are three different gates. I1 qualifies the first only. A fresh
Context/selection receives new process-local admission evidence; old retained report
rows cannot issue it. I3 and the later explicit publication owner must separately
address any promised same-C or effect continuation.
