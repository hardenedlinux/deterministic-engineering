* SPECIFIED Same C and complete Q become a bounded review, not permission
:PROPERTIES:
:CUSTOM_ID: p6-review-adaptation
:STATUS: Design/source and static documentation only; no implementation, acceptance, verification execution, review submission or delivery
:END:

P6 consolidates 10.60 with P0-P5. The thin Scenario adapter consumes the same
recognized capture C and complete privately associated Q. Aitia prepares immutable
review binding R, independently verifies context, product inventory and substantive
criterion assertions, and produces an assessment with explicit gaps, refutations,
conflicts and current-use observations. Neither definite Q, a valid receipt nor an
assessment authorizes approval, exception, distribution, adoption or use.

Library publishes reusable requirements and the two distinct coding/design review
policies. Profile selects checked models, Integration slice and applicable policies.
Scenario binds real project inputs, adoption and roles into C, then forwards actual
Q and products. Aitia owns review semantics and trusted verification; POO/Core owns
local issuance/admission primitives. P7 owns history, decision authorization,
reassessment and withdrawal; P8 owns receiver-local validation and effects. No second
fact engine, project clock authority or receipt registry belongs in Scenario.

The sole Library declaration generation remains V1 at its declaration Contract.
Read that value through the actual checked selection. Namespaces remain stable;
policy semantic revision, document revision, project revision/dirty bytes, dependency
source/load identity and receipt lifetime are separate dimensions.

* SPECIFIED Independent context and content verification
:PROPERTIES:
:CUSTOM_ID: p6-independent-verification
:END:

Context verification checks whether this project occurrence actually adopted the
selected policy for this review stage and whether required roles/mandates and
independence constraints are established. Claimed signatures require real recognized
trust roots and applicable delegation/status checks, not string equality. P7 performs
the distinct action-specific authorization. Unassigned real reviewers remain a gap;
no invented people, grants or organizational adoption fills it.

Inventory verification reacquires actual authorized inert products/unique selectors
and finite reference closure using P4 source-bound observations. Org is parsed without
Babel/eval; architecture elements/interfaces/dependencies/assumptions and DE-D01-D05
records retain actual versus target and historical versus current status. Verify D01-D10
roles against independently required content, not headings, hash equality or count.
A receipt can truthfully establish complete accounting of a missing product. That
receipt cannot establish adequacy of the missing content.

Criterion verification independently checks the asserted interpretation of exact
inputs: DE-R requirement, validation obligation/unit, actual architecture/decision,
method/content observations, strength/domain/polarity and limitations. It may use
qualified evidence without pretending to rerun the method; required re-execution is
an explicit P4 application with new evidence. Independently verifying interpretation
requires a real operation, access and qualified policy route, not copying a Q row or
trusting the producer's pass label. Shared infrastructure is allowed only within
selected independence constraints; different function names, Agents, keys or modules
do not demonstrate independent reasoning or evidence.

Rust execution, QNT model properties, conditional Lean theorems, SysML named checks,
content/provenance and causal assertions keep P1/P4 distinct strengths. M06 control
met can refute ownership. A verified refutation receipt proves that exact refutation
was verified; it never turns into positive criterion support. Inaccessible material,
unknown roles or unavailable method is pending/unsupported, not false architecture.
Comparable opposed claims retain both original bases and conflict; different subjects,
model versus empirical domains or run-local contexts are not automatic contradiction.
No decision, exception or reviewer summary deletes counterevidence or veto.

For demanded causal assertions, retain actual premise/check/impact links, intervention,
comparator/outcome/unit/population/window/estimand, model/measurement/identification,
actual data/operations, uncertainty, contrary evidence and transport limits. No data or
qualified identification route means hypothesis/unsupported, not an estimated zero
effect. Failure to find confounding does not establish identification. A changed causal
assumption may invalidate the substantive assertion without invalidating receipt
provenance: fresh use blocks affected support, P7 handles reassessment/withdrawal,
P8 rechecks receiver applicability. Conservative whole-basis revalidation is sound;
minimal affected-set precision remains a research comparison unless policy requires it.
The paper discussed in 10.60 remains a research object, not a mandated architecture,
authority source or demonstrated project improvement.

* SPECIFIED Receipt lifetime, current use and replay
:PROPERTIES:
:CUSTOM_ID: p6-current-use-and-replay
:END:

Core records private issuance only after exact #t and equal frozen before/after
request snapshots. It checks the supplied [issued-at, expires-at) instant and private
adapter/receipt association. It does not authenticate the supplied clock, operation
competence, all file transitions or semantic truth. A constructible registered adapter
is not the expected trusted verifier merely because it uses the same public identity.

The factored Host owns its actual configured operation, clock domain, positive lease,
source/status readers and issuer/cut association. Reject clock rollback and changed
cuts under qualified guards. Live inputs need real before/after version/generation
checks or explicit non-atomic limits; equal snapshots cannot prove no ABA. Existing
assurance source epochs are an owner-specific precedent, not evidence that arbitrary
project/role sources already have equivalent guards. Known invalidity blocks use even
if the P5 transaction replacing eligibility fails. Engine rollback does not revive a
revoked receipt, role or source association.

Core admission indexes validity at its supplied fixed instant; it is not a moving
clock. Every aggregate use checks the actual required receipt set and fresh external
state through the real Host. Long operations require qualified checkpoints/final check
and bounded effect handoff; two independently fresh receipts do not create a global
atomic transaction over project files, policy adoption and role authority. Preserve
observed cuts and report unknown when required consistency cannot be established.

| Event | Required handling |
|-------+-------------------|
| Same exact assertion/basis/purpose with original receipt, same qualified owner and still-valid interval | Reuse original verification only with fresh live checks and original producer association. Normalized equivalent request values may represent the same assertion; physical request identity alone is not the rule |
| Different R/C/Q/criterion/conclusion/strength/purpose/project revision or action target | Refuse cross-assertion replay. Rebuild the changed basis/request and independently verify; no purpose coercion or copied public receipt fields |
| Expired/future/revoked receipt, mutated adapter/receipt, wrong owner or rollback | Refuse current use, retain original verification and diagnostic/history. Restoring old bytes does not restore revoked private association; fresh independent verification may issue a new receipt |
| Role/credential/mandate/adoption revoked or causal premise no longer applicable | Mark affected use blocked/unknown independently of receipt's intact historical issuance. Preserve scope-specific history; distinguish expired verification from changed project meaning and from authorization withdrawal |
| C-captured meaning changed | P3 new C, then applicable P4/P5/P6 lineage; no retroactive rewriting of C, Q or R |
| New technical/content evidence discharges or contests a Q unit | P4 observation/use -> P5 new Q -> new R. Review cannot append itself as evidence into its own already-frozen Q |
| Unchanged assertion but later source/status observations | New use/assessment or successor R when its bound basis changes; historical receipt remains immutable. No automatic recapture merely to refresh a clock |
| Process/Host loss or foreign serialized receipt/Q | Public JSON, digest, signature or IDs cannot recreate Core private issuance. Preserve portable assertions and trust basis as historical inputs; qualified local verification issues a new local association or reports unavailable |

A signature can provide separately qualified portable provenance; it does not import
original process-private authority. Same valid read verification can be reused where
policy permits; exactly-once submission/disposition and effect replay fences belong
to P7/Runtime, not a new P6 nonce database. Expiry alone is not withdrawal and a fresh
verification alone is not a restored authorization.

* SPECIFIED Partial failure, outputs and implementation dependencies
:PROPERTIES:
:CUSTOM_ID: p6-failure-and-order
:END:

If context seals then inventory/criterion fails or times out, retain that context
receipt, failed attempt and complete pending assessment. Do not report all verified,
erase the seal or invent a cross-operation rollback. If export/save fails after seal,
issuance remains at its owner; recovery must recognize the actual surviving receipt
or report unavailable, never deserialize a replacement private seal. History/Clue
updates and Q commits are distinct owner effects with explicit failure reporting.

The review package is an output envelope: original C/Q/R refs, exact policies/project
source cut and roles/products, required and observed criterion matrix, context and
inventory findings, qualified support/refutation/conflict/pending, requests/receipts/
uses, accessible closure, verifier/independence/trust limits and unresolved authority.
Dossier presentation may be produced only from that package without editing its basis.
This turn specifies it; it produces no verified package or submitted dossier.

|---------------+--------------------------------------------------|
| 1 / P0 owners | Refresh changed dependencies/read origins; fix old imports, actual build/load/recovery and retained Core candidate handoff. Source hashes alone do not close these gates |
| 2 / Library + Aitia Types owners | P1 complete inherited neutral records, twelve purposes once, fixed typed pairs, seven actions and all snapshot/normalization checks. Migrate every old request consumer with explicit unsupported refusal |
| 3 / Library/Core/Profile/Scenario owners | P2 real checked operations and policies, P3 actual same C/project/adoption/role input origins, retained normalized Scope values; no fixture substitution |

| 5 / Aitia verification/Host owners | Factor reusable Host mechanics without duplicating Core issuance or moving assurance graph authority; implement actual independent typed operations/source readers and current-use rules with bounded limits |
| 6 / Scenario/Aitia review owners | Thin prepare/verify/use/assess handoff and output package; retain all partial failures and independent axes; historical fixture remains clearly attributed or is migrated directly, never a compatibility authority fallback |
| 7 / P7-P9 owners | History and action authorization, receiver-local adoption/use, source/compiled/cold/recovery and matched controls under fixed budgets. Research comparison is a separate lane, not a correctness prerequisite |
