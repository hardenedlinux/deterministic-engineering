* Scope, invariant and evidence boundary
:PROPERTIES:
:CUSTOM_ID: i1-retention-scope
:END:

This unifies 10.96 I1, 10.90 and the actual entry/source ownership from 10.97.
POO owns value/Function normalization; Core contextual admission returns evidence
whose candidate is the effective receiver. The linker must consume that returned
receiver at Context, consumer edge and final Scope boundaries. This is direct
repair of existing fields/calls, not a new Type system, compatibility layer,
versioned Namespace, loader or Scope cache.

#+begin_example
K0 -- actual Context admission EK --> K1 = EK.candidate
Provider final SP -- optional exact package realization --> alias input SX
SX -- actual consumer requirement ED under K1 --> SD = ED.candidate
consumer.link(bindings of SD) -> opt-in bound exports -> S0
S0 -- actual final Scope admission ES under K1 --> S1 = ES.candidate
final record.scope = S1 -> namespace facade.scope / selected records / later edges
#+end_example

These symbols explain existing values, not public field names, protocol versions
or portable credentials. Each actual admission has its own expected Contract,
input/context/source association and normalized result. Extracting a candidate is
not a second admission; a new edge/session/process has its own admission. There is
no whole-graph exactly-once claim.

This is Org/D2 design and read-only source inspection. No implementation/model/
package change, build, load, test, cold start, restoration, acquisition, inference,
validation, publication or orchestration expansion is performed. Static document
checks/rendering are the only executed verification. All controls remain proposed.

Retain the actual admission-contract, classification/candidate, responsibility and
context associations. Evidence is factual history: EK.context is not rewritten to
K1, and ED/ES.candidate is never replaced afterward. In-process controls compare
exact expected receiver references as well as independent behavior, not equal-looking
strings/objects. Reports cannot reconstruct these producer associations.

Use existing lexical/record storage: EK stays privately associated with the linker;
dependency-records already carry provider and requirement-evidence; final record
already carries scope-evidence. No public K1/SD/S1 credential slots, redundant checked
Scope field, global registry or cross-consumer admission cache is required.

The public directory loader constructs context/reader-ref/original-current?,
read-located/candidate-read and candidate-location closures before private linking.
Replacing the local context variable alone cannot retarget those already-created
native closures. K1 must preserve their actual owner/generation/selected-source
association or the owner must reprepare/refuse. Same field values, a copied callback
or equal generation text does not authenticate that association.

Keep the native paired reader lazy and its existing closed-prefix/source-window
optimization only where its actual owner supports the unchanged path. A nonidentity
wrapper cannot inherit this privilege merely through POO shape. Use the actual
supported ordinary guarded path when provenance remains adequate, otherwise refuse
or reprepare; no author/normalizer/MOP callback may execute inside a reused pure
filesystem window. Do not eagerly create the reader or demand siblings to make a
test appear current.

Package relink has a new Context admission and fresh linker cache, while some source
publications/preparations and original build Graph remain shared. Their earlier
evidence still belongs to its actual earlier Context. Reuse requires adequate source/
Contract/selection/currentness compatibility with the new effective Context, not a
copied reference or renamed evidence field. If normalization changes the selected
source/permission/Graph meaning, the old original-graph cache cannot be seeded under
new roots. Re-admit/reprepare through the actual source owner or refuse; no fabricated
Graph equivalence or second realization is introduced.

The actual .with-packages call does not forward every original native paired-reader
argument. Do not assume its new linker retains the same fast prefix. Qualify its
actual ordinary source/package guards and retained preparation ownership separately.
Keep effectful package checks at their existing public boundary, outside the pure
source-read cache; package realization changes alias input, not publication identity.

** Nonidentity Context fixture gate

Production ModuleScopeContextContract remains Core-owned and fixed; no public
runtime Contract override or permissive test mode is added. Core's existing
admission-binding controls demonstrate actual nonidentity value admission, but do
not exercise this linker Context handoff through the identity-preserving default.

The required fixture must use a real Core-owned expected normalizing value Contract,
produce an owner-compatible distinct Context receiver through actual admission,
and exercise the same production retention/continuation path. A possible private
factorization may share that path with a statically owner-bound test fixture;
only one linker algorithm is permitted. The concrete test-only binding/access/
compilation arrangement remains to be qualified at Core, not assumed available.
No mocked evidence, public setter, global descriptor mutation or duplicate linker
can close this gate.

Test caller-supplied object Context behavior separately from native paired directory
provenance. A diagnostic marker/nonidentity wrapper with unchanged permission may
exercise retention; it does not prove arbitrary transformed native callbacks safe.
Native paired compatibility/ordinary fallback/refusal and lazy-reader controls must
use actual producer paths. Until both positive behavior and required refusals are
implemented, the advertised K1 qualification remains open.

| Final scope admission and record | S0 -> ES -> S1; keep scope-evidence=ES and scope=S1. Existing final current!('scope-linked') must pass before cache insertion |

An alias-local provider child with scope=SX can retain the base provider's original
scope-evidence for SP. That evidence must not be described as a fresh proof of SX.
Actual package Scope provenance and ED describe this edge; the original provider
record/evidence still describe its own SP. Do not overwrite provider evidence with
consumer ED or treat a shared source/generation as universal Scope validation.

For provider P shared by A.Left and B.Right (or two aliases of A), keep one provider
factory/final admission and independent actual ED/SD per edge. Same Contract name,
alias spelling or equal result does not authorize cross-consumer ED reuse. Each
consumer final admission owns its own ES/S1. Repeated warm reads of that cached
record preserve exact identity and counts without rerunning factories or normalization.
Required currentness checks still execute at actual use/publication boundaries.

Final normalization may wrap Functions/children and rebind derived fields. Keep
those exact semantics, including preforced-parent-cache controls. No copying raw
siblings over S1, rebuilding a raw Scope from Config or repeating .bind-publication
after ES is permitted. If a normalized wrapper loses a required bound-export behavior,
its actual expected Contract/control must refuse; post-admission repair cannot alter
the attested receiver.

Refusing a requirement/factory/final admission inserts no accepted consumer record.
Existing resolve/prepare fences can poison the linker session, while active-cycle
markers unwind through dynamic-wind. Isolation means no provider/sibling value
mutation, not permission to keep using another module through a refused session.
Check unaffected sibling meaning in a separately admitted fresh session; retained
historical references are not current authority. No global rollback promise applies
to external effects performed by unsupported author code.

* Compilation, actual loads, cold start and recovery
:PROPERTIES:
:CUSTOM_ID: i1-retention-lanes
:END:

Every advertised lane needs the independently expected K1/SD/S1 behavior and actual
source/Contract/currentness association. Within one process compare exact actual
candidates; across processes compare independently specified meanings and genuine
new evidence, never pointer equality or serialized EK/ED/ES authority.

| Complete compiled / actual source/build projections | Full selected POO/Core/ASCENT/Project and required product/test roots, macro/runtime phases, compiler/VM/SDK/native image and all produced interfaces/named sections with genuine issuance | Focused object/mop only, equal wrapper with wrong ~0/.ssi/.ssxi, omitted normalizer/test source, stale Context type or hidden source fallback fails |

Cold OS/hardware caches are not inferred |
| Supervised build/use handoff / Core artifacts | Actual parent run-build-artifact-process channel, matching projection/identities/source/libdir and real child receiver admission, then fresh actual Scope retention checks | Foreign entry/channel, stale source/compiler/output or unsupported normalization inputs fails at proper owner; record bytes alone do not authenticate parent provenance |

Managed recovery cannot fall back into a compiled pass through source loading |

accept-build-artifact-handoff! validates actual packet/projection/source/artifact
association but does not itself authenticate an arbitrary input port as a supervised
parent. A byte-identical disk packet can satisfy data comparisons; rejection of an
unapproved route belongs to the actual trusted entry/channel or selected approved
source owner. Do not assert this helper universally rejects a matching copy or add
a parallel credential registry to pretend it does.

Ordinary unissued source publication remains distinct from selected managed recovery.
The former may be inert; a failed managed recovery invalidates the receiver and
cannot downgrade to source-only success. A fresh process rebinds the actual selected
Graph generation only after real source/compiler/output checks. It does not recover
old Context/edge/final evidence objects from a report.

Build restoration, original C/view continuation and SysML publication-state recovery
remain independent gates. I1 qualifies only actual build/use and newly admitted
Scope lineage. No recovered machine code or product store pin grants I3 origin,
I4 accepted-view recognition or I6 publication permission.

10.97's Core TestingScript/Fixture/native harness and selected entry refinements
remain the test execution path. Use exact actual Justfile/fragments/cwd/argv/env/
observer mode and complete nonzero independent case inventory. Common process or
marker/count admission is necessary, not K1/SD/S1 semantics. Preserve 2 GiB and
applicable 120-second focused/180-second complete-build/30-second static-model caps,
actual signal/grace and narrower owner limits. No wider generic default, heap/timeout
increase, hidden child or incomplete log can qualify an advertised lane.
