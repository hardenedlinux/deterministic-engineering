* Scope and acceptance meaning
:PROPERTIES:
:CUSTOM_ID: i4-unified-scope
:END:

This unifies 10.93 with 10.97--10.100: consume the original C, project complete
application facts, execute the actual bound ASCENT Program and supply an immutable,
owner-associated accepted inference view to SysML. Accepted means that this bounded
computation and its application projection passed their actual reception boundary.
It does not mean that a proposed architecture is correct, all obligations are met,
a model is validated, or an effect is authorized. A complete view may contain only
conflicts and gaps and still be an accepted computation.

#+begin_example
I0 real source/load + I1 retained K1/SD/S1 + I2 actual Program + I3 original C
 -> checked reasoning request + independently recognized current findings/use cut
 -> private pure demand expansion / owned rows / source and semantic coverage
 -> actual synchronous Session prospective evaluation
 -> Module's pure accept-result -> native final checkpoint and adoption
 -> actual successful returned result -> frozen normalized accepted view
 -> same C + view + supported candidate/plan/catalog/mapping -> I5
#+end_example

These are target design boundaries, not new implemented APIs. Only source reading
and Org/D2 editing/rendering take place here. No C acquisition, implementation,
Program/tool execution, acceptance/build/load/cold/recovery run, model publication
or orchestration expansion is performed. Earlier runtime receipts remain historical.

ASCENT owns generic rule/schema evaluation, source transactions, execution control
and native result snapshots. Module owns application projection, complete demand,
recognized input/use associations, expected result checks and accepted-view handoff.
Library publishes reusable meaning; Profile selects; Scenario acquires and binds C
and performs its actual current-origin operations. Actual method/finding/use owners
recognize A/E/W/use and checks. Core/POO retain source/Scope and value admission.
No second evaluator, schema DSL, fact mirror, scheduler, global issuer/view registry
or public arbitrary fact-upload endpoint is introduced.

I3 captures the finite supported Program/method/candidate/plan/catalog/mapping domain
before reasoning. I4 cannot fetch a new asset, change predicate/provider/codec meaning,
or append a later witness into C. New captured meaning requires actual new selection/
acquisition/C and binding. Later recognized findings can refer to original C only
within the supported footprint; their original execution basis and target-use basis
remain distinct. Any claimed reuse needs the actual owner's complete applicability
and non-impact justification; matching content is insufficient.

Use I1's actual normalized K1/SD/S1 and I2's final operation references. Different
consumer SD wrappers can be legitimate; join through actual provider/source/publication/
family/semantic binding, not raw equality or equal IDs. Receiver normalization cannot
repair stale lexical captures. Read the sole Library V1 through the actual declaration
owner; do not copy a new version into Program/Profile/view or Namespace. Scenario's
design-reasoning purpose does not enlarge Aitia's request purpose/action domains.

Require every actual controlled source handle once, including empty relations. Any
other fixed source must be explicitly declared, immutable and included in captured
Program meaning; no ambient mutable source escapes coverage. Compare complete source
rows and independent semantic units, input occurrences, expected checks and plan joins,
not just labels/counts. Required duties derive from selected definitions and both
applicable policies, parameters and activity before candidate offers and witnesses.
Missing offers or evidence must not erase requirements. LIB-C02 conflicts and LIB-C03
gaps remain valid consequence-bearing proposals.

The local primitive codec deep-owns strings/containers and maps refs to actual admitted
meanings and opaque operation associations. Reject unknown/foreign refs and unsupported
cells. Preserve symbol/string distinctions, relation-specific ordered/occurrence/set
semantics and duplicate budget charging. A bag cannot be silently deduplicated; a
functional key cannot have incompatible meanings. Canonical output ordering is an
inspection choice, not a new truth or identity rule. The codec is not an issuer registry.
Projection performs no IO, tool execution, evidence issuance, verification or recapture.

The actual full use Contracts from 10.70/10.77 remain authoritative for method,
execution provenance, input footprint, claim polarity, strength, premise/check/impact
and trust. Origin refs are typed acquisition/finding/use associations, not one
interchangeable universal receipt. Unsupported full association refuses trusted
projection; genuine unavailable/negative findings stay explicit. Unknown tags or
unsupported semantic pairs are not interpreted as empty relations.

A use needs an adequate eligible finding for every exact expected check at its
actual owner-selected cut, with no applicable contrary/unestablished finding.
Missing checks block use. An empty expected-check set cannot imply eligibility
unless the actual owner recognizes a supported independent no-demand basis. Never
choose the newest-looking timestamp or use a favorable check from another requirement.
Coverage is verified outside Datalog against genuine C and producer associations;
an LLM-provided coverage=true row or a self-consistent source list cannot certify it.

A proposal saying established can support declared_ready, not qualified_support.
A genuine acquisition proves origin, not the proposition acquired. Harness success,
method tag, exit zero, QNT path or Lean theorem label must retain the actual asserted
claim: M06 expected detection is not positive ownership; a Lean refutation remains
counterevidence; finite QNT exploration is not universal Rust refinement. A genuine
positive and refuting use may coexist; the unit remains conflicted and has no
unqualified successful conclusion. Stale uses remain historical and cannot support
current reliance. No Datalog host guard implements an empirical causal estimator
or silently substitutes for a proof checker.

Closed-world negation applies only to the finite completely accounted domain.
Unknown repo-wide truth is not false. Authentic missing content can be a covered gap;
missing coverage/origin capability cannot become trustworthy merely by emitting a gap.
A preselected design policy may permit structural model work despite explicit method
evidence gaps only when all mandatory model inputs hold. That conditional structural
eligibility is not an I5 execution grant or I6 publication permission. Aitia performs
its own later independent checks; this formation view is not automatically full Q/R.

Preserve the historical eight conflicts/34 gaps/nine nodes/eleven edges and four
LIB-C01 capability gaps as their original structural observations. Compare matching
semantic subsets with an independent oracle; new relations/coverage need not preserve
old total counts. Renaming candidates and adding supported requirements must change
results declaratively, without engine branches on LIB-C01--C03 or Project constants.

The acceptance callback must not perform IO, tool verification, Session reentry,
source mutation, publication or new credential issuance. The application binds it
inside the actual expected operation. Before exposure, require that operation's
actual successful C/Program/batch/result association; an arbitrary rows-of object,
accepted=true, matching hash or internal engine token is insufficient. If the selected
operation interface cannot preserve/recognize that handoff, keep a named blocker;
do not invent a global epoch/view table or duplicate issuer. Direct owner calls and
existing qualified POO/Core associations are the boundaries to qualify.

Freeze complete data from the successful owned result/checked prospective extraction,
not lazy live Session getters. Enforce primitive/deep ownership before reliance because
native row-spine detachment is insufficient for nested mutability. No half-view escapes
if normalization or freezing fails. A successful native adoption followed by a failed
freeze is an application failure after a native commit, not native rollback. A final
external stale finding blocks current use without rewriting the earlier computation.

Fresh Session is the selected synchronous route. A future retained refresh Session
requires separately qualified single-writer ownership and full replacement; native
reentry checks alone do not serialize concurrent users. Do not substitute an Actor/
async route without its own qualification. Whole-operation limits cover preparation,
field predicates, evaluation, callback extraction/freezing and export; a completed
run-timeout call cannot retroactively bound earlier work. Actual source/predicate/
provider purity and stability remain qualification obligations.

* Invalidation, causal changes and recovery
:PROPERTIES:
:CUSTOM_ID: i4-unified-invalidation
:END:

| Event | Required state and response |
|-------+-----------------------------|
| Foreign/malformed C, forged evidence, incomplete mandatory semantic/source coverage | Refuse before native mutation; keep actual attempt diagnostic and prior accepted association; do not fabricate negative evidence from forged input |
| Predicate, budget, evaluation, callback or native final checkpoint failure | No new view; retain prior completed native state under actual Session contract; fresh failed invocation has no accepted view |
| Native adoption succeeds, view freeze/normalization fails | Retain actual commit/application-failure distinction, expose no partial view, no fictional rollback |
| C origin/source/use expires or is revoked during computation | Actual current-use owner blocks affected reliance; keep findings and historical result, no relabeling or rollback of external revocation |
| Captured intent/parameters/parents/policies/Program/plan/catalog/mapping/source meaning changes | New genuine selection/acquisition/C/binding as required; old view remains historical, never resealed as current |
| Same C, new recognized current checks or causal applicability findings | New full controlled cut and new accepted view, including empty sources; never union historical eligible rows, mutate old view or insert findings into C |
| Missing/refuted/unknown premise, changed applicability, incomplete causal impact | Preserve exact use/unit/premise/check/uncertainty; block unsupported reliance; reuse only with genuine complete non-impact/adequacy support, not absence of a dependency edge |
| Later validation/effect or process loss | I5/I6 own independent validation/publication/recovery; build restore and report replay do not recover original C/view recognition or undo external writes |

Origin validity, evidence applicability and hypothesis truth are different dimensions.
A changed causal assumption invalidates the dependent current use through actual
checks/impact; it does not retroactively change the source of the original witness.
A later full view can withdraw support while retaining counterevidence and original
history. Do not choose favorable findings or infer a global minimal impact cone from
incomplete edges. Research hypotheses remain explicitly uncertain until tested.

The accepted view before model validation cannot depend on that future validation
as proof of its own reception. Later validation A/E/W/use retains its execution basis
and may enter a separately recognized later cut, not its earlier immutable view.
New O is not added to original C. New analysis of O needs a new C. Original-C/view
continuation, fresh cold issuance, Core build restoration and effect recovery are
independent capabilities; persisted rows/hashes do not recreate private recognition.
