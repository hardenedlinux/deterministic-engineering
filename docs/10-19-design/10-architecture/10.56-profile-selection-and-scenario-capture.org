* DESIGN Objective and evidence boundary
:PROPERTIES:
:CUSTOM_ID: s3-profile-scenario-capture
:STATUS: Existing-file/field/call design only; no implementation or acceptance execution
:END:

S3 consumes S2's admitted provider graph, binds an independent Profile request
and explicit project request, acquires actual input meaning/bytes through their
owners, and creates one captured occurrence C. Library publishes reusable
meaning; Profile requests choices; Scenario owns their project binding/capture
composition. Core owns source/read/admission provenance. None substitutes for
another, and no new linker, fact store, version service or receipt issuer is added.

This refines 10.44 with the complete S1 role/Contract boundaries and S2's
consumer-local checked Scope handoff. Unique means one authoritative basis per
capture occurrence, not one global capture or one digest per project. All later
methods, observers, projection and review refer to that actual C association.
A descriptive C can retain explicit gaps; each later operation must independently
satisfy its own prerequisites. Capture never implies verified, approved or usable.

The 75 selected implementation/build/runner files still match the S0 baseline
at this inspection. Project HEAD is 8044732d505f84e373119a70f947df00e1767300;
linked dirty Core HEAD remains 52130d2d338b09622a3f55e37987ddc0375b6187.
Those identities do not establish actual loaded closure. BS01-BS09, WP00 and
the restart-two timeout remain open. No capture, acceptance or delivery is run.

* SPECIFIED Profile is a request, not observed state or permission
:PROPERTIES:
:CUSTOM_ID: s3-profile-fields
:END:

| Effective field | Meaning / admission |
|------------------+---------------------|
| identity | Stable reusable Profile name; no generation counter or assertion of observed project identity |
| selection | Supported model-role, published review-policy choice and purpose, plus optional provider/source restrictions. Trusted selector maps these to fixed expected exports/Contracts |
| parameters | One parameter child, admitted using the selected actual role/capability Contract; no duplicate outer capacity/item/worker/scopes fields |
| investigations | Supported method questions, subject roles, modes and bounds. Rust six-case assumptions must hold; arbitrary tool commands/callbacks are not method selection |
| products | Optional requested additions to mandatory architecture/Org/decision/reference products; never subtract independently required products or duties |
| project-constraints | Expected project/subject/revision/mandate restrictions; actual observed values come from explicit qualified project inputs |

LifecycleProfile/resource-64 retains its controlled resource intent; the larger
variant/resource-128 refines the parameter child and related declared workload
intent once. An Integration request selects the published integration entry,
not a locally reconstructed mapping or delta. The default bounded Rust request
is distinct from DE-CASE-01 design review. Changing parameter, model, policy or
required input meaning creates a new binding/C, not an update to retained C.

The contract generation read is checked role Contract -> admitted shared
BackpressureDeclarationContract -> contract-version, authored once in Library
abstract/types.ss as V1. Profile/Scenario/Config/Org/D2 do not store another
version value or parse generation from Namespace or semantic revision. Parent
and policy semantic revisions remain opaque source-authored meaning identities.

* SPECIFIED Checked Scope, parent chain and two policy choices
:PROPERTIES:
:CUSTOM_ID: s3-scope-parent-policy
:END:

S2 must retain publication evidence.candidate, each required-edge
requirement-evidence.candidate, and final scope-evidence.candidate. Scenario's
actual aliases consume the latter checked handoffs, with actual provider/source
and currentness associations retained by Core. Profile does not supply a Scope.

| Role / policy choice | Fixed trusted export and required association |
|-----------------------+----------------------------------------------|
| generic-model | Explicit Generic/backpressure-memory Scope; Generic.entry with its entry-contract, parent=false and applicable generic parameter/method Contracts |
| rust-model | Domain.entry / entry-contract; exact Rust parent is its own checked Parent edge's Generic entry; retain inherited duties and qualified source associations |
| integration | Domain.integration-entry / integration-contract; parent is the returned admitted Rust of this Domain Scope; mapping/delta/case-links stay Library-owned |
| Bounded coding-method review | Domain.review-policy / review-policy-contract; own fixed identity and coding-purpose applicability; no coverage of all design/document/history/delivery duties |
| DE-CASE-01 design review | Domain.design-review-policy / design-review-policy-contract; separate fixed policy identity and source-authored semantic revision; required content/history/authority/delivery meaning retained |
| Explicit no-review request | Allowed only for an operation whose actual trusted project mandate permits it; cannot erase required review or assume unknown adoption means optional review |

Both policies are sibling Library declarations with parent=false, not model
parents or grants. Selection binds the actual adopted policy source/restrictions
when known, and preserves missing/unverified adoption as a gap. WP07/WP08 still
verify context/content/authority. Generic selection cannot use the Rust case
policy just because Domain advertises it. Complete S2 Domain publication requires
both policies and their descriptors; a missing design revision blocks that Scope,
not a silently reduced set of exports.

Scenario's explicit Generic edge can legitimately normalize a different local
view from Rust's Parent edge. Verify their actual shared provider/source/family
and qualified normalization association. Do not patch an admitted Rust parent,
accept equal printed names as lineage, or require global raw eq? between all
views. If coherence cannot be established, refuse the affected binding.

The all-role Scenario still resolves its explicit dependencies before Profile
choice. A Generic request cannot prune an invalid required Domain. An independent
Generic-only route must be explicitly assembled and admitted using the same
operations; no Profile-triggered loader or fallback after failed admission.

* SPECIFIED Binding, acquisition and owner-separated inputs
:PROPERTIES:
:CUSTOM_ID: s3-input-binding-acquisition
:END:

ResourceSelectionContract associates provider origins, selected actual model and
ordered parent chain, expected declaration/role descriptors and revisions, returned
Profile/parameters, selected policy/applicability, independently expected duties/
products, and the explicit project request. This binding is not already C: it
contains expected restrictions and qualified acquisition sources, not invented
observations about a project implementation. Recheck the binding before capture.

| Input role | Actual captured basis / acquisition boundary |
|------------+----------------------------------------------|
| Library | Admitted definitions, parent/policy/Contract meaning, selected mapping/delta, formal assets and relevant method/observer/reader/framework dependencies; actual source/build/load association or explicit unresolved gap |
| Reference workload | Provider-owned six-case crate/lock/source, oracle and declared protocol, if it is the selected subject. Its results never prove an arbitrary service implementation |
| Project implementation | Explicit repo/worktree/subject, revision plus dirty/untracked included bytes, lock/build/model/config dependencies and effective architecture/document/decision inputs |
| Tools and execution configuration | Actual selected tool identity/bytes, environment, Cargo ancestor/CARGO_HOME config and relevant dependencies through qualified acquisition owners; a path or version string alone is insufficient |
| Products and references | Required product identities, concrete chapter/element locators and captured bytes/reference closure, with current candidate, historical reference, missing or ambiguous status |
| Governance and prior history | Actual project mandate, policy adoption, role/authorization/prior review/recipient-purpose sources with qualified origin/trust limits, or explicit discovery gaps |

A supplied file list does not define completeness: expected demand derives from
selected duties/capabilities/policies and trusted project requirements first.
Trusted acquisition sources satisfy that demand with actual qualified reads and
owned values/bytes or explicit gaps. No caller-supplied current! callback, shell
command or alleged reader label authenticates acquisition. Existing Core/host
source/read capabilities must be qualified at their actual owner; S3 adds no
public hash-to-capture signing service or new provenance registry.

Library root and project root are distinct logical roles even for this self-case.
The same physical bytes may satisfy both, with content deduplicated but role/
subject/dependency associations preserved. The actual network-service repo is
bound separately from the reference crate. A six-case method refuses an unsupported
implementation protocol rather than relabel its reference output as service proof.

Acquisition can inspect actual inputs using bounded supported readers; it cannot
execute verification/build methods to manufacture capture evidence. Qualified
read domains/owned immutable values bound what was observed. Capture is not an
atomic whole-filesystem transaction. An input changing during acquisition must
be refused/reacquired under supported guarantees or retained as an explicit gap;
no coherent ready basis may be asserted from mixed unstable observations.

* SPECIFIED Unique C, normalization and operation lifetimes
:PROPERTIES:
:CUSTOM_ID: s3-c-fields-and-lifetimes
:END:

| C field group | Required retained association / exclusion |
|---------------+------------------------------------------|
| Occurrence identity and input-basis | Actual Scenario-owned capture occurrence plus canonical owned input meaning/bytes; digest is an integrity index, never private issuance or authority |
| selection | Returned checked Profile/parameters, selected model/ordered parents, expected Contracts, family read and actual policy definition/purpose/adoption constraints; own effective meaning rather than mutable pointers alone |
| project and subjects | Actual project/revision/dirty basis and logical implementation/reference subject identities, related to the explicit request and actual source origins |
| provider-inputs / project-inputs / tool-inputs | Complete required owned footprints, actual source/acquisition/read/load associations and their limitations; no ambient reopen after a hash check |
| requirements and products | Independent required-unit inventory, requested additions, precise architecture/Org/decision/ref targets, candidate/historical/missing distinctions; absence never deletes a required unit |
| mandate / prior references | Captured governance/history/recipient-purpose inputs and origin qualification, including missing or unverified appointments/adoption/history |
| acquisition / gaps / use-constraints | Actual bounded observation associations, unresolved/unavailable/conflicting inputs, supported domains and per-operation prerequisites; no universal ready/approved Boolean |

Scenario builds C only after normalizing request/parameter/project/binding inputs,
then admits the complete C and retains that returned candidate. Normalization
must preserve/re-establish actual producer/input association at the owner boundary;
a wrapper or copied receiver is not recognized solely because it has equal fields.
Unsupported loss of origin/coherence refuses. Tests must use nonidentity returns,
not identity-only validators that hide discarded-value defects.

Consumers recognize C through the actual trusted producer/input association and
qualified current use, not public snapshot, identity, matching hash, eq? to a raw
leaf, alleged private flag or caller-provided guard. The actual association must
be established and qualified during implementation using existing owner mechanics;
current resource-native-context snapshot recomputation does not already provide it.
Malformed/forged binding or C refuses. An honest capture with absent reviewer or
model input may preserve a typed gap: operations requiring it are blocked, while
unrelated qualified analysis remains possible under its own Contract.

Later Rust/QNT/Lean/SysML and content operations consume owned C inputs or qualified
immutable source domains. They must not check a digest and then reopen mutable
ambient paths. An unbound transitive dependency discovered later stops affected
use and requires new binding/C unless already within a qualified captured domain.
Output destinations/configurations affecting execution are bound by the operation
request and selected method's input contract before launch, never silently
appended to C. WP04 supplies actual A/E/W/use issuance and selective reuse.

A/E/W/use, generated QNT/SysML products, query Q, request R, receipts and decisions
are later outputs associated with C, not self-hashed inputs of that same C. A
later capture may legitimately include prior outputs as explicitly historical
inputs. Two equal-byte capture occurrences remain distinct; reuse requires the
qualified full dependency/use relation, never digest equality alone. A later
revocation/current authority event can block use without rewriting retained C;
a changed query meaning requires new Q/R, not a forged update to old findings.

* SPECIFIED Logical calls and direct migration
:PROPERTIES:
:CUSTOM_ID: s3-call-order-migration
:END:

These are target operation boundaries, not claims that new APIs exist today.

| Order / owner | Input -> retained output / failure boundary |
|---------------+--------------------------------------------|
| 1 Core + interface | Explicit providers -> checked aliases/final Scenario Scope and actual evidence/source/currentness. Failed required edge exposes no successful partial Scenario Scope |
| 2 Scenario bind | Scope-bound operations + Profile + explicit project request -> returned checked ResourceSelectionContract value. Fixed selector and expected role/parameter/policy/capability checks precede acquisition |
| 3 Qualified input owners | Selection + actual ResourceProjectInputsContract inputs -> independently demanded owned footprints and typed gaps. No verification-method launch or unrestricted ambient dependency discovery |
| 4 Scenario capture | Rechecked selection + qualified acquisition -> admitted ResourceCapturedUseContract C with actual producer/input association; no separately authoritative Rust Context or gateway snapshot |
| 5 Operation adapter | Actual C + supported operation request -> checked prerequisites/prepared request. No separate root/Profile/tool/policy arguments reconstructing a competing basis |
| 6 WP04/WP05/WP06 | Same C -> actual A/E/W/use -> deterministic Q retaining required units and gaps. Scenario does not mutate Evidence session sources or manufacture Q from supplied successful results |
| 7 WP07/WP08/WP09 | Same C/Q plus actual purpose/policy/project/role/history/current authority -> R and later review/decisions/delivery, each checked at its owner; selection is no grant |

The public operation names retain 10.44's split: bind(Profile, project-request)
returns selection; capture(selection, project-inputs) returns C; current!(C,
use-purpose) returns a purpose-bounded assessment or refusal without recapture.
observe/method(C, application-request, destination) is the later method surface;
open-evidence(C, qualified-results/uses) opens the inference association, including
an empty initial evidence set; prepare-review(C, exact-Q/uses, additional-inputs)
prepares R. Replace existing open-review with open-evidence for inference rather
than treating session creation as Aitia review. Future operation Function Types
in Scenario types.ss specify these complete inputs/results and normalized returns;
expose each surface only when its actual stage implementation is present.

Scenario Config's default-profile field, if supplied, is admitted as the same
ResourceSelectionProfileContract request used by bind; caller-explicit selection
and the documented default resolution produce exactly one effective request.
Unknown Config keys, competing effective requests or ambient project/tool defaults
refuse. Config has no capture identity, policy-adoption or generation field.

Required input normalization precedes all contextual checks; returned function
wrappers are the actual exported/invoked operations. A final Scope normalizer
must preserve operation/provider coherence, not leave closures over an unrelated
raw graph. No supported call accepts both C and independently overriding semantic
inputs. Existing direct flat capture/open-review/native-context and driver paths
migrate together; retained fixture helpers remain explicitly bounded test inputs,
not production fallbacks. Shared operations import Types/algorithms only, avoiding
Scenario Module/Config/init import cycles and a duplicate gateway capture manager.

* SPECIFIED Dependency order, exit criteria and open gates
:PROPERTIES:
:CUSTOM_ID: s3-order-and-open-gates
:END:

1. S1 supplies complete Library/Scenario-effective field Types, both policy
   declarations and purpose/applicability boundaries; S2 supplies actual checked
   object/parent/Scope/function returns. Qualify nonidentity returns at the Core
   owner before relying on them in Scenario. No repeated consumer check workaround.
2. Migrate outer Profiles/parameter children, Scenario closed Config, explicit
   dependencies, fixed selection and contextual Contracts together. Admit only
   supported model/policy/parameter/capability combinations and preserve required
   inventories independently of candidate inputs.
3. Qualify actual source/read/acquisition/producer association at its real owner,
   separate Library/project/reference/tool/governance roles and close owned C.
   Migrate existing Context/currentness and gateway/driver callers directly;
   expose only implemented coherent operations, with explicit acquisition gaps.
4. S3 exits only with actual positive/negative CX observations, normalized return
   retention, no competing flat-input route and full actual source/build/load
   identity at the claimed verification cut. Document lint is not this exit.
5. S4a and S4b then use the same C for method and content operations independently
   under their own prerequisites; S5+ consume the same associations for Q/R and
   authority/delivery. No inferred completion of these downstream stages.

S3 allocates DE-R01/R03/R04/R06 and DE-T03/T04/T05 through the existing 10.44
inventory/subject/product bindings. These are obligations to verify, not DE-O
findings. Missing design-policy semantic revision, loaded dependency closure,
qualified acquisition guarantees/origin recognition, project adoption/appointments,
content/history/recipient inputs and actual negative-control receipts remain open
until supplied and checked at their actual owner. No new Org counter resolves them.

S0's q34 artifacts do not establish current default build/load parity. WP00
source/compiled/cold/recovery qualification remains required; keep 2 GiB/180-second
limits and historical restart-two failure. Do not rerun the unchanged failed route
or widen the budget to claim S3 qualification. The original 10.34 dossier catalog
and historical receipt identities remain unchanged; current document/view changes
require a future fresh capture rather than rewriting that historical evidence.

Only Org and paired D2/SVG change here. No implementation, directory migration,
build, acceptance run, method/content/model/ASCENT/Aitia execution, signing,
review submission, authorization, adoption or actual delivery occurs.
