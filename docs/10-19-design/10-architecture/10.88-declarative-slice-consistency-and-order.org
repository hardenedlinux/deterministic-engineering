* Verdict and audit boundary
:PROPERTIES:
:CUSTOM_ID: coherence-verdict
:END:

10.82--10.87 describe a coherent target direction, but neither current code nor the
joint acceptance is closed. The audit finds missing cross-boundary commitments:
Scope must precede capture; declaration-to-implementation binding must not introduce
a dependency cycle; the accepted inference view needs an actual producer association;
and publication needs an expected state transition rather than an unchanged-input
check on its own output. These commitments below qualify the earlier target plans.
They do not rewrite historical receipts or imply implemented mechanisms.

This is a read-only source audit and documentation update. No implementation/model
change, package operation, build, inference, validator, acceptance run, review,
publication, delivery or orchestration expansion is performed. Org/D2 syntax, links,
exports and diagram rendering are document checks only. Correctness criteria and
research hypotheses remain separate. None of the proposed control IDs is a receipt.

The intended chain is:

#+begin_example
Project declared providers -> Core K1 / dependency SD / final S1
 -> checked Library + Engine Scopes -> checked Profile + consumed Scenario Config
 -> genuine project-input acquisition -> one immutable original capture C
 -> complete C-bound projection + actual Program -> accepted frozen inference view
 -> selected candidate / plan / catalog / mapping -> exact validated model bundle
 -> separately requested, guarded Project publication -> observed publication outcome
#+end_example

C links to the already admitted Scopes. It is not an argument to their prior
admission and cannot repair a raw Scope or unqualified loaded implementation.
Likewise, an inference view or published root is a result associated with C, never
an input inserted into the original C after the fact.

** Publication as an expected transition
:PROPERTIES:
:CUSTOM_ID: coherence-transition
:END:

1. Capture retains the prior root B as actual observed input, with companion/catalog,
   program/method, policies and selected source basis. Stage candidate bytes O outside
   the input/write set; validate those exact owned bytes and complete closure.
2. A separate request binds C, the actual accepted view, candidate/plan, O, validation
   and exact target. Before replacement, recheck genuine origin/current eligibility,
   live causal assumptions as required, expected root B and all supporting inputs.
3. The Project effect owner must establish actual exclusion/check-and-replace for
   the target and required stable support. A check followed by an unguarded write
   is not atomic; a hash alone is not exclusion. Unsupported cross-process or
   cross-file exclusion is an explicit blocker for the corresponding activity.
4. The allowed observed transition is exactly B -> O at the permitted root. Postchecks
   verify O and unchanged required support plus current eligibility over the defined
   effect interval. The old root's changed bytes are recorded as the intended effect,
   not reclassified as a fresh input or exempted along with unrelated changes.
5. C remains historical with B. The publication outcome references C and B -> O;
   any subsequent analysis of O acquires a new C. If a live premise/policy/support
   changes during the effect, record invalid/unknown completion and actual state;
   never infer rollback or valid current use from successful file replacement alone.

This refines A4/A5's freshness wording without introducing a publisher framework.
The exact supported filesystem/exclusion primitive and its crash/interval semantics
must be selected and qualified before this gate can close. A root-only gate cannot
advertise an atomic root/Org/D2/catalog update.

Correctness requires complete lineage, exact normalized-value retention, independent
coverage, preserved counterevidence, valid current use, real tool/load associations,
explicit effect authority and truthful failure/recovery states. It does not require
the research approach to outperform a baseline.

Research hypotheses include whether LLM proposals with ASCENT feedback improve
architecture completeness, whether captured applicability improves safe reuse, and
whether SysML/Org traceability lowers review effort. Use A5's matched exogenous case
corpus, actual separately acquired inputs/C per variant, independent gold standard,
equal budgets and retained failures/uncertainty. Causal-assumption invalidation is a
correctness obligation when a selected policy requires it; better causal explanations
or reduced rework are empirical hypotheses. No proposed benefit from the research
paper or this architecture is admitted as established evidence.

The resulting design closure is conditional and reviewable: ownership and handoffs
are assigned, cross-boundary requirements are explicit, and remaining capabilities
are named. Implementation, joint acceptance, review and publication remain unexecuted.
