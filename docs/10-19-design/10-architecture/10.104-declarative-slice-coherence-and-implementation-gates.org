* Audit verdict and evidence boundary
:PROPERTIES:
:CUSTOM_ID: coherence104-scope
:END:

The 10.97--10.103 target contracts have a coherent owner direction and conservative
failure semantics, but the executable slice is not closed. Important associations
are specified as gates, not demonstrated capabilities: actual compatible source/load,
normalized handoffs, expected acquisition/origin, accepted-view recognition, independent
validation and protected effect/recovery remain open. This audit resolves cross-chapter
ambiguity without claiming that a document, source hash or refusal qualifies them.

#+begin_example
I0 actual source/build/test route -> I1 K1 / SD / S1 -> I2 actual offerings
 -> I3 original C -> I4 actual Program / complete facts / accepted frozen view
 -> I5 selected plan / exact O / actual independent validation
 -> I6 separate explicit protected B -> O + actual poststate/products
 -> later I7 execution and separate matched research
#+end_example

Read-only inspection on 2026-10-22 and Org/D2 editing/rendering are the only work here.
No implementation, package/model/directory change, build/load/test/acceptance run,
capture/inference/validator invocation, publication/restoration or orchestration
extension occurs. Preserve prior dossier/receipts and all concurrent dirty work.
Contract version V1 remains read from the neutral Library declaration owner; chapter
numbers, source/tool identities and semantic revisions are not additional versions.

Three different conclusions remain mandatory: mechanism/lane correctness (including
expected refusals), real positive completion of the preselected DE-CASE-01 activity,
and separately measured research results. No activity narrowing after failure, marker,
model syntax success or comparative metric can substitute for the positive case.

* Same-C chronology and stage-qualified demand
:PROPERTIES:
:CUSTOM_ID: coherence104-chronology
:END:

The following are explanatory associations, not a new public record format or a
second source of declaration fields. I names C's acquired immutable basis; B is its
prior model root and S its necessary support. O is generated candidate output.
A use retains both its original execution basis and target-use basis on C.

| Stage | Required actual association | What must not be inferred |
|-------+-----------------------------+----------------------------|
| Offering/selection before C | Normalized actual parents/policies/Program/method/candidate/plan/catalog/mapping/tool domain and independent required duty/input/check templates | Published method as executed, or future inference selecting uncaptured assets |
| I3 original acquisition | Actual occurrence/producer/origin/time plus owned I, source units and genuine permitted gaps | Transcript/HEAD/digest as origin, future O as captured input, missing origin repaired by a gap label |
| I4 accepted view | Same C + actual Program + complete controlled batch and independently recognized findings cut -> actual native accepted return/frozen view | Declarations as trusted use, future validation as reception proof, hidden new C or stale row union |
| I5 derived candidate | Exact selected C/view/plan/assets -> owned O/support/trace from actual materializer | O added to original I, missing ID/kind invented by serializer, model syntax as implemented architecture |
| I5 actual validation | Actual execution basis includes exact derived O and actual load/check footprint, plus original C/view/plan derivation and target-use association | Every validator input existed before C, or hashing O retrospectively authenticates C; outcomes exist only after real execution |
| Later current findings/view | Actual recognized findings/use on original C with full replacement and exact earlier view/O/result links | Mutation of earlier view, automatic validation rebinding to a later view, or old eligibility revived from absent checks |
| I6 explicit effect | Same original chain + exact selected current view/O/adequate outcomes/use and real expected B/S/permission/primitive | Validation as publication grant, old C currentness automatically valid over an intentional target write |
| Analysis after effect | Historical C/B/effect retained; actual analysis of current O acquires new C | Reread report or equal bytes as original issuer recovery |

Demand remains independent of outcome availability. Distinguish (1) acquired-input
requirements, (2) derivation/output conformance requirements and (3) subsequent
execution/current-use requirements. This is a stage qualification of existing duty/
input/check meaning, not a new authored obligation list or silently enlarged enum.
The appropriate Library/method/policy definition and actual owner operation must
carry the association in effective Types before it can be trusted.

An independently required validation check may be known before rendering while its
subject O is bound only after actual materialization. It cannot be marked acquired
by I3 or required as proof of the very earlier view that produced it. Schedule the
check later, supply genuinely prior adequate evidence, or block that activity. A
preselected bounded design activity may retain method-evidence gaps only where its
policy permits; it never waives mandatory model inputs or wider case duties.

The validator's original footprint includes O as a derived subject and actual loaded
resources. Its target use on C retains the actual C/view/plan-to-O derivation. O's
bytes are not a new exogenous input to old C. A changed generation/plan/Program/tool/
catalog/semantic basis may require genuinely new selection/C/view/validation. An
unchanged captured basis with new recognized status produces a new immutable view;
use/relevance/non-impact rechecks must determine what can still be relied on.

* Currentness domains and protected publication
:PROPERTIES:
:CUSTOM_ID: coherence104-transition
:END:

| Domain / actual owner | Independent guard obligation |
|------------------------+------------------------------|
| Scope/source and operation binding / Core | Actual source/load/admission lineage and exact K1/SD/S1; no record/descriptor from another cohort substituted by name |
| Original C origin / Scenario and expected acquisition owner | Actual original acquisition/basis/lifetime recognized without mutation; fresh observations do not renew its old receipt |
| Evidence/causal/policy applicability / actual use/check owners | Exact requirement/check/cut, footprint/strength/premise/mandate and revocation conditions; no absent-edge proof of non-impact |
| Candidate/validation / materializer and checker/tool owners | Exact O/support/view/plan/tool/load/diagnostic/check association, adequate original execution and supported current target use |
| Effect target and support / actual Project effect owner | Qualified expected B -> O, actual target/write set/staged bytes, support S stable and actual interval/exclusion/crash guarantees |

I5 validation may write owned caches/reports only as declared outputs; it cannot
quietly alter an input/discovery domain and preserve a stale current-use claim.
Isolated HOME/env and -no-record-cache do not prove complete discovery control.
Actual supported load/effect observations must cover required negative inputs and
intended output domains. Otherwise the attempt is drifted/incomplete and broader
reliance remains blocked; no C extension or unsupported IO sandbox is invented.

Publication prechecks verify B/S and actual current eligibility. The guarded effect
protects exact target/staged bytes and the promised interval; postchecks verify O/S
and unchanged original provenance/applicability within their actual support. Original
C still records B. A general current! that rereads the entire old basis cannot be
called unchanged after B -> O and then bypassed when it fails. The qualified owner
must distinguish immutable acquisition history, permitted output transition and
unchanged support. If its existing API cannot, the effect gate is open. Remote
mandate/premise expiry is not made atomic with local rename by sequential checks.

Effect occurrence, valid completion, durability, multi-file visibility and later
current reliance are distinct. An advisory lock only excludes its covered cooperating
writers; hash-then-write is not CAS. Root-only cannot promise atomic root/companion/
Org/D2 completion. A postwrite failure retains actual O/B/other/support and incomplete/
invalid/unknown state, without fictional rollback or overwrite of concurrent work.

* Recovery, evidence recognition and failure closure
:PROPERTIES:
:CUSTOM_ID: coherence104-recovery
:END:

| Claim | Actual owner prerequisite / proof | Refused substitution |
|-------+----------------------------------+----------------------|
| Receiver build restoration | Real approved-source/parent channel, current compiler/source/artifacts and receiver-local issuance followed by fresh normalized Scopes | Matching disk packet/JSON/input port, no-op/recursive restore, source fallback in compiled lane |
| Genuine original-C/view continuation | Supported producer recovery and actual recognition of original occurrence/basis/view/Program, plus adequate current checks | Serialized IDs/receipts, warm issuer inherited into claimed cold lane or build restoration as domain authority |

| Effect-state recovery/replay | Actual effect-owner request/target/operation association and supported crash/durability/interval semantics | O equality, missing completion file or copied success bit as writer attribution/exactly-once proof |

A failed Session replacement leaves its actual prior retained state under native
contract; a successful adoption followed by freeze failure is a different application
failure. Neither undoes external revocation or filesystem writes. A successful
verification issuance followed by final C admission failure similarly retains the
real attempt/receipt outcome rather than claiming the issuance never happened.
These distinctions must survive joint report and cleanup failure handling.

No pre-existing Project report writer supplies durable effect provenance or portable
C/view recognition. If no such supported mechanism exists, preserve unknown effect
completion and refuse blind replay. That unsupported continuation can pass its
negative control while the promised positive recovery activity remains unclosed.
