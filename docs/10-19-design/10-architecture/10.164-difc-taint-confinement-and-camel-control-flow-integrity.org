* Problem: Why Capabilities Alone Cannot Stop the "Lethal Trifecta"
:PROPERTIES:
:CUSTOM_ID: difc164-problem
:STATUS: implemented-verified
:END:

Even when an AI Agent holds strictly attenuated capabilities (=B3=), indirect
prompt injection exploits the *Lethal Trifecta* whenever a single agent holds
permission to (1) read private/secret data, (2) ingest untrusted external input
(webpages, public GitHub issues, third-party READMEs), and (3) invoke an
external sink (HTTP POST, PR comment, Slack webhook).

Capability authorization says "allowed" to both the private read and the public
write. Closing this vulnerability requires *Information Flow Control*
(Bell-LaPadula 1973; Biba 1977; Myers & Liskov SOSP 1997; HiStar OSDI 2006;
Debenedetti et al. Google DeepMind CaMeL 2025).

* Architecture (Scenario B7): Dual-Lattice M1 Envelopes × M3 Declassifiers
:PROPERTIES:
:CUSTOM_ID: difc164-architecture
:STATUS: implemented-verified
:END:

| Governance Mechanism | Stratification & Lattice Law | Security Guarantee |
|----------------------+------------------------------+--------------------|
| Immutable =M1= =TaintedValue<T>= | Carries monotonic =secrecyTags= (Bell-LaPadula union) and =integrity= (Biba meet: =TrustedSystem > VerifiedInternal > UntrustedExternal=); every =deriveValue= joins parent tags mechanically | LLM summarization, paraphrasing, or Base64 encoding cannot strip confidentiality taint or launder untrusted input |
| Sink Clearance Gate (=dispatchToToolSink=) | Enforces BOTH *No-Write-Down* (=allFlowingTags ⊆ sink.allowedSecrecyTags=) AND *CaMeL Control-Flow Integrity* (=controlArg.integrity >= sink.minControlIntegrity=) | Blocks secret exfiltration, cross-tenant leakage (=tenant:alpha -> tenant:beta=), and untrusted URL/command hijacking |
| Non-Serializable =M3= =DeclassificationCapability= (=R3=) | Branded with =M3_NON_SERIALIZABLE_CAPABILITY=; authorized only for explicit =removableTags= + mandatory deterministic redaction sanitizer + immutable =M1= =DeclassificationAuditReceipt= | Agents cannot self-declassify or leak declassification capabilities into =M1=; only sanitized aggregates cross to public sinks |

* Limits
:PROPERTIES:
:CUSTOM_ID: difc164-limits
:STATUS: implemented-verified
:END:

Explicit data-flow taint envelopes eliminate direct, summarized, and encoded
exfiltration through governed tool sinks, as well as untrusted control-flow
hijacking. They do not eliminate low-bandwidth timing/termination covert
channels or out-of-band exfiltration if an agent executes arbitrary unsandboxed
native code outside the governed tool runtime.
