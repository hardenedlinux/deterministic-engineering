* Scope, verdicts and design-only boundary
:PROPERTIES:
:CUSTOM_ID: i5-scope
:END:

I5 consumes the actual same C and I4 accepted inference view, selects a supported
candidate/plan/catalog/mapping, materializes an exact bounded SysML candidate bundle
and obtains independent conformance/language/property outcomes at their actual owners.
Candidate production and validation are separate from I6's explicit Project promotion.
Neither a successful inference nor a syntax-valid file grants publication authority.

#+begin_example
I0 qualified source/load -> I1 normalized Scopes -> I2 actual declarations/bindings
 -> I3 original C -> I4 actual accepted view
 -> selected candidate/plan/catalog/mapping -> resolved element/name/reference plan
 -> exact candidate bytes + closure -> actual independent validation outcomes
 -> explicit I6 publication request only if its own conditions are satisfied
#+end_example

This update changes Org/D2 only. No implementation/model/package change, actual C,
inference, model generation, validator/version command, acceptance/build/load/recovery,
promotion or orchestration is executed. Reading files/tool bytes is source inspection,
not a validation receipt. All proposed controls and operational calls remain planned.

Keep four distinct verdicts: binding/projection completeness, actual language and
resolution validity, selected model-property conclusions, and current eligibility
for an explicitly permitted publication activity. Actual architecture/content/review
and receiver obligations remain independently required. Negative and incomplete
results are products of the process, not reasons to silently weaken its contract.

* Catalog, mapping and name/identity resolution
:PROPERTIES:
:CUSTOM_ID: i5-names
:END:

Library owns reusable catalog/mapping meaning; Profile selects supported refinements;
Scenario captures actual definitions/assets/project inputs; Module interprets them
with its qualified implementation. Plan-local symbol checks are bounded domain
algorithms, not a second model registry or full SysML parser.

| Declared item or conflict | Required resolution behavior |
|---------------------------+------------------------------|
| Catalog identity/Contract/revision/source | Bind actual admitted element/kind/namespace/asset/dependency inventory and supported mapping/profile; DECaseOrganization label or companion filename alone cannot qualify |
| Stable root/node/edge identity | Use captured identity or supported published identity rule over actual project/plan/role meaning. Display labels and serialization order are separate; adding an edge cannot renumber unrelated identities |
| Local definition versus reused catalog type | Reuse only actual supported definition/meaning; local descriptive definitions need explicit declared kind/semantics/limits. A usage can be a dependency target but not silently substituted as a type definition |
| Qualified names | Preserve typed segment lists. One quoted segment containing :: differs from two namespace segments; never validate a flat suffix then emit it raw |
| Quotes/reserved words/Unicode/whitespace | Use supported selected language spelling and separate text encoding. Refuse unsupported spelling precisely; Unicode normalization/case/filesystem alias policy must not collapse distinct identities |
| Duplicate scoped name/short ID/import alias | Require intended unique target under actual selected resolution semantics. Distinct identities colliding in required scope refuse; no first/last wins, guessed import or de-duplication by label |
| Shared type label | Reuse only a proven same admitted definition under supported equivalence. Different structures/kinds/owners with equal labels remain a conflict |
| Wildcard/shadowing | Prefer exact qualified references. Wildcard is permitted only with captured bounded namespace and demonstrable unique intended target; hidden imported candidates cannot be ignored |
| Documentation/prose | Encode as supported text/documentation with safe delimiters, separate from names; intent strings/comments cannot inject declarations or terminate a generated comment |
| Determinism | Identical admitted plan/view/method inputs yield identical candidate bytes under declared set/trace ordering. Invocation timestamps and staging paths remain in attempt envelopes, not semantic names |

The local OpenSysML qualified-name frontend preserves quoted segment boundaries;
export/names.go checks spellings against actual intended elements. These are
source references to behavior that the selected actual tool/adapter must qualify,
not exported Gerbil APIs. CLI -convert api-json and -id spelling options may be
possible observation routes only when supported and qualified on the actual tool.
Name-derived qualified/UUID export IDs do not automatically provide rename-stable
Library identity; retain original declared semantic IDs and explicit trace mapping.

Do not write a full parser to compensate for an unavailable observation surface.
If the supported adapter cannot demonstrate required unique binding/kind/reference
conformance, report that check as unestablished/incomplete, never infer it from
exit 0 or a guessed public name. Missing source-owned catalog revisions or mapping
semantics remain I2 prerequisites; I5 cannot repair them with empty stub definitions.

Preserve legitimate supported reference cycles with bounded visited/identity handling;
closure is not an acyclic-tree requirement. Unknown semantic relation/kind or invalid
encoding refuses; recognized missing content stays an explicit gap where permitted.
All mandatory input/reference units remain independently accounted for.

Finalize content manifest after exact candidate bytes/support closure and before
validation/publication outcomes. It need not include its own digest, a future
receipt or a result that cites it. The candidate root is output over C's captured
baseline B, not another input appended to that same C. Staging acquires no new
semantic inputs and must not reopen mutable originals after hashing.

If the tool discovers another resource during validation, the source owner must
prove it belongs to the already captured qualified input domain; otherwise the
attempt is incomplete/drifted and requires appropriate new acquisition. It cannot
extend C silently. Staging relocation must preserve declared references and document
base semantics; output locations cannot select a different catalog or ancestor project.

no invented executor/service API or caller-selected command fills a missing binding.

not the general architecture validator.

-validate=<object> (assertions about that object), -instantiate and explicit

cannot be replaced by error count. Check actual tool/version support before assigning
these meanings to the installed executable. No validation command is run here.

The same source supports -baseline suppression, -disable-lint, enabled lint settings
and -warnings-as-errors. A controlled diagnostic profile must record flags, exact
baseline/filter content, suppressed counts and stopping/unsupported tiers. Required
binding/content findings cannot be suppressed into a pass. A policy-permitted known
finding remains explicit with its scope; suppressed output alone cannot establish
full required findings. No baseline/waiver is invented by this update.

actual argv/cwd/env, adapters/libraries/resources/search roots/project metadata,
cache/profile/limits, exact bundle digests, start/completion/exit and stdout/stderr/raw

accounted for. Existing local CLI load/discovery sources show enclosing project and
installed-library discovery, while -no-record-cache only addresses interface record
cache. An isolated HOME/env or complete explicit file arguments do not by themselves
prove every implicit load dependency is disabled.

Execution, validation, property conclusion, negative-control outcome and current use
stay distinct under I2 Types. A deliberate false property may be the expected
negative control; it does not become a positive architecture verdict. Timeout, tool
failure, truncated diagnostics, unknown completion, unsupported property or input
drift is not accepted validation. Process exit alone does not prove every requested
check actually ran or every subprocess terminated; qualify actual owner behavior.

Check exact byte/load/input identity and required currentness before/after execution.
Tool-created cache/report files are separate owned outputs with declared effects,
never model inputs masquerading as immutable originals. If a required signed/admitted
A/E/W/use result is demanded, use that actual producer's qualified protocol; no
always-true adapter or model writer creates a validation credential.
