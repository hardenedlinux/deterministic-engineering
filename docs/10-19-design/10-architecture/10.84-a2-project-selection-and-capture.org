* Result, scope and actual source boundary
:PROPERTIES:
:CUSTOM_ID: a2-scope
:END:

A2 consumes actual admitted provider Scopes, binds one effective Profile and explicit
project request, acquires their required real inputs at their supported owners, and
returns one Scenario-owned capture C for that acquisition occurrence. Reporting,
application reasoning and SysML materialization consume that same captured meaning
and original provenance. They do not separately reconstruct it from Profile data.
One capture does not mean one global snapshot forever: a genuinely new acquisition,
changed captured meaning or different selection requires an appropriate new C.

This chapter unifies 10.82--10.83 with 10.68/10.77 for the current Library repo. All
new field/call boundaries are proposed, not implemented exports. Only Org and D2
are updated. No code, package, generated SysML, runtime acceptance, capture operation,
review or automatic orchestration is run. No Source/receipt/clock/authority registry,
Profile loader or new Project manager is proposed.

The domain operation selects only capabilities published by the admitted provider set.

add a handwritten core.link alongside generated exports or leave Config unused.

Generic-only request cannot suppress a failed required Domain or silently switch to

* Explicit project request and real input acquisition
:PROPERTIES:
:CUSTOM_ID: a2-acquisition
:END:

The runner supplies a project request distinct from Profile: requested repo/worktree,
subject and source/include/exclusion/alias restrictions; logical Library/reference/
project/product roles; selected operation/purpose; permitted bounded reads; output
intent and prior mandate references where needed. A requested path, revision, URL or
tool name is a constraint, not an observation or permission to fetch/install/build/run.
The trusted Scenario operation binds expected readers, source/Host/clock/lease policy
and validators. Callers do not supply current! lambdas, seal functions or trust roots.

Derive complete required input roles/occurrences/multiplicities and adequacy first
from the admitted selection, claims, parameters, policy, plan and operation. Acquire
an observed binding or explicit typed gap for every demanded unit. Never remove a
required unit merely because its input or check capability is missing.

| Logical input role | Concrete DE-CASE-01 acquisition example / required recorded basis |
|--------------------+------------------------------------------------------------------|
| Confirmed intent / proposals | Retain the actual confirmation and proposal content/source occurrence where supported, including what was confirmed and what remains unverified. 10.79's authored account and Profile strings are claims, not a substitute for an unavailable original acquisition channel |
| Library and methods | Actual admitted Scope/parent/policy/model/catalog/Contract/method/program/mapping definitions and selected source/semantic revisions; required dirty/build/load associations from A0 or explicit gaps |
| Current repo implementation | Explicit worktree/subject, observed HEAD plus included dirty/untracked bytes, relevant source/build/package/config inputs and file/enumeration/negative dependencies. HEAD alone does not capture the current formation implementation |
| Architecture/model products | Current project.sysml and selected companion/catalog bytes, base, element selectors, actual/target classifications and demanded references. These are captured baseline inputs, not future generated output |
| Org and decisions | Selected product/section/decision requirements, actual Org bytes, selectors, references/access and current/historical/missing classifications. 10.82--10.84 are examples of selected products; obligation-driven selectors, not another hardcoded file inventory, determine the actual closure |
| Reference workload | Separate Library-owned six-case crate/lock/oracle/protocol when selected; retain its own subject/source and intended claim domain. It cannot stand in for an unrelated receiving repo implementation |
| Tools/environment | Selected executable/ABI/config/environment and resource identities through supported reads; tool labels and old manifest versions are requested/historical inputs until observed. Reading identity is not executing Rust/QNT/Lean/SysML |
| Premise/data/mandate/history intent | Required causal/model/data/measurement/applicability/transport inputs and actual policy/role/mandate source associations or explicit gaps; preserve uncertainty. C creates no result, causal finding, authority or future history decision |

For this self-hosted case, Library and project roles may point to identical physical
bytes; their subject, demand, dependency and provenance roles remain distinct. Storage
may deduplicate bytes. It must not merge evidence meaning or relabel target/project
code as the reference workload. Adding output to its own input closure is forbidden:
newly generated project.sysml belongs to a later result; baseline root bytes already
captured in C remain historical inputs for that run.

Readers preserve actual operation/input/result/source-cut/limits and owned immutable
bytes or supported immutable retained source domains. File reads require owning base,
symlink/alias/relocation rules, content/enumeration/negative observations, dependency
closure and supported stability checks. Changes during acquisition refuse/reacquire
under declared limits or become an explicit unstable gap in a supported partial
variant; do not combine old metadata and new bytes into a claimed stable cut.
A digest then reopening a mutable path during execution is not consuming C's inputs.
Any permitted staging must record original-to-copy and actual byte acquisition.

POO issued reads authenticate their actual producer/token/root observation domain;
Core Module SourceRef authenticates its qualified module source boundary. Neither is
a universal arbitrary-repo or tool reader. Forward actual supported issued tokens;
never fabricate token-shaped records or an always-true checker. Unsupported required
reader/provenance support blocks complete acquisition. Actual OS/Host reader support
must be qualified at that owner; no generic snapshot authority is assumed available.

* Capture basis, original origin and C
:PROPERTIES:
:CUSTOM_ID: a2-one-capture
:END:

| Value / boundary | Required retained fields and meaning |
|------------------+--------------------------------------|
| Acquisition occurrence | New Scenario-owned occurrence-ref, expected producer/operation/source-generation, actual selection/request, acquisition attempts/results and guard/read associations. A caller reuse token or content digest cannot choose this occurrence |
| Normalized basis | occurrence-ref; admitted Profile/parameter/selection/Scopes/parents/policies/model/method/catalog/plan; confirmed intent and all candidate bases; actual project/source/product/tool/environment/mandate/premise inputs, independently required demand and explicit gaps/limits; canonical owned basis and acquisition associations |
| Original origin assertion | Exact normalized basis/occurrence and actual producer/reader operation/source/retained acquisition; precise claim that this operation acquired this basis under its declared limits. Does not claim architecture validity, true premises or policy approval |
| Original receipt association | Actual expected source-bound adapter/operation, genuine receipt and interval, assertion/basis refs and trusted clock/lease limitations. Never serialize a private issuer table or accept matching public fields as issuance |
| Final C | Returned checked immutable basis-ref plus original origin association, expected declaration/operation and provenance/lease limits. No future A/E/W/Q/R/decision/generated model or later verification result is appended |
| Later current-origin use | Separate actual target operation/request/assertion, same C/basis/occurrence/origin, fresh verification observation if supported and live source/premise/status/role/clock findings. Does not mutate or renew the original C |

Canonicalization follows the expected Types: preserve symbol versus string,
ordered acquisition/trace sequences, declared set semantics and every meaning-changing
negative/gap/limit/role/source association. Qualified operation/function references
retain actual source binding and supported live guards; do not serialize closures or
silently omit their meaning because they are not JSON. A digest is an integrity aid,
not an issuer or a substitute for the actual retained acquisition association.

The implementation boundary is normalize basis -> actual origin verification ->
retain genuine original association -> final C admission. The receipt is not in its
own basis snapshot. Final normalization must preserve the already-attested meaning;
if it changes that meaning, refuse/reverify under the supported owner, never patch
receipt data or re-run normalization merely to recreate a lost receiver.

Current Core's real API is [[file:../../../../poo-flow/core/contribution/verification.ss][contribution/verification.ss]], exported as
:yuanxu/contribution/verification. The isolated cohort has the same file under
:core/contribution/verification and poo-flow-* names. The current API provides
yuanxu-verification-adapter, yuanxu-verify, yuanxu-verification-valid?,
yuanxu-verification-admission, yuanxu-verification-admission-valid? and revocation.
These are existing mechanisms, not a newly implemented Scenario capture service.

The actual source-bound operation must recognize the retained acquisition, expected
producer/selection/reader and allowed gaps and return exactly #t. Core copies the
snapshot string, requires matching pre/post snapshots and privately binds a genuine
receipt to snapshot/issuer/interval. The interval is [issued-at,expires-at), with
exact nonnegative integers and issued-at < expires-at. Valid? checks the exact
issued receipt/adapter association and snapshot at the supplied instant. The trusted
Host supplies the actual clock/lease policy; a caller-provided now/until is not a
trusted clock. Snapshot equality proves neither historical IO truth nor universal
ABA absence; actual read/source stability requires its qualified owner guards.

Anyone can construct an adapter around a trivial operation. Therefore registration,
adapter name or successful generic valid? is insufficient: the consuming Scenario/
method must bind the expected actual producer/source operation independently. A
forged/copied/modified receipt or adapter cannot replace the original private
association. Core admission objects index a supplied fixed instant, not a moving
clock; fresh use still needs the operation's actual current instant and conditions.

Two kinds of failure are distinct. A recognized acquisition of a missing document
can form a valid gap-bearing C only if its selected partial variant permits that
gap; no complete/readiness claim follows. Missing qualified acquisition/origin
recognition produces an unrecognized draft or refusal, never an authentic C with a
fabricated receipt. If final admission fails after issuance, retain the attempt and
any actual receipt in its owner diagnostics; do not claim issuance rolled back or
return a partially recognized C.

A later supported re-verification may preserve the same original occurrence only
when actual retained provenance and unchanged meaning are independently checkable.
It creates a new observation/receipt with a real new interval, not an edited old
receipt or second C. If that is unavailable, expired/revoked/process-lost origin
stays unestablished for current use. Actual reacquisition creates a new occurrence/C.
JSON, hashes, restored files or copied Scope/C objects cannot reconstruct private
issuance. No portable/restart origin protocol is assumed implemented by this design.

The unique capture contains the candidate set and applicable plans so alternatives
can be compared over one declared input basis. If an investigation needs incompatible
model/policy/method selections, declare separate captures or a supported common demand
and source association; do not compare unrelated results as if they shared C. New
intent, parameter, candidate meaning, plan or required source meaning changes create
new captured meaning. Status-only checks, later results and origin observations stay
separate. Append-only provenance/history links connect old and new occurrences.

catalog revisions and bindings; the chosen Core cohort's supported Scope/source
association; actual bounded arbitrary-project/product/tool acquisition support;

No review submission, root-model promotion, delivery or automatic LLM iteration is
part of this design task. Correctness of capture/binding and negative preservation
is separate from research claims about better architecture, causal reasoning or cost.

* Scope-before-capture and current-use consistency
:PROPERTIES:
:CUSTOM_ID: a2-coherence-followup
:END:

Admitted K1/SD/S1 and Library/Engine Scopes precede C; capture retains their qualified selection lineage, never supplies its own upstream admission premise. Program construction precedes capture while fact projection consumes C afterward. Later status/evidence/use records bind the immutable original C; genuine reacquisition is a new occurrence, not reconstructed original provenance.
