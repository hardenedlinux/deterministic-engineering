* Scope, target direction and execution boundary
:PROPERTIES:
:CUSTOM_ID: i0-migration-scope
:END:

This unifies 10.96 I0 and 10.89 against the actual local POO/Core/ASCENT/Flow
sources, with explicit test-policy, recipe and fixture ownership. It specifies a
coherent direct migration, not a namespace alias, alternate loader, new test runner
or second dependency/version registry. I0 establishes compatible selected sources
and entry closure; complete build/load/cold/recovery and I1 normalized-value behavior
remain separately evidenced gates, not consequences of making imports resolve.

#+begin_example
POO validation/observation -> Core source/Scope/build/TestingScript/Ops/Fixture
 -> generic ASCENT Program/Session -> this Project's formation consumers
Core / generic ASCENT -> optional Flow products -> selected Project evidence/review
Flow development package -> ASP discovery/batching -> original native harness
Actual test entry -> selected source + policy -> TestingScript .run
 -> Fixture precheck -> Ops child -> process gate -> receipt refinement
 -> Fixture postcheck -> actual domain/lane verdict
#+end_example

The arrows indicate dependency/use, not a new orchestration pipeline. Formation
need not depend on Flow products, ASP or Nix merely because their tests exist in the
workspace. Selected full evidence/review/provider lanes must include their actual
Flow/Aitia/product dependencies instead of borrowing retired ASCENT application APIs.

This update reads sources, metadata, launcher bytes and selected artifact bytes;
it changes Org/D2 only. No package operation, recipe parsing/execution, build, load,
source namespace check, test, cold start, restoration, inference, SysML validation,
publication or orchestration expansion occurs. Even just --list can evaluate
backtick environment expressions; recipes are read as source here. Proposed calls
and acceptance conditions are not executable receipts.
