This chapter unifies 10.66 with 10.75-10.76. Retain that complete field inventory,
finite semantic domains and P2-P9 associations; the tables below refine their actual
file/ancestry/field/current-use boundaries, not a reduced replacement schema. Public
values remain ordinary POO objects, existing value Contracts and Aitia CLOS classes.
Pure field/relational validation cannot authenticate acquisition, clock, signature,
issuer, actual execution or permission. Actual expected source-bound operations do so.

One C captures an actual acquisition occurrence and immutable meaning. Its original
provenance, expiring verification receipt and later re-verification/current use are
separate associated values. Fresh checking can preserve that C only when the original
owner association and required current conditions are actually verifiable. No mutable
current flag, second capture, seal renewal by editing timestamps or generic nonce/
version/assumption registry substitutes for this boundary.

A new verification observation is not a new acquisition. Reverify same occurrence
only through the actual qualified owner retaining independently checkable original
acquisition/basis/source association. Verify that assertion with the current Yuanxu
adapter/verify/valid? operation; a registered adapter alone is not trusted, the actual
expected operation source/Host is. Operation must return exactly #t and pre/post owned
snapshots must agree; actual native/external guards still supply required stability.
Snapshot equality alone proves neither universal ABA absence nor historical IO truth.

No general renewal API is assumed implemented. Successful actual re-verification
creates a new receipt/observation with actual now/until selected by trusted Host;
it does not extend or revive old receipt, change captured meaning, restore revoked
authority, rewrite R/Q or create a second authoritative C. Normalize later observation
and call inputs retaining genuine issuer association; if transformation changes sealed
assertion meaning, refuse/reverify appropriately, never patch after checking.

Expiry alone does not change historical acquisition or captured meaning. It blocks
current reliance on that receipt. If retained original association cannot be verified,
report unestablished/expired/unavailable use; real reacquisition has appropriate new
occurrence/C, and foreign assertion verification has a new local origin/target binding.
Process loss, restored bytes or JSON cannot reconstruct original private issuer. Same
normalized presentation of original meaning can be supported only with actual qualified
association; neither raw eq? nor equal printed IDs is the general origin rule.

Long methods need actual prelaunch/checkpoint/final guards under qualified operation
clock/source semantics. If current gate fails after execution, retain A/E/raw outputs
and exact workload origin; issue no positive W/use by pretending lease covered the
whole envelope. Fresh verification does not re-observe/rerun workload. Core admission
indexes its supplied fixed instant, never a moving clock. Known source/role/premise
invalidity blocks affected use regardless of still-valid historical seal or failed P5
transaction. Captured meaning change requires new C, technical view change new Q/R,
status-only refresh a later H/use; no output goes into its own sealed input.
