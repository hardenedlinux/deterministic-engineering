* DESIGN S1 scope and coordinated target
:PROPERTIES:
:CUSTOM_ID: library-aitia-types-contracts
:STATUS: File/field/inheritance/validation design only; no implementation or acceptance execution
:END:

S1 defines complete expected Types and Contract boundaries for Library publication,
selection/capture/application/evidence and Aitia review/history/delivery requests.
It unifies the later WP05-WP09 requirements into WP01's existing owners, before
S2 exposes checked values and deferred real operations. There is one Library
declaration generation owner, two distinct policy definitions, four declaration
role categories and one finite Aitia verification-purpose domain.

This is a target design for ordinary POO Types/ObjectContract/Function and Core's
Contract/CLOS mechanisms. It creates no parallel schema grammar, generic registry,
version service, policy evaluator, evidence issuer or contribution framework.
Actual source-qualified producer recognition, freshness, authorization and effects
remain separate from data conformance. Types do not issue C/W/Q/receipts, appoint
roles, accept decisions or install/deliver a Library.

S0 appendix at this inspection. Project HEAD is

Each role descriptor has identity, role, declaration-contract and value-contract.

and validation. Exact descriptor identities already specified in 10.42 remain;
the design-policy descriptor receives a distinct source-owned identity at its own
Types owner. It is not the bounded descriptor with a candidate-selected validator.
Both policy descriptors share the family owner but neither has its own generation
slot. Aitia references actual selected policy/Contract/source associations without
importing a backpressure-only generation into its generic request base.

The only read chain is checked Scope -> selected expected role descriptor ->
its admitted declaration-contract -> contract-version. Scope's family export,
each definition.contract and every expected role/source association must agree.
Read guards/actual source ownership matter: copied symbols, object pointer equality
or restored version bytes do not authorize mutation. Org/D2 show that relationship;
package manifests, namespace names, record schemas, Git/dirty/compiled identities
and semantic revisions never supply or advance that generation.

Shared shape inheritance is common declaration -> model -> Rust -> integration;
policy shape is a sibling derived from common declaration. Concrete role Contracts
compose full effective shape and their own fixed identity/parent/applicability
checks. Rust must not inherit the Generic fixed identity/parent=false constraint;
integration must not inherit the Rust fixed role/Generic-parent constraint.

criteria. Engineering POO value ancestry and Contract-shape reuse are distinct;
use required-prototype only where actual ancestry is explicitly promised.

the parent's prepared map has already been forced. Preserve all inherited
constraints, required duties and returned normalized/wrapped values. Required
unknown fields are rejected by name without evaluating their values; an undeclared
poisoned getter must not run merely to reject its name. Closed rejection must not
misapply the parent's incomplete field inventory to a valid full child.

verification is a new local observation of its precise assertion, not imported
original private issuance. All complete runtime/issuer/currentness operations
are later S3-S8 work; S1 defines their expectations and source owner boundaries.

only the five review/delivery purposes already specified in WP07/WP09. Author
that domain once at SdlcVerificationRequest's existing Types owner. It is separate
from a review's intended use and a disposition action; no concatenated purpose
strings, version suffixes or policy-selected validators are introduced.

All new request classes derive from the existing request base, retain its bound
subject/revision/scope and narrow purpose to exactly one supported symbol plus
its expected facts class. Their facts binding must agree on project/revision/
scope, R or manifest identity, policy and precise assertion/target. Operations
select the expected class/facts/domain, never a submitted classifier or arbitrary
facts object's own validation method. Existing purpose spelling is retained;
the word approval does not change a disposition action's actual polarity.

Inherited CLOS predicates conjoin: a wider subclass enum cannot widen the old
seven-purpose base. Update the actual base once, while every snapshot/verifier
retains an explicit finite operation-specific allowlist and expected facts/action
checks. NASA lifecycle's missing explicit refusal must be repaired in that same
migration; certification/history/authority and new review/delivery snapshots must
reject unsupported purpose/facts before reading them. No base-only widening is
publishable, no unrelated request is accepted via an unspecified/default case,
and no pre-existing signed artifact is rewritten as a new-purpose record.

* SPECIFIED Validation order and trust limits
:PROPERTIES:
:CUSTOM_ID: s1-validation-and-trust-boundaries
:END:

| Boundary / order | Required check and returned value | What it cannot establish |
|------------------+-----------------------------------+--------------------------|
| 1. Trusted entry | Choose expected role/model/request/Function from actual source-qualified operation/Scope and finite supported role/purpose | Candidate-supplied Contract, callback, class or issuer label cannot choose the validator |
| 2. Kind and actual promised ancestry | Check object kind and required prototype/expected CLOS model before forcing unrelated fields | Ancestry/shape alone cannot authenticate source, private issuance or project authority |
| 3. Full effective field/slot inventory | Inspect allowed names, required fields and supported metadata policy; reject extra/missing fields before demanding unknown values | Current CLOS check-model by itself is not a closed-schema check |
| 4. Primitive/nested field Types | Exact signs/domains/enums, finite unique lists/maps, typed references and parameter/capability shapes under the complete expected receiver | Missing fields are not silently defaulted; a string identity/digest is not an actual source/owner association |
| 5. Pure cross-field relations | Identity/parent/family/policy applicability, full inherited duty/input/product roles, unique keys and exact request/facts/R/project/action association | Present declarations do not prove premises, semantic adequacy, real appointments or accepted history |
| 6. Validation/admission return | Retain actual normalized/wrapped candidate and real Core contextual evidence at the expected boundary | Diagnose/element?/boolean success cannot replace the returned checked value |
| 7. Qualified producer and later use | Actual C/A/W/U/Q/receipt/accepted history/source/clock/role/currentness under its real producer and supported footprint | Types cannot synthesize this step; genuine negative/missing findings remain at their actual meanings |

For the new closed Aitia public request/facts boundaries, derive allowed semantic
slot names from the same class's effective slot metadata. After the existing
expected-ancestry check, inspect field names before full effective-slot value
validation; then run actual check-model and pure cross-field relations. Keep the
name/metadata and relation helpers at the Aitia Types owner; do not create an
independently maintained duplicate field map or replace Core's model validation.
The framework's inherited %poo-clos-class marker is checked as expected model
metadata, not arbitrary semantic payload; no blanket allowance for all percent-
