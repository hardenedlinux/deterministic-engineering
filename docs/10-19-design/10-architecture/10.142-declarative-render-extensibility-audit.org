* Downstream declaration contract
=compileFigureSource(sources, inputPath, resources?)= accepts data-only resources:
=themeLayers= and =iconPacks=. Defaults are immutable. A downstream extends them
with ordinary module exports, then D2 selects ordered names. No global registration,
new manifest, cache or automatic discovery mechanism is required.

A declared variant may select =kind=, =layout=, =themes= and =icons=. Unspecified
resources inherit the view's resolved selection. =selectFigureVariant= preserves
the captured sources, model, Questions and evidence links; it does not recompile
or rewrite the model. Unknown or duplicate variants fail. Explicit icon packs are
complete selected maps, not implicit word-based icon inference.

=kind= is open. =purpose= remains architecture or workflow. Reserved standard
kinds keep their original purpose, so allowing a new kind cannot silently turn
an existing architecture view into a Workflow. Project =presentation= stays
unknown at the generic boundary and is specifically validated by its compositor.

The Case's =project-owned= variants declare =responsibility-map= and
=capture-handoff= kinds, compose =field-notes + workbench + compact= and select
=engineering + repo= glyphs. These names are absent from framework source.
The Case remains explicitly English and still displays =capture-blocked= with
=capture = #f= and no issued C/Q/R. Source assertions remain source observations.

* Intentional retained defaults and limits
Upstream palettes/styles and the Engineering glyph pack are optional maintained
resources. Their existence does not limit downstream kinds or assets. The Case
has an authored explanatory layout; its headings, role placement and section
organization belong to that Case, not to =composeFigure=.

D2 supplies labels, relationships and metadata. Its geometry/SVG is discarded.
Actual browser font and glyph measurements feed the existing ELK.js layout engine;
its native graph/options control placement and routing. Explicit authored HTML
connectors may use XYFlow, separately from scene layout. No local solver is added. Rough.js adapters expose the selected
primitives; other explicit SVG markup can be supplied by a compositor. Unknown
primitives do not silently render as rectangles.

OpenSysML's supported reflow adapter retains capability refusals for unsupported
notation. This audit does not claim live SysML service validation. Static HTML
export still bounds width/scale, closes its browser context, records actual fonts,
backend pins and output hashes, and rejects stale inputs and detected clipping.
Visual quality remains a review judgment separate from correctness controls.

* Acceptance and execution entrypoints
The normal CI entrypoints run package =bun install --frozen-lockfile=,
=typecheck=, =bun test=, =bun run test:export=; then the actual consumer's frozen
install, typecheck, tests, Case export, comparisons and measured TS overview views.
Playwright owns browser fixtures; tests do not start another test runner. Worker
limits remain two and existing job/resource bounds are unchanged.

Required positives include native D2 notation, project-only kinds/themes/icons,
variant retention, real Library/Profile/Scenario sources, source fingerprints,
independent architecture/Workflow artifacts and actual font/image export.
Negatives retain unknown resources, hidden Questions, source/model mutation,
invalid lanes/relations/ports, unsupported primitives, stale input and broken images.

Ten full candidates and two comparison sheets are derived from 90.132/90.133.
90.134 is the TS scene ownership/dependency view for this audit. CI is authoritative
for Linux/macOS and its exact commit; local results alone do not establish both.
No artifact-upload action is added; generated image candidates are tracked as
requested documentation. No model publication, review or delivery is performed.

* Measured scenes and removal of Legacy
The previous raw-D2 fallback was a design error: it bypassed the new visual
Library while retaining old geometry. Removed =renderCatalog=, =renderView=,
=pipeline.ts=, duplicate D2 themes/theme registry and =examples/render/native.ts=.
Current README views are emitted by =overviews.ts= through =composeDiagram= and
=exportFigure=. Their Questions, labels and native ELK graph projections stay in
D2. Historical diagrams remain historical, not current renderer acceptance.

| Boundary | Owner / implementation | Control |
|----------+------------------------+---------|
| Syntax / model | Official D2 SDK; supported OpenSysML projection | No old positions or SVG in compiled model |
| Figure organization | Downstream pure composer | No mandatory card/page layout |
| Font / glyph dimensions | Actual browser with embedded Inter or Kalam | SVG glyph viewport explicitly set before measurement |
| Spatial layout / routing | ELK.js native graph/options | Measured node/edge-label sizes; no second constraint DSL or solver |
| Hand-drawn geometry | Rough.js primitives/options | Actual measured scene frames; different font metrics enter layout |
| Output checking | Browser-observed containment and pairwise overlap checks | Nodes/content/edge labels; invalid post-layout CSS refuses |
| Export | Explicit SVG scene/annotations and browser PNG | No raster wrapper, foreignObject or raw-D2 fallback |

The initial ELK bundled fake worker left timers alive after image generation;
those successful image writes did not establish natural completion. The official
Node worker mode, with its declared =web-worker= dependency and =terminateWorker=
in =finally=, fixes lifecycle ownership. The overview entry now exits naturally.
Nested SVG CSS width alone also left an oversized intrinsic glyph viewport;
explicit viewport attributes fix that root cause before font-box measurement.
D2 SDK compilation returns formatted source text in its output filesystem; that
text must not overwrite captured repository bytes. The model worker now retains
the actual input filesystem, and the overview driver verifies source hashes again
before writing. Formatted compiler output is not relabeled as original evidence.

The adapter supports orthogonal/polyline serialization and root-owned model edges.
Ports, nested edge containers and splines require a dedicated compositor and refuse
at this boundary. This is an adapter capability limit, not a limit on downstream
kinds, themes or independent composers. Geometric checks detect stated violations;
they do not prove optimal space usage or aesthetic quality. Functional composition
makes inputs explicit and repeatable; it does not itself solve spatial constraints.

Primary references: [[https://github.com/kieler/elkjs][ELK.js]] and
[[https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html][ELK Layered]],
[[https://roughjs.com/][Rough.js]]. Reuse these implementations rather than introducing
another layout engine or editing/interaction runtime.

* Visual language is a declarative extension boundary
The first measured scenes still repeated identical rectangular nodes and nearly
identical glyphs. That met geometry checks but failed visual communication.
Themes now compose native SVG surface assets, typography, semantic CSS, connector
marks and spacing, alongside palette and font resources. Native ELK layout preferences
compose in the theme too; explicit view options take precedence. No parallel
constraint schema or solver is introduced. Project role names are
open; surfaces use the existing SVG asset contract, not a new shape language.
Node composers receive the immutable selected theme. No editor runtime is added.

Editorial intentionally leaves supporting nodes unboxed, emphasizes the published
Library and distinguishes external / pending boundaries. Technical node-editor
uses explicit node and connector marks. Sketchbook uses actual Rough.js frames
and Kalam metrics. These names remain optional maintained defaults; downstream
can introduce another visual language without editing a framework switch.
90.135 selects them as independent variants over the same captured model.
Icons are explicitly chosen by responsibility in D2, replacing the earlier
repetition of the generic model glyph. Architecture and Workflow remain separate.

Annotation heights also follow measured selected-font ascent/descent: the first
sketch variant correctly failed for a clipped fixed-height heading, and that
fixed-height assumption was removed. Output checks are correctness controls;
visual beauty remains subject to the user's review of actual rendered candidates.

* SVG serialization order control
Linux run 41284866523 failed the repeated SVG byte check while the PNG and ELK
layout hashes matched. Preserve that failure separately from earlier green runs.
A controlled native-browser CSSOM enumeration reversal reproduces the same class
of failure: identical pixels/layout but different SVG bytes. Computed custom CSS
properties were emitted in the browser's enumeration order. Sort those unique
property names before standard XMLSerializer output; keep the original strict
repeatability assertions and the new environment control. This fixes an observed
serialization defect without replacing the serializer, relaxing checks or changing
layout. The original failed CI did not retain SVG payloads, so its precise byte
difference cannot be claimed as recovered; the controlled witness is explicit.
