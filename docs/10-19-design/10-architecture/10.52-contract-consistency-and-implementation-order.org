* AUDITED Overall finding and scope
:PROPERTIES:
:CUSTOM_ID: whole-slice-consistency-audit
:STATUS: Design consistency audit and documentation corrections only; no implementation or acceptance execution
:END:

10.42-10.51 specify one coherent target pipeline with distinct semantic owners,
immutable stage inputs, real producer/verification boundaries and conservative
negative/currentness handling. They did not yet form a fully synchronized contract
set: WP05's later policy publication and Config wording had not been completely
reconciled with WP01-WP03, and WP06's unconditional history-to-Q wording needed
WP08's technical-versus-authority lifetime distinction. These documentary seams
are corrected in place by this audit, rather than hidden behind another pipeline.

The result is a reconciled target design, not a claim of complete operational
closure. Actual expected Contract implementations, source/compiled boundaries,
finite supported domain/budget assignments, substantive case content, real roles/
mandates, recipient route and the remaining recovery qualification are still open.
The implementation can proceed in the dependency order below; positive project
acceptance and actual distribution/use cannot be inferred from the design.

Audit basis is the active dirty checkout at HEAD
8044732d505f84e373119a70f947df00e1767300, the ten named design documents, existing
file/entry associations recorded there and retained historical limits. Current
source identities remain distinct from historical receipts. This task does not
re-run Core/POO/ASCENT/Aitia or refresh an old evidence cut.

One origin can have several consumers without becoming several issuers. Org and
D2 describe/locate the same bindings; they do not publish executable meaning,
appoint a principal or make an ASCENT row authoritative. Actual project roles
must be appointed through real sources; ownership in this table does not appoint
anyone.

The import graph must remain acyclic: POO/Core -> shared Types -> concrete role
Types -> authored definitions/implementation units -> interface assembly ->
Profile/Scenario adapters -> project projection/review/delivery orchestration.
Common Aitia Types/semantics do not import this repo's DE identifiers or Scenario
classes. Expected C/A/E/W/use data Types can be defined at their declared lower
owner before operations; real C/W recognition stays with the actual producer.
Library Types cannot import Scenario or methods to authenticate them. Trusted
assembly binds actual source-qualified producer operations/Contracts; arbitrary
caller callbacks cannot fill that boundary. No second capture, Host, policy
engine, Session store, decision log or transport package manager is introduced.

* SPECIFIED Stage order and loop closure
:PROPERTIES:
:CUSTOM_ID: consistency-call-order
:END:

The flow is directional within each captured technical basis. Feedback creates
new qualified observations/bases or current-use assessments, never edits an
immutable earlier stage or makes a result its own authority.

| Order / produced binding | Prior inputs and actual effect boundary |
|--------------------------+-----------------------------------------|
| Select and acquire C0 | Checked Library model/parents/policy, actual project source/products/mandates and bounded acquisition. Expected duties exist before results |
| Prepare A; observe E; issue W; qualify U | C0 plus actual derivations/commands/observer/issuer origins; each target required K has its independent expected demand |
| Accept complete Q0; prepare R0 | Actual qualified program/source cut and finished query; R0 binds exact technical Q0 and adopted policy/project/product/role input references |
| Verify R0; discover H0; propose action | Separate context/content/currentness and independently required accepted history/grants/status. Proposal/action receipt is not accepted inclusion |
| Accept decision D0 and observe H1 | D0 binds predecision H0/R0; actual append/publication -> accepted H1. Current checks bind real inclusion, original lineage and later relevant status |
| Materialize manifest M; accept distribution D1 | Exact reviewed publication/products and prior decision/current authority basis -> finalized M; distribution act binds M/recipient/purpose. D1 is outside M's own content identity |
| Transfer and verify at receiver | Actual authorized channel, exact arrival/access/omissions and acknowledgement; own trusted verifier/root/status/source/clock, no import of private authority |
| Capture C1; establish Q1/R1; accept adoption/use | Receiver's actual project/roles/policy/source/architecture and eligible publication; own method/content duties/evidence applicability. Later acceptance/current operation refers back to those inputs |

C1 is a recipient occurrence label here, not a new contract generation. D0/D1 in
this table name actual authority records conceptually, not replacements for the
case's authored DE-D01-DE-D05 decision-document identities. A received statement
of prior authority, its integrity verification and a newly authorized recipient
action remain different facts.

The receiver's prior project policy adoption/appointment mandates are inputs;
acceptance of this particular Library use is a later output. No bootstrap cycle
requires that later acceptance before constructing the receiver C, or permits
current use before the required adoption/operation authority actually exists.
Project qualification fixtures can test this mechanism under isolated real test
mandates; those test principals do not become actual DE-CASE-01 or recipient
project authorities.

* SPECIFIED Change impact and reuse rules
:PROPERTIES:
:CUSTOM_ID: consistency-change-impact
:END:

| Change / lifetime | Required transition and surviving original evidence |
|-------------------+-----------------------------------------------------|
| Declaration generation/role/source/parent/semantic meaning changes | Re-admit actual publication/selection and acquire affected new C. Same V1 label cannot preserve source/semantic compatibility automatically |
| Captured project/product/parameter/governance record content changes | New C when the selected input basis changes; old C/results remain historical. Reuse unaffected original W only through genuine fresh target use and compatible premises |
| Actual method/parser/generator/validator/tool/compiled/runtime footprint changes | Requalify affected execution/interpretation/use; new E/W where the claim requires actual new observation. Do not assume independent extraction until actual import/initializer/read closure proves it |
| New actual method/content observation or changed required technical/query inputs | New accepted source/query cut and Q/R as required; keep old W/Q/R and counters. Mandatory units remain even without a result |
| Later grant/decision/status event with unchanged captured records and technical Q meaning | Fresh actual H/current-use/clock/dependency assessment can refer to unchanged technical Q/R. It does not certify a query that claims to display the later event |
| Authority event becomes part of required query facts, coverage or technical demands | New Q/R at that projected technical cut; new C if captured inputs/selection/products/mandates also change. Do not insert later history into old Q |
| Expiry/withdrawal/revocation of use/receipt/decision/exception | Actual owning status/issuer changes current eligibility; dependent denial can reopen. Historical statement/transfer/execution stays recorded; old bytes or restored private IDs cannot reactivate use |
| Manifest inventory/recipient/purpose/redaction/access basis changes | New identified manifest and actual scoped authorization; receiver rechecks changed closure/custody/applicability. Whole-package approval never automatically covers altered subset |
| Process loss / accepted-but-unexported result | Re-establish actual selected custody and current verification at its real owner. Keep actual accepted state/known negatives/uncertainty; no file-based recreation of private W/Q/receipt authority or universal rollback |

An issued receipt's interval/seal is only one check. Every current use needs the
actual supported trusted instant, current source/status/role/accepted-history and
producer/target applicability checks. A cached admission's captured instant is
not a running clock. A receiver verifying a signed assertion issues only its
own exact verification assertion; preserving the claimed foreign origin does
not prove the original execution or import its private issuer association.

Implementation dependencies and execution prerequisites are different graphs.
Real deferred runner/observer bodies needed by an advertised S2 Scope must be
authored against S1 Types before exposing that Scope; defining them does not
invoke a method, require a captured project occurrence or import Scenario/init.
S4a/S4b are same-C execution/issuance/content integration and qualification stages,
not permission to publish a placeholder at S2 and implement it later. Actual
source-qualified recognition/operations are bound at trusted assembly; an incoming
C callback or candidate descriptor cannot choose the verifier. If those changes
require coordinated producer/capture/callable migration, S2-S4 form a coordinated
construction unit with no externally usable half-migrated Scope. Internal unit
work can proceed; the publication/capture exits are claimed only after their real
prerequisites exist. This prevents a Scope -> C -> method-definition -> Scope
bootstrap cycle while preserving the runtime requirement that methods consume C.

WP00 is a parallel qualification/repair lane through S0-S9, not a one-time green
checkbox before Types work. Start exact build/load and recovery diagnosis early;
qualify each actual changed source cut at its owner. No unchanged failed ordinary
restart is replayed for luck. Shared Aitia Types/Host factoring and finite custody/
recipient trust research may proceed alongside Library work, but live downstream
use waits for actual C/Q/R/authority prerequisites.

Avoid publishing half-migrated checked interfaces. Migrate active constructors,
Scope consumers, Profile/Scenario adapters and tests in dependency-coherent units;
retain historical artifacts as historical readers, without keeping a second
accepted implementation or compatibility facade. Required missing operations or
unsupported domains are explicit unavailable/gap results, never procedure-shaped
stubs. Existing source paths need no directory redesign to express this order.

248 design rows total. Per-lane instances and retries do not change the required
row inventory. Coverage must be keyed by document + control + declared lane,
including exact real test/filter/API/oracle/artifact/expected state; old fixture
SC identifiers cannot collide with WP03 SC requirements. Applicability is fixed
before execution and cannot shrink after a failure.

A passing negative control establishes correct refusal/retention at its scope,
not approval of the rejected claim. M06 and formal counter semantics remain
negative where observed. A complete positive operation is possible only when
its actual selected policy's premises are met or a genuinely permitted scoped
exception/resolution exists; this design grants neither. The requirement to
exercise rejection/defer/withdraw paths must not depend on a successful positive
technical verdict for those negative actions.

Source loading, actual compiled loading, new-process cold use, complete ordinary
restarts, intentional interrupted intake/repair and actual recipient use require
their distinct evidence as specified in 10.51. No static audit closes one of
these lanes. Optional scope choices are explicit predeclared policy decisions;
mandatory mechanism-conformance controls cannot be waived while retaining a
full-conformance label.
