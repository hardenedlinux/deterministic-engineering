* Scope, authority and prerequisites
:PROPERTIES:
:CUSTOM_ID: i2-scope
:END:

I2 unifies effective declarations, POO Types/Contracts, authored values, deferred
implementation binding and Core Scope publication in existing files. Library owns
reusable meaning; actual execution owners bind implementations; Core owns selection,
source/context/edge/final admission and currentness. Profile chooses advertised
capabilities and Scenario later binds actual project inputs into C. No declaration,
Config, callable or published model is itself a captured occurrence or an approval.

The target uses 10.83's sole Library generation owner and 10.90's K1/SD/S1. Earlier
10.43/10.67/10.77 proposals that put V1 in backpressure abstract/types.ss are refined
by 10.83; they are not parallel authorities. Historic revision strings/receipts remain
unchanged. No Namespace, filename or Module ID gains a contract-version suffix.

This is a source-grounded design update only. No source/model/package change,
construction workload, tool run, inference, build/load/acceptance/recovery,
publication effect or orchestration expansion occurs. Org/D2 checks and rendering
are document checks. The I0 compatible tuple and I1 runtime return-retention/load
qualification remain open prerequisites, not completed by specifying I2.

* Type ownership, effective fields and inheritance
:PROPERTIES:
:CUSTOM_ID: i2-types
:END:

Use actual POO Type/ObjectContract/Function composition and selected Yuanxu contextual
Contracts. Do not add a schema parser, universal builder, role registry, copied
validator or declaration interpreter. Field validation executes no external workload.
Compute the complete inherited field map before closed-field rejection; inspect
unknown semantic names before demanding getters. A child may add supported fields,
but cannot hide an inherited obligation or relax its expected family constraint.

| Existing Types owner | Target descriptor/shape responsibility | Dependency limit |
|-----------------------+----------------------------------------+------------------|
| library/project-organization/types.ss | LibraryDeclarationContract; common reference/revision/model/policy/method/capability shapes; OrganizationDeclarationContract, OrganizationModelContract, OrganizationConfigContract, OrganizationScopeContract and formation Profile expectations | Only qualified POO/Core primitives and neutral data Types; no authored objects, Module implementation, Config, Profile, Scenario or init |
| backpressure-memory/abstract/types.ss | BackpressureDeclarationContract; shared backpressure model/parameter/claim/premise/strength/input-demand shapes; BackpressureModelContract, BackpressureConfigContract and BackpressureScopeContract | Consume neutral Types, retain own family identity; no organization authored values or Rust implementation import |
| backpressure-memory/rust/types.ss | RustResourceModelContract, BackpressureIntegrationContract; sibling BackpressureReviewPolicyContract and BackpressureDesignReviewPolicyContract; mapping/delta/case/asset/Function and complete Rust Config/Scope refinements | Consume common/abstract Types; never import objects/methods/interface to discover expected meaning |
| modules/project-formation/types.ss | Effective method binding, Program/relation/source/output/limit, C-consumer request/result/view/plan/model-bundle operation Types; Formation Config/Scope expectations | Consume neutral/library declaration Types and actual generic ASCENT Types; no duplicate Library version, policy schema or application evidence issuer |
| Profile/Scenario/Aitia Types | Later selection/acquisition/C and review/authority refinements consume these exports | They do not redefine Library generation/model ancestry, invent methods or enlarge Aitia purpose/action domains |

Three graphs must remain distinct:

| Graph | Required relation |
|-------+-------------------|
| Declaration descriptor inheritance | LibraryDeclarationContract -> sibling OrganizationDeclarationContract / BackpressureDeclarationContract; each fixes its own family constraints |
| Model Contract shape refinement | Common model shape -> appropriate concrete Generic/Rust/Integration siblings; no Rust inheritance of Generic's fixed identity or parent=false predicate |
| Actual model values | Admitted Generic -> checked Rust -> checked Integration through actual POO prototype composition and explicit immediate parent; both associations agree |

Coding/design policy Contracts are sibling refinements of common policy shape.
Concrete policy values have parent=false; policy applicability is composition, not
model ancestry. Organization and backpressure can publish distinct applicable design
policy definitions under these shapes. Sharing a policy requires explicit supported
family/model applicability, not copied identities or a forced universal policy.

** Single version source and actual revisions
:PROPERTIES:
:CUSTOM_ID: i2-version
:END:

LibraryDeclarationContract in existing library/project-organization/types.ss owns
the sole authored contract-version=V1 value/constraint. Family descriptors inherit
that metadata through POO composition. Actual declarations/roles reference their
trusted expected descriptors; objects, Config, Module, Profile, Scenario, manifests,
Org and D2 do not own an independently editable generation field.

Read generation through admitted Scope -> expected role descriptor/family declaration
association -> inherited neutral metadata. A submitted contract slot, matching name
or V1 string cannot select its own validator or establish the original owner. Core
source/publication associations must agree with the actual expected descriptor.
The common declaration base must not fix one concrete model/family identity.

Preserve ownership-budget/v1, backpressure/v3 and backpressure-integration/v1 as
opaque existing semantic revision values, not Library V2/V3. Organization model,
policy/catalog/mapping and each method/program association require their own actual
source-authored semantic revisions before full publication. No new revision strings
are invented by this plan. Source hashes, Git pins, Core generations, document
revision and wire protocol tags are separate; missing revision blocks the relevant
complete capability rather than receiving a guessed default.

** Effective required field groups

These are target POO fields/relations, not a wire schema. Absence is explicitly typed.
References are inert identity/role/owner/revision associations; validating a reference
does not recursively execute referenced models, descriptors or methods.

| Role | Required fields / effective constraints |
|------+-----------------------------------------|
| Family declaration | identity, family, expected contract/role descriptors, inherited generation association, supported applicability and source owner; family identity fixed by expected refinement |
| Model | identity, role, family/declaration-ref, contract, parent, revision, lifecycle/rules/dependencies, premise/input/obligation demand, supported claims/strength/limits, assets/capabilities/method refs; child preserves inherited meaning |
| Organization definition | Model fields plus roles/allowed owners, owner categories, protected owners, product/content/duty/capability demand and supported mapping/catalog references; no acquired repo observations or candidate-specific winning allocation |
| Policy | identity, contract/family, parent=false, revision, applicability to model/slice/purpose, required criteria/products/duties/method strength, negative/conflict/causal applicability and responsibility/history/use/delivery conditions; no actual principal, adoption or grant |
| Method declaration | identity, revision, kind, actual supported model/policy/claim/mode domain, expected input/output Function Types, operation/provider reference, complete required input/premise/asset footprint and finite limits; program/catalog/mapping/validator references where relevant |
| Bound operation | Actual expected method definition, implementation owner/source/revision and admitted provider association, normalized Function, supported input/output meaning and mode. Actual execution/current-use evidence is separate |
| Catalog / model mapping | identity, revision, actual owner/asset refs, supported model/element kinds and qualified-name segments, definitions versus usages, dependency/reference closure, role/edge/obligation links, projection loss and supported validation profile |
| Integration mapping/deltas | Sole source-owned case/factor/claim links, observed-state/cut semantics and loss, typed guard/effect/frame/affected model/premise and required verification duties; no generic prose-to-transition language |
| Scope | Exact checked declaration/model/policy/catalog/method/Contract associations and supported actual bound operations, plus Core source/dependency/currentness lineage; no project selection or successful result synthesized by publication |

Finite method kinds remain application-reasoning, model-projection, content-observation,
implementation-execution, model-verification and theorem-check. Claim, execution,
validation, conclusion, control and current-use domains remain distinct as specified
in 10.83/10.77. Formation's design-reasoning purpose is not a new Aitia request
purpose. Object/candidate/product identities are open typed references within
supported catalogs; LIB-C01--C03, D01--D10 or case M01--M06 are not engine enums.
Unsupported semantic tags or cross-domain combinations refuse at their owner Type.

Keep one immediate parent field. Remove the live generic-entry/parent dual source
and the public integration factory when migrating callers. Integration is an object
role assembled within existing rust files, not a new directory or independent
Library family. Private pure composition helpers may remain; public extensibility
is the POO object/descriptor and checked Scope, not a second builder API.

The engineering child-to-parent state map is waiting->waiting, queued->queued,
cpu-running->active, result-pending->returned, cleanup->cleanup, released->released.
It replaces the current shorthand direction; observed Rust event/QNT running/done
mapping is separate. This declaration is not a proof of full Rust refinement.

One selected Integration owns mapping, deltas and exactly the six RL-M01/SI-M01/TM-M01
through RL-M06/SI-M06/TM-M06 associations and factors. correspondence.ss consumes
these values; remove its independent semantic case/factor/mapping authority and
cancelQueued transition literal as a second source of meaning. Keep bounded rendering
algorithms and independent native oracle expectations. A checker must not derive all
its expected answers from the same declaration/renderer and thereby become tautological.

The queued-cancellation delta declares queued guard, queued removal and cleanup
addition, with unchanged limit/queueLimit/admitted/running/returned/done frame. Its
own model/premise/duty links and projection loss remain explicit. Renderers refuse
unsupported semantics; no general transition DSL or synthesized proof engine is added.
Methods bind the actual generator/checker source footprint, not only mapping labels.

Policy combination is explicit applicable-set composition. Full Rust/design
DE-CASE-01 activity requires both relevant coding and design definitions. Formation-only
design activity can select its applicable design policy without claiming coding
qualification. Neither case discards inherited mandatory duties. The bounded M01--M05
worker-owned review and M06 investigation remain distinct; NASA class-a/SWE fixture
choices do not become universal Library policy or actual institutional attestation.

* Method, Program, model and catalog bindings
:PROPERTIES:
:CUSTOM_ID: i2-bindings
:END:

The logical Library/implementation distinction does not force a new directory split.
Rust methods can keep their implementation bodies in current rust/methods.ss and
pure correspondence algorithms in correspondence.ss. Their actual provider/issuance
operations follow I0's Core/Flow ownership. rust/func.ss privately assembles checked
deferred operations for rust/interface.ss; it does not publish an unbound global
ResourceMethods table as authority or issue results during declaration construction.

| Binding | Definition owner | Actual implementation/publication boundary |
|---------+------------------+---------------------------------------------|
| Generic/Rust/Integration meaning | Existing Library Types/objects | Explicit Generic Scope Parent edge and local checked construction; not inferred from algorithm behavior |
| Rust/QNT/Lean/SysML domain methods | Library method declarations and expected Function/claim/strength/input/limit Types | Existing Rust func/method/oracle/correspondence owners bind actual source and selected Core/Flow operations; bodies deferred until later same-C request |
| Application reasoning | Organization publishes inert expected provider/operation and semantic domain, without importing Engine values | modules/project-formation binds actual generic ASCENT Program, source/output/schema/codec/predicate/limit metadata and real reason operation |
| SysML materialization | Organization catalog and expected projection/mapping/validation declaration | Module binds actual supported selected-plan serializer/validator capability; later request carries C and accepted view. Pure render is distinct from validation and explicit Project publication |
| Content observation / review | Published required content/criterion/strength and operation expectations | Actual observer and Aitia/Host owner bindings remain separate; declaration validation cannot manufacture A/E/W/use, Q, R or role grants |

A supported method offering is not a current installed-tool attestation. I2 binds
the actual implementation provider, expected tool/validator profile and declared
input/asset requirements; Scenario later observes actual executable, environment,
resources and catalog bytes in C. Mandatory packaged assets must belong to the
qualified Library source/build closure, but field validation cannot certify their
content by reopening ambient files. Keep definition completeness, implementation
availability and actual invocation eligibility as separate claims.

Complete the Formation Module's existing requires with an explicit Library alias,
module-id project-organization and OrganizationScopeContract. Its core.exports binds
operations against that actual checked Library Scope. The Library's method reference
to provider project-formation is inert data, not a Core requires edge or import;
there is no Library -> Engine -> Library cycle. Scenario can still require Library
and Engine independently. It later corroborates their actual source/descriptor/
semantic revisions and bindings; consumer SD wrappers may differ, so raw Scope
pointer equality across edges is not the source-lineage test.

Module Config references the actual bound Program/operation definitions and finite
supported limits, not a second LR01--LR08 list. Extracting actual Program metadata
can be inert construction; it must not evaluate a fact batch. Program source/schema,
codec and input/output coverage are bound to the real implementation before C;
I3 captures that association, I4 supplies complete C-bound facts and performs inference.

The existing project.sysml and docs/10.78-case-organization.sysml are current Project
model assets, not automatically a reusable Library catalog. Catalog declaration
requires actual source-owned element/kind/name/reference and mapping semantics.
Project-specific companion bytes, actual architecture allocations and revisions are
later Scenario inputs when selected. Do not reclassify their captured facts as
Library definitions. A string such as DECaseOrganization is not an admitted catalog.
Missing actual catalog assets, semantic revisions or supported implementations block
full publication of that capability. A predeclared reduced design capability can
express missing/unimplemented support; a callable placeholder or label cannot claim
full method availability or quietly remove a mandatory capability after failure.

Config selects authored values, not its validator, parent source, arbitrary callback,
project revision, tools or grants. Reuse core.exports lowering and deferred linking;
current Core source/declaration.ss generates core.link and rejects authoring both.
No new linker, global initializer or Library cache is introduced.

The family declaration association and model entry are separate roles. Current
Organization declaration=raw ProjectOrganization is directly migrated; I3 consumers
read admitted model/catalog demand rather than preserving declaration.roles as a
second compatibility path. Map/asset/contract indexes may reference the same checked
definition objects; no Scope.mapping/delta/catalog row copy becomes another authoring
site. Supported offering keys are exact Types, not ad hoc optional extras.

| Construction boundary | Exact returned subject used next |
|------------------------+----------------------------------|
| Expected Config validation | Retain the normalized Config and its selected checked fields; no raw Config alias enters assembly |
| Generic final publication -> required Parent | Core retains provider S1; consumer alias receives I1's SD. Rust uses that actual Parent.entry rather than importing abstract objects or init |
| Role construction | Normalize Generic/Rust/Integration/policy definitions at actual boundaries; build descendants from returned checked predecessors, with coherent inherited obligations and immediate parents |
| Bound operation validation | Keep expected Function wrappers and actual implementation association; validate signatures/results without executing workload merely to publish a declaration |
| core.exports assembly -> bind-exports -> Scope admission | Assemble from these checked values; Core performs opt-in export binding then admits S0. Complete Scope value normalization precedes contextual cross-export association checks |
| Final S1 -> future dependent SD -> consumers | record.scope=scope-evidence.candidate; namespace facade.scope and selected-record.scope retain S1. Edge candidate is consumer-local; no Library precheck conceals I1 gaps |

Final Scope normalization can return another receiver or wrapped fields. References
inside effective descendants, policy applicability and bound operations must refer
to the final checked predecessor/definition fields through actual POO receiver-aware
rebinding. Do not assume validators are identity-preserving or repair relationships
by revalidating every referenced object, mutating parents, copying raw fields back,
or running another post-publication assembly. A mismatch must fail contextual
admission; a demonstrated primitive rebinding gap belongs to POO/Core qualification,
not a Library-specific graph repair layer. Verify preforced parent caches, shared
references and Function wrappers with nonidentity controls at all real boundaries.

Construction is once per actual successful linked Scope, not a global singleton or
exactly-once effect guarantee. New source sessions and package relinks have their
own admissions. Preserve lazy siblings, current source/Contract/wrapper read coverage,
I1's failure poisoning and no usable partial cache insertion. Apart from Core's mandatory source/admission/currentness guards, authored declaration assembly
performs bounded pure value construction/checking; it acquires no repository C,
reads no project tools, runs no Rust/QNT/Lean/SysML/ASCENT workload and grants no review.
