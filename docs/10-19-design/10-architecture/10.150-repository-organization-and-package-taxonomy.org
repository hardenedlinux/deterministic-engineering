* Decision
:PROPERTIES:
:CUSTOM_ID: org150-decision
:STATUS: design-only-not-implemented
:END:

The repository organization is a maintained Scheme declaration, not a convention
recorded only in prose. The existing =project-organization= Library already owns
nine responsibility roles and =project-formation= already renders =project.sysml=
from an ASCENT result. Neither reaches the physical tree: no directory, distribution
package or language asset appears in the rendered SysML model. This item adds that
physical layer and makes the actual tree an input checked by finite rules.

#+BEGIN_QUOTE
Directories and packages are checked placements of declared responsibilities.
They are not chosen by hand and then described afterwards.
#+END_QUOTE

The paired view is [[file:../../90-99-views/90-architecture-views/90.141-repository-organization-and-packages.d2][90.141 D2]]. The organization is declared in
[[file:10.150-repository-organization-and-package-taxonomy.sysml][the companion SysML model]]. Quint model content and tooling are a consumer of
this taxonomy, specified in [[file:10.151-quint-models-library-and-packages.org][10.151]]. Landing gates are in
[[file:10.152-organization-and-quint-landing.org][10.152]]. This item changes no source, build input or dependency.

* Placement definitions
:PROPERTIES:
:CUSTOM_ID: org150-placements
:END:

Each placement binds a path pattern, an ecosystem, the responsibility roles it
carries and content it must not contain. Roles keep their current identities.

| Placement | Path pattern | Ecosystem | Roles carried | Must not contain |
|-----------+--------------+-----------+---------------+------------------|
| =SchemeModule= | =library/<module>/= | Gerbil, Yuanxu | definitions, method-contracts, selection; refined by =tags:= | Process execution, TypeScript, other-language sources, generated output |
| =LanguageAssets= | =languages-engineering/<lang>/<domain>/<subject>/= | Native language toolchain | Maintained subjects checked by method plans | Scheme declarations, execution results |
| =DistributionPackage= | =packages/<pkg>/= with its own =package.json= | bun | Consumer-installable tools and artifacts | Source-of-truth declarations; another package's responsibility family; references outside its directory |
| =ProjectEntry= | =projects/<project>/= | Yuanxu selection | project-entry | Definitions |
| =UserExample= | =examples/= | Yuanxu Config | User Settings | Operations |
| =DevelopmentVerification= | =t/=, =t/support/= | gerbil test | Actual tool execution, independent gold, evidence registration | Product declarations |
| =DocumentItem= | =docs/<area>/<category>/<JD>-*.org= | Org | documentation | — |
| =ArchitectureView= | =docs/90-99-views/90-architecture-views/90.<n>-*= | render package | Projection of documentation | Authoritative claims |
| =PackageInfrastructure= | Root =gerbil.pkg=, =init.ss=, =build.ss=, =types.ss=, =config.ss=, =Justfile=, workspace =package.json= | — | Selection, build entry, shared vocabulary | Business declarations, package implementation |

=SchemeModule= keeps the flat tree of 10.148. Its =tags:= classify a leaf as
domain, specialization, method, rule, organization or profile; classification
never adds a directory level.

** Package responsibility families
:PROPERTIES:
:CUSTOM_ID: org150-families
:END:

A distribution package belongs to exactly one family. Its =exports= must not
cross families.

| Package | Family | Allowed | Rejected |
|---------+--------+---------+----------|
| =@deterministic-engineering/render= | presentation | D2/SysML figure compilation, composition, export, compression | Verification models, Quint content, check plans |
| =@deterministic-engineering/quint-models= | quint model content | Quint models by domain, check plans, projection receipts | Tool code, rendering, other-language models |
| =@deterministic-engineering/quint-modules-resolver= | verification tooling | Package-aware source resolution for official Quint | Model content; modification or redistribution of Quint |

* Declaration, rules and projection
:PROPERTIES:
:CUSTOM_ID: org150-rules
:END:

=project-organization= adds placement definitions and package families to its
catalog. =library-formation-profiles= declares this repository's placement
instances. =project-formation= receives the actual tree and each =package.json=
as input facts and adds the following finite rules.

| Rule | Rejection |
|------+-----------|
| OR01 single owner | A managed path matches zero or several placements |
| OR02 forbidden content | A placement contains its rejected content, for example =.qnt= or =.lean= under =library/*/= |
| OR03 package family | A =DistributionPackage= exports cross families |
| OR04 package closure | A package references a file outside its directory |
| OR05 reference closure | A Project selects an absent Module; =files= names an absent path |
| OR06 coverage | A responsibility role has no carrying placement |

The existing =render= method extends =project.sysml= with one part per placement
and package, their roles and dependency edges. =organization.sysml= gains the
placement =part def= declarations. Findings are design findings: they establish
neither capability, authorization nor acceptance of a candidate.

* Distribution by subtree
:PROPERTIES:
:CUSTOM_ID: org150-distribution
:END:

bun installs a git dependency from its repository root and cannot select a
subdirectory. Deterministic Engineering remains the only development repository.
Each =packages/<pkg>/= prefix is split by CI and published to a read-only mirror
whose root is that package.

| DE prefix | Mirror (created, empty) | Tag |
|-----------+----------------------+-----|
| =packages/render/= | =hardenedlinux/deterministic-engineering-render= | =render-vX.Y.Z= |
| =packages/quint-models/= | =hardenedlinux/deterministic-engineering-quint-models= | =quint-models-vX.Y.Z= |
| =packages/quint-modules-resolver/= | =hardenedlinux/deterministic-engineering-quint-modules-resolver= | =quint-modules-resolver-vX.Y.Z= |

- The root =package.json= becomes a private workspace over =packages/*=.
- Mirror commits record =DE-Source-Commit=; mirrors accept pushes only from CI.
- One DE commit can change Scheme sources, projected package content, documents
  and views together. Consistency is checked inside that commit.
- Render source already lives under =packages/render/=; its manifest and license
  files move into that directory and the first split retains history.

* Limits
:PROPERTIES:
:CUSTOM_ID: org150-limits
:END:

This is a design item. It does not add placement code, rules, packages, mirrors
or CI. It does not change the Module tree, the =programs= Config interface or any
dependency revision. Rule findings will be design assertions over captured tree
facts; they do not replace native build, test or remote CI acceptance.
