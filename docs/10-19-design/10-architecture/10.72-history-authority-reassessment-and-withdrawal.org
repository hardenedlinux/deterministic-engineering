* SPECIFIED Historical truth, authorized acceptance and current permission
:PROPERTIES:
:CUSTOM_ID: p7-history-authority
:STATUS: Source/design and static documentation only; no implementation, acceptance execution, review submission, withdrawal execution or delivery
:END:

P7 consolidates 10.61 against P0-P6. It consumes the same genuine C, complete accepted
Q, immutable R and actual P6 assessment/request/receipt/use associations. It discovers
required history H, checks the real principal and exact action authority, records an
accepted decision through actual custody, and checks fresh permission at each use.
A good technical result does not erase a denial. A verified proposal is not an
accepted record. An accepted record is not automatically a currently usable grant.

Library publishes reusable policy meaning, never appointments or project history.
Profile selects checked models/Integration and applicable coding/design policies.
Scenario captures project mandate, source and role inputs, then adapts actual source,
credential, publisher and change findings. Aitia owns generic discovery/authorization/
resolution semantics, Core owns pure graph and local verification primitives, and
actual custody/Runtime owners own acceptance, recovery and effects. No generic
approval flag, parallel ledger, receipt table or global revocation service is added.

Sole Library declaration generation remains V1, read from the checked declaration.
Stable Namespace, semantic revision, project/dirty revision, document revision,
accepted source cut and credential lifetime remain distinct. Historical signed
schemas retain their original interpretation; no relabeling into a new authority.

* SPECIFIED Required discovery and durable negative meaning
:PROPERTIES:
:CUSTOM_ID: p7-discovery-and-negatives
:END:

Actual adopted mandate/custody defines relevant technical failures/counters, decisions/
denials/exceptions/withdrawals, role/grant/key status and predecessor sources before
any candidate records are inspected. Submitter-selected favorable files, all-supplied
signatures-valid or an empty directory cannot establish a complete clean history.
Genuine initialization needs recognized no-predecessor/source mandate evidence.

Resolve actual current selections/closed prefixes, inventories, original signatures,
acceptance-time authority and lineage through qualified readers. Required unavailable
source, inventory-known missing negative proof, truncated/shrunk prefix, forked heads,
conflicting identities or missing predecessor leaves discovery incomplete/conflicting.
Retain known accepted records and intake diagnostics, but forged rejection text is
not an accepted denial. Old history remains immutable across policy/revision changes;
changes to relevance or source retirement need explicit qualified continuity/impact.

H is an observed bounded source vector, not instantaneous globally complete history.
Required consistency/freshness must be qualified at actual owners; bounded offline
grace is permitted only by adopted policy with explicit limits. At current use,
rediscover later relevant records. An old successful frame cannot hide a subsequent
accepted denial, withdrawn grant or source advance. A new policy label cannot reset
old unresolved denials or alter the original claim scope.

Accepted historical denial remains a denial through ordinary signer/verification
expiry; fresh verification may establish historical authenticity/inclusion without
pretending that old Core receipt is live. Targeted effective compromise, correction
or withdrawal follows actual policy and preserves original history plus its new status.
No untrusted denial is promoted merely to make the system conservative. Missing proof
for a known accepted record blocks required completeness rather than erasing it.

* SPECIFIED Proposal, acceptance and current-use operations
:PROPERTIES:
:CUSTOM_ID: p7-calls-and-acceptance
:END:

| Target operation / actual owner | Input -> result and boundary |
|---------------------------------+------------------------------|
| discover-history / source adapter + Aitia | Same C/Q/R, actual mandate/readers and independent source demand -> owned H/findings. No candidate directory/root override |
| verify-history / actual expected Host -> Core | Exact typed H/assertion/source selection/lineage/trust -> scoped verified finding/receipt or truthful incomplete/refusal. Completeness is a separate proposition from authenticity of supplied records |
| prepare-disposition / principal through thin adapter | Exact R/H/technical/roles plus action/target/conclusion/conditions -> inert typed proposal. Agent drafting neither appoints a reviewer nor submits anything |
| verify-disposition / Aitia + actual Host | Real credential/root/role/grant/delegation/quorum/status, exact action/target/stage and action-specific prerequisites -> finding/receipt or refusal. Select operation from checked Scope; candidate callback cannot grant itself authority |
| accept-disposition / actual custody owner | Exact verified proposal, expected prior selection and fresh basis/grants -> accepted immutable record/prefix or refused/unknown. Actual scoped serialization/durability and acceptance association required |
| verify-inclusion / Aitia + actual source/Host | Accepted record at actual returned head/prefix and original proposal/H0 lineage -> distinct inclusion assertion; equal proposal bytes/signature alone cannot establish acceptance |
| assess-authority-use / Aitia + actual Host | Accepted decision, current H2 and fresh P6 technical/role/status/receipt use -> scoped usable/blocked/unknown with limits. Runtime effect still requires its own exact authority/handoff |
| reassess / actual technical/content/Scenario/Aitia owners | Actual trigger/old basis -> affected current-use block, new observations/C/Q/R/H as required, then explicit resolution proposal/acceptance or remaining blockers |
| withdraw / authorized actor + actual target owner | Exact target/effective scope/authority -> accepted record and distinct real revoke/retire/status result. Retain pending dispatch and unknown effect; never claim global revocation from a local receipt |

Grant chains cannot widen parent action, target, scope, validity or redelegation
conditions. Reject cycles, ambiguous roots, unsupported conditions and false quorum.
Multiple keys/signatures of one principal count once. Real independence/role separation
is a policy fact, not different module/Agent names. Current positive permission needs
actual required context/content/technical/history/roles and allowed exceptions.

Authenticated reject/defer/withdraw has its own bounded target/source/authority
prerequisites and does not require positive technical success that it denies. It may
retain truthful incomplete technical basis and grants no positive permission. This
negative path does not waive authentic target binding, grant or action-specific
source coverage. Unavailable required negative-action authority stays pending/refused.

Decision proposal binds immutable C/Q/R and predecision H0. Actual acceptance yields
H1; later H2 verifies H0 continuity, real inclusion and all relevant subsequent records.
Never sign a future prefix containing the signature itself. Inclusion and later use
are new output assertions, not edits to Q/R/H0. If a later Q claims these records, it
needs a new accepted P5 projection; unchanged technical Q may remain historical input.

Expected-prior selection, fresh verified basis/grants, write/close/sign and publication
are serialized at actual custody scope. A hash comparison or rename is not proof of
cross-host CAS, crash durability or exactly-once effects. On competing source/grant/
head change refuse or prepare again; no last-file/timestamp winner. Known accepted
negative plus failed/ambiguous publication blocks that owner's positive use until
qualified recovery; no rollback to a favorable old frame. Rejected unaccepted proposal
remains diagnostic, not accepted history. After real acceptance, export/ack failure
retains actual state with unknown acknowledgement, not fabricated rollback.

* SPECIFIED Repairs, exceptions, replacement and typed withdrawal
:PROPERTIES:
:CUSTOM_ID: p7-resolution-and-withdrawal
:END:

| Transition | Required technical and authority consequences |
|------------+-----------------------------------------------|
| Supply missing evidence / technical repair | Actual new supported observation/use and old/new claim correspondence -> new Q/R as affected. Old failure/counter remains; a fix for M04 cannot repair M06 or unrelated document content |
| Resolve accepted denial | Qualified technical basis plus genuine current action authority and explicit accepted scoped resolution. Favorable W, reviewer summary or changed source hash alone cannot cancel denial |
| Request/accept exception | Policy permits exact unmet duty and bounded operation; actual risk authority/mitigation/conditions/expiry required. Retain false/unknown property and limits; no waiver of identity, authentic authority, truth or non-exceptable conditions |
| Use exception | Check current mitigation/status/scope/expiry and accepted authority. Exception does not prove the property or authorize unrelated deployment/receiver use |
| Supersede decision/exception | Explicit accepted predecessor IDs, compatible scope/lineage/impact and authority to replace each affected record. Exact allowed supersession action-target pair; forward/unknown/unrelated IDs or ID-list membership alone refuse |
| Resolution/exception withdrawn or no longer eligible | Re-evaluate live coverage; original denial blocks uncovered scope again unless another eligible accepted resolution covers it. History was never deleted |
| Withdraw receipt/evidence-use/grant/decision/exception/publication/adoption/owner | Dispatch to actual issuer/producer/trust/decision/custody/receiver owner with exact target/effective scope. Local private revoke, accepted project withdrawal and remote current-use consequences remain distinct |

Use existing Core cycle/dependency algorithms on authenticated scope-correct edges;
graph topology authenticates nothing. Supersession must be acyclic and unambiguous.
Partial resolution covers only its explicit compatible scope; remaining denial or
veto stays live. A veto retains its actual principal/role, accepted rejection record,
protected scope, policy condition and permitted resolution authority; it is not an
extra action enum or a public blocking flag. An ordinary approval quorum cannot
override a policy-protected veto without that exact authorized resolution route.
Concurrent approval and denial remain visible until policy-qualified resolution,
not majority of green receipts or lexical latest. If required conditions
cannot be compared, preserve conflict/unknown rather than fabricate precedence.

Restoring bytes, repairing storage or a new receipt does not revive revoked private
issuance, retired owner or withdrawn authority. Fresh verification/authorization may
establish a new current association while original records remain. Archive recovery
requires actual selected closed prefix/origins/trust/lineage, fresh reader activation
and predecessor retirement at qualified custody scope. Authorized exact prefix repair
preserves accepted signed bytes/records/negatives; it is not a semantic repair, grant
or replacement decision. Replayed repair authorization/old head after source advance
refuses. Process-private receipts cannot be reconstructed from the restored archive.

* SPECIFIED Causal assumption change through evidence, review and authority
:PROPERTIES:
:CUSTOM_ID: p7-causal-reassessment
:END:

Assumption identity/source/claim/domain belongs to selected model/criterion/project
basis; status comes from an actual qualified check at a declared cut. Retain original
premise -> check/impact -> W/target U/required K -> Q/R -> decision condition/use
links. A public trigger name or graph edge is not authenticated impact. Core traversal
can compute closure only after edges are qualified; incomplete closure requires
conservative whole-relevant-basis blocking/revalidation, not guessed selectivity.

| Actual trigger | Required response and retained limitation |
|----------------+-------------------------------------------|
| Identification/isolation/interference prerequisite demonstrably violated | Block affected empirical causal use at its real currentness owner; preserve original W and diagnosis. No zero-effect conclusion or invented opposite W |
| Premise evidence unavailable/stale/check unfinished | Support/use is unestablished at required scope. Missing data is neither proved violation nor a waiver; keep required unit and pending reason |
| Comparable qualified contradiction | P4 records actual counter, P5 retains both bases/conflict, P6 review preserves it, P7 blocks unresolved positive permission according to actual policy. Different model/formal/empirical scope is not automatic contradiction |
| Population/environment/measurement/data/model/transport changes | Qualify changed applicability and actual impact/identification; new C/Q/R or use as affected. A model title, revision string or unchanged estimate does not establish transport |
| Actual uncertainty/robustness condition no longer satisfied | Record exact selected condition and observed finding/limits; reassess affected criterion/decision use. No invented effect interval or universal invalidity from a heuristic |
| Actual repair/new design/experiment supports prerequisite | New method/content observation/use and current interpretation -> new Q/R if affected; rediscover H and obtain any required accepted denial resolution. Assumption recovery alone does not cancel denial |
| Grant/role/history/custody fails with unchanged estimate | Block exact authority/use independently of causal validity; technically sound estimate cannot supply missing permission |

Operational route: qualified observation -> actual affected binding -> immediate
policy-defined technical use block/unestablished finding -> preserve diagnosis and
negatives -> actual P4 recheck -> appropriate P5 Q/P6 R -> current H -> authorized
resolution if required -> real acceptance -> fresh technical/authority use. Automatic
eligibility loss is not an automatic signed withdrawal: only a genuinely authorized
policy operation can issue the latter. A future automation must have an actual bounded
delegation; an Agent event handler cannot invent it.

Captured meaning/selection/project/mandate changes require successor C. Changed
technical evidence/obligations/query meaning requires new Q/R. History-only inclusion,
status or unchanged-grant validity can retain original C/Q/R with new H/use; any Q
asserting that history itself needs a new projection cut. Never mutate W/C/Q/R/H or
rerun unrelated Rust/QNT/Lean/SysML merely to rediscover decisions. Independently known
invalidation blocks use even if the ASCENT transaction publishing it fails.

For the network retry example, concurrent scaling can invalidate an isolation premise
for a latency-effect claim without refuting formal ownership or proving zero retry
effect. For DE-CASE-01, preserve E06/I04 -> T03 -> DE-D04 as the first source/capture
impact chain; its source assumptions trigger actual architecture/capture review, not
an invented latency estimate. Actual roles, empirical data and identification routes
remain unqualified. The paper is a research object: full versus selective revalidation,
causal assessment quality and simpler scoped authority designs need matched comparison.
Sound invalidation/negative retention are correctness requirements; superiority or a
minimal affected set is unproved unless separately qualified and explicitly required.

* SPECIFIED Replay, failures and downstream use
:PROPERTIES:
:CUSTOM_ID: p7-replay-and-custody
:END:

Same original verified read assertion may be reused only with P6 fresh Host clock,
source/role/status checks and exact receipt association. Equivalent normalized request
meaning need not have identical physical request identity. Changed R/H/action/target/
stage/conclusion/conditions/grant cannot replay the old assertion. Core admission is
fixed at its checked instant; old preflight cannot establish current decision use.
Ordinary verification reuse and repeat acceptance/effect execution are different.

A retried acceptance checks actual selected history and operation/proposal identity:
if the exact record was already genuinely accepted at the expected lineage, report
that original inclusion without a duplicate decision/effect; if completion is unknown,
recover actual state or remain unknown. Reusing a key with different content refuses.
Actual custody/Runtime must qualify this behavior under concurrency/recovery; P7 does
not invent a global exactly-once database or infer it from a file name/signature.
One accepted review decision never acts as a distribution/adoption/use replay token.

Source/Host loss, foreign archive or copied JSON/signatures cannot recreate private
Core authority. Reverify actual portable provenance, historical acceptance and current
mandate through qualified local operations, producing new local associations or gaps.
Accepted decision, private receipt, delivery/receiver effect and acknowledgements are
different owners' states; no multiowner atomic rollback is implied. Preserve every
known accepted counter/denial and exact unknown/pending effect on recovery.

P8 consumes original C/Q/R, actual accepted decision/inclusion, current authority-use,
H/source vector, exception conditions/limits and unresolved negatives with delivery
purpose/recipient binding. Recipient rechecks local mandate/applicability/status; no
instantaneous global withdrawal or permission from serialized producer approval.
P9 qualifies the actual source/compiled/cold/recovery/effect routes separately.
