* Result and implementation boundary
:PROPERTIES:
:CUSTOM_ID: a3-scope
:END:

A3 projects one admitted C and separately recognized current-use/findings into a
complete application-controlled source batch, evaluates the actual selected ASCENT
program, and returns an owned, bound consequence view. Every candidate, conflict,
gap, invalidation and evidence limit remains inspectable. Declaration assertions
and trusted observations have different sources and derivation paths. Neither an
ASCENT result nor a structurally eligible model grants execution or review authority.

This is the complete target for the formation reasoning boundary, coordinated with
10.70's later resource-evidence projection. It does not replace that full C/A/E/W/use/Q
contract or claim that a formation result is already Aitia-ready Q. Proposed relation
changes and operation expectations below are design only: no implementation, package,
model, inference run, acceptance or automatic orchestration is changed or executed.

Use one capture and one selected program binding per private Session. All source rows
belong to that prepared request; no implicit mixing of projects, captures or method
semantics through equal IDs. References encoded into primitive rows have an immutable,
bounded association to actual admitted values in that prepared projection. This is a
local codec, not origin authentication or a public registry; unknown/foreign handles
refuse. Copy mutable strings/containers as required. Native row-spine copying is not
ownership of arbitrary nested host objects.

Derive mandatory roles/products/duties/coverage units and input multiplicities from
selected definitions/policies before candidate offers or available outcomes. Each
required input is represented by an actual binding or a permitted typed gap. Complete
accounting may correctly conclude missing support; it does not mean every input was
available or every requirement passed. Unsupported projection/reader domain prevents
a complete claim; supported partial variants retain exact limitations.

The application supplies every controlled source exactly once, explicitly empty
when appropriate. Compare that set to actual Program source-handles and the expected
application schema. Labels alone, table counts or finished=true cannot establish
coverage. Coverage validation also checks joins/keys/required-unit expansion; merely
listing every relation name cannot detect a deleted duty or swapped source row.
Closed-world negation is sound only for the accounted declared finite domain. It
never proves that an unobserved repository obligation or contrary finding does not exist.

Fresh Sessions are sufficient for the current synchronous slice. If the same bound
operation retains a Session for later current-use cuts, require qualified single-writer
serialization and replace the entire application-controlled batch, including explicit
empty current-status/use relations. Native reentry rejection is not a multi-writer
lock. A different C, rule/schema/codec/predicate/provider meaning needs a new qualified
binding/Session; changed captured method/selection meaning needs an appropriate new C.
No update smuggles new proposals or definitions into an old sealed capture.

For each use, select its expected required check/status cut at the trusted operation
boundary. Eligible current use needs that actual check, complete compatible footprint
and required premise/strength basis, with no applicable blocking or contradictory
finding for the same use. Missing status means unestablished, not eligible. Do not
join one favorable historical check while ignoring the required newer check. Distinct
valid positive and refuting uses can both remain recognized observations; their unit
has an evidence conflict and cannot become an unqualified successful conclusion.

LR01--LR04 and LR06--LR07 keep domain responsibility/structural/basis meanings.
LR05/LR08 derive only declared condition outcomes after the explicit naming change.
Adding trusted support is a separate admitted-input/rule path with its own required
units and checks. A forged trusted? flag is rejected before projection, not interpreted
as a new kind of support. A valid missing/negative use finding remains inspectable.
An unknown status or unsupported semantic pair refuses at its expected Contract.

A captured source assertion can support the narrow claim that this declaration was
observed; it does not prove the declaration's proposition. A genuine capture-origin
receipt proves only its precise operation assertion. A method witness proves only
its bounded claim; QNT state exploration is not Rust refinement, and SysML language
validation is not implemented architecture or review approval. Aitia authorization
and runtime effects remain independent later owners.

The structural baseline from 10.80 remains historical: eight conflicts, 34 gaps,
nine role nodes, eleven edges and four open capability gates for LIB-C01. The old
synthetic all-established control proves only the declared condition. Target tests
preserve those structural semantics over matching declared inputs, while separately
checking new origin/coverage/evidence outputs. Expanded schema/coverage does not
inherit old counts or the fixed 4096 bound's adequacy without qualification.

Where required, the actual operation performs its final current-use/source guard
before exposing a current-use claim, and later consumers check their own effect
boundary again. A native successful return cannot make that external condition
permanent. Public view metadata or Type conformance alone is not producer recognition:
consumers need the actual operation's retained accepted association, never a forged
rows-of object or a digest presented as issuance. Missing qualified recognition blocks
the trusted handoff rather than adding a project-local result issuer.

Existing native result methods detach row spines; mutable payloads still require the
selected primitive codec's ownership rules. Public relation metadata and rules/rows
recorded explanation are useful diagnostics, not per-row proof or execution authority.
The explanation function itself says recorded-only. Required trace links must connect
actual projected origins and limitations; do not label a dependency list a causal proof.

If callback, bounds, predicate, evaluation or final native checkpoint fails, publish
no new application view. A retained Session keeps its prior accepted sources/result
under the native contract; preserve failure diagnostics separately. If final view
freezing/admission fails after Session adoption, do not claim native rollback: expose
no half-view and retain the actual accepted native result with the application failure.
No shadow fact database or generic two-phase commit engine is needed.

The supported route is synchronous and explicitly bounded. Actor/async/parallel
Session surfaces are not substitutes without their own negation/callback/serialization
qualification. Program source predicates/providers/codec must have the recorded
supported stable meaning; finished=true cannot excuse unobserved host IO or mutable
callback state. Do not increase heap/time/fact limits or truncate rows to obtain pass.

* Invalidation, refresh and retained history
:PROPERTIES:
:CUSTOM_ID: a3-invalidation
:END:

| Change / boundary | Required response |
|-------------------+-------------------|
| Current confirmed intent differs from candidate's original basis | Keep candidate/proposal lineage, derive invalidated and its reason; no materialization from invalidated alternative. A newly captured confirmed intent keeps old proposal basis rather than rewriting it |
| Role/product/input/plan demand is missing or incompatible | Preserve independently required units plus exact gaps/conflicts. A deletion of catalog definition that makes the projection malformed refuses instead of making demand disappear |
| C's captured selection, source meaning, policy/model/method revision or candidate/plan meaning changes | New actual selection/acquisition/C and program binding as required. Old result remains a conditional historical consequence, never relabelled current |
| Origin lease/revocation, live source/status or qualified-use check changes with unchanged C | Block affected current reliance immediately at real owner; preserve C and old evidence history. Re-project complete fresh use/status/findings cuts only where actually recognized; do not union old eligible rows into current sources |
| Premise/causal applicability is refuted, changed or unknown | Carry exact premise/check/impact and affected unit/use lineage from qualified owners; retain support and contrary findings and block invalid uses. No global assumption truth or minimal unaffected cone inferred without supported dependency coverage |
| Refresh transaction fails after external invalidation | Native prior view may remain available historically, but its current use stays blocked by the live owner guard. Session rollback cannot roll back revocation or restore truth/authority |
| Program/rule/schema/predicate/provider/codec/load source changes | Refuse stale binding, qualify new semantics and Session; bind an appropriate new C if captured method meaning changes. Same textual program ID/digest alone is not reuse proof |

If impact/dependency coverage is incomplete, report uncertainty and conservatively
revalidate/block the affected supported scope. Do not invent precise minimal ripple
results or causal efficacy. Current-use freshness is separate from deterministic
logical consequences of a fixed admitted batch. Old snapshots and negative findings
remain at their original cuts even after successful repair/replacement.
