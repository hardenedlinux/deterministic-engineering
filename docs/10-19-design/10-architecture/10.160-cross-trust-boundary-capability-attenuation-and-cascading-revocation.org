* Problem: Confused Deputy & Privilege Laundering in Multi-Hop Agent Supply Chains
:PROPERTIES:
:CUSTOM_ID: cap160-problem
:STATUS: implemented-verified
:END:

When a Coordinator AI Agent delegates subtasks across organizational or tool
boundaries (Coordinator -> Contractor Agent -> Third-Party MCP/Tool Worker),
ambient-authority or stateless-JWT authorization fails along five classic
capability-security axes (Hardy 1988; Miller/Yee/Shapiro 2003; Birgisson et al.
NDSS 2014):

1. *Blank-Check Forwarding (Confused Deputy)*: Forwarding a parent's broad =M3=
   token to a narrow leaf tool lets a prompt-injected sub-agent wield root
   ambient authority.
2. *Caveat Stripping & Scope Escalation*: A compromised intermediate agent tries
   to widen =read -> write=, escape path prefixes (=/src/parser -> /src/parser-evil=),
   extend TTL, or re-delegate past =remainingHops == 0= / =delegatable == false=.
3. *Bearer Theft*: A sibling agent steals and presents a peer's certificate
   under a different caller identity.
4. *Orphaned Zombie Subtree After Ancestor Revocation*: Stateless leaf tokens
   keep executing even after an intermediate contractor is revoked.
5. *Delegation Chain Wash & Root Key Leak (=R3=)*: Multi-hop logs lose upstream
   custody attribution, or a root HMAC signing key leaks into =M1= storage.

* Stratified OP × Macaroon Capability Architecture (Scenario B3)
:PROPERTIES:
:CUSTOM_ID: cap160-architecture
:STATUS: implemented-verified
:END:

| Governance Primitive | Stratification & Cryptographic Mechanism | Security Invariant |
|----------------------+------------------------------------------+--------------------|
| Non-Serializable =DelegationRootKey= | Branded with =M3_NON_SERIALIZABLE_CAPABILITY= (=R3=); =toJSON()= throws | Root HMAC key can never enter =M1= Merkle persistence |
| Macaroon HMAC-SHA256 Caveat Chaining | =childMac = HMAC(parentMac, canonicalChildCaveats)= stored in immutable =M1= Merkle DAG; verified in constant time (=timingSafeEqual=) from live =M3= root key | Any holder can narrow offline without the root key; any caveat stripping/tampering fails verification |
| Monotonic Attenuation Meet | Segment-boundary-safe =isPathWithinPrefix=, action subset, non-increasing TTL, strictly decreasing =remainingHops=, =delegatable= lock | Zero privilege amplification across hops (=escalationViolations == 0=) |
| KeyKOS/EROS Cascading Revocation | Live =M3= caretaker registry checked against *every* ancestor certificate & principal along root -> leaf at consumption time | Revoking =Contractor-A= instantaneously invalidates downstream =ToolWorker-C= while leaving sibling =Contractor-B= intact |
| Immutable =M1= Chain-of-Custody Receipt | Every authorized execution pins =custodyLineage= (=[root, ..., leaf]=) into =M1= Merkle store | Zero-wash cross-organization forensic attribution |

* Limits
:PROPERTIES:
:CUSTOM_ID: cap160-limits
:STATUS: implemented-verified
:END:

Macaroon HMAC chaining proves cryptographic integrity against any external party
lacking the =M3= root key; for fully decentralized cross-organization verification
where the verifier cannot share a symmetric root key with the issuer, production
deployments should substitute asymmetric signature chains (Ed25519/UCAN/Biscuit)
preserving the exact same =M1= Merkle custody and live =M3= cascading revocation model.
