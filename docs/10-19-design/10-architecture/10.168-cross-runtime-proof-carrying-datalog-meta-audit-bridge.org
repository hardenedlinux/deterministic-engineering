* Purpose: N-Version Proof-Carrying Governance Across Imperative and Declarative Runtimes
:PROPERTIES:
:CUSTOM_ID: bridge168-purpose
:STATUS: implemented-verified
:END:

In safety-critical systems (Avizienis 1985 N-Version Programming; Necula POPL
1997 Proof-Carrying Code), relying on a single imperative coordinator risks
silent logic bugs or subtle tampering passing unnoticed. Document [[file:10.167-durable-ai-governance-research-synthesis-and-declarative-datalog-meta-audit.org][10.167]]
introduced the declarative Gerbil Scheme ASCENT Datalog meta-auditor
(=DurableGovernanceMetaAuditProgram=). This document completes the live
cross-runtime bridge ([[file:../../../languages-engineering/ts/defense/agent-audit/ascent-meta-audit-bridge.ts][ascent-meta-audit-bridge.ts]]):

1. *Zero-Handwriting M1 Fact Projection*: =extractMetaAuditBundleFromLiveObjects=
   projects live TypeScript =B1=–=B9= governance objects (=DelegationCertificate=
   chains, =MemoryBeliefNode= graphs, =TaintedValue= derivations, Ed25519
   =SignedTreeHead= observations, release proposals, Saga pivot flags) into an
   immutable =M1= content-addressed =MetaAuditFactBundle= and injection-safe
   Scheme S-expression alist.
2. *Live Gerbil Scheme ASCENT Subprocess Oracle*: =runLiveGerbilAscentMetaAudit=
   streams the S-expression bundle via =stdin= to the compiled Gerbil Scheme
   runtime (=gxi=), evaluates =reason-durable-governance-meta-audit=, and parses
   the framed JSON response.
3. *Fail-Closed Cross-Language Agreement Gate*:
   - If a buggy or compromised TypeScript coordinator claims =ADMIT= while the
     independent Scheme Datalog oracle disqualifies the release, admission is
     refused (=oracle-disagreement-fail-closed=) and a forensic receipt is pinned
     in =M1=.
   - If the external Gerbil binary is absent or emits malformed output, the gate
     fails closed as =PendingMethod= / =SetupDefect= (never masking missing
     verification as =ok: true=).
   - Only when *both* heterogeneous engines agree =ADMIT= is an immutable =M1=
     =DualOracleAdmissionReceipt= pinned across GC.

* Limits
:PROPERTIES:
:CUSTOM_ID: bridge168-limits
:STATUS: implemented-verified
:END:

Running the live Scheme oracle subprocess requires the compiled Gerbil runtime
and =.gerbil/lib= artifact tree; in Bun-only environments lacking Gerbil, the
bridge deterministically surfaces =PendingMethod= rather than silently admitting.
Production high-throughput deployments should host the Gerbil ASCENT oracle as
a persistent local IPC/socket sidecar rather than spawning one =gxi= process per
release.
