** Concrete abstraction hazards

The progress model declares inflights as a set of last-entry indices. Its own
comments identify loss of duplicate-index behavior and ring-buffer implementation
details. ~AddInflight~ uses set union; ~FreeInflightsLE~ retains indices greater
than an acknowledged index. A cardinality bound on this set is insufficient to
check repeated retries consuming distinct resources under the same business key.

~InflightsMonotonicInv~ checks maximum >= minimum for a nonempty set; it does not
establish that successive additions strictly increase. The source comments also
recognize that ordering of additions is temporal. The gateway must instead track
unique attempt/incarnation identities, event order and explicit resource ownership.
A set of those unique owners can be suitable; a set keyed only by request or
payload index can silently merge real allocations.

The historical log identifies random simulation and a ~ProgressSafety~ failure in
the initial state. Its paths/name differ from the checked-in MC wrapper, and the
wrapper's active invariant list differs from the log's aggregate property. Without
source/config hashes and an exact diagnostic, classify it as historical model
counterevidence with unresolved binding. It is neither a current source bug nor
an exhaustive completed result for the archived configuration.

** Harness assumptions exposed by source inspection

The harness supports skipping expected-output validation; empty expected blocks
also bypass comparison. It warns when tracing hooks are disabled and then may
produce empty NDJSON, while metadata writes a declared build-tag list. Therefore
completion text and tag metadata alone cannot establish tracing or validation.
A qualified replay must bind actual build options, enabled hooks, nonempty expected
observations, selected scripts, all validation settings and process completion.

The source uses reflection/unsafe access for a RawNode field and requires an
instrumented raft tree. These are version-specific dependencies. The relative
~../raft~ replacement and ~testdata~ scripts are missing here. Record those as
replay prerequisites, not evidence that the archived code has been compiled or
that the missing paths are available under a modern upstream version.

* Formal task: exact progress claim and premises
:PROPERTIES:
:CUSTOM_ID: selected-proof-task
:STATUS: inspected-no-proof-run
:END:

Sources: [[tlaps:benchmark/proof-from-scratch-module/manifest.json][module manifest]], [[tlaps:benchmark/proof-from-scratch-module/etcd_raft/etcd_raft.tla][target]],
[[tlaps:benchmark/proof-from-scratch-module/etcd_raft/etcd_raftDefs.tla][definitions]], [[tlaps:benchmark/proof-from-scratch-module/etcd_raft/etcd_raftModel.tla][transition model]],
[[tlaps:tests/fixtures/etcd_raft/CommitProgress.tla][finite witness fixture]], [[tlaps:tests/dataset/test_etcd_progress.py][positive/adverse controls]].

The target quantifies a leader l, a quorum Q of the initial server set and every
positive natural index n. It states that ~LiveSpec(l,Q,n)~ implies
~CommitProgress(l,n)~. The latter eventually reaches a suffix where a current-term
entry at n leads to that leader's commit index reaching n. It is not unconditional
availability, leader election progress, or a bound on response latency.

#+NAME: formal-premise-register
| Premise/action | Meaning in the selected definitions | Gateway adaptation boundary |
|----------------+-------------------------------------+-----------------------------|
| Spec | Init and stuttering Next with modeled faults | Define gateway Init/Next separately; do not import Raft state |
| StableReplication | Eventually a stable leader/term and restricted quorum faults/actions | Explicit eventual service/cleanup stability assumption, if required |
| Ready weak fairness | Persistence work is eventually taken when continuously enabled | Resource/cleanup executor fairness needs its own action-level meaning |
| Send/self-append weak fairness | Continuously enabled replication work is not starved | Per-attempt queued/cleanup work cannot rely on aggregate worker fairness |
| Receive/ack strong fairness | Recurrently enabled relevant message classes are processed | Preserve strong versus weak distinction if claiming corresponding progress |
| Commit weak fairness | Continuously enabled commitment is eventually advanced | A fair scheduler cannot compensate for a no-op completion transition |
| CurrentTermEntry | The progress antecedent is actually present | Show a reachable admitted request/owned resource trigger |

The finite fixture starts from real model election and requests, then explores a
restricted continuation. It checks non-vacuity and a deterministic fair witness.
The test source enumerates entry indices 1/2 and progress, witness, unfair and
fault variants. Removing commit weak fairness or replacing commitment with a no-op
expects a temporal-property violation. These are read test expectations, not new
results; their finite scope is not the quantified theorem. The target contains
~PROOF OMITTED~ in the shipped task, so the task file itself is not a proof artifact.

The selected unit belongs to a nine-unit module. A one-unit derived evaluation
must record an explicit selected-unit scope and validated dependency closure;
it cannot be reported as a whole-module TLAPS pass or compared to nine-unit totals.
The source digest in the manifest hashes the original source specification,
verified locally as an identity check. It is not the raw generated-target hash.

* Gateway semantic correspondence
:PROPERTIES:
:CUSTOM_ID: gateway-correspondence
:STATUS: proposed
:END:

#+NAME: reference-to-gateway-map
| Reference concept | Gateway concept | Property to preserve | What is not transferred |
|-------------------+-----------------+----------------------+-------------------------|
| Inflight replication message | One locally resource-owning upstream attempt | Unique ownership, acquisition/release and cap | Raft log ordering or business idempotency |
| Replication ack / FreeLE | Confirmed local transport termination / release | Release must have an owned attempt and correct incarnation | An ack is not arbitrary cancellation, and timeout is not remote stop |
| Progress reset / snapshot transition | Retry/transport teardown or process incarnation transition | Old callbacks cannot release a new owner's permit | Resetting local state does not revoke remote execution |
| Model-to-trace matcher | Gateway event-to-transition correspondence | Ordered pre/post states and allowed stuttering | Finite trace acceptance is not universal source refinement |
| Stable-period replication progress | Conditional queue/cleanup progress | Reachable antecedent plus sufficient action fairness | No quorum or Raft leader is invented in a local gateway |
| Persisted model state | Durable evidence/operation record where required | Distinguish retained versus volatile state | No automatic exactly-once effect or authenticated persistence |
| Fixed theorem context | Fixed gateway claim/assumptions/methods | Agent cannot silently weaken the target | Reviewed design revision is a separate lifecycle result |

Define the new gateway model in QNT with typed attempt/replica/epoch state and
explicit resource accounting. Use TLC through the established Quint compilation
and checker path, retaining generated artifacts as derived evidence. Lean covers
parameterized laws and justified proof transport. Equal TLC verdicts on a TLA+
reference and QNT output are useful correspondence controls, not independent
validation of their common backend.

The small gateway reference semantics should enumerate attempt records and count
actual owned resources independently of a free-counter implementation. A separate
trace validator checks guards, event identities, pre/post state and allowed
stuttering. Human-reviewed contracts and threat cases define expected obligations.
No oracle derives its expected answer from the same R01-R15 rule output it grades.
