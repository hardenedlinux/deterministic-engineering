* Purpose & Scope
:PROPERTIES:
:CUSTOM_ID: study4006-purpose
:END:

Modern polyglot verification repositories combine heterogeneous toolchains
(*Quint + Apalache MBT*, *Lean 4 / Lake*, *Gerbil Scheme / Fun-Flow*, *Rust /
Cargo*, *Go 1.26 -race*, *C / CBMC*, *C++20*, and *TypeScript / Playwright*).
As the model fleet grows toward hundreds or thousands of subdomains and models,
naive CI pipelines fail in two opposite directions:

1. *Cold-Rebuild Explosion*: Re-downloading package ecosystems, browser
   binaries, and Lean toolchains on every push while running the entire model
   fleet serially in one job stretches CI latency linearly ($O(N)$) and wastes
   runner compute.
2. *Unsound or Conflicting Caches*: Naive =actions/cache= configurations
   introduce *stale false-hit poisoning* (under-specified keys omitting engine
   or transitive dependency digests), *cross-shard write-write collisions*
   (parallel matrix jobs racing on a shared immutable key), and *10 GiB quota
   ratchet eviction thrashing* (append-only cache files growing unboundedly
   until GitHub Actions LRU evicts healthy base caches).

This study establishes the formal foundations (=SM18=), proves their unbounded
invariants in Lean 4, and applies them as a **live production case study** to
this repository's own CI/CD ecosystem (=.github/workflows/*.yml=,
=packages/quint-modules-resolver/=, and =t/harness/verify-framework.ts=).

** Layer 1: Read-Mostly Immutable Toolchain & Ecosystem Caches

Layer-1 caches contain *only* external packages, compilers, and browser binaries
keyed strictly by =(runner.os, runner.arch, toolchain/lockfile hash)=:

| Ecosystem | Cached Path(s) | Exact Immutable Key | Invalidation Trigger |
|-----------+----------------+---------------------+----------------------|
| Bun Workspace (=.github/actions/setup-bun-cached=) | =~/.bun/install/cache= | =de-bun-v1-${os}-${arch}-1.3.11-${hash(bun.lock)}= | =bun.lock= or Bun version change |
| Go 1.26 (=-race= / =synctest=) | =~/go/pkg/mod=, =~/.cache/go-build= | =de-go-v1-${os}-${arch}-1.26-${hash(go.mod, go.sum)}= | Go version or module graph change |
| Rust / Cargo | =~/.cargo/registry=, =~/.cargo/git=, =.../target= | =de-cargo-v1-${os}-${arch}-${hash(Cargo.lock)}= | =Cargo.lock= change |
| Lean 4 / Elan Toolchain | =~/.elan/toolchains= | =de-elan-v1-${os}-${arch}-${hash(lean-toolchain)}= | =lean-toolchain= version bump |
| Playwright Chromium | =~/.cache/ms-playwright= (Linux) / =~/Library/Caches/ms-playwright= (macOS) | =de-playwright-v1-${os}-${arch}-${hash(bun.lock, packages/render/package.json)}= | Playwright version bump in lockfile |

** Layer 2: Shard-Scoped Cryptographic CAS Verification & Incremental Build Caches

Layer-2 caches separate *GitHub Actions transport keys* from *per-unit
cryptographic soundness*:

1. *Dynamic Zero-Hardcoding Shard Discovery*:
   =just verify-matrix quint= (=t/harness/verify-framework.ts matrix quint=)
   discovers every subdomain under =packages/quint-models/<domain>/<subdomain>/=
   automatically and deterministically bin-packs them into balanced parallel
   matrix shards (e.g., =engineering-concurrency=, =engineering-defense=,
   =engineering-consensus-plus-3=, =threat-execution-plus-2=,
   =threat-supply-chain-plus-1=). Adding a new subdomain requires **zero**
   changes to =.github/workflows/quint.yml= or =Justfile=.
2. *Strict Shard Namespace Disjointness*:
   Every parallel shard writes exclusively to its own immutable transport key:
   =de-quint-cas-v1-${os}-${arch}-${matrix.shard}-${engineHash}-${github.sha}=
   with shard-scoped restore prefix
   =de-quint-cas-v1-${os}-${arch}-${matrix.shard}-${engineHash}-=.
   Because =${matrix.shard}= and =${github.sha}= are embedded in the key:
   - Parallel shards **never collide** when saving caches.
   - An upgrade to =packages/quint-modules-resolver/src/**= or =bun.lock= changes
     =${engineHash}= and cleanly drops obsolete restore prefixes without
     downloading stale caches.
3. *Per-Unit SHA-256 ActionKey Verification Inside Restored Caches*:
   Inside both =run-fleet --cache=<dir>= (=packages/quint-modules-resolver/src/mbt.ts=)
   and =verify-framework.ts --cache=<dir>=, every model/unit computes:
   $$\mathrm{ActionKey}(u) = \mathrm{SHA256}(\text{schema} \parallel \text{engineDigest} \parallel \text{flags} \parallel \text{transitiveClosure}(u))$$
   - Unchanged models in a touched shard hit exact SHA-256 CAS in $O(1)$ ms.
   - Editing 1 model invalidates *only* that model (and any overlay extending
     it via =@quint-extends= or importing it).
   - Failing verdicts are *never* stored.
   - Active-set GC prunes obsolete entries on save and writes atomically via
     temp-file + =renameSync()=.

* Explicit Limits
:PROPERTIES:
:CUSTOM_ID: study4006-limits
:END:

- Layer-1 caches accelerate dependency installation and browser/toolchain
  bootstrapping; they do *not* bypass lockfile integrity (=bun install --frozen-lockfile=
  still verifies exact hashes).
- On GitHub Actions, PR branches cannot write to the default branch's cache
  scope (security isolation by design); warm Layer-2 CAS hits across unrelated
  PRs reach maximum efficiency after a base branch push populates the base
  cache, while consecutive pushes on the same PR branch warm immediately.
- PR diff auditors (=audit-agent-patch --diff-file= and
  =audit-agent-stability --diff-file=) intentionally run uncached on every PR
  commit so policy decisions always inspect the live diff against =origin/${base_ref}=.
