* Case-study archive: identity and qualification
:PROPERTIES:
:CUSTOM_ID: case-archive-observations
:STATUS: source-inspected
:END:

The earlier [[file:../../30-39-evaluation/30-benchmarks/30.01-benchmark-design.org::#external-references][external reference summary]] records the archive and historical-study
boundaries. Local inspection additionally read the selected run's
[[cases:systems/etcd/modules/raft/runs/etcd-raft-ci-evolution-20260923/.record/manifest.json][record manifest]] and
[[cases:systems/etcd/modules/raft/runs/etcd-raft-ci-evolution-20260923/provenance/upstream-versions.json][upstream version index]].

The manifest identifies a curated historical-evaluation collection and marks
report presence. Its top-level ~source_revision~ is null; actual system revisions
come from the separate version index. That index explicitly distinguishes
standalone raft revisions from old etcd monorepo identities. The manifest also
flags the curated subset and retained historical-path limitations.

Implications for our record contract:

- Archive commit, wrapper commit, run ID and actual system revision are distinct fields.
- A non-null archive identity cannot fill an unknown system revision.
- A report-present status and a metadata confidence label are not replay or acceptance verdicts.
- A file inventory supports provenance checking, not completeness of the execution environment.
- Each missing dependency/artifact gets a qualification state; unresolved source identity blocks source-specific scoring.

For the gateway, apply the same distinction to Library revision, design snapshot,
implementation tree, tested binary, deployment configuration and runtime attempt.
An accepted report about G1 cannot silently become source evidence for G2.

* TLAPS-Bench: grader boundaries in code and controls

:CUSTOM_ID: grader-observations
:STATUS: source-and-test-inspected

#+NAME: inspected-grader-controls
| Source | Inspected behavior / boundary | Transfer to our evaluation contract |
|--------+-------------------------------+-------------------------------------|
| [[tlaps:src/common/check_proof.py][check_proof]] | Independent canonical-target check, official-library shadowing check, context staging and fixed-region integrity | Canonical target/context outside editable Agent workspace; dependency substitution must be checked |
| [[tlaps:tests/common/test_canonical_replay.py][canonical replay tests]] | Staged submitted target uses canonical dependencies and excludes workspace-only modules; fixed scaffold/marker changes are negative controls | A private workspace copy is insufficient; exercise altered dependencies and target-alias cases |
| [[tlaps:src/tlacheck/rules/statement_modified.py][statement rule]] | Compare normalized baseline theorem statements using structured source locations | Check proposition identity independently of proof insertion and shifted lines |
| [[tlaps:src/tlacheck/rules/extra_axiom.py][axiom rule]] | Compare structured assumptions against baseline allowances | Preserve reviewed premises; combine checks rather than treating one detector as complete |
| [[tlaps:src/common/proof_from_scratch_manifest.py][module manifest]] | Declared task/context paths, regular-file checks and canonical task validation | Freeze exact dependency closure and reject ambiguous paths or context leakage |
| [[tlaps:tests/evaluator/test_proof_unit_scoring.py][proof-unit scoring tests]] | A control supplies inconsistent persisted trust counts and a validated module report; the report governs the score | Grade from checked underlying evidence, not self-reported totals |

The context-staging function chooses dependency source according to its required
canonical mode. The integrity function compares fixed segments outside editable
regions. Their presence is source evidence of those mechanisms, not a fresh test
pass or a proof that every invocation enforces them. A caller's mode, manifest and
isolation policy must be bound in the run receipt. Likewise, individual statement
or axiom detectors are parts of a gate suite, not a complete anti-tampering proof.

For engineering tasks, the canonical target includes requirements, obligation
methods, assumptions, standard tailoring and expected outcome. An Agent may propose
a reviewed design revision in a design task; it cannot receive proof-task credit
by silently weakening the original claim. Evaluate revision quality in its own
lane with the original unmet requirement still visible.

* Additions to the independent control inventory
:PROPERTIES:
:CUSTOM_ID: transferred-controls
:STATUS: proposed-not-run
:END:

#+NAME: transferred-negative-controls
| ID | Proposed adverse case | Required grading behavior |
|----+-----------------------+---------------------------|
| EXT01 | Archive metadata exists but actual system revision is unknown | Mark source qualification unresolved; do not score as replayed source case |
| EXT02 | Report is present but dependencies or runtime image are incomplete | Keep replay unqualified; distinguish documentation from execution |
| EXT03 | Agent workspace modifies a model/helper dependency | Grade only the frozen canonical context; reject substitution |
| EXT04 | Canonical target aliases the submitted target | Reject grader setup as an independence failure |
| EXT05 | Submitted proof changes target or reviewed premise outside allowed work | Refuse fixed-task success, preserving the actual reason |
| EXT06 | Result reports trusted counts inconsistent with checked artifacts | Recompute from independently validated evidence; reject misleading totals |
| EXT07 | Canonical-mode or method-policy selection is absent/changed | Treat protocol binding as unresolved or invalid, not an ordinary proof result |
| EXT08 | Sparse checkout omits an asset present in the upstream Git tree | Record local materialization gap; do not misreport upstream absence |

Map EXT03-EXT07 to B0/B2/B3/B5/B6 as applicable. They complement the gateway's
GAP controls and do not imply external code or checker reuse has been integrated.
