The maintained [[file:../config.ss][Config]] disables both languages by default. A downstream
Module combines its assigned values with that Config using Yuanxu's native
=config-defaults=. Only supplied fields override defaults. Nested objects merge
recursively; explicit false stays false, and lists/scalars replace their field.
The result must pass the named Config Type. Examples contain no inheritance,
loader, tool paths, evidence session or custom merge implementation.

* What these settings do
| Path below programs.deterministic-engineering | Meaning |
|----------------------------------------------+---------|
| languages.c.enable | Enable the configured C verification capability |
| languages.c.settings.profile | Select a maintained C Profile, such as capacity-native or capacity-contract |
| languages.cpp.enable | Enable the configured C++ verification capability |
| languages.cpp.settings.profile | Select a maintained C++ Profile, such as lifetime-native |
| languages.<name>.settings.timeout | Per-command wall-clock seconds; default and maximum 45, minimum 1 |

| Language / example Profile | Actual engineering subject | Check |
|----------------------------+----------------------------+-------|
| C / capacity-native | [[file:../languages-engineering/c/numeric/bounded-capacity/][Buffer, parser and pool capacity calculation]] | Native assertions for capacity arithmetic, overflow and preserved failure output |
| C++ / lifetime-native | [[file:../languages-engineering/cpp/memory/resource-lifetime/][Resource ownership and transfer]] | Native assertions for transfer, occupied refusal, cleanup and destruction |

Other maintained choices are C =capacity-body=, =capacity-contract= and
=capacity-callers=, and C++ =lifetime-body=. They select the existing real CBMC
checks. A Profile belonging to another language refuses before tool execution.
This interface currently supports C and C++; it does not advertise executable
support for an unimplemented language.

Omitting C++ while configuring C preserves the C++ defaults. Setting C enable to
false does not change C++ settings. Disabled language plans refuse; prior evidence
is retained as historical data. Assignment does not execute tools or grant
application authorization. Mandatory safety flags remain Library-owned.

* Maintainer verification
=just test-file t/user-configuration-test.ss= checks defaults, the actual Example,
recursive partial overrides, false preservation and all prior selection controls.
Internal selection declarations remain under =t/support/=.

=just test-source-contracts '.*' t/source-contract-owner-config-test.ss= consumes
the actual Example through a native Module owner, compiles and runs the real C and
C++ subjects, and registers/queries both results in ASCENT. It disables only C in
a new configuration snapshot, checks old-owner/result refusal and frozen evidence,
and confirms that C++ remains enabled with its original settings and plan.

=just test-source-contracts= retains the complete actual C/C++ independent counter,
tool-closure and cross-project reuse/invalidation suite. See
[[file:../docs/10-19-design/10-architecture/10.149-unified-language-engineering-configuration.org][the interface contract and qualification limits]].
