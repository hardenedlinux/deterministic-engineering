* Import and assign
:PROPERTIES:
:CUSTOM_ID: user-config-assignment
:PUBLIC_IMPORT: :deterministic-engineering/library/source-contracts/config

Import the maintained Config and assign a value. Examples do not define Types,
inheritance, generic methods, Module loading or verification orchestration.

** Direct assignment
[[file:source-contracts.ss][Use the maintained Config unchanged]].

#+INCLUDE: "source-contracts.ss" src scheme :lines "4-"

** Plain POO object assignment
[[file:source-contracts-disabled.ss][Disable verification while retaining the maintained Settings]].

#+INCLUDE: "source-contracts-disabled.ss" src scheme :lines "4-"

The object literal contains ordinary assigned values. It does not require the
user to declare prototype ancestry. Library Modules own defaults, inheritance,
Types, dependencies and derived plans. A consuming Profile assigns this value to
its verification Config; its existing native dependency refinement and Type
admission supply the final method scope.

* Configuration contract
| Field | Meaning |
|-------+---------|
| enable | Boolean permission to produce this capability's verification plans |
| settings | Complete maintained verification policy, reused from the imported Config in the object-assignment example |

The present policy preserves the 45-second command deadline and required safety
flags. Wrong types, missing required fields and unknown options reject. Partial
Settings merging is not implemented: use the complete maintained value, or supply
a complete value satisfying the named Type. Assignment itself launches no tool,
creates no evidence session and grants no application authorization.

Disabled configuration refuses plan issuance. It does not erase old witnesses or
make an old source owner current. It also does not promise that the Module's
namespace or compiler demand disappears; those are separate native selection
properties.

* Maintainer verification
:PROPERTIES:
:CUSTOM_ID: user-config-verification
:END:

=just test-file t/user-configuration-test.ss= checks the two actual imports and
retains all internal selection-parser controls. Those selection declarations now
live in =t/support/source-contract-modules.ss= and
=t/support/rust-backpressure-modules.ss=, outside the user Examples.

=just test-source-contracts '.*' t/source-contract-owner-config-test.ss= copies
the actual Example files into a real native consumer package. The Profile imports
the enabled value, the existing method compiles and runs the actual native C
subject, and the result is registered and queried through ASCENT. Switching the
Profile to the disabled Example rejects the old owner and old result's current
registration, admits the new disabled dependency and preserves frozen evidence.

=just test-source-contracts= retains the complete actual C/C++, independent
counter, active-tool closure and cross-project reuse/invalidation suite. Product
build roots do not include Examples or these execution helpers. See
[[file:../docs/10-19-design/10-architecture/10.148-flat-declarative-library-boundary.org][the architecture and separate unqualified package/CI gates]].
