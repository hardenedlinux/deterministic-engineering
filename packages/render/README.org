* Ownership
=@deterministic-engineering/render= is a functional static-rendering Library.
D2 / SysML and project adapters own Questions, model relationships, source links
and explanatory content. Architecture and Workflow are separate selected views.
=package.json= is the sole package version source. Namespaces have no version.

No fixed card/page template, closed diagram taxonomy, editor or interactive runtime
is required. Downstream supplies a pure composer, theme layers and SVG icon packs.

* Model and composition
=compileModel(sources, inputPath, options?)= delegates syntax/import compilation
to the official D2 SDK. It returns model IDs, labels, relationships and declared
metadata; D2 geometry and raw SVG are discarded. =compileFigureSource= resolves
that metadata into =FigureInput=. Nested declarations use D2 =|json=.
=modelSource= may select a host-captured OpenSysML result by an existing source
reference, exact model hash and requested view. =compileFigureSource= checks the
captured JSON and directly projects the SDK model without emitting/recompiling D2.
Saved-response tests do not establish live model validation.

=composeFigure(input, composer)= captures immutable sources and invokes a pure
function returning markup/CSS. Its context exposes selected Questions, copy,
references, glyphs, model and project-owned presentation data. The framework
neither invents Questions nor duplicates evidence/authorization registries.

* Layout through mature libraries
=composeDiagram(context, {graph, icons?, edgeLabels?, roles?}, nodeComposer?)=
creates an SVG scene. =graph= uses ELK's own =ElkNode= type and layout options,
not another constraint language. Node IDs and edge identity/direction must exist
in the captured model. By default, edges are the model relations between selected
leaf nodes. The optional callback produces project-specific SVG node contents.

Export loads the declared fonts, measures actual browser SVG text and glyph boxes,
then passes those dimensions to ELK.js. ELK owns node placement, label placement
and routing. The Library applies its returned geometry, checks observed content
containment and node/label overlap, and rejects detected violations. It does not
solve the layout again or silently retry alternative layouts.

The current SVG adapter supports orthogonal and polyline edges, root-owned
single-source/single-target model relations and optional group nodes. Ports,
nested edge containers and spline serialization require a dedicated compositor;
unsupported declarations refuse rather than implying full ELK feature coverage.
ELK's official Node worker uses =web-worker= and is terminated in =finally=.
Function purity alone does not guarantee readable layout or optimal space usage.

#+begin_src typescript
const compose = context => {
  const scene = composeDiagram(context, {
    graph: {id: 'ownership', children: [{id: 'library'}, {id: 'profile'}],
      layoutOptions: {'elk.direction': 'RIGHT', 'elk.edgeRouting': 'ORTHOGONAL'}},
    icons: {library: 'library', profile: 'selection'},
  });
  return {markup: `<section data-question="ownership">${scene.markup}</section>`, css: scene.css};
};
#+end_src

An existing explicitly authored HTML compositor may use XYFlow's public smooth
step path utility for its declared connector endpoints. It is not an obstacle
solver or fallback for ELK scenes. parse5 parses actual Question markers.

* Declarative visual styles
=composePresentationTheme= composes immutable layers: typography/font assets,
semantic CSS, SVG surfaces, palette, spacing and Rough.js =Options=.
Open project roles select theme surfaces; a surface is an ordinary SVG asset,
not a closed rectangle/ellipse enum or another drawing language. ELK
=layoutOptions= can also compose in theme layers; an explicit view option takes
precedence. Layout preferences do not rewrite model relations or Questions. Pure node
composers can use the immutable selected theme as well. D2 selects ordered themes,
icons and variants. =selectFigureVariant= preserves the same model and resolved
custom resources. =FigureResources= allows downstream layers and packs without
editing global registries. New diagram organization belongs in project composers,
not palette selectors or framework kind enums.

Inter fonts are embedded for default metrics; sketchbook embeds Kalam and uses
Rough.js primitives for measured scene frames / explicitly authored surfaces.
Editorial uses open space, typographic hierarchy and distinct publication/external
marks; node-editor defines technical node/connector marks; sketchbook changes
strokes and font metrics. They are complete independent visual layers, not palette
aliases. Node-editor CSS is a separate style layer. Icons are independent SVG assets.
Excalidraw's complete editor and React dependencies are not installed.
Current case language follows its English D2/SysML sources.

* Export and checks
=exportFigure(figure, browser, {scale?, regions?, minimumTextSize?, transparent?})= owns only its browser context.
It returns PNG, offline materialized HTML, explicit SVG scenes and a receipt.
For vector compositions =svg[0]= combines explicit SVG scenes/annotations and
declared =data-surface= backgrounds in document order;
remaining entries are standalone scenes. Arbitrary HTML is not silently converted
to vector. These outputs contain no raster wrapper or =foreignObject=.

Receipts bind source/composition/style/icon fingerprints, fonts, browser identity,
layout input/result hashes, actual dependencies and output hashes. Modified HTML,
invalid assets, hidden selected Questions, detected clipping/overlap and failed
layouts refuse. Host code owns writes and explicit publication. Pixel equality
across operating systems/browser releases and aesthetic optimality are not claimed.
Rendering receipts are not issued C, accepted Q, review R or authority.

The legacy =renderCatalog=, raw D2 SVG pipeline, duplicate D2 theme registry and
example renderer have been removed. No active fallback preserves old layout.

* SDK model adaptation
The SDKs own parsing, checking and transport decoding. D2 observations retain
exact IDs, labels, classes, typed class/SQL members and arrowhead values.
No dotted-name ownership guesses, escape reinterpretation or lifeline ID filters
are applied. Automatic =graphFromModel= uses explicit parents; a nested D2 view
selects its own graph projection. =composeModelView= is an optional pure helper.

The =./opensysml= projection returns a =model= and source trace directly. Captions
use SDK node IDs. =portProjection: owner= is explicit and checks each port
against its endpoint; source references survive owner-level display. Unsupported
notation and unsupported SVG arrowheads refuse. The former generated =text=/
=source= projection result has been replaced in this unpublished PR.

=modelSource={ref,modelHash,view,portProjection?,labels?}= binds an existing entry
in =references= and its actual captured JSON. =FigureResources.sysmlViews= supplies
SDK snapshots. The model selection and trace enter input fingerprints and exported
metadata; source acquisition and evidence admission remain host responsibilities.
No rendering fact confers model validity, review authority or C/Q/R identity.
See [[../../docs/10-19-design/10-architecture/10.143-sdk-model-adaptation-audit.org][10.143 audit]].

SVG endpoint marks currently support =none=, =arrow=, =triangle= and
=unfilled-triangle=. Other D2 Arrowhead values remain in the observed model and
refuse this renderer capability instead of being silently replaced.

* Functional visual resources and readable parts
Theme layers compose style, palette, typography, density and layout options
independently. =./palettes= exports color data; =./layouts= exports optional
ELK preference layers. Downstream can extend both through the existing theme map.
Color/spacing tokens are open, typography uses =--type-<name>=; numeric spacing is
finite/nonnegative. Results deeply clone/freeze assets and Rough options, while
caller inputs remain editable. Later palette selection preserves the visual style.
Compact/comfortable density changes spacing without shrinking type.

Actual layout defaults < theme preferences < explicit view options. Font,
icon, padding and label metrics are measured before ELK. =composeModelView= renders
all selected Questions in declaration order; its page structure remains optional.

=composeHeading(context, {role, text, questionRef?, ordinal?, glyph?})= returns a
pure markup/CSS part. Roles are open. A Question reference checks source wording;
its default =?= role marker is declared in =theme.headingMarkers=. An ordinal may
replace that marker; a domain glyph is independently selected. Whole ordinal /
glyph / text bounds are measured and centered together. Theme CSS defines role
hierarchy; downstream does not need per-heading coordinate patches.

Root figures and independent SVGs have a theme backdrop. Explicit =transparent=
requests a transparent outer canvas. =receipt.readability= observes SVG text sizes
after scene scaling; =minimumTextSize= is the caller's optional CSS-pixel threshold,
not a global readability score. Font/annotation clipping and detected line overlap
refuse; there is no hidden font shrinking or alternate-layout retry.

The source-driven cases live in =packages/render/examples= and run from the repository root with its shared dependency installation.
See [[../../docs/10-19-design/10-architecture/10.144-functional-themes-layouts-and-package-examples.org][10.144 implementation contract]] and the separate architecture/Workflow variants.

* Declared vector surfaces
An HTML host marked =data-surface= (or =rectangle=, =ellipse=, =diamond=) is an
explicit surface declaration. Export materializes it as SVG before capture in
both precise and Rough styles. Its vector background precedes its child headings
and nested surfaces in document order; scene-internal Rough strokes stay inside
their scene. Precise surfaces read the browser's solid color, uniform solid/dashed/dotted border
and uniform pixel corner radius. Unsupported background images, nonuniform /
unsupported border styles and corner forms refuse; declare an SVG asset for those shapes.
Unmarked HTML backgrounds and HTML text are not converted to SVG. Use vector
heading/scene parts for content that must survive standalone vector export.

Dashed/dotted surface borders use SVG dash arrays and browser stroke rendering;
exact CSS-border raster parity and HTML shadows/pseudo-elements are outside this
primitive surface projection. Custom SVG assets can supply a different visual mark.

* Design and Taste public interfaces
=./design= publishes =DesignSchema=, inferred =Design= and =defineDesign=. Source
briefs declare audience, medium, message, selected Questions, required subject /
relation IDs and focal subjects. They enter the existing immutable context and
input footprint. Composition/export refuse missing or hidden required identities.
Variants can replace Design and project-owned presentation through the existing
selection API. Graph ownership stays in explicit ELK children, not dotted IDs.

=./taste= publishes =TasteRule=, =Taste=, =composeTaste= and =reviewTaste=. Pure rules
inspect captured Design and actual readonly browser observations. Reasons and
optional scalar parameters are retained. Notes distinguish observation, advice
and unobserved; no total score, automatic winner or aesthetic acceptance is added.
=minimumTextSize= and =focalBudget= are optional criteria. Downstream extends the
rule list with ordinary functions. Valibot provides schema/type inference; renderer
and browser lifecycles retain their existing owners.

Review verifies output hashes and observations baked into the materialized HTML.
Inspectors cannot mutate the supplied context. They are user code whose purity is
a contract, not sandbox enforcement. Rendering receipts and taste notes are not
model validity, trusted execution evidence or review authority.

#+begin_src typescript
const figure = composeFigure({...input, design: defineDesign(declaration.design)}, compose);
const image = await exportFigure(figure, browser);
const report = reviewTaste(figure, image,
  composeTaste(minimumTextSize(12), focalBudget(1), projectRule));
#+end_src

=receipt.observation= contains browser canvas, subject IDs/roles/display owners,
relation IDs and heading boxes. Internal scene edges and child frames must remain
inside their display scopes; crossing edges are distinguished by an attribute
for project/theme styling. ELK remains the placement/routing owner.

Run =bun run example:design= from the repository root for the real Library/Profile/Scenario
comparison. See [[../../docs/10-19-design/10-architecture/10.145-design-taste-public-contracts.org][10.145 contracts, tradeoffs and controls]].

* Taste before composition and artifact rights

=selectTaste(input, policies)= runs ordered pure selections before composition.
=questionFocus= binds explicit Question subjects/relations; =questionScope= retains
mandatory closure; =dependencyLayout= chooses an existing ELK direction from
model relations; =evidenceFocus= and =visualHierarchy= expose selected source gaps.
Policies are ordinary =TasteRule.select= functions, composed by =composeTaste=;
post-export =inspect= remains optional and separate. No fixed layout catalog is
required. Unknown references, intent/fidelity changes and stale selections refuse.

=EvidenceProjectionSchema= describes source-bound display observations, not
verified execution. Each selected projection binds an actual source reference,
exact excerpt, state, subjects and relations. A supported declaration grants no
approval. The selection and actual export observations remain in the Taste report.

=exportFigure= accepts optional =attribution: {copyright, license}= supplied by
the publishing host. It inserts comment notices before HTML/SVG fingerprints.
No project copyright is assigned to downstream output by default. See
[[file:THIRD-PARTY.org][asset notices]] and the bundled LICENSE and LICENSE.OFL-1.1 texts. This repository
uses official REUSE lint/CI; binary and strict JSON files use standard sidecars.


* Git dependency and package ownership
The repository-root =package.json= is the sole TypeScript package manifest and
version source. Implementation, examples and tests remain under =packages/render=.
The root exports point directly to those sources; no forwarding implementation,
installer hook or duplicated dependency list is maintained.

Downstream Bun consumers install the repository Git URL at a reviewed revision:
#+begin_src sh
bun add @deterministic-engineering/render@git+https://github.com/hardenedlinux/deterministic-engineering.git#<commit>
#+end_src
Bun owns Git fetching and the lockfile. A Git install needs no committed package
archive. Release tags are created only after the package/consumer checks pass.
* Compiler allocation lifetime
=compileModel= owns one ephemeral compiler process and its internal SDK worker.
The result is accepted only after the process closes its worker, disconnects
IPC and exits naturally. The parent waits for native =close= before either
resolution or rejection; spawn/IPC errors are retained until that boundary. No process exit call, signal kill, fallback renderer
or consumer-maintained pool is used. This process boundary releases terminated
Bun worker allocation domains that otherwise remain in the long-lived host.
Concurrent callers remain independent; the Library imposes no CPU-count clamp.
The host still owns cancellation, batch scheduling and browser lifetime.


Lifecycle controls observe real native child handles. They cover successful D2
compilation, synchronous IPC failure, native disconnected IPC, spawn failure,
missing/duplicate results and nonzero exit. The existing 24-call parent RSS guard
remains 256 MiB; caller scheduling and the two-worker browser CI are unchanged.
IPC fault fixtures test protocol admission only; they are not alternate compilers.
The child keeps IPC referenced through worker termination and send acknowledgement,
then disconnects. Removing the last message listener before that point can make
Bun exit before delivering the result, and must not be used as a cleanup shortcut.


* Raster encoding and format choice

The export effect uses pinned Sharp/libvips for PNG and WebP encoding. The default
PNG is losslessly recompressed with compressionLevel 9 and adaptiveFiltering true;
if this grows the file the original browser PNG is retained. Default WebP is also
lossless (effort 4). =preferredRaster= returns the smaller generated raster with
its actual format, MIME type and bytes. The caller uses that extension/MIME; WebP
bytes are never returned under the PNG property. =png=, =regionImages= and =svg=
retain their existing roles. Regions use the same PNG compression options.

#+begin_src typescript
const image = await exportFigure(figure, browser);
const {format, mimeType, bytes} = image.preferredRaster;
// Write bytes to `overview.${format}` or send with mimeType.

// Explicit compatibility/performance choice: skip WebP encoding.
await exportFigure(figure, browser, {webp: false});
// Explicit smaller, lossy alternatives; never implied by a quality value alone.
await exportFigure(figure, browser, {
  webp: {lossless: false, quality: 95, smartSubsample: true},
});
await exportFigure(figure, browser, {
  pngCompression: {palette: true, quality: 95, effort: 7},
});
// Preserve the exact browser PNG bytes if required.
await exportFigure(figure, browser, {pngCompression: false, webp: false});
#+end_src

Sharp owns codec validation and implementation. Unsupported controls refuse; a
quality/quantization control requires explicit lossy WebP or palette PNG selection.
No resizing, global Sharp concurrency/cache mutation, or external optimizer process
is added. Errors propagate through the existing browser-context cleanup boundary.
Receipts bind final PNG/WebP/region hashes, native encoder parameters and input/
output byte counts. The model fingerprint still identifies model/composition;
encoding choices belong to the export receipt. Lossless WebP can discard invisible
RGB beneath fully transparent pixels; alpha and visible content are preserved.

SVG remains an independent vector deliverable for zoomable documentation. Its
embedded fonts, standalone behaviour and editability differ from raster formats;
it is not silently substituted into the raster interface based on size alone.
=bun run example:images= writes PNG/WebP and source-bound size/fidelity observations
for actual repository figures under =.cache/render/raster-comparison/=. It also
reports existing SVG sizes separately. Hosts choose which artifact to publish, avoiding duplicate
committed assets and retaining existing source/publication checks.
