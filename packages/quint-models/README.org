* Overview

=@deterministic-engineering/quint-models= is the reusable Quint model library
projected from =hardenedlinux/deterministic-engineering= and distributed as a
read-only =git subtree= mirror.

It organizes finite-state protocol specifications into two primary domains,
together with methodology guides, Zero Trust state-layer mappings, and research
references:

1. *Threat-First Modeling (=threat/=)*: pre-implementation security and Zero
   Trust state-machine models — capability acquisition, authority currentness,
   exact-effect handoff, blast-radius containment, and monotonic state against
   host rollback.
2. *Engineering State Models (=engineering/=)*: deterministic systems-engineering
   state machines addressing *Concurrency* (backpressure, memory budgets,
   ownership), *Parallelism* (scheduling, work-stealing, barrier synchronization),
   and *Garbage Collection* (tri-color invariants, write barriers, safepoints).

* Consuming Models

Official =@informalsystems/quint= resolves relative paths only. To import models
from this package using bare package specifiers, pair it with
=@deterministic-engineering/quint-modules-resolver= and pinned
=@informalsystems/quint= (=0.33.0=):

#+begin_src quint
module my_wallet_host {
  import state_rollback(MaxSends = 1).*
    from "@deterministic-engineering/quint-models/threat/state-rollback/StateRollback"
}
#+end_src

Every model directory ships a single self-contained pure =.qnt= file with
embedded verification directives (=// @quint-model=, =// @verify=,
=// @countermodel=). Git commit integrity owns provenance — no redundant
=plan.json= or =receipt.json= sidecars are committed.

* Limits

These models are finite-state protocol abstractions checked with bounded model
checking (Apalache) and deterministic traces. They do *not* prove cryptography,
compiler/codec correctness, kernel isolation, or physical storage atomicity.
Every model declares its explicit limits in its =// Limits:= header directive.
