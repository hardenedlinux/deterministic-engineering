* Overview

Beyond security and Zero Trust threat boundaries, Quint is equally effective for
*systems-engineering determinism*: verifying finite-state protocols where
interleavings, resource budgets, parallel scheduling, or memory reclamation can
violate safety or liveness invariants.

All engineering models live under =engineering/= and are partitioned into three
sub-domains corresponding to distinct runtime failure classes:

| Sub-domain | Path | Failure Classes Addressed |
|------------+------+---------------------------|
| *Concurrency* | =engineering/concurrency/= | Backpressure exhaustion, memory-budget overrun, ownership leaks across async boundaries, cancellation races, non-idempotent retries |
| *Parallel* | =engineering/parallel/= | Work-stealing deque ABA/lost-task races, barrier/phase desynchronization, epoch-based reclamation (EBR) premature free, parallel worker admission |
| *GC* | =engineering/gc/= | Tri-color invariant violations (black-to-white pointer without barrier), lost objects during concurrent marking, mutator/collector safepoint deadlocks, write-barrier omission |

* 2. Parallel (=engineering/parallel/=)

Parallel runtime primitives fail subtly when multiple workers mutate shared
metadata concurrently without a global lock. Quint models in =engineering/parallel/=
target:

- *Work-stealing deques (Chase-Lev)*: verifying no task is lost or executed twice
  under concurrent owner =push/pop= and thief =steal=, plus countermodels for
  missing memory ordering / CAS failure handling.
- *Epoch-Based Reclamation (EBR)*: verifying that no worker dereferences a
  retired object while pinned in an active epoch, with a countermodel for
  premature epoch advancement.
- *Parallel Admission & Barriers*: bounded worker-pool admission derived from
  observed host budgets, preventing oversubscription and barrier livelock.

* 3. Garbage Collection (=engineering/gc/=)

Concurrent and incremental garbage collectors are classic state-machine
verification targets: a single missing write barrier or misordered handshake
produces rare, non-deterministic use-after-free or heap corruption.

Quint models in =engineering/gc/= target:

- *Tri-Color Marking & Write Barriers*:
  - State: object graph colors (=White=, =Grey=, =Black=), mutator pointer
    writes, collector mark/sweep steps.
  - Hardened invariants: *Strong Tri-Color Invariant* (no Black object points to
    a White object — Dijkstra insertion barrier) or *Weak Tri-Color Invariant*
    (any White object reachable from Black is also protected by a Grey path —
    Yuasa SATB deletion barrier).
  - Required countermodel: =stepNoWriteBarrier= (mutator stores a White pointer
    into a Black object and drops the old reference → collector sweeps a live
    object, violating =noLiveObjectSwept=).
- *Mutator/Collector Safepoints & Handshakes*:
  - Asymmetric safepoint polling and phase transitions (=Idle → Mark → Remark →
    Sweep=) ensuring no mutator runs with stale barrier state across phase
    boundaries.

* Shared Verification Discipline

Just like =threat/= models, every =engineering/= model must:

1. Declare explicit abstraction limits (e.g. finite heap size, abstract memory
   model rather than hardware TSO/ARMv8 weak memory unless explicitly modeled).
2. Ship =plan.json= and =receipt.json= bound to =deSourceCommit=.
3. Pair every safety invariant with at least one *broken-invariant countermodel*
   (such as missing write barrier, missing CAS check, or dropped backpressure
   guard) that fails at bounded depth with an inspectable ITF trace.
