* Why Threat-First Modeling?

Conventional security engineering treats threat modeling as post-hoc prose
(architecture diagrams, checklists, or audit spreadsheets) detached from
executable state transitions. By the time code is written, subtle state-machine
bugs — stale authorization tickets, missing durable acknowledgements, unverified
clearing reports, host-rollback replay, zombie refresh tokens, or cross-tenant
egress leaks — are already baked into control flow.

*Threat-First Modeling* inverts this order:

1. *Model the threat boundary before implementation*: express attacker
   capabilities, trust boundaries, authority freshness, and irreversible external
   effects as a finite-state machine in Quint.
2. *Separate reusable protocol primitives from scenario bindings*: keep generic
   guards and state transitions in
   =@deterministic-engineering/quint-models/threat/<subdomain>/<model>/*=,
   and let downstream projects (such as =cedar-poo-spec=) bind concrete domain
   capability graphs, constants, and host observation bits.
3. *Require both positive proofs and auto-derived negative countermodels*: a
   safety invariant that passes only because transitions are vacuous proves
   nothing. Every security-critical guard is wrapped in a typed Scheme AST
   =(guard id expr)= node and paired with an *auto-derived weakened
   countermodel* that drops that single guard and produces an explicit Apalache
   ITF counterexample.

* The Four-Layer Workflow

#+begin_example
Co-Located Scheme POO AST Unit (packages/quint-models/<domain>/<subdomain>/<model>/)
   │  types.ss + objects.ss + interface.ss (Yuanxu Design 165 slots + 3-axis Profiles)
   ▼
Pure Quint Projection (library/quint-methods/ + library/quint-profiles/)
   │  Validates typed AST refs, derives countermodels by guard pruning,
   │  emits self-contained *.qnt (embedded // @quint-* headers) + README.org
   ▼
Subtree Distribution (@deterministic-engineering/quint-models)
   │  Consumed via bare specifiers with @deterministic-engineering/quint-modules-resolver
   ▼
Downstream Scenario Gate & MBT Refinement (e.g. cedar-poo-spec / host implementations)
   │  Binds domain capability graphs, constants, or AST overlays (compose)
   ▼
Bounded Verification (Quint 0.33.0 + Apalache 0.62.1)
   ├─ Deterministic traces (seed=7, max-samples=1)
   ├─ Positive bounded check (profile bound.*, exit 0)
   ├─ Required broken-boundary countermodels (exit 1 + ITF predicate check)
   └─ Model-based testing (--mbt ITF trace replay against concrete implementations)
#+end_example

* Mandatory Discipline for Every Threat Model

** 1. Explicit Limits and Trust Assumptions

Every module must state what it *does* model (finite-state transitions, authority
currency, durable-ack ordering, quarantine retention, revocation epochs) and what
it *does not* model (cryptography, real consensus, codec parsing, side channels,
or implementation refinement unless separately checked via =--mbt= ITF replay).

** 2. Hardened Step vs. Auto-Derived Weakened Countermodels

Never weaken the hardened =step= action to test failure modes. Instead:

- Keep =step= strictly hardened and verify emergent relational =safety= at the
  converged positive depth (default =12=, expected exit =0=).
- Declare each countermodel with =derive-from-transition:= and =dropped-guard:=
  so =library/quint-methods/ast.ss= structurally prunes that single guard from
  the hardened transition and emits a separate weakened =step*= action (or, for
  additive host-environment attacks like =state-rollback=, declares the explicit
  host fault transition).
- Verify each countermodel at bounded negative depth (default =6= or profile
  override =bound.extended-counterexample= / =bound.deep-counterexample=,
  expected exit =1=) and assert on the generated Informal Trace Format
  (=*.itf.json=) that the exact intended failure predicate holds.
- Enforce Band-5 monotonic =governance.mandatory-countermodels= via Yuanxu
  Design 165 so no peer profile can silently disable countermodels on stateful
  models.

** 3. False-Claim Witnesses

Where operators or stakeholders might assume a control does more than it
actually can (for example, assuming a local =pause= cancels an already-settled
external transaction or revokes an already-confirmed external delegation), encode
those assumptions as explicit *false-claim invariants* (=falseCancelClaim=,
=falseRevokeClaim=) and require Apalache to refute them with retained ITF traces.

** 4. Self-Contained Pure =.qnt= Directives & Commit-Bound Provenance

Every projected =.qnt= embeds its verification contract directly in leading
header directives (=// @quint-model=, =// @quint-version=, =// @apalache-version=,
=// @verify=, =// @countermodel=, =// Limits:=) with zero JSON sidecars:

- Downstream gates pin exact mirror commit SHAs in =package.json= + =bun.lock=,
  verify all installed models via =quint-modules-resolver verify-deps=, and run
  =quint-modules-resolver run-plan <Model.qnt> --verify=.
- DE CI re-projects all 34 co-located models dynamically from =init.ss= and
  refuses any drift between Scheme POO sources, =*.qnt=, and =README.org=.
