* Emergent Safety Invariant

Live persisted state files are never truncated in-place (tornReads == 0), concurrent writers stage into disjoint unique temp files in the target parent directory (tempCollisions == 0), every staged file is fsynced before atomic rename so crashes never leave zero-length live files (zeroLengthOnCrash == 0), and failed writes remove staged temp artifacts (orphanTemps == 0).

#+begin_src quint
val safety = (h.committedVer >= 1 and h.activeUniqueTemps >= 0 and h.activeUniqueTemps <= h.maxWriters and h.tornReads == 0 and h.tempCollisions == 0 and h.zeroLengthOnCrash == 0 and h.orphanTemps == 0)
#+end_src

* Grounded Papers & Specifications

- *T. S. Pillai et al. (USENIX OSDI 2014 Best Paper)*: All File Systems Are Not Created Equal: On the Complexity of Crafting Crash-Consistent Applications — renaming an un-fsynced temp file can expose a zero-length live file after crash.
- *J. Bornholt et al. (ACM ASPLOS 2016)*: Specifying and Checking File System Crash-Consistency Models — atomic write-temp + fsync + rename + parent-dir sync prevents torn state across concurrent readers and crashes.
- *IEEE Std 1003.1 POSIX rename(2) Semantics*: Atomic directory entry replacement requires disjoint per-writer temp files (PID/counter/nonce) so concurrent writers never collide on a shared .tmp path.
