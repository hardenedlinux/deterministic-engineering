* Emergent Safety Invariant

Subprocess stdout/stderr capture retains at most maxRetainBytes in heap (peakRetainedBytes <= maxRetainBytes, never buffering full output before post-hoc truncation), continuously drains excess pipe bytes into a fixed-size discard buffer until EOF so the child never deadlocks on a full kernel pipe (pipeDeadlocks == 0), and enforces an explicit byte cap on every line-framed subprocess read (lineCapBreaches == 0).

#+begin_src quint
val safety = (h.retainedBytes <= h.maxRetainBytes and h.peakRetainedBytes <= h.maxRetainBytes and h.retainedBytes >= 0 and h.discardedBytes >= 0 and h.pipeDeadlocks == 0 and h.lineCapBreaches == 0)
#+end_src

* Grounded Papers & Specifications

- *W. R. Stevens & S. A. Rago (Addison-Wesley 2013)*: Advanced Programming in the UNIX Environment (APUE, Ch. 15 Pipes) — failing to drain stdout/stderr pipes past kernel pipe-buffer capacity blocks the child writer and deadlocks parent wait().
- *M. Grottke & K. S. Trivedi (IEEE Computer 2007)*: Fighting Bugs: Remove, Retry, Replicate, and Rejuvenate — unbounded wait_with_output/read_to_end followed by post-hoc truncate() retains spike payloads in heap until OOM.
- *S. A. Crosby & D. S. Wallach (USENIX Security 2003)*: Denial of Service via Algorithmic Complexity — unbounded single-line BufReader::read_line() without a byte limit lets a single delimiter-free payload exhaust host memory.
